# Experimental presentation services

This package ports the presentation controller, connection-source, Models facet, and server service-host logic from the pinned upstream files under `packages/coding-agent/src/experimental/services/`. It is an opt-in library. It does not change command dispatch, start a client, open a socket, select a model by default, or contact an external service.

## Host boundaries

`AgentController` carries the `pi.agent-controller` command contract. `CreateAgentController` consumes an `AgentLane` adapter. The adapter returns tagged admission failures as `harness.TaggedError` and Promise rejections as ordinary Go errors. It projects completed or suspended observations into `LaneOperation`. It projects compaction and navigation results from their `compaction` and `navigation` members. The controller retains admission versus terminal failure, strips private result details, and awaits every command.

`CreateServerServiceSource` and `CreateSessionServiceSource` consume a `ServiceClient`. Each source owns the bindings returned by `ServiceSourceOptions.NewBinding`. The caller supplies a Chord host binding implementation. The source does not own the client or its transport. `ServiceClient` owns catalogue request completion, cancellation, and shutdown draining. A catalogue request can outlive source disposal, as it does upstream.

The client invokes lifecycle listeners in event order after updating its current state. The binding starts `Rebind` synchronously in invocation order and invokes its completion exactly once. `Ready` synchronously registers a hydration/release waiter and completes inline when already settled. Both adapter methods return promptly. These callback boundaries retain the synchronous prefix of upstream's Promise operations. Starting blocking methods in independent goroutines can reorder detach and attach or change which immediately rejected readiness error reaches the caller.

`Ready` cancels only a waiter, not shared hydration or the underlying attachment. Source readiness starts waiters in binding insertion order, cancels and drains remaining waiters on the first failure, and preserves that failure rather than an induced cancellation. Already-settled failures follow invocation order; a later binding's asynchronous rejection does not wait for earlier pending bindings. Background server transitions run in order. Session transitions can overlap. Initial lifecycle publication precedes transition registration; a listener panic propagates without creating transition work. Revision and full attachment identity prevent old completions from publishing current state. Disposal removes the listener, drains source-owned transitions, and attempts every remaining binding's disposal. It does not dispose the client.

`SourceState` exposes lifecycle snapshots and context-bearing hydration/update deliveries. It hydrates subscriptions synchronously, including reentrant subscriptions. It suppresses equal replacements and preserves publication order. Each publication snapshots listeners when delivery starts; removing a listener affects later publications, not the current snapshot. A subscriber does not replay publications at or before its hydration sequence. Publication attempts every listener before propagating a listener panic or an aggregate. Callbacks run outside source locks. Callbacks and error reporters must return promptly. The caller must not synchronously dispose a source from a callback whose transition that disposal would drain.

## Concrete server and Models hosts

`CreateModelsServiceFacet` returns an `internal/chord.Facet`. Its setup provides `pi.models` with concrete replicated state. The Chord host connects bindings with a background context and activates the provider after setup, using the background context for lane reads. Method calls retain the caller's context. The Models contract registers both its guarded service view and its typed remote client. In-host consumers use Chord's loopback replica. Retained methods and state follow provider replacement, and retained views reject access after their consuming facet retires. The caller supplies the configuration lane, optional model catalogue runtime, and optional settings manager. Creating the facet does not read the lane or activate a provider.

`CreateExperimentalServerServices` reads the initial Session directory with the background context. Its `Host.AttachClient` creates a connection-scoped provider and endpoint for `pi.session-directory`, `pi.session-management`, and `pi.presentation-plugins`. Attachments share the directory and one FIFO mutation queue. Each attachment retains its own prepared package selection and owns its subscriptions. A nil selection request means defaults. An explicitly empty selection means no packages. Failed preparation or failed detachment retains the prior selection. Successful detachment clears only that attachment's selection.

Create and remove refresh the directory only after the application operation succeeds. Removal first awaits the presentation's attachment cleanup. A failed directory read retains the last published revision and snapshot, even when the preceding storage operation succeeded. The next mutation still runs after a failure. The queue does not check cancellation or substitute contexts. Each admitted callback receives its original context after preceding operations finish. Pass `context.Background()` to `Refresh` for upstream's omitted-context behavior.

Attachment release removes subscriptions immediately and rejects new calls. Server disposal releases current attachments before joining the queued mutations. It does not cancel admitted application operations. The mutation queue creates no background goroutines. It retains one completion channel per in-flight call and one settled tail. The caller owns admission and cancellation of external requests. An application callback must not wait on a mutation that it queues behind itself.

These factories exercise the concrete local Chord host, endpoint, operation stream, and replica. The package does not supply a durable lane watch/snapshot/reducer implementation or a Session worker host. The controller's narrow `AgentLane` adapter is not that durable observation contract. The connection sources still require the client's binding adapter and routed transport.

## Go representations

Go uses one namespace for types and values, so `AgentControllerID` names upstream's service token. Contexts are leading parameters on controller methods. Nullable fields use pointers or nil slices without `omitempty`. The anonymous cancellation response has the Go name `AgentCancelQueuedResponse`.

The consumer-owned lane contract contains only controller-consumed arguments and result fields. It does not declare a second durable harness runtime. The client and binding contracts contain only operations used by connection sources. They do not implement Chord wire encoding, keyed instance management, or client connection establishment.

## Evidence

Run `go test -race ./internal/experimental/services`.

The tests exercise local controller and binding paths. `TestControllerMatchesPinnedProvider` executes the exact pinned TypeScript provider with local lane outcomes. `TestConnectionMatchesPinnedSourceWithLocalBindings` executes the exact pinned connection-source bodies with local client and Chord dependencies. The probe replaces imports only. It compares lifecycle states, catalogue retention, rebind order, and ownership cleanup. The changing wall clock is checked separately for ISO millisecond formatting.

The controller and connection lifecycle tests use barriers for delayed hydration, replacement, cancellation, and disposal. They also cover client-owned catalogue requests, early readiness failure, stale completion rejection, aggregate errors, inactive bindings, and subscription order. Those tests do not claim framed-transport, Chord-host, durable-AgentLane, or published-CLI integration coverage.

`TestModelsFacetOnConcreteChordHost` exercises delayed activation, background-context lane reads, and remote state publication. `TestFacetHostReadinessUsesBackgroundContext` in `internal/chord` checks upstream `facets/host.ts`'s background-context connection rule independently of caller cancellation. `TestModelsFacetConsumerRetainsGuardedServiceAcrossReload` exercises every Models method through the concrete host's in-host loopback, caller cancellation and errors, retained state subscriptions across provider replacement, and access revocation after consumer retirement and host disposal. Both new regressions fail on the unmodified runtime; removing the guarded-view registration or returning an unguarded target also fails the Models consumer regression. `TestServerServicesMatchPinnedUpstream` compares the complete structured trace to the unmodified pinned server and Chord sources. Calls and publications cross the local provider, endpoint, JSON-copy transport, and replica. `TestServerMutationsFIFOAndDisposeDrainFailure` compares disposal ordering against an exact-source oracle and checks context retention separately. Compiling mutations demonstrate that the tests reject broken activation context, FIFO ordering, disposal draining, detach selection clearing, and removal preparation. Failure tests cover initial reads, storage mutations, refreshes, and retained snapshots. Concurrent tests exercise independent selections for 128 attachments. No test contacts a network service or claims durable-lane or CLI integration.

Run `go test ./internal/experimental/services -run '^$' -bench 'Benchmark(SourceStatePublication|ConnectionLifecycle|ServerServiceLifecycle)' -benchmem` to measure state publication, an eight-binding attach/detach/dispose lifecycle, and a server lifecycle with 16 subscribed attachments and 256 advertised Sessions. Every source-owned transition is drained. Catalogue tasks remain client-owned. No extension IPC runs on an input or render loop in this package.
