# Divergences

Pig preserves upstream pi-coding-agent's observable behavior unless an entry below records an intentional exception. Numbers are stable identifiers; do not reuse a retired one. Read this page with `pig docs show divergences`. The call sites and evidence for each entry are in the PiG source repository. This page lists every active divergence. [Additive features](additive-features.md) lists the PiG-only features an author needs.

## Behavior differences

| ID | Title | Summary |
|---|---|---|
| D2 | Pig branding | Banner says "PiG", binary is `pig`, config root defaults to `~/.pig`. `PIG_USE_PI_DIRS=1` explicitly selects Pi's agent directory and project `.pi` resources. See [Configuration](config.md#using-pis-directories). A binary named `pi` refuses to run. |
| D14 | Archive extraction | The tools manager extracts archives with the Go standard library instead of spawning `tar`, `unzip`, or PowerShell. |
| D26 | PiG never identifies as Pi | Every value Pi sends to identify itself carries PiG's value instead, in the Go host and in the Pi JavaScript that Node extensions use: OpenRouter, NVIDIA and Cloudflare attribution headers (gated by the telemetry setting, as in Pi), the OpenCode client header, the OpenAI Codex `originator`, the xAI `referrer`, the user agent and `AI_AGENT=pig`. Pi-owned endpoints route to `pi-in-go.dev` or are refused, as D62 and D64 describe. GitHub Copilot's editor headers and Anthropic OAuth's `claude-cli` user agent stay as Pi sends them, because those providers require them. |
| D27 | Word segmentation engine cache | Word segmentation always matches ICU with a warm dictionary-engine cache; a fresh Pi process can place one boundary differently at a U+30FC or U+FF70 span start. |
| D30 | Extension runner scope | The extension runner belongs to the host and is not rebuilt on an in-process session switch. |
| D37 | Stale thinking signatures | When a provider rejects stale thinking-block signatures, Pig retries once with the signatures stripped. |
| D39 | Self-update | A standalone binary updates itself from a release instead of through a package manager. |
| D44 | Herdr image capability | With `HERDR_ENV=1`, Pig ignores inherited outer-terminal image hints. |
| D48 | Orphaned tool results | Orphaned and duplicate tool results are removed from normalized history. |
| D51 | Interactive SIGINT | SIGINT restores the interactive terminal before numeric exit 130. Print/JSON leave SIGINT to the default signal action. Both products restore a live terminal on SIGTERM/SIGHUP; a disconnected terminal exits 129. |
| D53 | Wrapped-row clearing | The renderer fully clears when a differential rewrite would leave wrapped rows behind. |
| D55 | Debug hotkey | The `ctrl+shift+d` debug hotkey fires once per press, not again on key release. |
| D56 | Subprocess liveness | Heartbeats, request-state reporting, and renderer isolation for subprocess extensions. See [Extension API](extension-api.md). |
| D57 | Unloadable install source refused | `pig install` fails when a complete conventional extension source is selected as a Package root and nothing would load, and records nothing. Pi reports success and the resources never load. Empty packages still install. See [Extensions](extensions.md). |
| D61 | Session replacement | Replacing the session keeps the startup project's Services and Resources. |
| D62 | `/bug` | Writes a local report archive and prints a prefilled PiG issue link. Nothing is uploaded. |
| D64 | Hosted endpoints | The share viewer, install report, version check, and installer API use `https://pi-in-go.dev` instead of pi.dev, with the same paths and overrides. |
| D65 | PiG User-Agent | HTTP providers and local bug-report metadata use `pig/<coding.Version> (<platform> <release>; <arch>)` instead of Pi's package-specific `pi...` identities. Configured provider headers retain upstream precedence: they override ordinary defaults, while Codex forces the product identity; Anthropic OAuth keeps `claude-cli/2.1.280`. |
| D66 | Narrow TUI rows | Truncated text reduces fixed padding and the user-message selector clips list rows when an unusually narrow pane cannot fit upstream's full row. PiG stays within the requested width; Pi terminates only if an over-wide row reaches its differential-render overflow check. |
| D68 | Windows owner-only files | Windows has no POSIX mode bits, so files PiG keeps owner-only (Piglet secrets and signing keys, the staged secret environment, the update transport CA, and the standalone update receipt) are checked and written by DACL there: only the owner, SYSTEM, and Administrators may have access. Elsewhere they use mode `0600`. |
| D70 | Module state across session replacement | Every session replacement (`/new`, `/resume`, `/fork`, `/clone`, `ctx.newSession()`, `ctx.fork()`, `ctx.switchSession()` and their RPC equivalents) starts extensions in fresh runtime processes, so module-level state and `process.env`/`globalThis` changes reset. Pi keeps an `.mjs` module's state in Node's module cache. `/reload` is not affected: it re-invokes each factory in the process that holds its module, as Pi does. Keep per-session state inside the factory. |
| D73 | Live main-process object identity | Extensions use Pi's pinned coding-agent and TUI implementations for imported objects, including independent Sessions, ModelRuntime, themes, ScrollView, terminal/image helpers, and caller-created screens. These objects do not expose the live Go Main Screen or arbitrary Go component references. An overlay's `unfocus({target})` accepts `null`, the extension's installed editor component or another of its mounted overlays and throws for any other component. Editor input and rendered frames cross the subprocess connection. |
| D74 | Pi-ai provider calls in extensions | An extension's `stream`, `complete`, `streamSimple` and `completeSimple` use Pi's own dispatch and credential rules, and the request runs on PiG's port of the same provider. Provider-specific `stream()` options beyond the common ones are not forwarded, results lack `responseId` and `rawStopReason`, and OpenRouter image generation returns an error. A direct pi-ai call also carries PiG's OpenRouter and NVIDIA attribution headers, which Pi's pi-ai does not send there. |
| D78 | SDK Provider object carriers (known gap) | Registered-native methods cross SDK processes. Builtin/composed native SDK retrieval remains incomplete, and foreign registered configuration is snapshot data rather than an author's live object. Owner-approved for 0.3.x on 2026-09-28, not completed parity. |
| D79 | User-package metadata registry isolation | User-scoped package version lookups run from managed storage, not the invoking project's cwd, so its `.npmrc` cannot redirect them. The selected command and user configuration remain active. Trusted project-scoped packages keep Pi's behavior. |
| D80 | Secret-input privacy | `maskSecretInput` defaults to true and shows dots, a count and a last-four suffix for secret login input. False restores Pi's plain-text behavior. Change **Mask secret input** in `/settings`. |
| D82 | Partial-message observation (RPC33) | Foreign partial messages are snapshots, not live references. Initial content/usage/stop state and named parser scratch fields can differ. The strict RPC33 comparison retains its raw failure. |
| D83 | Cross-process event-bus boundaries (known gap) | Every Node extension shares one `pi.events` bus and listeners in other processes receive the original payload by reference. Independent tasks in different processes are ordered by timing, only a listener's first post-await continuation is ordered with the emitter's microtasks, cross-process reference cycles are released when a process exits, and brand checks such as `util.types.isMap` fail on foreign objects, where `util.types.isProxy` also returns true. Because V8 offers no hook, `util.inspect` with `customInspect: false` (`console.dir`) prints an empty placeholder object (inside `Proxy(...)` on Node 26.0.0 and later), `util.inspect` with `showProxy: true` shows the Proxy wrapper, and on Node 26.0.0 and later `util.inspect` of a non-extensible foreign payload prints it inside `Proxy(...)`; Node 25 and earlier print that payload as Pi does. Every other inspect, clone and write case must match Pi; the Promise nesting level and cross-owner shared clones are open defects targeted at 0.3.1. |
| D84 | Direct Go provider registration | A Go caller that registers a Provider directly on the Model Registry or Model Runtime, without an extension host, sees the synchronous projection until its next awaited model-runtime call runs Pi's local refresh. Extension-host registrations match Pi. |
| D85 | RPC stdin-end residuals | After RPC stdin ends, a suspended extension command's continuation (timer, I/O, nested `setImmediate`, child process) can still run its side effects before PiG stops that runtime process; Pi never runs it, and stdout matches Pi. A suspended `session_shutdown` handler in one runtime process does not keep another runtime process's command alive, so PiG does not print a response that Pi prints. |
| D86 | RPC settle-tail stdin hold | In RPC mode PiG holds stdin from `agent_end` until `agent_settled`, as Pi does in effect. A settle-tail handler in the Go, Rust or Python SDK that waits on a timer or I/O keeps the hold closed, so a command sent during its wait is answered after `agent_settled`, where Pi answers it during the wait. Node handlers report their wait and match Pi. Temporary: removed when those SDK runtimes report a tail handler's suspension. |
| D87 | PiG's easter eggs | In fullscreen mode, clicking the pig in the header plays Pi's logo animation with the pig head; where Pi's logo plays its puzzle, a big side-view pig in the sprite's colors runs in place. In fullscreen mode `/arminsayshi` plays Pi's 3D egg with the sprite's pig head where Pi shows Armin; elsewhere it draws a pig head labeled `pigsayhi` with Pi's effects. `/pigsayhi` is a second name for it. `/dementedelves` is Pi's. |
| D88 | PiG first-time setup | On an interactive start in the default agent directory with no `settings.json`, PiG shows Pi's first-time setup dialog on its own screen before the session starts (theme with live preview, then analytics opt-in) with a sprite step between them that previews the built-in sprites and ends with `Create your own...`. As in Pi, `PIG_CODING_AGENT_DIR` skips it. Pi shows the dialog only for its official distribution with `PI_EXPERIMENTAL=1`. |
| D89 | Tool renderer resolvers of extension processes | A Node, Go, Python or Rust extension's `pi.registerToolRenderer()` resolvers are asked once per tool, off the interactive loop. Until the extension answers, a tool card draws with the renderers `next()` returns; a different answer then draws the tool's cards again. `next()` returns a marker for those renderers: a resolver can return it but cannot call or wrap its render functions. In-process Go extensions, including the built-in MCP extension, resolve as Pi does. |
| D90 | llama.cpp thinking levels | A llama.cpp model whose chat template supports thinking offers the off, minimal, low, medium and high thinking levels, and each level sends its own `thinking_budget_tokens`. Pi offers only off and medium and sends no budget. |
| D93 | /reload evaluates an edited ES module extension again | Pi keeps an edited `.mjs` extension, or a `.js` one under `"type": "module"`, until it restarts, because Node caches ES modules by URL. PiG's `/reload` evaluates the edited ES modules and the local modules that import them again, decided once per reload pass, so an unedited shared module keeps one instance. An edit that breaks the module fails that extension on `/reload`, and a re-evaluated module's `import.meta.url` carries a `pig-reload` query. |
| D94 | Subprocess editor working status | An editor that embeds working status gets host-driven animation snapshots instead of running Pi's own timer, and its opt-in is read once at install rather than each time a status is shown. Colors and rows match Pi. |
| D96 | Remote execution daemon | The `pi-env` daemon that `env` deploys over SSH is a Go program with Pi's command line and wire protocol, not Pi's Rust binary. Pi and PiG share the `~/.pi/mobile/tools` directory and each deploy removes the other tool's daemon, so a host used by both uploads again when the tool changes. |
| D99 | Windows npm self-update waits out a held image | Before an npm update on Windows, Pi moves the running image with one rename, which fails while anti-virus or an indexer has it open. PiG retries that rename for up to 10 seconds and then fails with the same error. |
| D98 | Eval harness OAuth credential file | The documentation and host evals run the agent as a pig process. An API key stays in the harness, as in Pi. An OAuth credential is written to the run's isolated `auth.json`, which the agent's file tools can read; Pi's eval harness keeps it in memory. The run's root is removed afterwards and the evals are a developer tool. Owner sign-off is pending. |
| D103 | JS Error.stack is not modelled | Pi copies `error.stack` into a diagnostic's error info and into error snapshots, so a persisted diagnostic can carry a JavaScript stack trace. PiG's `DiagnosticErrorInfo.Stack` stays empty and PiG error types have no `stack` member; the error type's `Name()` is the inherited `name` and `Unwrap()` is `cause`. A Go stack would name build-machine paths and could not match Pi's text. |
| D105 | The interactive driver owns terminal input | In Pi, `TUI.start()` reads stdin and runs the color replies, the input-listener chain and the focused component. In PiG the interactive driver owns the raw-mode reader and calls the renderer's consumers in Pi's order for each chunk. An extension's terminal-input listener runs after them, asynchronously, because an extension is a subprocess and no blocking extension call may run on the input loop. |
| D110 | Git package sources | `#subdirectory=` selects a subdirectory of the repository for a Piglet source; `git://` and upper-case-scheme sources, and `git:file://` sources, resolve to a usable repository. Pi reads the subdirectory spelling as a ref and returns repositories no Git client can clone. |
| D111 | Aborted extension tools | When a run aborts while an extension tool runs, PiG fires the tool's abort signal and waits 3 seconds for it to settle; a tool that has not settled then fails with `Operation aborted`. Pi waits without a limit. |
| D113 | A Session has no `extensionRunnerRef` cell | Pi's `AgentSessionConfig.extensionRunnerRef` is a cell the caller creates and the session assigns on every runtime build. PiG's `SessionOptions` has no such field: a Session reads its own current runner, and `Session.ExtensionRunner()` returns it after every replacement. |
| D114 | `StdinBuffer` has no listener limit | Pi's `StdinBuffer` inherits Node's limit of 10 listeners per event, `getMaxListeners` and `setMaxListeners`, and Node warns on stderr when a registration passes the limit. PiG's `tui.StdinBuffer` accepts any number of listeners without a warning. |
| D115 | Gemini 2.x tool-result images follow the whole run of function responses | For a Google model without multimodal function responses (a `gemini-*` id below version 3), PiG sends the "Tool result image:" turns of a run of tool results after the last function response of the run, so every function response of one model turn stays in the single user turn after it. Pi pushes each image turn right after its result. |
| D116 | Bedrock Converse messages of one role are merged | PiG's Bedrock Converse request merges adjacent messages of the same role into one message whose content blocks keep their order. Pi pushes every user message, tool-result run and assistant message as its own message and never checks the previous role, so two user messages can sit side by side. |
| D117 | `DiscoverAndLoadExtensions` takes no event bus | Pi's `discoverAndLoadExtensions` hands an optional `eventBus` to every extension it loads, so the call's extensions and the caller share one `pi.events` bus. PiG's `coding.DiscoverAndLoadExtensions` takes a context instead and no bus: the Extension Host routes `pi.events` between the extensions it hosts, so the extensions of one call share that bus and a caller cannot join it. |
| D118 | A durable commit with an unknown task or submission status fails | A commit to PiG's `MemoryStorage`, or to the JSONL storage built on it, whose task or submission status is outside the closed set fails before anything is stored, with `Unknown task status "<status>"` or `Unknown submission status "<status>"`. Pi has no such check: it accepts the batch and then throws a V8 `TypeError` while indexing the status. |
| D120 | A streamed tool call without an id or name no longer wedges the session | A provider can stream a tool call with no id, or with no function name. Pi stores and replays it, so every later turn fails with a 400 about an empty `tool_call_id` or a missing function name. PiG gives a call streamed without an id a unique `<name>_<epoch ms>_<counter>` id when its block ends. |
| D121 | The Anthropic SSE reader holds back a trailing carriage return | A proxy that flushes the CR and the LF of a CRLF in separate chunks makes Pi end the line early and abort the turn with a JSON parse error. PiG waits for the next chunk before it ends a line at a trailing `\r`; at the end of the stream the `\r` ends its line as before. |
| D122 | OpenAI Completions keeps a signature-only `reasoning.text` delta | OpenRouter streams the signature of an Anthropic reasoning block in a later delta with no `text`. Pi drops that delta, so the reasoning details it replays after a tool call lose the signature. PiG keeps a `reasoning.text` detail without `text` when its `signature` is a string and merges the signature into the preceding reasoning detail. |
| D128 | OpenRouter image models that need the Images API are retried through the Images endpoint | Some OpenRouter image models refuse `chat/completions` and ask for the Images endpoint. Pi returns an error with no images. PiG retries once through the provider's Images endpoint and reads the images and usage from the response. |
| D129 | Responses tool calls streamed with an empty call_id | Pi stores a Responses function call streamed with an empty `call_id` under an id with an empty call part and replays `call_id: ""`, so every later request fails (Pi #10299). PiG gives the call a generated call id, and the Responses replay omits a stored call whose call id is empty, with its results. Other targets replay it as Pi does. |
| D130 | A managed-effort Anthropic request sends each managed field only with its beta | For a model with `compat.supportsMidConvoEffort`, Pi always sends `thinking.block_binding` and the `output_config` effort markers, even when an explicit `anthropic-beta` header drops the betas they need, so the API returns 400. PiG sends each managed field only when its beta is in the request. |
| D131 | A stalled SSE stream with keepalives ends after the HTTP idle timeout | Pi's `httpIdleTimeoutMs` counts bytes, so a gateway that sends only comment lines or pings keeps a dead generation open for ever and `pi -p` hangs (Pi #10761, #10762). PiG restarts the timeout on a `data:` line of an event other than `ping`, and also on keepalives while the last event was a reasoning or thinking event (a silently reasoning model is not stalled); after `httpIdleTimeoutMs` without one the stream fails with `SSE Event Timeout Error`, and the retry policy applies. `0` disables it. |
| D132 | Session directories are created owner-only | Pi creates the sessions directory and each project's session directory with the umask default (0755), so other users can read every session (Pi #10770). PiG creates the directories it makes for sessions with mode 0700; an existing directory keeps its mode. |
| D134 | One SSE line is bounded at Node's maximum string length | Pi's SSE readers hold a line in a JavaScript string, so a line longer than Node's maximum string length ends the stream with a `RangeError`. PiG's shared SSE decoder ends the stream at the same bound, in bytes, with its own error text. |
| D135 | clearQueue keeps queued extension custom messages | Pi's `clearQueue()` also destroys custom messages queued by `sendMessage({ deliverAs })` without returning them (Pi #9886). PiG clears and returns only user messages, for RPC `clear_queue`, the SDK and the interactive dequeue action; custom messages stay queued. |
| D136 | A context edit after the usage anchor keeps the anchor | Pi discards the last assistant usage when any later `context_edit` exists, so omitting a failed retry attempt makes the context estimate jump (Pi #10287). PiG keeps the anchor when the edits only target later entries. |
| D137 | A request carries at most the model's maxPerRequest images | Pi ignores `inputLimits.images.maxPerRequest` (Pi #10162). PiG keeps the newest images and replaces older ones with a text placeholder in the request. Past the limit, each new image moves the omitted set, so the prompt cache misses from the oldest kept image onward. |
| D138 | session_compact custom messages reach the overflow retry | Pi defers `sendMessage({ triggerTurn: false })` from `session_compact` to the end of the run, so the overflow retry misses it (Pi #9051). PiG appends it before the retry. |

| D142 | Settlement keeps idle waiters pending and abort discards deferred prompts | Pi resolves a `waitForIdle()` waiter registered during a run while an `agent_settled` handler is still compacting, and its `abort()` from an `agent_settled` subscriber does not stop a continuation already deferred (Pi #10704, #10705). PiG keeps such a waiter pending through the handlers and the prompts they deferred, and an abort during settlement discards those prompts. Interactive mode is not covered. |
| D143 | A device-attributes reply split across slow reads is not forwarded as input | Pi forwards the leading fragment of a DA1 reply delivered in slow reads and then emits its remaining digits and `c` as printable key input (Pi #10657). PiG keeps an `ESC[?` prefix buffered until its final byte, as the issue's reference fix does, and absorbs the rest of an owed reply after a replayed bare `ESC[`. |
| D145 | Nested Errors keep their name and message in codemode output | Pi serializes a rejected nested call as `"reason":{}` in `text()`, console output and the returned value (Pi #10650). PiG writes `{"name":...,"message":...}` there. |
| D146 | RPC stdin end answers a Session-replacing command that Pi leaves unanswered | Pi exits at stdin end while `new_session`, `fork`, `clone` or `switch_session` still awaits and never answers it. PiG finishes the replacement and writes its response. Both answer a later `get_state` of the same batch first. |
| D147 | Compactions requested in one input batch run one after another | Pi starts two `compact` lines of one batch together; neither aborts the other. PiG chains them. A small Session answers "Nothing to compact" twice, as in Pi. For a larger Session Pi writes two compaction entries and answers both with success; PiG writes one and answers the second "Already compacted". |
| D148 | An aborted compaction answers one error; two Pi defects of overlapping compacts are not reproduced | A replacement aborts the compactions of its batch at its teardown and a refused replacement leaves them alone, as in Pi. With two compacts and a replacement Pi answers the first with a TypeError from its shared abort controller, in the order 2, 1, 3; PiG answers both with "This operation was aborted", in request order. An abort after the summary request started answers "Compaction cancelled" for every provider. PiG also writes a `compaction_end` event with `aborted: true` before the aborted compact's answer; Pi writes none. |
| D150 | `--no-stdin` skips reading piped stdin | Pi always reads piped stdin until end of input, so a caller that leaves the pipe open hangs startup (Pi #10415). `pig --no-stdin` skips the read. Without the flag PiG waits for end of input, as Pi does. Pi treats `--no-stdin` as an unknown extension flag. |
| D153 | The bash truncation notice names the last line's size | When the output ends with a newline, Pi's notice reports the bytes after it, `(line is 0B)` (Pi #10015). PiG names the size of the line that newline ended. |
| D156 | MCP server `url` expands environment references | PiG expands `$VAR`, `${VAR}` and `$$` in an MCP server's `url` as it does for `headers` and `env` (Pi #10654). A URL with an unset variable or a `!command` is used as written, and the `/mcp` server menu shows a `connects to:` line with the expansion. Pi always uses the URL as written. |
| D157 | PiG's startup additions stay quiet when the config root cannot be written | PiG prints no `extension SDK staging failed` warning and no `write Piglet verification cache` warning when the write into the config root fails with a read-only file system or a permission denial (`EROFS`, `EACCES`, `EPERM`). Every other failure of either write still warns. Pi has neither write. A signed Piglet Binary then checks itself in full at every start, and `pig diagnose` says so. |
| D158 | A setting of the wrong JSON type is ignored | PiG drops a `settings.json` value whose JSON type does not match the setting and applies the rest of the file. Pi 1.4.0 exits 1 for `{"skills":5}`, `{"extensions":{}}` and `{"enabledModels":[5]}`, and warns once per character for `{"enabledModels":"ab"}`. PiG prints one warning per settings file that names each ignored setting and its expected type. |
| D159 | A single grapheme wider than the editor's wrap width stays one chunk | Pi's editor re-wraps a segment wider than the wrap width by calling itself on it, so a one-grapheme segment (a tab at a width of 2 or less, a double-width character at width 1) recurses until a `RangeError`. A Go stack overflow kills the process, so PiG keeps such a grapheme as one chunk that overflows the width and re-wraps only segments of several graphemes. |
| D167 | A history longer than the model's context window is summarized in chunks | Pi sends the whole history of a compaction in one summary request, so a session already longer than the model's context window is refused with the provider's overflow error and can never be compacted. PiG splits such a history into window-sized chunks, each updating the summary of the one before (Pi's own previous-summary update prompt), and halves a chunk the provider still refuses. A split turn whose prefix is longer than the window moves all but the prefix's last window-sized part into that chunked history. `/tree` branch summarization retries with the newest half of a request the provider refuses, always keeping the newest message. A history that fits is one request, identical to Pi's. |
| D177 | The calls of a parallel durable tool round start in unspecified order | In a parallel tool round of `durable/harness`, PiG runs each call on its own goroutine, so the calls start concurrently and the order of their first side effects within the round is unspecified. Pi starts them in call order because its single event loop runs each `execute` up to its first await in turn. The next model request still carries the round's tool results in call order, and a sequential round runs one call after another. |
| D180 | A provider transport failure records its Go cause as a diagnostic | Pi records `provider_transport_failure` only for the Codex WebSocket path. PiG adds the same diagnostic (error name, message and Node-style code, plus phase) to any failed provider request, so a reset, a dial timeout and a DNS failure can be told apart in the session file and `/bug`. The error message, stop reason, retry behaviour and events are Pi's. |
| D181 | The commits of an unawaited durable job are ordered by goroutine scheduling, not by Pi's microtask hops | A job (a conversation-owned task) that nothing waits for commits in an order Pi fixes by microtask hops and `durable/harness` leaves to goroutine scheduling, so its commit sequence numbers (`entries.commit_seq`, `document_revisions.seq`) can differ from Pi's. A read taken as `Submission.Wait` returns can still show the job running where Pi has it terminal; await the job or `WaitForIdle` before reading its state. A job its creator awaits is ordered as in Pi. |
| D182 | A proxy start event with an unusable content index ends the stream with an error | Pi stores the block at `partial.content[contentIndex]`, leaving holes for an index past the end and a hidden property for a non-index key. PiG's message holds only real blocks, so `StreamProxy` ends the stream with an error. Well-formed streams are Pi's. Pending owner approval. |
| D183 | A message delivered at the terminal proxy event is not changed by later events | Pi keeps applying events after `done` or `error` to the message it already delivered. PiG drains the rest of the body without applying it, because a later write would race the consumer's reads. Pending owner approval. |
| D184 | A script's unawaited tool call can be aborted before its tool starts, where Pi always starts it first | A code mode script that calls a tool and does not await it, then ends, aborts that call. Pi's call has always started its tool by then; PiG's has too, except when the goroutine of the call stalls for milliseconds while the next call's runs its whole round trip (0.15% of runs of the Pi test at 8 CPUs, about 0.8% at 3, under heavy load). The call's task is `terminal` and `aborted` either way; only whether its tool code started differs. An awaited call, a replayed call and every result the script sees are Pi's. Await the call before the script ends. |
| D185 | A Kitty CSI-u Shift+letter with no shifted alternate decodes as the uppercase letter, where Pi keeps the base letter | A terminal that reports Shift+a as `ESC[97;2u`, with no shifted-key field, types `A` in PiG's editor and input; Pi's `decodeKittyPrintable` types `a`. With the shifted key (`ESC[97:65;2u`) both type `A`, and a Shift+digit with no shifted key types the digit in both. PiG keeps the fallback so a terminal that omits the shifted alternate does not lose every capital letter. Owner-approved 2026-10-20. |
| D186 | A hung-up terminal under a session whose event loop holds nothing: Pi exits 0 or 129, PiG exits 129 | When a terminal's master closes under an interactive session, Pi's SIGHUP handler writes to the dead terminal, meets EIO and exits 129. Node's signal watcher does not keep the event loop alive, so a session with no other handle (a plain directory, no extension timers or sockets, no git watcher) has an empty loop when its input ends and Pi usually exits 0 before the handler runs; in a git repository Pi exits 129. PiG always exits 129 and records `terminal gone: <error> (exit 129)` in `exit.log`. A live SIGHUP (0) and a render that meets EIO (129) match Pi. |
| D187 | A native SDK holds a batch's first host calls and responses in call and answer order, where Pi's single thread lets a call that awaits work the SDK cannot see be overtaken | The Go, Python and Rust extension SDKs keep Pi's single-thread orders for the tool calls of one parallel batch: the first dialogs open in call order, and calls whose dialogs were answered back to back respond (and end) in answer order. To do it they hold a call: its first host call, of any kind, waits for the earlier calls' first host calls and then passes its place on (a call that awaits an `exec` before its dialog is overtaken by the later calls' dialogs, as in Pi), and a handler whose dialog was answered holds the later-answered handlers' responses until it returns or makes its next host call. ## Known gaps for 0.3.x

D78, D82 and D83 are owner-approved known gaps (2026-09-28), not waivers or evidence of parity. Same-process objects must keep Pi's identity and mutation behavior. Foreign configuration readers (D78) and partial-message observers (D82) receive snapshots. D83 was narrowed on 2026-09-29: foreign bus listeners receive the original payload by reference, and only the named cross-process boundaries remain. The earlier no-sharing rule for isolated extensions is retired.

RPC33 retains complete JSON and stderr comparison and three declared runs. Its raw partial-observation failure stays visible. Approval does not permit missing events, changed order, wrong deltas, broken cancellation, bad final results, persistence errors or lifecycle leaks. The authoritative integration boundary and outstanding same-process defects are in `docs/findings/0.3.0-known-gaps.md` in the source tree.

## Additive features

PiG-only features that change how you extend or modify PiG are listed in [Additive features](additive-features.md).

## Non-divergences

Items below are sometimes mistaken for divergences but are intentional **parity**:

- **Mermaid fallback.** Unsupported or oversized diagrams retain the original code block. Pig does not add an unsupported-diagram hint or narrow labels to force a diagram to fit.
- **Fenced-code wrapping.** Pi 1.4.0 wraps code rows in the final Markdown content-width pass. PiG uses the same pass and breakpoints.
- **TUI scrollback.** Pig now emits `\x1b[2J\x1b[H\x1b[3J` on full redraw, matching upstream `pi-tui`. Earlier pig builds omitted the `3J` (scrollback clear); that was a parity drift, fixed.
- **Model cycling.** `Ctrl+P` / `Shift+Ctrl+P` cycle through provider-qualified specs. Bare model IDs are legacy-accepted but always rewritten on save.
- **Provider auth precedence.** Environment variables override stored credentials at request time, identical to upstream.
- **Skill loader.** Skills require `SKILL.md`. Directories without one are silently inert, matching upstream.

## Forbidden runtime patterns

These are explicit non-options. Calling them out so the coding agent does not propose them:

- WASM extension runtime - not supported.
- Embedded JS / PigScript - not supported.
- Dynamic Go plugin runtime - not supported.
- Fused Go factories in a Piglet Binary use the same extension registration contract as subprocess factories.
- Protocol v2 multi-register payload - deliberately deferred; do not add `RegisterPayload.Extensions` or `RequestPayload.TargetExtension` without an explicit divergence + design.

## When to write a new divergence

Add an entry to `docs/parity/DIVERGENCES.md` when:

- Pig behavior differs from upstream pi in a way a user can observe (output, exit code, file layout, command surface).
- A capability is unsupported on the subprocess bridge and returns a typed `unsupported` error rather than silently no-op-ing.
- Pig adds product-neutral behavior that has no upstream equivalent and records it in the additive-feature ledger.

Do not write a new divergence when:

- The change is a pure refactor with no observable effect.
- The change restores parity that had drifted (parity is the goal, drift is a bug).
- The change is internal to runtime cells, since D20 already covers them generically.
