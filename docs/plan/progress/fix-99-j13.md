### Item 1: defaultTools bookkeeping after a failed reload

Pi keeps `addedDefaultTools` as a local of `reload()` (`agent-session.ts:3587-3609`): a throw from `settingsManager.reload()` or `resourceLoader.reload()` drops it, and only `_buildRuntime` consumes it. PiG stages it on `Session.toolRegistry` (`ReloadSettings`), so a reload that never reaches the rebuild left it pending and a later `RefreshTools` activated the tool. `ReloadSettings` now replaces the staged set instead of appending (`coding/session_tools.go`), and `Session.DiscardAddedDefaultTools` drops it. Interactive `/reload` defers the discard so every exit that skips the rebuild drops the staged set, and also discards explicitly in the `host.Reload` failure branch (`internal/codingagent/interactive_commands.go`). The red tests pass for both the extension and the resource failure.

### Item 2: Retry-After and `Date.parse`

`ai/js_date_parse.go` ports V8's `DateParser` (legacy and ES5 ISO grammars, the keyword table, the two-digit year rule, `TimeClip`) and the local-time rules that apply when a string has no zone. Local time honours DST gaps and overlaps with ICU's former-offset rule. It is used at the three Pi sites: `provider-retry.ts:60`, `github-copilot.ts:158`, `openai-codex-responses.ts:158`. Evidence: `ai/testdata/js_date_parse/corpus.json` holds 1170 strings with Node's value in UTC, America/New_York and Asia/Kolkata (`generate.mjs` regenerates it), and a 60,000-string fuzz in two zones matched Node with 0 differences (run once, not committed).

Findings that corrected the red tests (the commit message of `79d5b3d55` says so):
- ISO dates never reach `Date.parse` on the provider and Copilot paths. Pi tests `parseFloat(value)` first, and `parseFloat("2026-…")` is the leading year, read as seconds. `TestRetryAfterISODateIsItsLeadingYear` pins this. Only the codex path uses `Number(value)`, which rejects ISO text, so only the codex test keeps the ISO forms as accepted dates.
- Asctime and month-name forms with no zone are read in local time, as V8 does. Two-digit years 50–99 read as 19xx and 0–49 as 20xx.
- An unparseable value, a NaN, and a date in the past fall back to exponential backoff or no delay as Pi does (tests included).

### Item 4: Anthropic federation exchange body

`readAnthropicTokenBody` (`ai/anthropic_federation.go`) keeps a bounded 1 MiB prefix and counts the UTF-16 units of the rest while discarding them. The SDK reads the whole body (`oidc-federation.mjs`; `types.mjs:66-101` builds the message from `JSON.parse` of the text or the text itself with a `... <N more chars>` tail). When the prefix cannot be JSON (`anthropicBodyCannotBeJSON`), the visible message is identical to Pi's for any body size, including the count and the split of a multibyte character. Not matched: a body larger than 1 MiB whose prefix is valid JSON so far, for example a JSON string that goes on for megabytes. Pi parses the whole value and redacts fields by key, which needs the whole body in memory. Matching it exactly means an unbounded read of an untrusted response, so the bounded reading stays for that one shape. The red test covers the plain-text case; no test asserts the JSON case.

### Item 3: `ctx.reload()` in print, JSON and RPC

Pi binds the command context's `reload` to `session.reload()` in print mode (`print-mode.ts:97-99`) and RPC (`rpc-mode.ts:341-343`). In PiG:
- `Runtime.ExtensionCommandActions` binds `ReloadContext`/`Reload` for every mode; each mode installs its reload with `Runtime.SetReload` (`coding/runtime_replacement.go`).
- `cmd/pig/headless_reload.go` `reloadHeadless` follows `agent-session.ts:3587-3625`: emit `session_shutdown(reload)`, reload settings (with the queue-mode sync of `:3596`), resources (skills, prompt templates, context files, system prompt: `loadPromptResources`, extracted from `buildSession`, and the interactive snapshot provider), extensions (`Host.Reload` plus built-ins, in load order), `Session.ReloadExtensions` (new runner, `bindExtensionCore`, `ReplaceRunner`, old runner invalidated, `RefreshTools`), then the mode rebinds and emits `session_start(reload)` and `resources_discover`.
- The reload runs under the mode's process context joined with the command's request values (`internal/ctxowner`): the extension processes it starts must outlive the command that asked for it, and an existing test (`TestExtensionReloadUsesUIOwnerAndRequestContext`) requires the request values.

Real-binary proof (COMMON-DEFECTS 8): `TestExtensionReloadIsWiredInEveryHeadlessMode` runs the built binary with a Node and a Go extension in print, json and rpc; `TestExtensionReloadResolvesInInteractiveMode` does so in a PTY. Each extension's command rewrites the settings, a context file, a prompt template and a skill, awaits `ctx.reload()`, and logs. The log must read: factory; `start:startup` (old settings, no marker, no added tool, no reloaded commands); `shutdown:reload`; factory; `start:reload` (quiet startup changed, context marker in the system prompt, `grep` active, `reloaded` and `skill:reloaded-skill` in `getCommands()`); `returned` (the call resolved in the old instance); `shutdown:quit` where the mode quits by itself. `TestExtensionReloadFailureRejectsTheExtensionCall` makes the reload fail on an invalid `file:` URL in settings and expects the call to reject with Pi's message. Python and Rust SDKs share the host call (wire tests only); no real-binary run for them.

Mutation checks: stopping the old generation at once (no deferral) fails the node tests in print and interactive with "host call cancelled with parent request"; passing the command context as the owner fails the print test (the new generation dies with the command); both restored.

### Scope expansion: host generation retirement (approved, question file)

`await ctx.reload()` from a Node extension failed on the unchanged base in interactive mode too: `Host.commitStaged` stopped the old generation synchronously, and the Node runtime's `shutdown` aborted the awaiting command ("host call cancelled with parent request r2"), after which the new generation was disabled ("send_ready_failed: context canceled"). Tests: `TestCommitStagedKeepsAGenerationRunningWhileItsCommandRuns`, `TestShutdownStopsGenerationsADeferredRetirementStillHolds`, `TestCommandGateRunsItsCallbackOnTheLastReturn`. The reload call's error keeps Pi's message (no `reload_error:` prefix). Other files outside the nominal scope: `coding/session_tools.go` (queue-mode sync), `internal/codingagent/interactive_reload.go` (extension-initiated reload uses the run context), `docs/extension-api-parity.md`, `docs/plan/progress/audit-host-wiring.md` (the headless reload allowance is closed).

### Differences kept

- Interactive `/reload` that fails before the rebuild leaves the previous runner valid. Pi invalidates the old runner right after `session_shutdown` (`agent-session.ts:3580`), so an extension's captured API goes stale even on failure. The review (rev-fix-99-j13) made a failed headless reload invalidate the old runner and its extension host; interactive behaviour is unchanged and out of this lane.
- The Retry-After corpus assumes a Node build with ICU (America/New_York, Asia/Kolkata offsets); the zones are written into the corpus, so the test does not read the host zone.
