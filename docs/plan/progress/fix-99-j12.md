# fix-99-j12: JSON member order on the host paths

Base: staging `rev-fix-99-j10` 8beb98933. Oracle: real upstream 0.99.1 (`/tmp/pi99`, the npm 0.99.2 package is not installable here). `session-manager.ts`, `messages.ts` and `mcp-servers.ts` (registry and validate paths) are identical in `.upstream/v0.99.1` and `v0.99.2` for everything this lane reads; cited lines are from v0.99.2.

## Items

1. Host answers to Go/Rust/Python `sessionManager` reads (`internal/codingagent/extension_session_read.go`) built messages, projections and tree nodes from Go maps, so members came out sorted (`model` as `modelId, provider`, `role` last, `fromId` before `role`). Raw entries were passed as the file wrote them, but Pi's SessionManager holds `JSON.parse` output (integer-like keys first, `1.0` as `1`).
2. `extensionToolResultWire` (extension wire) and `rpcToolResult` (`--mode json`/RPC) wrote `content, details, structuredContent, isError, usage, terminate` whatever order the tool's result object had; Node's `normalizeToolResult` also rebuilt the object in a fixed order.
3. `McpServerRegistry` stored the config as a typed `McpServerConfig` and marshaled it from the struct: member order was the struct's, and members the struct does not declare were dropped. Pi's `validateMcpServerConfig` returns the object it was given and `list()` `structuredClone`s it (`mcp-servers.ts:192-283`).
