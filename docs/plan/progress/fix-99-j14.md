## Green

| Finding | Change |
|---|---|
| F4 | `agent.Agent.ObserveRunSignal` (`agent/lifecycle.go`) reports the claim (`beginRun`, once `Signal()` returns the run) and the release (`finishRun`, once it returns nil), outside the agent's lock, in registration order (Pi: `activeRun` set and cleared, `agent.ts:508-555`). `UIBridge.RunSignalChanged` (new `OnRunSignalChanged`, set by `Host.SetUIBridge`) runs `Host.runSignalChanged`, which queues the `run_signal` frames to every connected runtime on a Shutdown-joined task (`syncRunSignals`, the former `forwardRunAbort`): a run goroutine never waits for a runtime that stopped reading, and each frame is computed from the state current when it is sent under the Conn's lock, so two quick changes cannot reorder. ## Scope notes

- F5: `extensionRuntime.assertActive` throws once the runtime's connection closed. `Host.Invalidate` (session replacement) still does not tell the runtime, so a captured Node `ctx` between teardown and process exit still answers: this is D30 Part 1(a), whose remove condition is the host-to-extension invalidate notification in all four SDKs. The lead's answer to the question in `questions/fix-99-j14.md`: guards on the whole class, D30 stays, no invalidate notification in this lane.
- F6 class: `interactive_extensions.go` still reads `m.agent` from host goroutines in the `HasPendingMessages`, `Abort`, thinking-level and `hasPendingMessages` host actions (the same pattern the review noted). They are not changed: `TestInteractiveModeBindsEveryHostCallback` and its siblings assign `m.agent` directly, and the finding names `extensionSignal`. Not deferred silently: listed in the report.
- Run replacement in interactive mode does not send one report when the agent is swapped; the retired agent's last report happened when its run ended, and a replacement installs a new bridge and host.
- The timer extension `cmd/pig/testdata/ctx-signal-poll.mjs` records its first read synchronously in `session_start` (changed after the red run: with only the 5 ms interval its first read could land after a prompt had already started the run, so the nested and `turn_start` scenarios saw `live` first on pig; Pi passed by timing luck). `TestRunSignalChangedReachesEveryRuntimeWithoutARequest` takes `context.WithCancel(t.Context())` for its first run (`go fix -diff`).
- `TestPrintModeReportsRunSignalChangesToTheExtensionHost` was added with the green commit, mutation-proven rather than red-proven (removing the `watchSessionRunSignal` call fails it with `[]`).
