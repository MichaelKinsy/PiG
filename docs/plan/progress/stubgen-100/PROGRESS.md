# stubgen-100: gen-go-stubs, the API-stub generator

Lane: stubgen-100. Branch `stubgen-100` from `agg-100`. Upstream `.upstream/v1.0.0`.

## Status

READY. The generator compiles all 13 Pi 1.0.0 packages. `packages/protocol` and `packages/client` are closed: their 6 test-mapping rows are ported, and the client tests found and fixed one transport ordering bug.

## The tool

`test/parity/interface-extractor/src/gen-go-stubs.mjs` (library `go-stubs.mjs`, tests `test/go-stubs.test.mjs`), also `make go-stubs PACKAGE=<dir> OUT=<Go dir> [IMPORTS=npm=go,...] [SCOPE=public|module] [TEST_MAPPING=1]`.

- Input: the package's public entry points from `package.json` `exports` (`SCOPE=module` adds every `src/**/*.ts` export; a private package such as evals needs it). The TypeScript checker resolves workspace packages to their sources and third-party types (typebox) through `extensions/sdk-ts/node_modules`, so TypeBox `Static<>` aliases become real structs. A re-export of another workspace package's symbol renders through `IMPORTS` (or as `any`) and is not stubbed again.
- Output per upstream source file: `<file>_stub.go` with Pi's names (PascalCase; Pi's spelling kept, so `ServerId` stays `ServerId`; `PROTOCOL_VERSION` becomes `ProtocolVersion`), a doc comment `// X ports packages/<pkg>/src/<file>.ts:<line> (<symbol>).` plus the JSDoc text, and bodies `panic("unported: <path>#<symbol>")`.
- Shapes: data interfaces become structs with JSON tags; method-only interfaces become Go interfaces; string-literal unions become a named string with one constant per value; anonymous record unions merge into one struct; unions of named variants become sealed interfaces with marker methods, and the variants drop their literal discriminant; Error subclasses become `struct{Message ...}` with `Error()`, and an Error constructor that only forwards its message gets no `NewX` (a composite literal is its port). An omitted options object whose fields are all optional is the struct's zero value, not a pointer. Async functions take `ctx context.Context` and return `error`; a function returns `error` when it can throw (a throw statement, or an unguarded call to a package function that can throw, as a fixpoint).
- Tests: one `<file>_upstream_test.go` per upstream test file, one `t.Run` per `it()`/`test()` case with `// upstream: <path>:<line>` and `t.Skip("unported")`.
- Ownership: a generated file starts with `// Code generated by gen-go-stubs ...; DO NOT EDIT.` and a body hash. The generator writes or deletes only such files with an intact hash, and refuses (exit 2) on an edited generated file or a hand-written file at a stub path. Declarations hand-written files already have are omitted, so the stubs shrink as code is written and a stub file disappears when it is empty. `stubgen:omit <GoName>` in a hand-written comment records a deliberate omission (the client's `NewDisconnectedError`). A case cited by `upstream: <path>:<line>` in a hand-written test, and not followed by `t.Skip("unported")`, counts as written; a skeleton the porter claims (header removed) is left alone. `TEST_MAPPING=1` rewrites only this package's rows, byte-preserving the rest of the ledger: `ported` with the citing tests as evidence, `partial` with the missing cases, or `pending`. A reviewed ported row with unchanged evidence keeps its rationale. A reviewed `designed-out` or `divergence` row keeps its disposition and reason until every case is cited; flip it to `pending` by hand to track a partial port.
- Idempotent: a second run with no source change writes nothing (`--check` exits 0).

## Premise found while running it

`packages/protocol` and `packages/client` were not unstarted: `internal/experimental/protocol` and `internal/experimental/client` already hold a hand port of the 0.99.2 sources (unchanged at 1.0.0), used by the experimental server and client. The protocol tests were already written there and cite every upstream case; the three client test files were not. So the generator ran twice per package: into an empty scratch module (time to a compiling skeleton, and how much of it matches the hand port), and into the real package (stubs only for what was missing, then the tests to green). No second copy of either package was added.

Protocol differs only in `IsServerId(any)` (upstream takes `unknown`; the hand port takes `string`) and the hand port's `ResponseEnvelope.HasResult`. The client's hand port made Go-specific choices the generator cannot infer: a callback-based `ByteTransportFactory(ctx, handlers, complete)`, listener identity objects for `On*Change`, Chord types from the older `internal/chord`, and constants named `Connected` rather than `ConnectionStateConnected`.

Real-package runs:

- protocol: 5 proposed declarations. `ServerId` and `ProtocolErrorCode` were written unchanged (`type X = string`, now in `messages.go`). The 3 Error constructors were dropped by the composite-literal rule above.
- client: 6 proposed declarations. `Unsubscribe` and `ListenerErrorHandler` kept their names but became aliases (`= func()`, `= func(error)`) so the existing signatures stay. `NewDisconnectedError` is a recorded `stubgen:omit`. `NewClientDisposedError` was dropped by the composite-literal rule, and `ClientConnect` was a generator bug (a static method colliding with the hand-written `Connect`), fixed.
- tests: all 27 client subtest names and their `upstream:` line markers were kept unchanged; every body was written. All 6 ledger rows were flipped by the generator; their rationales were then written by hand.

Bug found: under `-race`, `discoverUnixServers › ignores an endpoint that closes before its handshake` failed 1 run in 5 with `Unix transport is closed` / `use of closed network connection`. When the peer closes, upstream's socket close listener (`unix.ts:121-141`, registered at connect) calls `handlers.onClose()` before the in-flight write's own close listener (`unix.ts:215-218`) rejects it with `Unix transport closed during write`, so the Connection sees a cause-less `DisconnectedError` and discovery omits the endpoint (`unix.ts:260-276`). PiG's writer goroutine could settle the write first, so the Connection failed with a caused error that discovery propagated. `unixByteTransport` now settles writes that a close interrupted only after the handlers have seen the close, with upstream's message. Regression: `unix_close_order_test.go#TestUnixTransportRemoteCloseNotifiesBeforeSettlingWrites` (synctest; fails before the fix with `["send: use of closed network connection" "close"]`). The discovery case passed 30 of 30 runs under `-race` after the fix.

Compiling mutations that each fail a client case: dropping the unmatched-response failure, the pre-abort check, the data-before-hello check, the cancel send, the pre-snapshot update queue, the missing-directory result, the version and validation omissions in discovery, the decoder end check on close, and raising the probe limit to 17. The cancel and queue mutations fail by never delivering the awaited message, as upstream's waits would.

## STUBGEN-VERDICT

The generator is clearly faster to a compiling skeleton: 1-20 s per package against 14-31 minutes per hand lane, after a one-time build of 13-19 minutes. It also produces the test skeleton for every upstream case and keeps the ledger rows current. It does not write behavior, and its signatures agree with the hand lanes' package-wide Go decisions only partly (below), so it should feed porters rather than replace the lanes that have started.

Why "feed" rather than "replace" where a lane runs: name agreement with the hand code is high (73% for durable; 45% for chord, whose existing code predates the 1.0.0 module layout) but signature agreement is low (28% and 16%). The hand lanes made package-wide Go decisions the generator cannot infer: `context.Context` for Chord `Context` (the generator keeps Chord's `Context` parameter and adds `ctx`), distinct `int64` ID types, erased-token overloads, and `(T, error)` for durable's `Result`. Running the generator into a lane's own package gives that lane only its missing declarations and test skeletons, and never overwrites its code.
