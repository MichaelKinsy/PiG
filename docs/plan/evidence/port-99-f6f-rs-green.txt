## Async contract (Rust realization; record in docs/extension-api-parity.md and test/parity/async-contracts.toml)
- registerMcpServer/registerVirtualModel/unregister*: Pi throws synchronously. Rust: one blocking host call on the caller's thread, `io::Result`; the host's validation message is the error. During load the registrations ride in the `register` frame, so a failure fails the load, as the factory's throw does.
- getSettings/getMcpServers/tools: synchronous in Pi, answered from state the host replicates (ready state, `state_update`, MCP registration replies and `mcp_servers_change` events). A change the host has not yet pushed is not visible, as for every replicated getter.
- executeTool (an awaited Promise): a blocking call that names the calling tool call and the calling request. Partial results go to `on_update` on a dispatcher thread that is joined before the call returns, so all updates precede the outcome, in order. `signal` sends `executeTool.cancel` after the call frame; without one the host cancels the nested call with the calling request. A tool failure is an outcome; only a lost connection, a cancelled request or a call outside a tool is `Err`.
- route (Promise or value, awaited by the host): a blocking function on the request thread; its `Context` is cancelled with the request. A panic or an `Err` is the request's error.
- prepareLoadout (synchronous in Pi): a host request the host awaits; a panic or a decode failure is an error response, which the host treats as no change.
