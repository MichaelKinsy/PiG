### Provider scope still incomplete

The SDK handoffs distinguish working callable methods from unimplemented source identity. Original OAuth callbacks, independent prompt signals, synchronous model/filter calls, stream/deferred methods and explicit callback leases are not substitutes for a shared object graph. Go/Rust reader facades and parked Node/Python reader drafts do not implement author-held aliases, accessor/receiver export, sparse/cyclic source ownership, first-export acknowledgement or distributed cycle collection. No compatibility reader is introduced here.

Canonical fractional credential expiry and optional metadata are closed on `team/smc1/gap-d78`: the Pi 0.87.1 oracle `ai/testdata/credential-expiry.json` drives `TestCredentialExpiryMatchesPi`, and the `conformance-oauth-object` provider proves the exact credential object in Go, Rust, Python, fused Go and Node. Registered configuration identity between Node processes is closed on the same branch through gap-xproc's cross-process references (`TestRegisteredProviderConfigAcrossProcessesMatchesPi`, `TestRegisteredProviderConfigXrefLifetime`); Go, Rust and Python authors and readers remain snapshots. Implicit refresh, retained post-callback signal lifetime, mixed-owner acceptance/rollback and final resource qualification remain explicit Provider obligations. The approved D78 record names the incomplete surface; it does not label those operations correct. Same-process accepted configuration roots, original children/functions, descriptors and receiver semantics must be fixed rather than hidden behind the foreign-snapshot rule.
