## F14 (new): classes that extend Node's EventEmitter

Go's StdinBuffer returns the parsed sequences from ProcessString/ProcessBytes/Flush instead of emitting events, so there is no listener API by design. Request: external-base-class rule (a class extending a Node builtin has no Go counterpart for the builtin's members), same family as the Error base members of D103.

## F15: PiMessagesRewriteImpact (ai/pi_messages_events.go:14)
Pi's `PiMessagesEvent.rewrite` is spread into the diagnostic details (`details: { ...rewrite }`, pi-messages.ts:169-178), so every member the backend sends reaches the diagnostic. ## F18: overloaded `ExtensionAPI.on(event, handler)` (42 rows, coding-agent)
Pi declares `on` once per event literal (`on(event: "tool_call", handler)`, types.ts:1563-1700); Go has one registration method per event on `extension.API`, named `On` plus the PascalCase of the snake_case literal (`OnToolCall`, `OnSessionStart`, `OnContextWithSystem`, coding/extension/api.go:86-150). ## F19: request auth carried by the summarization Completer (compaction, ~12 rows)
Pi passes `apiKey`, `headers` and `env` to `generateSummary` / `generateSummaryWithUsage` / `compact` as positional parameters and to `generateBranchSummary` as options members (compaction.ts:645-660, branch-summarization.ts:67-89), then builds `{ apiKey, headers, env, signal, maxTokens }` for the request (branch-summarization.ts:352). Go resolves the credentials once per run in `Session.prepareSummarizationRequest` (coding/session.go:2615) and carries them in the `SimpleCompleter` it hands to `GenerateSummaryWithUsage` (internal/codingagent/compaction/compaction.go:685, 11 parameters against Pi's 13) and `GenerateBranchSummaryOptions.Completer` (branch_summarization.go:79). The requests sent are the same. Request: a Pi parameter or options member that selects request credentials (`apiKey`, `headers`, `env`) is satisfied by a Go `Completer`/`StreamFn` parameter of the same call (representation rule), so `GenerateBranchSummaryOptions.{apiKey,headers,env}` and the three missing positional parameters of `generateSummary` stop being gaps. Tried measured alternatives: renaming `generateSummary` -> `GenerateSummaryWithUsage` moves the row from no-go-symbol to S4 without lowering the total, so it is not applied.

## F20: public SDK packages with no in-repo caller (P1(b) library classification, ~160 rows)
On integrate-042 (e3ea506f2) the detector leaves 1717 not-exercised rows. Of the 188 coding-agent rows whose members "no production code reads, sets or calls", 86 are `coding/rpcclient` (`RpcClient.Prompt`, `Steer`, `GetState`, `SetModel`, `Fork`, `Compact`, ... in commands.go, rpc_client.go, types.go) and ~85 are `coding/extension` (the `API` interface that extension authors call, `events.go`, `eventbus.go`, `host_actions.go`). Request: classify `coding/rpcclient` and `coding/extension` with the P1(b) library packages (durable, chord, telemetry, server, env, client, mcp, codemode), so a Pi-wire-tested, mutation-checked public member closes without an in-repo caller. Without that, the only alternatives are a fake production caller (forbidden) or deleting the SDK.

## F23: two Go implementations of Pi's one `delta/tracker.ts` (L3 duplicate rows: chord 30, durable 3, client 2 on integrate-042 72c9b252e)
Pi has one tracker: `track`, `Tracker`, `Change` and `Prepared` come from `@earendil-works/chord/delta` and are imported by both durable (`durable/src/session/session.ts:3`, `session/transaction.ts:2`) and chord's state (`chord/src/state.ts`). Go has two live copies: the public overlay tracker `chord/delta/tracker.go` (933 lines, Object/Array draft handles, driven by `internal/chord/state_overlay.go`) and the plain-JSON tracker `internal/chord/delta/tracker.go` (484 lines: `Track`, `BeginChange`, `PrepareReplace`, `PrepareCandidate`, `Adopt`), which `durable/session/session.go:869` and `durable/session/transaction.go:976,1029,1060` call. Rule L3 (duplicate of a wired or exported member) therefore stops both sides: `chord/delta/tracker.go#Tracker.Adopt` duplicates `internal/chord/delta/tracker.go#Tracker.Adopt` and the reverse (10 delta/tracker rows).
This is real code duplication, not a rule artefact, and no rename or placement record closes it. The same shape appears in `chord/state.go` (typed generic facade) against `internal/chord/state.go` (untyped core): `AttachedReplicatedState.Value/Subscribe` and `ReplicatedStateSourceFrame.Context/Cursor` flag each other. The facade rows are a legitimate wrapper if the public member forwards to the internal one (the L3 forward check already exempts a same-type forwarder, not a cross-package one); the tracker is not.
Fix (owner decision, touches durable session persistence, so not made on the release day by a helper): migrate `durable/session` to `chord/delta` `Track`/`Change`/`Prepared`, then delete `internal/chord/delta/tracker.go` and its tests that duplicate `chord/delta/tracker_upstream_test.go`. Until then these rows stay gaps by design of P1.
