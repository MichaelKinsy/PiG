## Real gaps found and fixed (tests first)

These are assertion gaps in the existing evidence: the upstream tests, or the Go tests that port them, did not pin behaviour the Go source implements from Pi. Each new test passes on the unchanged source (the source already matched Pi) and was proven to fail under the mutation named in the row.

- `cmd/check-model-data/hydrate.go` stamps `generatedAt` with `1970-01-01T00:00:00.000Z` (`hydrate-model-catalog.ts:65`); no test asserted it. New: `TestHydrateModelCatalogStampsTheEpochGeneratedAt` (mutation: the stamp changed by one second survived before it).
- `internal/codingagent/remote_catalog_provider.go` sets each remote model's `provider` to the requested provider id and drops entries without an id or with an unsupported type (`remote-catalog-provider.ts:47-49`); no test asserted it. New: `TestParseRemoteCatalogStampsTheRequestedProvider`.
- `coding/mcpext/oauth.go` `responseFromRedirectURL` messages and check order (`oauth.ts:384-402`) were only partly asserted. New: `TestResponseFromRedirectURLMessagesAndOrder`.
- `coding/mcpext/resources.go` argument errors, the server list in the unknown-server error, the cursor rule, the page cursor, the locale order of an all-server listing, the multi-content labels, the empty-read text and the tool definitions (`resources.ts:170-323`) had no assertion. New: `TestResourceToolsErrorsListingsAndReads`, `TestResourceToolDefinitionsCarryPisDescriptionsAndParameters`.
- `coding/mcpext/runtime.go` retries an HTTP connect twice (`CONNECT_RETRY_DELAYS_MS = [250, 1000]`, `runtime.ts:51,362`); only the first retry was asserted. New: `TestMCPConnectionsRetriesATransientHTTPFailureTwiceAndThenFails`.
- `internal/codingagent/first_time_setup.go` had no test of Pi's rendered steps (`first-time-setup.ts:56-130`: option markers, analytics text, `continue`/`finish` hints, clamped j/k/newline navigation). New: `TestFirstTimeSetupRendersPisStepsAndNavigates` (the pig-head logo is D88 and is excluded).
- `internal/experimental/plugin_package_profile.go` `NormalizePluginPackagePaths` (`plugins/package.ts:149-158`) had no direct assertion of path order, resolution, the empty-path check before the duplicate check, or duplicate spellings. New: `TestNormalizePluginPackagePathsResolvesInOrderAndRejectsEmptyAndDuplicates`.
- `packages/tui/src/native-module-path.ts` was only run inside `TestNodeVendoredTuiUpstreamTests`, which cannot pass on a host without Xvfb (its native clipboard case needs it). New: `TestNativeModulePathUpstreamCases` runs `native-module-path.test.ts` against the vendored `native-module-path.js` with `node` alone.

No production source needed a fix: every mutation-proof ran against source that already matches Pi.
