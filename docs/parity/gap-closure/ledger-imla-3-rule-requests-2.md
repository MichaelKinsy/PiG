## Measured: a rename cannot close the generic-method group

Mapping `pkg:durable/.#Session::property:snapshot` to the package function `durable/documents.go#Snapshot` (and the same for `snapshotAsOf`, `watchDoc`, `documentState`, `Tx.createTask`, `FacetEnvironment.use/observe/provide/provideMany` -> `internal/chord/facets.go#UseService` and its siblings) changed no row: `renames.json` member targets must be `Type.Member` of the owner. The group (about 50 rows with `TaskRuntime` and `FacetEnvironment`) needs the generic-method MemberRule described above, in lg-rules' family file.

## DS8 prototype: a MemberRule alone cannot close the generic-method group

`proposals/ds8_generic_members.go.txt` (+ `_test.go.txt`) is a working, mutation-checked MemberRule (4 mutants fail its table test) that maps a generic method property to the package-level generic function of the owner's package (`snapshot` -> `Snapshot`, `documentState` -> `DocumentStateOf`, `use` -> `UseService`; receiver-first, generic, an exact name wins, the shortest name must prefix the rest, a lowercase continuation never matches). Run against the detector on the P1(b)-restored tree it changed no row: `detect.go:registeredMember` accepts only a member rule result that is one of the owner's own fields or methods (`for _, m := range members { if m.Obj == obj ... }`), and a package function is not. The engine owner needs to let `registeredMember` return a package-level `*types.Func` for the property (the call rows then go through S3a's receiver-function handling). With that one change the rule closes `durable` Session/TaskRuntime/DocumentObserver/Tx and chord `FacetEnvironment` members (about 50 rows); `Tx.provide` stays silent by design because `ProvideService` and `ProvideMany` are unrelated candidates.

## DS8 measured end to end (integrate-042 9dc039230 + P1(b) engine)

With `proposals/engine_registeredMember.patch.txt` (registeredMember also accepts a package-level `*types.Func` found among the owner's package top-level symbols) and the updated `ds8_generic_members.go.txt` (a leading `context.Context` is skipped when matching the receiver parameter), the member rows of `durable` Session/TaskRuntime/DocumentObserver/Tx and chord `FacetEnvironment` find their Go function. No row closes yet: the call rows then fail the signature rule (`S4: upstream takes 1 parameters, Go takes 3`, `parameter conversationId: T2: upstream number, Go type is durable.DocTokenOf[T]`), because the Go function takes the receiver and the overload's tail as `...any`. Closing the group therefore needs three pieces from the rule owners: this engine hook, DS8, and an S3 receiver-function signature rule that drops the receiver (and a leading context) and accepts S3a's `...any` tail for overload parameters. The detector's totals with the first two pieces: 2150 -> 2161 gaps (11 members move from member-missing to signature-mismatch), 0 closed.
