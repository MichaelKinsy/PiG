# lg-help-3: P1(b) leftovers after the L6 evidence passes

Measured with p1-impl's detector (rules L1-L6) on integrate-042's placement table plus the evidence commits 316c85007 and 1b47069ac. Not-exercised rows left in my packages and why.

- **L5, schema data types** (telemetry `TelemetrySchemaDefinition`, `TelemetrySpanDefinition`, `TelemetryEventDefinition`, `TelemetryAttributeMetadata` fields; 13 rows): Pi declares them as types only (`packages/telemetry/src/index.ts`), no runtime reader reads them (`createTypedSpanStarter(_schemas)` ignores its schemas). Go keeps the structs as authoring API. Decision needed: designed-out as type-level declarations, or a reader (a schema validator) that Pi does not have.
- **L5, option fields no non-test code reads** (`ai.StreamOptions.TelemetryContext`, `ClassifierOptions.TelemetryContext`, `ImagesOptions.TelemetryContext`, `DeferredFetchOptions.Wait`, mcp `ContentAnnotations.*`, `ListToolsResult.*`, `ToolExecution.TaskSupport`): the Go packages accept the option but only a consumer outside the package reads it, or Pi's own reader is in another package (`coding-agent`). Wire a reader inside the package that Pi has, or record a rule: an option read in another Go directory that ports the same upstream package counts.
- **L4, `Cause()` on mcp errors** (`McpError`, `McpAbortError`, `McpConnectionClosedError`, `McpTimeoutError`, `OAuthRegistrationError`): the method returns the stored cause; the detector sees constants. Pi's `cause` is the Error base property; D103 stripped such members elsewhere. Same decision here: remove the five `Cause()` methods (callers use `errors.Unwrap`) or record the rule.
- **L3, duplicate chord implementations (27 rows, a real finding)**: `chord/delta` (public, 2.3k lines: handles, ops, tracker, json) and `internal/chord/delta` (2k lines: apply, codec, delta, diff, tracker) both implement Pi's `delta` module, and `chord/state.go` / `internal/chord/state.go` both implement `AttachedReplicatedState`, `ReplicatedStateSourceFrame`, `ReplicatedStateSourceOptions`. durable imports the public copy; `internal/chord` imports the internal copy. One of each pair must go, or one become a type alias of the other. This is a refactor with behavior risk (the two trackers differ: overlay with draft handles versus the older tracker), so it needs a lead decision; my chord tests reference both.
- **L3, other duplicates**: `durable.Extension.Name` vs `coding/extension.Extension.Name` (different upstream packages, PORT_MAP records both: rule request), `durable.Session.Close` vs `durableadapter.Session.Close` (adapter wraps the library type: rule request).
- **L2, unexported**: `ai.FauxProviderHandle.state`, `durable.DocToken.definition` (Pi's `[Symbol.docType]` phantom), `nodeSqliteExecutor.*` (unexported implementation of the exported `SqliteExecutor`): rule requests, the exported interface member is the row.
- **L1, coding-agent (142 rows)**: not a library by L1; closure needs production reach.
- **L6 with no asserting test**: durable (12), server (9), env (7), mcp (31), ai (5), agent (11). Each needs a Pi-cited test; the mcp `_meta`/`title` fields need tests that decode a Pi-shaped message and assert the field.
