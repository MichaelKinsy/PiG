## Proposed divergences (IDs to be assigned by the integrator)

1. `StreamProxy` rejects a content index past the end of the partial message (Pi builds a sparse array). Reason: a Go transcript cannot hold holes; reachable only from a malformed server. Remove when: never (language representation).
2. ~~Provider fallback~~ closed: `NewAgent` returns an error like Pi's constructor throw (see the `stream-fn.ts` row). No divergence.
3. ~~Standalone loop functions~~ closed: exported with Pi's names (see the `agent-loop.ts` row). No divergence.
4. (narrowed) Three TUI mechanics stay different. (a) Pi's `before/afterTerminalStart/Stop` are protected virtual methods that `TuiBase.start/stop` calls; Go has no virtual dispatch from an embedded base, so the main-screen and alt-screen `Start`/`Stop` carry those bodies inline and the shared 2031 handling is called from each. (b) Pi's `TUI.start`/`stop` own the `Terminal` object (raw mode, input subscription); in PiG the interactive driver owns terminal input and raw mode (`internal/codingagent/interactive_input.go`), so `HandleTerminalInput` is available on the renderer but the driver runs its own dispatch (extension dialog, editor action routing, asynchronous remote extension input listeners with ordering tickets) around `RunInputListeners` and the color/cell-size consumers. A remote extension listener cannot be a synchronous `TuiInputListener`. (c) `RemoveInputListener` takes the listener pointer, not the function value. Remove when: the driver adopts `HandleTerminalInput` for the whole pipeline.

4. TUI API split: Go can match.
