# Ledger rule requests: two cross-package root-cause families (integrate-042 90a40bbe9 + ledger-autobind-int 48e9d7af1)

Counts come from `make interface-gaps` (`build/interface-gaps/gaps.tsv`). Both families are rule shapes, not missing Go behavior; each request names the evidence read in the Go source.

## Family 1: the chord `Context` parameter is Go's `context.Context` (S4 rows: 381 in all packages: durable 244, env 26, coding-agent 40, tui 22, chord 20, server 16, ai 8, client 3, mcp 1, agent 1)
Upstream passes a chord `Context` (`signal`, trace and request scope; `import { type Context } from "@earendil-works/chord"`, for example durable/src/session/session.ts:1) as an ordinary trailing parameter: `absolutePath(path, _context)` (env/src/remote-env.ts:432), `appendFile(path, content, context)` (remote-env.ts:632), `submit(submission, context)`, `commit(change, context)`, `abort(context, options?)` (durable/src/harness/types.ts:506-545). Go carries the same value as the leading `ctx context.Context`: `env/remote_env.go:492 AbsolutePath(ctx, path)`, `:778 AppendFile(ctx, path, content)`, `durable/harness/harness.go:405 Submit(ctx, draft)`, `:416 Abort(ctx, options)`, `internal/chord/binding.go:307 Dispose(ctx)`. The S4 rule counts Go parameters without `context.Context` but counts the upstream `Context` parameter, so every such method reads "upstream takes N, Go takes N-1" (and "Go takes 0" for `agent(context)`, `viewState`, `waitForIdle`, `dispose`).
Request: in S4 (and the S3 variadic check), pair an upstream parameter whose type is chord `Context`, in any position, with the Go `context.Context` parameter and compare the remaining parameters. Cancellation/abort evidence is the existing context tests of each package; the async rule in AGENTS.md ("AbortSignal and request/session lifetime map to context.Context") is the authority.

## Family 2: members inherited from JavaScript `Error` (`name`, `stack`, `cause`, `message`; 92 member-missing rows: mcp 19, durable 14, env 12, server 12, chord 9, protocol 8, ai 7, client 5, codemode 4, coding-agent 2)
Pi error classes extend `Error` (for example ModelsError, PiMessagesResponseError, ConversationBusy, RemoteServiceError) and the ledger lists the inherited `name`/`stack`/`cause` members as properties of the subclass. Go errors expose `Error()` for the message and `Unwrap()` for the cause (ai/auth_resolve.go:181-183), and the concrete type is the name. Go has no stack.
Request: bind `cause` to the Go `Unwrap` method (or the struct's `Cause` field, ai/auth_resolve.go:165), `message` to `Error()`, `name` to the type name (ModelsError has an explicit `Name()`), and record `stack` as designed out (no Go equivalent; Go errors carry no stack). `ai Model::property:name` is not part of this family: it is `Model.DisplayName` (section E1 of ledger-ai-rule-requests.md).
