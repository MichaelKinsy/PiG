## F1 (rev-gap-interactive): credential synchronization messages

Reachable, so ported. `RequestAuthRuntime.SynchronizeCredentialState` (model-runtime.ts:591-611) recomposes the provider and refreshes availability; `readConfig` now records why it dropped an uncomposable models.json provider (`modelsConfig.composeFailures`), which is Pi's per-provider composition error. `/logout`, API-key login and the three OAuth login flows call it after committing the credential and show `Credentials removed for X, but ...` (interactive-mode.ts:6021), `Saved API key for X, but ...` (6202) or `Logged in to X, but ...` (6326) with the `Credential <op> committed for <id>, but local synchronization failed` message, skipping the completion step as Pi does. Tests: `TestSynchronizeCredentialStateReportsCompositionFailure`, `TestLogoutReportsCredentialSynchronizationFailure`, `TestAPIKeyLoginReportsCredentialSynchronizationFailure` (all red before). tmux probe of the built binary with the reviewer's repro (isolated HOME/PIG_HOME) prints Pi's exact error. The OAuth login sites share `synchronizeLoginCredential` with the API-key site; they are covered by the same helper, not by separate tests. `interactive-mode.ts` verdict: PORTED.

Review (rev-gap-interactive-2): `SynchronizeCredentialState` no longer rebuilds the runtime's provider maps (`recomposeProvider` and a full `Refresh`). The rebuild raced the off-loop Anthropic subscription check (`maybeWarnAboutAnthropicSubscriptionAuthAsync` reads `providerByID`; `go test -race` reported it). A full refresh also failed the synchronization of one provider when any other provider's credential could not be read. The method now reads the construction-time composition error, which a credential change cannot alter, and checks the availability of the changed provider only, as `refreshProviderAvailability` does (model-runtime.ts:380-431). New tests: `TestSynchronizeCredentialStateChecksOnlyTheChangedProvider` and `TestSynchronizeCredentialStateLeavesProvidersForConcurrentAuthChecks`, both red on 741e7894b. `TestRegisteredOAuthLoginReportsCredentialSynchronizationFailure` covers the registered OAuth call site, `TestOAuthLoginSynchronizationFailureNamesTheLogin` covers the `Logged in to` label, and `TestAPIKeyLoginCompletesWhenTheProviderSynchronizes` shows no false failure. A tmux comparison with Pi 1.0.4 matches for `/logout` of the uncomposable provider (error) and of a healthy provider (`Removed stored API key for Anthropic…`). The Codex and Copilot OAuth sites call the same helper and have no separate test. Verdict: `interactive-mode.ts` PORTED.
