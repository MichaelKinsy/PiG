## core/extensions/loader.ts

Verdict: PORTED for load-time behaviour, with the cached/inline loading difference already recorded as D70 (approved; re-probed against 1.0.4: `clearExtensionCache` at loader.ts:138, `useExtensionCacheCwd` at :144 and `resource-loader.ts:513,695,717` still have the shape D70 describes, so D70 stands unchanged).

New differential `TestNodeLoadTimeActionsMatchPiLoader` runs one factory that calls every action of Pi's `ExtensionAPI` while it loads, through Pi 1.0.4's own `loadExtensionFromFactory` (the pinned dist) and through the Node runtime, and compares each outcome. Red on a real defect: `await pi.exec()` in a factory (valid in Pi; `exec` runs locally) rejected with "extension connection closed or replaced", and once past that hung the register handshake. Fixes: the Node runtime opens its early connection for the first awaited host call and settles awaited calls on it as results arrive (`runtime.mjs` `call`, `Connection.loading`); the host serves `exec` before registration (`loadingBusCall`) and runs it in its working directory when no session has bound the exec action yet (`host_calls.go` `handleUnboundExec`, `UIBridge.hasExecAction`), as Pi's loader-bound `exec` needs no session. Production binds the session exec action only after extensions load, so before this change a factory's `pi.exec` returned code 127 "exec not available".

The Go, Rust and Python SDKs expose exec only as a handler `Context` method; they have no factory-time `pi.exec`, so there is nothing to port there (language-native process APIs run in their registration code, as Pi's local `exec` does).

## core/extensions/types.ts

Verdict: DIVERGENCE-PROPOSED for one item, DONE for the rest. `ctx.ui.setEditorComponent(factory)` takes a factory returning a subclass of pi-tui's `Editor` (`CustomEditor`). Node runs Pi's own class. Go, Rust and Python cannot subclass a JavaScript class, and re-implementing `Editor`'s behaviour in three SDKs would be a second editor, not the one Pi's extensions extend. Proposed divergence (number to be assigned by the integrator): non-JavaScript SDKs do not offer `setEditorComponent` factories; they use `ctx.ui.custom` remote components. Remove when: pi-tui's Editor has a language-neutral component protocol. The `addAutocompleteProvider` retained-factory path is implemented in every SDK (docs/extension-api-parity.md) and needs no further change.

## modes/interactive/components/markdown-transform.ts (lead-assigned)

Verdict: PORTED. Pi's chain is synchronous: a transformer body returns before the next one, or the next generation, enters. Contract tests in `internal/codingagent/markdown_order_test.go`:
- `TestMarkdownAbandonedBodyKeepsCallbackOrder`: red before the fix (`["A first entered" "A second entered" "A first returned"]`): the host's five-second renderer inactivity boundary (D56) abandoned the request and the next generation entered the extension while the abandoned body still ran. Fix: `HandlerStalledError.Settled` (new, closed by the late response or the connection ending; `conn.go` `abandon`/`settleAbandoned`) and `markdownTransformProxy` disables the transformer until the abandoned body returns (D56: the stalled generation is disabled), later chains keeping their markdown as for a throwing transformer, then re-enables it.
- `TestMarkdownBodyOutlivingDisconnectOrShutdownPublishesNothing` (disconnect and Mode shutdown while a body runs and returns later): passed before and after; it pins that the abandoned generation publishes nothing, no later generation enters the extension, and after a Mode shutdown no later transformer of the chain runs. After a disconnect, Pi's failed-transformer rule applies, so the next extension's transformer still runs.
- `TestMarkdownAbandonedBodyKeepsOrderAcrossSDKs` (`test/extension-conformance`): the real Python and Rust SDK processes run a body that blocks on a release file. Red without the fix in both (`"entered first\nentered second\n"`, the next generation entering the extension while the abandoned body ran); green with it, including the transformer re-enabling after the body returns. The Python and Rust fixtures gained a `trace:<dir>:<name>` hook in their markdown transformer.
- `TestStalledRequestSettlesOnLateResponseOrConnectionEnd` (`coding/extension/host/subprocess`): `HandlerStalledError.Settled` stays open until the late response arrives or the connection ends, and a request abandoned after the reader exited is already settled. Each of the two closing paths was mutated away and fails its subtest.
Not covered: an uncooperative body in the Node SDK cannot occur (synchronous transformers block the event loop, which the heartbeat reports as `extension_unresponsive`).
