## RR1: per-API option interfaces are one Go struct (773 rows)

Pi declares `AnthropicOptions`, `AzureOpenAIResponsesOptions`, `BedrockOptions`, `GoogleOptions`, `GoogleVertexOptions`, `MistralOptions`, `OpenAICodexResponsesOptions`, `OpenAICompletionsOptions`, `OpenAIResponsesOptions`, `PiMessagesOptions` and `ProviderStreamOptions` as interfaces that extend `StreamOptions`. Go carries every provider's request option in one struct, `ai/types.go#StreamOptions` (Effort, ThinkingEnabled, ThinkingBudgetTokens, ThinkingDisplay, InterleavedThinking, Region, Profile, BearerToken, Project, Location, ReasoningEffort, APIKey and the rest; `signal` is the `context.Context` of `Provider.Stream`). A property check against that struct found every inherited and provider-specific property present except: `apiKey` (Go `StreamOptions.APIKey`, a naming difference of the acronym), the Azure members (`ai/azure_config.go#AzureEndpointOptions`: `AzureAPIVersion`, `AzureResourceName`, `AzureBaseURL`, `AzureDeploymentName`; the struct embeds `StreamOptions`), PiMessages `debug` (`ai/pi_messages.go#PiMessagesConfig.Debug`) and Anthropic `client` (an injected SDK client object, designed out: Go builds its own HTTP client).

Request: bind each option interface to `ai/types.go#StreamOptions` as `ModelsApiStreamOptions` already is (`renames.json`), with `AzureOpenAIResponsesOptions` bound to `ai/azure_config.go#AzureEndpointOptions`, and let the member rows bind by name with the acronym rule (`apiKey`→`APIKey`, `baseUrl`→`BaseURL`).
