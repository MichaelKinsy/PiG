# lg-help-3 Findings from the ai, durable and env measurement (lg-help-3 at 0afeb85bb)

- **`OpenRouterRouting`** (types.ts:977, 13 members) is `map[string]any` in Go (`ai/types_unions.go`). The map carries a model's routing preferences verbatim, as Pi's JavaScript objects do: `ai/types_unions_test.go` keeps an unknown key, `internal/codingagent/model_registry.go` deep-merges overrides with `mergeCompatMap`, and `cmd/gen-models` writes the map literal. A typed struct would drop unknown keys and change the merge. Rule request: an open `map[string]any` stands for an upstream interface with many optional properties when the value is a JSON pass-through; or the lead approves the struct and the merge change.
- **`Model`'s flat members** (`api`, `baseUrl`, `compat`, `contextWindow`, `cost`, `headers`, `maxTokens`, `name`, `reasoning`) live in Go's `Model.ProviderMeta` and `Model.Capabilities`. Embedding both structs would promote the fields and close ten rows twice (ai and ai/compat), but renames `m.ProviderMeta.X` at every call site. Needs a lead decision with the `BaseModel` embedding.
- **Generic methods as package functions.** `Session.snapshot`, `snapshotAsOf`, `watchDoc`, `documentState`, `TaskRuntime.*`, `Tx.createTask` and `HookApi.*` are the generic functions `durable.Snapshot`, `SnapshotAsOf`, `WatchDoc`, `DocumentStateOf`, `CreateTask` (Go methods cannot have type parameters). `renamedMember` resolves only a method or field of a Go type, so a documented rename to a function leaves the rows `member-missing`. Rule request: let a reviewed member rename name a package-level function whose first parameter is the owner.
- **`InMemoryTelemetryContext` constructor.** The zero value is the constructor (`telemetry/memory.go`, `stubgen:omit NewInMemoryTelemetryContext`). Designed out.
- **`DiagnosticErrorInfo.stack`** has no Go reader: D103 strips `Stack` from Go errors.
- **`Draft`, `Context`, `ContextKey`, `BACKGROUND_CONTEXT`, `TODO_CONTEXT`, `withContextValue`, `awaitWithContext`, `createContextKey`** (chord) are `context.Context` and its helpers in Go.
- **`JSON_RPC_ERROR_CODES`, `isJsonRpcRequest`, `isJsonRpcResponse`, `JsonRpcResponse`** (mcp) are the `JSONRPC*` constants and `JSONRPCMessage.IsRequest/IsResponse`.

Landed in this slice: Pi-cited, mutation-checked tests for `SshConnectOptions.onLog`, `SshTarget.ssh`, `RemoteExecutionEnv.createTempDir` and `remove`, `ToolExecutionApi.memo`, `PowerShellToolOptions.prepare`, `Session.subscribeClose`, `JsonlCorruptionError.message` and `ConvertCompletionsMessagesOptions.grammarToolInputProperties`; `NewJsonlCorruptionError` is exported under Pi's constructor name.

## ExtensionAPI: about 100 rows need an extension-point route (measured at c14c67a8f, p1-impl rules)

`ExtensionAPI` (types.ts:1520 and following) is 60 `not-exercised` rows plus 42 `member-missing` rows (`on` and its 40 event overloads).

- **`not-exercised` (60):** every `coding/extension/api.go#API` method (`AppendEntry`, `Exec`, `GetActiveTools`, `RegisterCommand`, `RegisterTool`, `RegisterProvider`, `SendMessage`, `SetModel` and the rest) reports `P1: no production code reads, sets or calls ... P1(b) L1: upstream package coding-agent is not a library`. The in-process runner implements `API` and passes it to extension factories, and extensions call it through the interface (and through the subprocess SDK bridges). The static reach analysis does not follow that dynamic dispatch, and L1 rules out route (b). LEAD-ANSWERS names Tool Options and Operations as real extension points; the extension API is the primary one. Rule request for p1-impl: an extension-point route (L7) that closes a member of an interface when production code implements the interface and hands it to extension code, and a conformance row in `test/extension-conformance/` or an extension-runtime scenario exercises the member.
- **`on` (42):** Pi declares 40 overloads of `on(event, handler)`, one per event name, each with its own result type. Go has one `On<Event>` method per event (`OnProjectTrust`, `OnSessionStart`, ...). The detector evaluates every overload's call row against the single member that the `on` property maps to, so a per-overload mapping needs an engine extension point: "call row `on::call:<event>` is the method `On` plus the PascalCase event name". That is a new `RegisterMember`-style point for overload rows, which the engine owner adds (rules/README.md).

## `telemetryContext` pass-through: 78 rows need an L5 pass-through rule (measured at 850a8d053 plus integrate)

Every `*Options.telemetryContext` row (44 leaf rows and 34 parents: `StreamOptions`, `SimpleStreamOptions`, `ProviderRequestOptions`, `DeferredFetchOptions`, `ImagesOptions`, `ClassifierOptions` and the per-provider option types, each also under `ai/compat`) maps to one Go field and reports `P1(b) L5: no non-test code of ai reads or sets` it.

Pi reads `telemetryContext` nowhere in `packages/ai/src`, `agent/src` or `coding-agent/src` except one copy in `buildBaseOptions` (`api/simple-options.ts:48`); the providers only forward the options object, and `ai/test/telemetry-options.test.ts` asserts that the value reaches the provider, Models, deferred and image dispatch unchanged. Go has one `StreamOptions` struct that every layer passes by value, so there is no copy statement to read or set the field, and a faithful port cannot add one without a stand-in. Rule request for p1-impl (L5b): a field Pi only forwards is satisfied when (a) Pi has no reader of it besides copies, (b) the Go owner struct is passed by value through production dispatch, and (c) an asserting test observes the value at the far end (`ai/telemetry_options_upstream_test.go`, now declared `Ports packages/ai/test/telemetry-options.test.ts` with the 1.0.4 line numbers). The same shape applies to `mcp` annotation members and `DeferredFetchOptions.wait`.

## JSON-bridged fields: 46 leaf rows report `no production code reads, sets or calls` for fields production does read (measured at 5705df0c9, in-tree detector, 1374 open rows)

`extension.ProviderConfig.AuthHeader` (`coding/extension/provider.go:37`) is one example: `ModelRegistry.RegisterProvider` (reached from `cmd/pig/extensions.go:164` through the host callback) converts the extension configuration with `providerConfigFromRegistration` (`internal/codingagent/model_registry.go:863`), which marshals it to JSON and decodes it into `providerConfig`. The `json:"authHeader"` tag carries the value; no statement names the Go field, so L5 finds no reader. The same shape explains the rows of `coding/extension/events.go` (19: event structs the subprocess host decodes), `telemetry/schema.go` (13), `coding/rpcclient/types.go` (4), `mcp/types.go` (4), `mcp/content.go` (3) and `coding/extension/diagnostics.go` (2). Rule request for p1-impl (L5c): a field with a `json` tag counts as read and set when production code reachable from `cmd/pig` passes a value of its owner struct to `json.Marshal` or `json.Unmarshal` (or an encoder or decoder), and an asserting test or the Pi oracle observes the value after the round trip. The detector would need the marshal call sites in the reach set; a field-level test of the round trip (decode a Pi-shaped payload, assert the field) is the evidence.

Also measured: `coding-agent` rows can only close by production reach because L1 excludes the package; the largest clusters are `RpcClient` (80), `ExtensionAPI` (62) and the tool call events (14), all reached only through dynamic dispatch or callbacks.

## ExtensionAPI under rule L7 (103 not-exercised rows at a36331de77, int recipe)

`coding/extension/api.go` `API` is implemented only by `extensiontest.Fake`, so rule L7 closes a member only on a cross-SDK conformance test (`test/extension-conformance/*` or `TestConformance*`) that references it with a Pi cite. The conformance suite drives `sdk.Extension` (`extensions/sdk`, `OnEvent`, `RegisterTool`, `Command`, the Rust and Python realizations), never `extension.API`, so no existing test counts. A test of the Fake stays excluded: it is the test double L7 rejects, and giving it a `TestConformance` name would only satisfy the rule's prefix check. Two honest routes remain, both decisions for the rule owner:

1. A reviewed placement mapping `ExtensionAPI.<member>` to the `sdk.Extension` member that implements it (for example `on` to `Extension.OnEvent`, `registerTool` to `Extension.RegisterTool`), so the existing conformance rows (`event_coverage_test.go`, `extension_api_go_test.go`, `extension_api_rust_test.go`, `event_unsubscribe_test.go`) bind to the rows.
2. Delete `extension.API` as a hand-written interface and keep `extensiontest.Fake` as a helper, if nothing reaches it in production (the only non-test reference is the compile-time assertion in `fake.go`).

## Opaque extension aliases (about 30 undecidable rows at a3827e73c1)

`coding/extension/opaque_types.go` declares 33 upstream types as `= any` (`AgentMessage`, `Model`, `ImageContent`, `ModelRegistry`, `SessionManager`, `ReadonlySessionManager`, `OAuthCredentials`, `SimpleStreamOptions`, and others) because extension payloads cross the JSON subprocess boundary and the in-process renderer boundary as dynamic values. Rule T9 reads each as "upstream type with members against an untyped Go type" (11 `AgentMessage`, 5+3 `Model`, 3+3 `ReadonlySessionManager`/`ModelRegistry`, 2 `ImageContent`, and so on). Replacing an alias with the concrete type (for example `AgentMessage = agent.AgentMessage`, `Model = *ai.Model`) changes what every event handler and host adapter type-asserts, so it is a typed-boundary refactor for the extension owner, not a ledger edit. Rule request: record the opaque aliases as a reviewed placement (the typed contract is the concrete event and SDK types, as the file header says).

## Telemetry type-level helpers (10 no-go-symbol rows)

`InferEventAttributes`, `InferOptionalAttributes`, `InferRequiredAndOptionalAttributes`, `InferStartAttributes`, `SchemaTelemetrySpan`, `TelemetrySchemaSpanEndAttributes`, `TelemetrySchemaSpanEventAttributes`, `TelemetrySchemaSpanEventName`, `TelemetrySchemaSpanStartAttributes` and `TelemetrySchemaSpanUnion` are TypeScript conditional and mapped types that derive attribute and span types from a schema literal at compile time (`packages/telemetry/src/index.ts`). Go cannot derive a type from a runtime value, and Pi performs no runtime schema validation either (`CreateTypedSpanStarter` ignores its schemas, as upstream does). Rule request: record these ten as designed-out type-level inference with no runtime counterpart.
