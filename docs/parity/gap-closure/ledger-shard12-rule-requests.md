## Selector component list accessors (getMessageList, getSessionList, getTreeList, getSelectList, getSearchInput)

Pi's selector components return their inner list so the host can focus it: `{ component: selector, focus: selector.getMessageList() }` (interactive-mode.ts:5503). Go's selectors (tui/user_message_selector.go and its siblings) forward `HandleInput` to an unexported inner list and call `Invalidate()` afterwards, because a parent `Container` reuses a child's rendered lines until the child is invalidated and an inner list that took the keys directly would not invalidate its parent. An exported accessor with a host that focuses the list would drop that invalidation and leave stale lines on screen, so the accessor would be caller-free or wrong. Rule request (lg-rules): the `getXList()`/`getSelectList()`/`getSearchInput()` accessors are a reviewed placement onto the selector's own `HandleInput` (the host drives the selector, the selector drives the list). `ModelSelectorComponent.dispose` (model-selector.ts:224-229) clears the refresh timeout and aborts the background catalog refresh. Go's selector receives refresh results from its host (`UpdateModels`, `SetRefreshSuccess`), so the 15 s refresh timeout and cancellation belong to the host: `InteractiveMode.pickModel` (internal/codingagent/interactive_models.go:42-72) creates `context.WithTimeout(ctx, 15*time.Second)` for the refresh and its deferred `cancel(); <-done` runs when the selector closes, which is `dispose()` (clear timeout, abort) in Pi. Rule request: `ModelSelectorComponent.dispose` is a reviewed placement onto that host-owned cancellation.
