# lg-help-1: package durable open rows (1,023; gaps.tsv on integrate-042 + lg-decide) — rule requests for lg-rules

No lane touches `durable/`. Of 1,023 open rows only 85 are `child-gap`; the rest fall in four classes that a rule closes, not a code change. Each class names the Go form that already exists (see `docs/parity/gap-closure/gap-durable.md`, "Go shape").

## D1. chord `Context` parameter is Go's `context.Context` (233 of 262 `signature-mismatch` rows)
Pi's `Context` (chord, a cancellation + identity token) is the leading `ctx context.Context` of the Go call, exactly as `AbortSignal` is (rule M4). The detector counts it as a missing parameter: "S4: upstream takes N parameters, Go takes N-1". Evidence the extra parameter is always the Context: of 262 durable S4/S3 rows, 233 have an upstream parameter of type `Context` (`Conversation.abort(context, options)` -> `Abort(ctx, *ConversationAbortOptions)`, `Conversation.submit`, `commit`, `compact`, `configure`, `context`, `entries`, `fork`, `reset`, `agent`; `Session.*`, `TaskRuntime.*`, `HookApi.*`, `Storage` readers, ...). Callback parameters whose type mentions `Context` (`AgentEventStream.start(listener: (events, context: Context) => Promise<void>)`, `Session.subscribeCommits`) are Go callbacks whose first parameter is `context.Context`.
Request: S4 treats an upstream parameter of the chord type `Context` (including inside a function-typed parameter) as satisfied by a leading `context.Context` Go parameter; the same for results typed `Promise<T>` (blocking call, `(T, error)`).

## D2. Generic methods are package-level generic functions (S3 `signature-mismatch`, `member-missing`)
Go methods cannot take type parameters, so Pi's `snapshot(token, ...)`, `snapshotAsOf`, `watchDoc`, `documentState`, `createTask`, `doc(token, id|key, seed)` members of `Session`, `TaskRuntime`, `ToolExecutionApi`, `HookApi`, `DocumentObserver` and `Tx` are `durable.Snapshot[T](ctx, reader, token, args...)`, `durable.SnapshotAsOf[T]`, `durable.WatchDoc[T]`, `durable.DocumentState[T]`, `durable.CreateTask[T]` and `durable.Doc[T](tx, token, args...)`. Rows: `Session::{snapshot,snapshotAsOf,watchDoc,documentState}`, `TaskRuntime::{snapshot,snapshotAsOf,watchDoc}`, `ToolExecutionApi::{createTask,snapshot,snapshotAsOf,watchDoc}`, `Tx::{createTask,doc::call:1..3,appendEntry::call:1}`, `HookApi::{snapshot,snapshotAsOf}`, `DocumentObserver::watchDoc` (~40 rows). Request: an upstream member whose signature has a type parameter is satisfied by a package-level function of the same name whose first parameter is the owner (or the owner's reader interface); the variadic tail (`key`, `seed`, `taskId`) is the Go form of Pi's per-token overloads (S3).

## D3. Library reachability (P1 `not-exercised`: 510 rows; 137 "no production code reads", 373 "only in X, which no path from cmd/pig reaches")
`durable/` is a public library: the Pi product (`pig`) does not drive it, so a static path from `cmd/pig` never exists. The 373 "only in X" rows name an in-package caller (`typedWatch.Start`, `taskRuntime.WatchDocErased`, `WatchEvents`, `StorageConformance*`): the member is used by exported package code that tests and the `durable/examples`, `durable/interop` programs exercise. Request: P1 accepts, for a package outside the `cmd/pig` product graph (`durable`, `env`, `chord`, `client`, `server`, `telemetry`, `protocol`), a production caller in the same package that is itself exported or reached from an exported function (an in-package production call site, not a test). The 137 "no production code reads" rows (JsonlStorage 34, NodeExecutionEnv 21, SqliteStorage 17, ToolExecutionApi 7, NodeSqliteDatabase 7, FileSystem 7, ExecutionEnv 7, Tx 6, RegistrySnapshot 6, Conversation 6, AgentEventStream 4, ...) are implementer methods of the storage / environment interfaces (`Storage`, `ExecutionEnv`, `FileSystem`, `ToolExecutionApi`) that are called through the interface: the same interface-dispatch rule as tui R1 (a call on an interface-typed value reaches every implementer in the module).
