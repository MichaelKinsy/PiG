Corners of eemeli/yaml that `internal/yaml12` does not reproduce (proposed divergences or follow-ups; numbers are for the integrator to assign):

1. Named tags the core schema resolves only on request (`!!binary`, `!!timestamp`, `!!set`, `!!omap`, `!!pairs`, `!!merge`): the library builds `Uint8Array`, `Date`, `Set` and `Map` values that no Go value stands for; `internal/yaml12/known.go` resolves them as unknown tags (a warning and the string).
2. A value that contains an alias to itself (`&a [*a]`): the library builds a cyclic object; Go cannot, and reads the inner alias as null.
3. A collection used as a mapping key whose members are not plain words, whole numbers or booleans: the library stringifies it with its full flow stringifier; Pig returns the error `yaml: a collection as a mapping key is not supported`.
4. `%YAML 1.1` documents are composed with the core schema; they always fail with `Missing directives-end/doc-start indicator line` in frontmatter, and only the wording of an earlier content error could differ.
5. Warnings (unknown tags and directives, ambiguous aliases) are not reported; the library logs them with `process.emitWarning` and does not throw.
