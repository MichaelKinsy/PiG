## Component constructors that take Pi's `tui` and `theme` handles (S3/S4 rows)

Pi components are constructed with the TUI handle and the theme (`new BorderedLoader(tui, theme, message, options)`, bordered-loader.ts:12; likewise ExtensionEditorComponent, ExtensionSelectorComponent, CustomEditor, TreeSelectorComponent and other selectors). Go components read the one process theme through `tui.ActiveTheme()` and receive render requests through the owning `Tui`, so their constructors take neither handle (`tui.NewBorderedLoader(message, cancellable)`, bordered_loader.go:22). The remaining construct rows with this shape (BorderedLoader::construct:0 and the editor/selector constructors whose only gap is the tui/theme/keybindings handles) are not member ports: adding the parameters would be unread arguments. Request: a reviewed placement "Go components take the active theme and TUI from the process, not from constructor arguments", closing those construct rows, or an explicit decision to inject them.

## FooterComponent construct / setSession: AgentSession against footerSession (T9, undecidable)
Pi's `FooterComponent(session: AgentSession, footerData)` and `setSession(session: AgentSession)` read three things from the session on each render: the all-entry usage totals, the routed model, and the model and thinking level. Go's `NewFooterComponentForSession(session footerSession, footerData *FooterDataProvider)` and `SetSession(footerSession)` take the consumer-owned two-method interface `footerSession` (`footerUsageTotals`, `footerRoutedModel`), which `InteractiveMode` and `coding.Session`'s handle satisfy. `internal/codingagent` cannot name `coding.Session` (import cycle), and the footer needs no other AgentSession member. Request: a reviewed T9 type decision stating that `footerSession` is the Go form of `AgentSession` for these two parameters. After it, the construct and setSession rows (4) close.

## Provider options toolChoice: string-literal union against StreamOptions.ToolChoice `any` (U1, type-mismatch, 11 rows)
`GoogleOptions`, `GoogleVertexOptions`, `OpenAICodexResponsesOptions` and `SimpleStreamOptions` (each at `ai/.#`, `ai/api/<file>#` and `ai/compat#`) type `toolChoice` as a union of string literals (`"auto" | "none" | "any"`, `"auto" | "none" | "required"`, `ToolChoice`). Go carries one `StreamOptions.ToolChoice any` that holds the name or a provider object, and every provider reads it through `toolChoiceName` (types.go:666). U1 answers No (`interface{} is not a string or number type`), and a No is not an exception row: `reviewed-types.json` entries for these ids were rejected as stale ("no undecided row"), so the only closing route is a rule or a typed field. The Azure and OpenAI Responses rows close because their union is T10 (unknown). Request: a U1 rule that accepts `any` for a string-literal union when the Go field is the shared options carrier, or the owner's call to type `ToolChoice` (a break for the provider-object form). Evidence added in this lane: `ai/google_tool_choice_option_test.go` (Gemini and Vertex payload `toolConfig` mode for none/any/auto, mutation-checked); Codex is locked by `TestCodexRequestHonorsToolChoice`.
