# Interface ledger closure (Pi 1.0.4)

Base `12429f15b`. Ledger: `test/parity/interfaces/mapping-v1.0.4.json` (9950 interface IDs: 9885 package, 65 CLI). A row is closed when its disposition is `ported`, or `divergence` with a numbered `D<N>`. `deferred` and `pending` are not closure.

## Closure kinds

A ported row closes under one of two production statuses, and the ledger keeps them apart.

- **`complete`** (production layer): the row cites a `call:`, `registry:`, `wire:` or `reflection:` production reference, and the cited function is reachable from the PiG binary. `python3 test/parity/interface-closure/audit.py` proves it: it lists every closed row whose `call:` reference is not reachable by rapid type analysis from `cmd/pig` and `cmd/pig-experimental` (`go run ./test/parity/cmd/prodreach -out /tmp/reach.json -tags pig_experimental ./cmd/pig ./cmd/pig-experimental`). The audit must list zero rows.
- **`public-api-tested`** (production layer, production reference `public-api:<file>#<ExportedSymbol>`): a public library API whose Pi counterpart is a public export, whose Go symbol is exported from a public package, and that no PiG binary calls. Test callers (go/types, `methodrefs`) are the only proof, so the status says "tested" and not "production". `interfaceinventory` enforces it: a row that cites only `public-api:` references must carry the `public-api-tested` layer and a `test:` reference; a row with any other production reference must not carry it; the symbol must be exported and declared in a non-test file. Decision of the lead, 2026-05: RpcClient and similar public libraries close this way, never as production.

Counts by package (agent 26, ai 368, codemode 25, coding-agent 188, mcp 43, tui 101) are printed by `python3 test/parity/interface-closure/report.py`.

Order of operations after `close.py <spec>`: `python3 test/parity/interface-closure/reproduce.py /tmp/reach.json --apply --public` re-points a row whose cited caller is unreachable to a reachable caller (go/types), or rewrites it as `public-api-tested` when the Go symbol is a public export with test callers, and reports the rest (revert those to pending). Then run `audit.py`.

Findings from the audit (the first caller go/types found was not reachable from the binary): `RetryAssistantCall` (retry stack; PiG's session retry does not call it), `ai.BuiltinModels`, `ai.GetAllBuiltinModels`, `ai.CreateProvider`, `ai.LazyAPI` and the faux provider helpers (the `ai` Models/Provider stack is not built by `cmd/pig`), `agent.EstimateContextTokens`, `MarshalToolCallEvent`, and `rpcBeforeSessionFork`, `rpcBeforeSessionSwitch` and `rpcResultCancelled` in `cmd/pig/rpc_mode.go`, which only a test calls (possible dead code or a missing production emission of the RPC `session_before_fork`/`session_before_switch` events: for gap-ledger-followups to check).


## Why nothing was closed

1. **Closure is hand-authored per ID and no generator produces it.** `interfacerecommend` can only suggest candidates. It found none for 8850 IDs, none for the 7995 member IDs ("member-level candidates require parent-aware shape translation; leaf-name matching is disabled") and a single unverified name match for 730 top-level IDs. Every `ported` row needs Pig targets, a production call site, a test and the `shape`/`production`/`behavior` layers, each checked by `interfaceinventory` against the Go source (`validateMappingClosure`, `validateReferenceFragment`). A parent is `ported` only when every child is.
2. **A version leap resets `ported` to `pending` by design.** `carriedDispositions` in `test/parity/cmd/interfaceinventory/main.go` carries only `deferred` and `designed-out` across a leap, because a shape hash does not see behaviour. The 0.99.2 ledger had 172 `ported` rows. The 1.0.4 leap (`66a6c7fe7`) turned all 172 into `pending`, and nobody re-reviewed them.
3. **The 6405 `deferred` rows are a scope decision carried from 0.84.0** ("file-level covered, not individually re-verified per semantic interface"). `-strict` rejects only `pending` and `partial`, so `interface-mapping-strict` would go green with every one of them still unreviewed. Do not count `deferred` toward an interface-parity claim.

So: not missing tooling and not a policy that refuses to close. The tooling works and the ledger was unreviewed after the leap.
