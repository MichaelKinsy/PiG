# Pending upstream tests: production-risk triage

## Baseline and method

This review starts at `67621208de1e3fa3b4a9940082a7ae404794451d`, against Pi 0.87.1. The denominator is every entry with `disposition = "pending"` in `test/parity/interfaces/test-mapping-v0.87.1.json` at that commit. Case counts come from the matching `files[].caseCount` in `test/parity/interfaces/upstream-tests-v0.87.1.json`, not from guessed Go test counts. There are **208 files and 1,311 case sites**. An `it.each`/`test.each` site can expand to several executions; these counts are not the expanded matrix (for example, #9068 contains three RPC rows and two interactive rows at two sites).

The table is a review snapshot, not a second disposition ledger. Its mapping rationale is copied from the baseline and can mention historical branches whose existence or integration is not verified. Current closure belongs only in the JSON mapping. A pending entry does not prove that no Go tests exist. Audit exact inputs, outputs, callbacks, errors, and production reachability before promoting it. The first-case line anchors below refer to `.upstream/current/` and identify each obligation, not proof that its entire file has been ported.

Risk orders potential production harm, not implementation effort:

- **HIGH**: tool side effects/admission; request, streaming, or authentication failure; lost/poisoned Session state; host callback or ordinary input/rendering failure.
- **MEDIUM**: optional/experimental paths, explicit setup, catalog/configuration, platform integrations, and supporting operations. These remain obligations.
- **LOW**: build-time catalog checks and pure supporting format/URL checks without per-turn execution.
- **hot-path**: the production mechanism runs in a normal text coding session, including its selected Provider, builtin tools, Session, ordinary Main Screen, loaded-extension hooks, and error/cancellation branches. The specific error need not happen on every turn. Optional clipboard, image, example extension, experimental/new harness API, and explicit maintenance paths are not tagged merely because their names contain “tool” or “session”. This is a conservative release-candidate tag proposal, not an approved scope exclusion.

Within HIGH, review stock tool output/search first, then admission/cancellation and the new harness boundary, then Providers, Sessions, Extension Host, Main Screen, and modes. `packages/ai/test/validation.test.ts` is HIGH/hot-path but belongs exclusively to `fix-tool-arg-coercion`; do not change its tests or disposition here. New harness tests remain HIGH even where stock reachability is missing; do not substitute older agent-loop tests for that API.

## Enabled release gate

The owner ratified this as porting law. `AGENTS.md` now requires matching upstream tests in the same production change and forbids release with pending or partial hot-path tests. `make ci-contracts` includes `make test-porting-release`, which runs `test/parity/cmd/testinventorycheck -release-policy test/parity/interfaces/test-porting-policy-v0.87.1.json`. There is no allowance, skip, or default-off switch in that Make target.

The checked-in policy reviews **all 598 upstream test files**, including partial and closed files, rather than only the original pending subset. It binds exact paths and hashes to `tools`, `providers`, `sessions`, `extensions`, `tui`, `cli`, or `utilities` and an explicit `hot-path` tag list. This broader release review supersedes the initial pending-only recommendation below. Selected-provider catalog, auth, image, and TUI platform paths are included conservatively. Only separate new-harness/experimental APIs, explicit example/Worker adapters, and supporting utility paths are untagged, with a rationale. Missing paths, stale hashes, unknown areas/tags, duplicate entries/tags, and missing rationales fail closed.

The ported baseline contains the **121 exact ported paths** from committed mapping `fe46b5896c` (the policy stores its full hash). The checker reads that mapping from Git and requires the stored baseline to retain every path it ported before comparing the current total ported count. The stored list may extend past the anchor with later ports. A release squashed onto public history anchors on a public commit and keeps its full list. A missing baseline object is an error: fetch the recorded commit instead of lowering the baseline. Counts are derived from path dispositions, not a hand-entered expected number. Ratchet the baseline after an accepted port commit with `python3 automation/gen/test-ported-baseline.py --commit <full-commit>`; the command refuses a decrease. Commit the policy update with the accepted port's integration. The gate also rejects hot-path partial entries, so porting one case cannot bypass release closure. Live credentials do not exempt a test.

The normal mapping validator still reports 121 ported, 209 partial, 65 designed-out, 1 divergence, and 202 pending files. A green mapping inventory means those dispositions are accounted for, not that release is permitted. `docs/parity/pending-tests-batches.md` partitions all original 208 pending and 209 partial files into dispatchable, non-overlapping batches and keeps the six closed files visible.
