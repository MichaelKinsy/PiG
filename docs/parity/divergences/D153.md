## D153 The bash truncation notice names the size of the last line, not the bytes after the final newline (Pi #10015)

What: when the last line of bash or PowerShell output is over the byte limit, PiG's `[Showing last 50.0KB of line N (line is <size>)...]` notice gives the size of that line. If the output ends with a newline, Pi's `getLastLineBytes` (`packages/coding-agent/src/core/tools/output-accumulator.ts`) returns the bytes after the newline, so Pi's notice reads `line is 0B`.

Why: `node -e 'process.stdout.write("a".repeat(60000) + "\n")'` produces `[Showing last 50.0KB of line 1 (line is 0B)...]` in Pi (measured on the previous pin; the bash truncation notice is unchanged in Pi 1.3.0) and in PiG. The tail it shows belongs to line 1, which is 58.6KB. Pi has no fix (Pi #10015 is open, with no PR).

Observable effect: PiG prints `line is 58.6KB`; Pi prints `line is 0B`. Output without a trailing newline is the same in both.

Call-site markers: `internal/codingagent/tools/output_accumulator.go` (`LastLineBytes`).

Locked by: `TestBashLongLastLineNoticeNamesTheLineSize` (the bash tool) and `TestOutputAccumulatorLastLineBytes` (chunk boundaries, blank last line, split multi-byte character) in `internal/codingagent/tools/last_line_bytes_test.go`.

Parity allowance: none. No paired scenario runs a command whose last line exceeds the limit and ends with a newline.

Remove when: Pi reports the size of the last counted line.
