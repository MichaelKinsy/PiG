## D633 A failed settings save is reported where the change was made, where Pi reports it only in its settings diagnostics

What: Pi's settings setters cannot fail: they change the value in memory and queue the write (`packages/coding-agent/src/core/settings-manager.ts:576-588`, `:635-642`), and a write that fails is recorded for `drainErrors()` (`:561-563`, `:674-678`). Pi's callers therefore go on as if the save had worked: the `/settings` callbacks apply the live effect (`modes/interactive/interactive-mode.ts:5154-5173`), `set_steering_mode` and `set_follow_up_mode` answer success (`modes/rpc/rpc-mode.ts:540-548`), `pi install` prints `Installed <source>` (`package-manager-cli.ts:1061-1063` over `core/package-manager.ts:1130-1133`), the config selector keeps the toggle (`modes/interactive/components/config-selector.ts:552-564`, `:626-628`) and an extension's `settingsManager.set...()` returns. The failure shows only where Pi drains the recorded errors: the settings diagnostics collected at startup and when a runtime is created (`core/settings-diagnostics.ts:5` from `main.ts:721` and `:860`) and the `Warning (<command>, <scope> settings): ...` lines the package and config commands print before they run (`package-manager-cli.ts:283-290`, `:926`, `:1038`).

PiG's setters perform their write before they return (the write queue is drained on the caller) and return its failure, besides recording it for `DrainErrors` as Pi does and keeping the change in memory as Pi does. Each caller below acts on the returned error at the point of the change:

- `/settings`: prints `Failed to save settings: <error>`, does not apply the change's live effect and shows the manager's value on the row again.
- The model selector of an interactive run without a Session: shows the error instead of the selection status.
- RPC `set_steering_mode` and `set_follow_up_mode`: answer an error response; the queue mode of the running agent has changed, as in Pi.
- `pig install` and `pig remove`: print the error and exit 1 after the package was installed or removed, where Pi prints `Installed` or `Removed` and exits 0. The package API of an extension (`addSourceToSettings`, `removeSourceFromSettings`) returns the error.
- `pig config`: prints `config toggle: <error>` and shows the entry in its previous state.
- An extension's `SettingsManager` setters and the Session operations `setSteeringMode`, `setFollowUpMode` and `setCacheWarmingMode`: return the error to the extension.
- `Session.SetCacheWarmingMode`: returns the error without telling the cache warmer that the mode changed. The mode in memory is the new one, as Pi keeps it, so the warmer's status reads the new mode; the call does not stop a refresh that is scheduled.

Internal, with nothing a user sees: `GetOrCreateDeviceID` keeps the new ID in memory when its save was skipped; the Session's default model, default thinking level, retry and auto-compaction setters, the changelog version setters, the enabled-models setter and the interactive cache-warming setter discard the returned error, as Pi's callers have none.

A setter called from inside a write of the same manager (a settings storage whose lock callback calls a setter) returns nil before its own write runs; its failure is recorded only.

Why: a user who changes a setting and is told nothing believes it is saved; on the next start the old value is back. Pi reports the failure at a later start, away from the change that caused it. PiG says so when and where the change was made.

Pi bug: not reported upstream yet. A draft for the owner to file is in `docs/parity/gap-closure/ledger-coding-agent-pi-issue-drafts.md` (D633).

Scope: `internal/codingagent` (`SettingsManager.UpdateGlobal`, `UpdateProject` and the setters over them; `settingsHandlerTUI`; `persistDefaultModel`; `GraphSettingsManager.Call`), `internal/packagemanager` (`AddSourceToSettings`, `RemoveSourceFromSettings`), `coding` (`Session.SetSteeringMode`, `SetFollowUpMode`, `SetCacheWarmingMode`) and `coding/cli` (RPC `set_steering_mode`, `set_follow_up_mode`; the config selector; the child session operations). The recorded error, the value kept in memory and the order of the writes are Pi's.
