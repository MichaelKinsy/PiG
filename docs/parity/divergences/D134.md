## D134 One SSE line is bounded at Node's maximum string length

What: Pi's SSE readers (the OpenAI SDK's `LineDecoder`, the Google GenAI SDK reader and `iterateSseMessages` in `anthropic-messages.ts`) have no line cap of their own, but each one holds the line in a JavaScript string. Node cannot make a string longer than `buffer.constants.MAX_STRING_LENGTH` (536,870,888 UTF-16 code units on 64-bit V8), so a longer line ends Pi's stream with `Cannot create a string longer than 0x1fffffe8 characters` or `RangeError: Invalid string length`. PiG's shared SSE decoder (`ai/sse.go`, used by OpenAI Responses, Google and the Codex WebSocket path) ends the stream at the same bound in bytes, with `bufio.Scanner: token too long`. Before comb-audit row 4 it ended at 32 MiB; the lane's first fix removed every bound.

Why: Go strings have no runtime length limit, so without this bound a server that never ends a line grows the buffer until the process runs out of memory. Pi's process fails at this length instead.

Scope: `newSSEDecoder` in `ai/sse.go` (`sseLineLimit`). The error text differs from Pi's, and the bound counts bytes where Node counts UTF-16 code units. The Anthropic, Mistral and Codex SSE readers keep their own buffers and are not changed.

Owner decision: 2026-10-10, lead review instruction for fix-pi-bugs-ai 58a029e731: "the SSE line-cap removal must still bound memory (cite Pi)". Number taken from the top of fix-pi-bugs-ai's block (D120-D134) by its reviewer rev-fix-pi-bugs-ai-2; the lead confirms or renumbers it.

Call-site markers: `ai/sse.go` (`sseLineLimit`).

Evidence: `TestSSELineLimitIsNodesMaxStringLength` (`ai/sse_long_line_test.go`) compares the bound with `require('node:buffer').constants.MAX_STRING_LENGTH` from the pinned Node. `TestSSEDecoderBoundsALine` lowers the bound and requires a longer line to end the stream with `bufio.ErrTooLong`; it fails when the decoder is given no bound. `TestSSEDecoderAcceptsALineLargerThan32MiB` keeps the comb-audit row 4 case.

Parity allowance: no paired scenario streams a 512 MiB line.

Remove when: Pi bounds an SSE line itself, or divergence-guard accepts Node runtime constants as upstream references so that `sseLineLimit` can cite `MAX_STRING_LENGTH` directly.
