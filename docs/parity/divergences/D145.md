## D145 Nested Errors keep their name and message in codemode output (Pi #10650)

What: an Error's `name` and `message` are not enumerable, so Pi's codemode serializes a nested rejection as `{}`. `text(await Promise.allSettled([...]))`, console output and the returned value then show `"reason":{}` although the message is available in the VM. PiG serializes `text()`, console output and the returned value with a replacer that writes an Error as `{"name":...,"message":...}` followed by the own enumerable fields Pi already writes, such as `code` or `status`. A value whose prototype, `name` or `message` cannot be read is written as Pi writes it. Stacks are not written. Arguments a script passes to a tool, and an explicit `JSON.stringify` in the script, keep normal JavaScript semantics.

Why: The output is the only view the model gets of a failed nested call.

Scope: `codemode/assets/prelude.js` (`errorReplacer`, `serializeOutput`, `format`, `outputText`). The file no longer matches Pi's `PRELUDE_SOURCE` byte for byte; `codemode/assets/PROVENANCE.md` records both hashes and the refresh step reapplies the patch.

Owner decision: 2026-10-10, owner ruling that every confirmed Pi bug is fixed now, ported from Pi or not.

Call-site markers: `codemode/assets/prelude.js` (`errorReplacer`).

Evidence: `TestNestedToolErrorsKeepTheirMessageInSerializedOutput` in `codemode/nested_error_output_test.go`. It failed before the change with `"reason":{}` in both the output and the returned value. `TestNestedErrorsKeepTheirEnumerableFields` fails when the replacer drops the fields Pi writes. `TestNestedErrorsKeepTheirMessageInConsoleOutputAndMixedResults` in `codemode/nested_error_console_test.go` fails when console output or the returned value skips the replacer. `TestNestedErrorsWithUnreadableNamesSerializeAsPiDoes` in `codemode/nested_error_unreadable_test.go` fails when the replacer throws for a value Pi serializes.

Parity allowance: none.

Remove when: Pi's codemode serializes nested Errors with their name and message.
