## D391 The worker heartbeat does not count time the process did not run as silence, and a lost worker link is recovered

What: PiG ports Pi main 9f7d909f8 (`fix(chord): recover worker links after a sleep or a lost link`), which is not in Pi 1.5.0. The heartbeat no longer counts time the process did not run (a laptop's sleep, a blocked event loop) as silence: after such a pause each open link pings at once and closes only if its peer stays silent for `close - ping`. A running worker's lost link is a stop, not a failure: `worker_link_lost` is reported and the held route starts a new worker; a second lost link within a minute of the last recovery still fails the address. Observable difference from Pi: the pause Go measures between heartbeat ticks is truncated to whole milliseconds where Pi's is fractional (`performance.now()`), so a pause is recognised from `ping` ms of lateness on both with at most 1 ms of difference.

Why: After a sleep every link was closed before the data the peer sent meanwhile was read; a lost worker link left its address failed.

Pi bug: The heartbeat closes links after a sleep, and a worker whose link was lost stays failed (1.5.0).

Scope: `chord/next/link/channel.go` (`tick`), `chord/next/host/host_host.go` (heartbeat), `chord/next/host/remote_host_link.go`, and `chord/nextnode/workers`.
