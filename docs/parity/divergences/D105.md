## D105 The interactive driver owns terminal input; extension input listeners run asynchronously

What: Pi's `TUI.start()` owns the terminal. It reads stdin and runs `handleTerminalInput` (color reply, light/dark report, input-listener chain, cell-size reply, overlay focus fix-up, focused component), and `TUI.stop()` runs the protected `beforeTerminalStop` and `afterTerminalStop` hooks. In PiG the renderers (`tui.TUI`, `TuiAltScreen`) own frames, overlays, the listener chain (`RunInputListeners`), and the color and cell-size consumers (`ConsumeTerminalColorResponse`, `ConsumeTerminalColorSchemeReport`, `ConsumeCellSizeResponse`) with Pi's names and order. The interactive driver owns the raw-mode reader and calls those in that order for each chunk. An extension's terminal-input listener runs after them, asynchronously, with an ordering ticket per chunk. The `before` and `after` terminal start and stop hooks are inline in each renderer's `Start` and `Stop`.

Upstream state: Pi runs extensions in-process, so an extension's `addInputListener` callback is a synchronous member of the listener chain, and TypeScript's protected virtuals let a subclass add the start and stop hooks.

Why: an extension is a subprocess that answers over a socket, and no blocking extension IPC may run on the input loop. The driver must therefore keep the extension pass off the loop and resume the chunk with the verdict. Go has no virtual dispatch from an embedded base, so the two renderers carry the hook bodies directly.

Owner decision: lead ruling of 2026-10-07 15:20 (LEAD-RULINGS-1520, gap-agent-tui) under the owner's standing parity-scope approval; flag it in the 0.4.2 release notes for the owner.

Call-site markers: `internal/codingagent/interactive_input.go` (`dispatchInputChunk`), `internal/codingagent/terminal_input_queue.go` (`passTerminalInput`), `tui/tui_input.go` (`RunInputListeners`).

Remove when: never (subprocess-only extensions), or when Pi's extension input listeners become asynchronous and the driver can adopt Pi's `handleTerminalInput` whole.

Evidence: `tui/tui_input_pipeline_test.go`, `tui/main_screen_oracle_test.go`, the `tui/tui-base/terminal-input-pipeline` contract in `test/parity/behavior-contracts.toml`, and the `extensions-runtime` terminal-input scenarios.

Parity allowance: the observable key order and the listener verdicts match Pi; only the thread that runs an extension's listener differs.
