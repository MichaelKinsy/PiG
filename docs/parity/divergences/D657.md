## D657 Every handler of an event gets its own copy of the payload, in every SDK; Pi's handlers of one emit share one event object

What: Pi calls every handler of an `emit` or an `emitToolCall` with the same event object (`runner.ts:1103-1110`, `1256-1262`: `handler(event, ctx)` in the loop over `snapshotEventHandlers`); `emitBoundary` builds a fresh shallow event for each handler (`runner.ts:1043-1060`, the event at `1053-1058`) whose `context` and `message` are the session's live objects; `emitContext` makes one `structuredClone` of the messages (`runner.ts:1312-1322`, the clone at `1314`) and every handler of the dispatch reads and edits that one copy. A handler's write to nested event data (a message in `event.messages`, a member of `event.context`, a block of `event.content`) can therefore reach the next handler, and at a boundary the session. In PiG a handler gets the payload from its own request: the host sends one request for each registered handler (`handler_id`), and each SDK hands the handler what it decoded for that request. A write to the payload reaches no other handler of the extension, no other extension and not the host, and a handler that keeps the payload and writes it again after it returned (a Go or Python thread, a Node timer) writes into a copy nobody reads. What a handler returns is carried as in Pi.

The set is the same in every SDK. The conformance row `TestConformance_EventHandlersDoNotShareTheirPayload` (`test/extension-conformance/event_isolation_test.go`) runs two handlers of one extension on a `turn_end`, a `context` and a `context_with_system` payload through `Runner.Emit` (which hands every handler its own copy and does not chain; a session dispatches `context` and `context_with_system` through `EmitContext`, which chains, so the claim of this row is true of `Runner.Emit` only; the session's behaviour is `TestConformance_ContextEditsInASessionReachTheNextHandler`) in the isolated Go, Node, Rust, Python and Lisp realizations, the Node packed cell, the fused Go realization and the packed Go, Rust, Python and Lisp cells, and requires each handler to receive the original. How each realization copies:

| Realization | Two handlers of one extension | Two extensions in one packed cell or one process | Two extensions in separate processes |
|---|---|---|---|
| Go, isolated or packed | a copy: `extensions/sdk/extension.go:1696`, `unmarshalFrameObject(req.Args)` decodes each request's frame (a streamed payload: `event_stream.go:62`, `cloneStreamValue(root)` of the replica the connection keeps) | a copy each: every member has its own connection and its own frame | a copy each: a frame cannot be shared |
| Go, fused (`LoadInProcess`, D31) | a copy: `extension.go:1690-1697`, `fusedEventArgs.decodeWithMaster` decodes a payload once for the process and returns `cloneStreamValueOrdered` of the master (`event_args_memo.go:90-91`) | a copy each from the one master | n/a |
| Node, isolated or packed | a copy: one request frame for each `handler_id`, `request.args` at `runtime.mjs:5602`; the message objects of a message event are shared between the handlers of a process (`shareEventMessages`, `runtime.mjs:5603`), which is D541 | a copy each (a frame per member); message objects shared in the process, D541 | a copy each |
| Rust | a copy: `event_stream.rs:48`, `req.args = Some(root.clone())` (a streamed payload; a frame that carries `args` is decoded for the request) | a copy each | a copy each |
| Python | a copy: `pig_sdk/__init__.py:5979`, `req["args"] = _clone_stream_value(root)` (streamed payload; a frame with `args` is decoded for the request) | a copy each | a copy each |
| Lisp | a copy: `extensions/sdk-lisp/src/dispatch.lisp:206`, `(clone-stream-value root)` (streamed payload; a frame with `args` is decoded for the request) | a copy each | a copy each |
| Go, in-process (`inproc.Runner`: an extension that is a Go function in the host's own process) | NOT a copy: `coding/extension/host/inproc/runner.go:3005`, `callHandler(handler, event, dispatchCtx)` passes the one event to every handler, as Pi does | the same one event | n/a |

Across processes isolation is forced by the transport. Within one extension it is not: a frame decoded for each request is a copy by construction, but the streamed path of every SDK clones the replica it keeps, and the fused Go memo clones a shared master, where handing the handler the retained object would be Pi's sharing. Those are choices, made so that the realizations of one extension agree.

What is not different: the edits a handler's write carries back to the next handler and to the host, for the message of `message_start`, `message_update`, `message_end`, `turn_end` and `agent_end`, are governed by D541 (its table and its tests: three Rust rows differ, owner decisions 17 and 18 of 2026-11-17); this record adds no list to it. What D541 does not cover is the other events. A handler's in-place edit is carried as Pi's shared object carries it for these, in every SDK (Go, Node, Python, Rust, Lisp): the messages of `context` and `context_with_system` (a message edited, an element pushed: `TestConformance_InPlaceContextEditsFollowPi` on every isolated and packed realization, and `TestConformance_ContextEditsInASessionReachTheNextHandler`; Lisp pushes nothing in place because its arrays are fixed-size vectors); the `input` of `tool_call` (`TestToolCallInputMutationAcrossSDKs`, every isolated realization); the content and details of `tool_result` (`TestConformance_InPlaceToolResultEditsFollowPi`, every isolated and packed realization); the prompt options and system prompt of `before_agent_start` (`TestBeforeAgentStartChainSeesEveryEarlierEditAcrossSDKs`, `TestPromptOptionEditsAcrossSDKs`, the five SDKs, including across extensions); the payload of `before_provider_request` (`TestConformance_InPlaceProviderHookEditsReachTheRequest`, every isolated and packed realization); the `entries` of `turn_end` (`TestTurnBoundaryMetadataMutationAndPreviewAcrossSDKs`, every isolated realization). That the NEXT EXTENSION reads such an edit is shown for Node (`TestNodeInPlaceEditsReachTheNextExtension`: tool_call, tool_result, before_provider_request, turn_end, context removal and swap), Python (context push, `TestConformance_ContextListEditsInASessionReachTheNextExtension`) and, for before_agent_start, all five SDKs; the claim is made for no other SDK. What is not carried: the nested data of the `context` of a `turn_end` (contextMessages, llmMessages, contextEntries) and the event of every other event name; an in-place write there reaches neither the next handler nor the session (`TestEventHandlersOfOneDispatchShareTheirPayloadInPiAndNotInPiG` runs Pi and PiG on a `turn_end`; `TestConformance_EventHandlersDoNotShareTheirPayload`); a handler returns the change. Replacing the member itself (assigning a new list or object to `event.messages`, `event.input`, `event.entries`) is not an in-place edit; Pi carries it only where its runner reads the member after the handler (`tool_call` input, runner.ts:1262).

Why: the transport gives each handler a decoded copy of a frame, and a runtime that keeps one object per payload would have to hand every handler the same object across a thread, a process and a language boundary. Every realization that can share does not, so that an extension behaves the same in the isolated, the packed and the fused load, whichever the author or the Piglet Binary chooses (D31, D18), and so that a handler that writes after it returned (a goroutine, a timer) cannot change what another handler or a later dispatch reads. The fused path pays one decode and one clone for each handler (`TestFusedDispatchAllocations`).

Pi bug: none; sharing the event is Pi's design.

Scope: the nested data of an event payload written in place by a handler, read by another handler of the same dispatch (of the same or another extension) or by the host afterwards, for an event that D541 does not cover, in the Go, Node, Rust, Python and Lisp SDKs in every load mode. Not: the in-process Go runner (`inproc.Runner`), which shares as Pi does; the message objects of a message event, D541; what a handler returns.

Owner decision: 2026-11-17, decision 28: "D31 per-handler event copies ... become their own numbered divergence; behaviour kept." Numbered as its own divergence; behaviour kept.

SCRUTINIZED:approved

Remove when: the SDKs of every language hand the handlers of one dispatch one event object (a handle API for the payload) so that a write reaches the next handler as it does in Pi; the copy then goes from `eventArgsMemo`, the replica clones and the per-request decode of the shared object.

Call-site markers (`pig divergence (D657): ...`, in each language's comment syntax): `extensions/sdk/extension.go` (the fused and non-fused decode of `req.Args`), `extensions/sdk/event_args_memo.go` (`decodeWithMaster`), `extensions/sdk/event_stream.go` (`cloneStreamValue(root)`), `extensions/sdk-rs/src/event_stream.rs` (`req.args = Some(root.clone())`), `extensions/sdk-py/pig_sdk/__init__.py` (`_apply_event_stream`), `extensions/sdk-lisp/src/dispatch.lisp` (`apply-event-stream`), `coding/extension/host/subprocess/runtime-node/runtime.mjs` (the `event` case), and, where it does NOT copy, `coding/extension/host/inproc/runner.go` (`Runner.Emit`).

Evidence: `TestConformance_EventHandlersDoNotShareTheirPayload` (`test/extension-conformance/event_isolation_test.go`; two handlers of one extension in subprocess Go, Node, Node packed, Rust, Python, Lisp, fused Go and the packed Go, Rust, Python and Lisp cells; not the in-process Go runner and not two extensions), `TestFusedDispatchAllocations`, `TestOutboundFramesAreTheEncodersBytes` (the frames are the encoder's bytes).

Parity allowance: no scenario compares a nested write of one handler read by another handler of the same dispatch: Pi's tests (`packages/coding-agent/test/extensions-runner.test.ts`) check what a handler returns and the `entries` a boundary handler pushes (`keeps shared mutations made before a handler throws`, line 1063; D541's field), not a second handler's read of a nested payload the first wrote; the conformance row states PiG's behavior, not Pi's. A test that fails when Pi changes (a pinned-Pi run in which the second handler of an `emit` reads the first's write) is owed.
