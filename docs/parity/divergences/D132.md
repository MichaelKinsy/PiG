## D132 Session directories are created with mode 0700 (pi-mono #10770)

What: Pi creates the sessions directory and each project's session directory with the umask default (`mkdirSync(..., { recursive: true })`, 0755 under a 022 umask), so any other user of the machine can list and read every conversation, tool output and secret a model saw. PiG creates every directory it makes for sessions with mode 0700: the agent directory, `sessions` and the per-project directory when they do not exist yet, on session creation, clone, fork-from-file, `/import` and the migration of sessions out of the agent root. A directory that already exists keeps its mode; session files keep the default mode and are protected by their directory.

Why: the sessions are private data, and the report calls the default a security problem.

Scope: `MkdirSessionDir` (`internal/codingagent/session_manager.go`), called by `SessionManager.Create`, `Clone` and `ForkFromFile`, by `/import` (`coding/session_import.go`) and by `migrateSessionsFromAgentRoot` (`internal/codingagent/migrations.go`). The HTML export directory (`session_export.go`) is not a session directory and is unchanged.

Owner decision: 2026-10-10, lead ruling "fix (security) ... all four MkdirAll sites, red test".

Call-site markers: `internal/codingagent/session_manager.go`, `internal/codingagent/migrations.go`, `coding/session_import.go`.

Evidence: `TestSessionDirectoriesAreCreatedOwnerOnly` (`internal/codingagent/session_dir_mode_test.go`) creates a session through `Create`, `Clone` and `ForkFromFile` under a fresh agent directory and checks every created directory is 0700; it fails with Pi's 0755.

Parity allowance: no paired scenario inspects directory modes.

Remove when: Pi creates session directories with mode 0700.
