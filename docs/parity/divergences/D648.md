## D648 A Rust extension receives U+FFFD for a lone UTF-16 surrogate, and writes it back when it echoes text, where Pi's JavaScript string keeps the unit

What: a JavaScript string can hold a lone UTF-16 surrogate (`"\ud83d"` alone), and the host spells it as the escape `\ud83d` in a frame. The Go, Node, Python and Lisp SDKs hand the extension the unit and write it back unchanged. A Rust `String` is UTF-8 and a `serde_json::Value` string cannot hold the unit, and `serde_json` refuses the frame that spells it, which ended the connection. The Rust SDK's frame decode (`extensions/sdk-rs/src/protocol.rs`, `decode_frame` and `decode_json_str`) therefore decodes a refused frame or value again with each lone surrogate escape written as U+FFFD. A Rust handler (`on_event` over a `Value`, `on_before_agent_start` and its `snapshot()`, a command's `args: &str`, a tool's arguments) holds ONE U+FFFD for the unit, and a result or host call it builds from that text (an `input` transform, a `tool_result` content, a `context` message, `sendUserMessage`, `sendMessage`, `registerProvider`) carries ONE U+FFFD back to the host. Pi's extension in JavaScript echoes the unit. The typed UTF-16 fields (`JsString`: terminal input, editor text) keep every unit, and a frame without a lone surrogate is untouched. Since v0.5.0 (the first Rust SDK that survived such a frame).

Why: the lossless alternative is a Rust value type that holds UTF-16 units wherever a `Value` or `String` is in the public API (`serde_json::Value` in `on_event`, `&str` in `args`, `String` in every snapshot field). That is a breaking change of the Rust SDK's public types for every Rust extension, and it is its own lane after the release. Until it lands the decode must not refuse the frame, and a replacement is what Go's decoder makes in a `string`.

Pi bug: none. (The host-side loss the same rows found, eight event types that wrote U+FFFD on the way out to every SDK, is cured in 0.8.0 and carries no divergence.)

Scope: the Rust SDK (isolated and packed) on every frame position that is not a `JsString` field. No other SDK; no host code.
