## D645 A name that is an `Object.prototype` member is no entry of five Stock lookup tables, where Pi's plain objects answer with the inherited member

What: Pi keeps these five tables as plain JavaScript objects and reads them with `table[name]` or tests them with `name in table`. A plain object inherits the members of `Object.prototype`, so for a name such as `constructor`, `toString`, `valueOf`, `hasOwnProperty`, `isPrototypeOf` or `__proto__` the lookup does not answer "no entry": it returns the inherited function (or, for `__proto__`, the prototype object), and the code that follows treats that value as the entry it asked for. PiG keeps the same tables as Go maps (and, for the MCP overrides, as an ordered list of own entries), which have no inherited members: such a name has no entry, exactly like any other name the table does not hold. The name comes from outside in every one of the five: the math of a model's answer, a chunk of terminal input, a theme file, the name an MCP server gives a tool, the name of a selected tool.

Why: these are defects of Pi, and PiG does not port a defect. None of Pi's five answers is something a user or a caller can use: the text of a native function drawn inside a formula, a function returned as a key id, a `TypeError` in place of the loader's own message, a function returned as an exposure, and a system prompt that cannot be built because a tool has a certain name. Reproducing them would mean adding the members of `Object.prototype` to five Go tables by hand.

Pi bug: yes, at Pi 1.5.2 and at Pi 275dde410065. For a name that is a member of `Object.prototype`, Pi draws the source text of a native function inside a formula, returns a function where a key id is promised, reports `TypeError: value.startsWith is not a function` for a theme color, does not offer an MCP tool of a `direct` server, and ends print mode with `function is not iterable` before any turn when an extension tool has such a name. Pi has no test for such a name at any of the five sites.
