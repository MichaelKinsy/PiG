## D645 A name that is an `Object.prototype` member is no entry of nineteen Stock lookups, where Pi's plain objects answer with the inherited member

What: Pi keeps the tables of these nineteen lookups as plain JavaScript objects and reads them with `table[name]` or tests them with `name in table`. A plain object inherits the members of `Object.prototype`, so for a name such as `constructor`, `toString`, `valueOf`, `hasOwnProperty`, `isPrototypeOf` or `__proto__` the lookup does not answer "no entry": it returns the inherited function (or, for `__proto__`, the prototype object), and the code that follows treats that value as the entry it asked for. PiG keeps the same tables as Go maps (and, for the MCP overrides, as an ordered list of own entries), which have no inherited members: such a name has no entry, exactly like any other name the table does not hold. The name comes from outside in every row: the math of a model's answer, a chunk of terminal input, a theme file, the name an MCP server gives a tool, the name of a selected tool (rows 1 to 5); the name of an MCP server and an option on the `mcp` command line, a key of `keybindings.json`, a theme name, an environment reference in an API key or a header, a provider id, a key of a project settings file, a provider of a legacy `apiKeys` entry (rows 6 to 15). In rows 6, 7 and 14 Pi's code also writes with `table[name] = value`, which for the name `__proto__` sets the table's prototype and makes no entry. Rows 16 to 18 were added on 2026-11-14: the file extension behind the read and write cards (Pi's table, row 16), and two tables of libraries Pi runs on: TypeBox's property test and value hash (row 17) and Node's `TERM` table behind the evals report (row 18).
