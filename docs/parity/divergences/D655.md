## D655 User-initiated model switches are refused before mutation when known session tokens exceed the target model's positive context window

What: in Pi (`packages/coding-agent/src/core/agent-session.ts:2562-2585`, `2604-2706`), `setModel` and `cycleModel` switch to the target model without comparing the session's current context token count against the target model's `contextWindow`. PiG checks `refuseOversizedModelSwitch` before any mutation on user-initiated switches (`SetModel`, `SetModelOnMain`, `BeginModelChange` with `ModelSelectSourceUser`, and `beginModelCycle`). When the target model has a positive `Capabilities.ContextWindow` and `Session.ContextUsage()` reports known tokens (`Tokens != nil`) strictly greater than that window, PiG refuses the switch with `"<provider>/<model> holds <window> tokens; this session has <tokens>. Run /compact first, then switch."` and leaves the active model, thinking level, and transcript unchanged. Switches where tokens fit (`*Tokens <= ContextWindow`), tokens are unknown (`Usage == nil || Tokens == nil`, e.g. after compaction), the target window is unknown (`ContextWindow <= 0`), or the switch comes from an extension (`ExtensionSetModel`, `BeginModelChange` with non-user source) are not refused.

Why: manually switching to a smaller-window model mid-session when the current context already exceeds its window strands the next turn; refusing before mutation lets the user run `/compact` first.

Pi bug: no: intentional guard in PiG.

Scope: user-initiated model switches (`SetModel`, `SetModelOnMain`, `BeginModelChange` with `ModelSelectSourceUser`, and `beginModelCycle`) in `coding`. Extension-sourced switches (`ExtensionSetModel`) and non-user `BeginModelChange` retain Pi's unrefused behavior.

SCRUTINIZED:pending-owner-review

Remove when: upstream Pi refuses user-initiated model switches whose target `contextWindow` is below the session's known context tokens, or PiG drops the manual-switch guard.

Call-site marker: `coding/session.go` (`refuseOversizedModelSwitch`, `SetModel`, `SetModelOnMain`, `BeginModelChange`), `coding/session_model_cycle.go` (`beginModelCycle`), and `coding/session_extension_core.go` (`ExtensionSetModel`).

Evidence: `coding/session_model_window_refusal_test.go`: `TestUserModelSwitchRefusedWhenTokensExceedTargetWindow` (`SetModel`, `SetModelOnMain`, `BeginModelChange(user)`), `TestUserModelSwitchAllowedWhenTokensFitTargetWindow`, `TestUserModelSwitchAllowedWhenTokensUnknown`, `TestExtensionModelSwitchAllowedWhenTokensExceedTargetWindow`, and `TestUserModelSwitchAllowedWhenTargetWindowUnknown`.

Parity allowance: observable only when a user-initiated switch targets a model with `ContextWindow > 0` below the session's known `ContextUsage().Tokens`; fitting targets, unknown tokens, unknown windows, and extension switches match Pi.
