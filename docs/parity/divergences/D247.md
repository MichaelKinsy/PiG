## D247 An interactive quit starts no turn from a message an agent_settled handler sends while it waits for the interrupted run

What: `Runtime.EmitQuitShutdown`, the first step of `Runtime.Close` and of the interactive quit, aborts the current Session and waits until it is idle before it emits `session_shutdown` with reason `quit`, as Pi's `dispose()` does at the pin (Pi main 7a53c310a, `fix(coding-agent): settle tool results before disposal`, #9126: `agent-session-runtime.ts` `dispose`, `await this.session.abort()` before `emitSessionShutdownEvent`; the pinned Pi's CHANGELOG lists it). That part is equal to Pi and is not a divergence. What differs: the quit starts no new turn while it waits. A user message that an `agent_settled` handler of the interrupted run sent (`pi.sendUserMessage`, or a custom message that triggers a turn) is dropped, and the provider sees no request for it. Pi's session defers a `prompt()` or a turn-triggering `sendCustomMessage()` made during `agent_settled` and runs it once the handlers returned (`agent-session.ts` `_emitAgentSettled`, `_deferredSettledActions`; `prompt`, `sendCustomMessage`), and the idle wait of `session.abort()` resolves only after those deferred actions ran (`_resolveIdleWaitIfIdle` in the `finally` after them), so at the pin a turn starts from the message, its reply is saved, and `session_shutdown` follows it.

Why: the quit waits for the interrupted run on the owner loop; a turn started from a handler's message would run provider requests and tools after the user asked to leave, and its own `agent_settled` could send the next one.

Pi bug: no. At the pin Pi awaits the abort, as the quit here does; the remaining difference is only that Pi lets a message sent from `agent_settled` start a turn that the quit then waits for.

Scope: `Runtime.Close` and the interactive quit, and only a message sent from an `agent_settled` handler (or a start posted before the quit key and released after it) while the quit waits for the interrupted run. Nothing else is dropped: the interrupted tool's result and the final assistant message are persisted first, and extensions see `session_shutdown` after the settled turn. Like Pi's `await this.session.abort()`, and like the replacement path's `teardownCurrent`, the wait has no timeout: a tool that ignores cancellation holds the quit. This record does not describe print mode's signal hook or RPC shutdown (`EmitQuitShutdownContext`).

Owner decision: approved by owner Michael Kinsy for 0.7.1 (SCOPE-PROPOSAL row S5) for the earlier text of this record, which described the whole abort-and-wait as a divergence from the Pi that then was pinned; the narrowed text above awaits the owner's re-approval.
