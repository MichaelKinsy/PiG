- D247: An interactive quit started no turn from a message an `agent_settled` handler sends while it waits for the interrupted run. Retired before it shipped: probed with the pinned Pi (cead615b48b80d1c61eecab2f0b576d16eeaf4c5) under tmux, a quit by Ctrl+D, by Ctrl+C twice and by `/quit` while a tool runs, with an `agent_settled` handler of the aborted run calling `pi.sendUserMessage("second")`, Pi starts the turn of that message (5 of 5 runs for each key) and emits `session_shutdown` only after that turn settled, exits 0 and leaves the message in the session file. PiG now does the same: the three `requestExit` checks that dropped such a start (`deliverUserMessageAfter`, `startCustomTurn`, `emitAgentSettledFor`; main #483) are removed, and the quit waits for the turn as Pi's does. The abort-and-wait of the interrupted run before `session_shutdown` was never a divergence. Evidence: scenarios `115-quit-settled-send-user-message-ctrl-d`, `-ctrl-c` and `-slash-quit` (extensions-runtime), `TestInteractiveQuitRunsTheDeferredStartOfASettledAction`, `TestAgentSettledStartsDeferredStartsOnceExitIsRequested`, `TestQuitAfterTheReleaseOfADeferredStartStillBeginsTheTurn`. The ID remains reserved.
