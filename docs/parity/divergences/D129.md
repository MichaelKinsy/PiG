## D129 A Responses function call streamed with an empty call_id no longer wedges the session (pi-mono #10299)

What: D120's Responses counterpart. Pi stores a streamed `function_call` or `custom_tool_call` under the id `${item.call_id}|${item.id}` (`openai-responses-shared.ts` `createSlot`). An absent `call_id` is stored as `undefined|<item id>` and `null` as `null|<item id>`; PiG stores the same ids, and both replay them. An empty `call_id` is stored as `|<item id>`, and its replay sends `call_id: ""` for the call and for its output, which the API rejects on every later request. PiG gives a call streamed with an empty `call_id` the generated `<name>_<epoch ms>_<counter>` call id of D120 (`<generated>|<item id>`), and on the Responses replay a stored id whose call part is still empty after ID normalization (`|`-prefixed) is omitted with the tool results that name it, as D120 omits an empty id. Other targets replay such a call as Pi does: Chat Completions normalizes `|fc_1` to `_fc_1`, Anthropic, Bedrock and Mistral normalize the whole id, and Gemini sends it unchanged.

Why: the same fault and fix shape as D120; the Responses id has two parts, so an empty call part is not an empty id.

Scope: `ai/openai_responses.go` (`responsesStreamedToolCallID` on the stream, `omitEmptyResponsesCallIDs` in `prepareResponsesTranscript`, which every Responses-family converter uses). A call with a non-empty, absent or null `call_id` is unchanged.

Owner decision: 2026-10-10, owner ruling "fix every confirmed bug now, ported from Pi or not".

Call-site markers: `ai/openai_responses.go` (`responsesStreamedToolCallID`, `omitEmptyResponsesCallIDs`).

Evidence: `TestResponsesToolCallWithoutCallIDDoesNotWedgeReplay` (`ai/openai_responses_idless_tool_call_test.go`); red before the fix (`function_call` and `function_call_output` replayed with `call_id` ""); disabling either half fails it. `TestResponsesEmptyCallIDOmissionIsConfinedToTheResponsesReplay` checks that Chat Completions and Gemini targets keep the call and its result, as Pi does. `TestOpenAIResponsesToolCallIDPartsMatchPi` and `TestStoredEmptyCallPartReplaysToOtherTargetsAsPi` (`ai/openai_responses_call_id_oracle_test.go`) compare the stored ids for absent and null `call_id` and `id` members, and the Chat Completions and Gemini replay payloads, with the pinned pi-ai (rev-fix-pi-bugs-ai-4).

Parity allowance: Pi 1.3.0 replays the empty `call_id`, so no paired scenario can assert the fixed behavior.

Remove when: Pi fills the id at stream end and omits unreplayable calls on replay, for the Responses id form too.
