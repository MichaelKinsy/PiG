## D249 Images in queued steering and follow-up messages are resized when the message is delivered

What: PiG ports Pi main 4cf69332c (`fix(coding-agent): resize images in queued steering and follow-up messages`, #11782, fixing #11738), which is not in Pi 1.5.0. `Session.QueueSteer` and `QueueFollowUp` (and so `Steer`, `FollowUp`, `prompt` with a streaming behavior, extension `sendUserMessage`, and RPC `steer`/`follow_up`) mark a queued message that carries images. When the Agent delivers it (`message_start`), after its queue entry was matched by its original text, the images are normalized in place with the same code as an idle prompt (`NormalizePromptContent`, the model current at delivery) and the resize hints are appended to its text. This happens before extensions and listeners see the message, before it is saved and before it joins the request context. Enqueueing stays synchronous.

Why: Pi 1.5.0 queues the images unprocessed, so a 1200x9000 PNG reaches the model and the session file at full size and is replayed on every later request.

Pi bug: Pi 1.5.0 (`agent-session.ts` `_queueSteer`, `_queueFollowUp`), fixed by Pi main 4cf69332c ([#11738](https://github.com/earendil-works/pi/issues/11738)).

Scope: queued user messages with images only. Idle prompts are unchanged.

Owner decision: approved by owner Michael Kinsy for 0.7.1 (SCOPE-PROPOSAL row S7).

SCRUTINIZED:approved

Remove when: the pin reaches a Pi release containing 4cf69332c.

Call-site markers: `coding/session.go` (`queuedUserMessage`, `normalizeDeliveredImages`), `coding/session_boundaries.go` (`handleAgentEvent`).

Evidence: `TestSessionResizesImagesInQueuedSteeringAndFollowUpMessages` (Pi's test for steer and follow-up; the 1200x9000 image becomes 267x2000 with the hint, no request carries the original).

Parity allowance: Pi 1.5.0 has no test of queued-image sizes; the agent-session oracle queues text only.
