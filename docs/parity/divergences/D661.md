## D661 After an external SIGTSTP and `fg` pig arms the terminal again; the terminal is not reset before the external stop, and `TUI.setSuspendSignalHandler` is absent, where Pi main resets the terminal and exposes the member

What: four things, stated apart.

1. Cured: re-entry after an external stop. `kill -TSTP <pig>` (another process, a supervisor, `pkill -TSTP`) stops pig by the kernel's default action. Pi before 1.6.0 (`cead615b`) and PiG before this change continued after `fg` with whatever the shell left on the terminal and did not enter the TUI again; Pi 1.6.0 (`faac585884ae`) is now the pin and fixes #12272 via `e4f50d76` and `3107a58d`. Now pig listens for SIGCONT while the process terminal is owned (`tui.SetContinueSignalHandler`; ownership begins before `MakeRaw` in `ProcessTerminal.enterRawMode` and in `TuiAltScreen.BeforeTerminalStart`, spans `TuiMainScreen`, `TuiAltScreen`, and `TuiSurface` start/resume, and ends as the last step of stop and raw-mode restore, matching Pi's `ownsTerminal` rule of `3107a58d` without leaving a startup gap between `startTerminal` and `startInteractiveTui`). On SIGCONT in the foreground of its terminal, on the owner loop, pig stops the renderer with `PreserveScreen: true` (so fullscreen does not dump the transcript into main-screen scrollback; on a frontend surface it calls `Suspend`), re-applies raw mode and terminal modes via `tui.RearmRawMode` (popping Kitty keyboard flags before re-pushing and keeping the saved cooked termios intact without restoring cooked mode or pausing the stdin reader), and restarts the ANSI renderer with a forced full redraw (on a frontend surface `TuiSurface.Resume` resumes the session and draws what changed since `Suspend`, which is no frame when nothing changed). Re-arm runs unconditionally on foreground SIGCONT rather than gating on a raw-mode probe, so shells that restore a job's saved raw termios before sending SIGCONT (such as fish and mksh) still re-arm bracketed paste, keyboard/mouse modes, and redraw. There is no effect before `startTerminal`, after a stop and restore, while an external editor or any other child owns the terminal, or while the Ctrl+Z path waits for its own SIGCONT.

2. NOT cured: the terminal is not reset before an external stop. Pi main (`e4f50d76`, `3107a58d`) catches SIGTSTP while its TUI owns the terminal, restores the terminal, and only then stops the process group (`process.kill(0, "SIGTSTP")`). PiG does not catch SIGTSTP, because under Go 1.27 `signal.Stop` and `signal.Reset` do not restore `SIG_DFL` for SIGTSTP (see mechanism below). Between `kill -TSTP` and `fg`, the user and shell therefore see three differences from Pi main (plus the killed-while-stopped case):
- Armed terminal modes stay on at the prompt: the cursor is hidden; Kitty keyboard flags are pushed (or modifyOtherKeys is on); bracketed paste (`ESC[?2004h`) stays enabled (shells like bash 5 and zsh manage paste at their own prompts, while shells that do not leave pig's paste mode on); in fullscreen mode (the default), the alternate screen stays entered (the prompt is drawn on it) and mouse reporting stays on (`1000`, `1002`, `1003`, `1004`, `1006`), so mouse movement and clicks are typed into the prompt as text. The main-screen renderer has no alternate screen and no mouse reporting.
- Raw termios under shells that do not touch termios: shells like bash, zsh, fish, and mksh set their own prompt termios (under bash on Linux, `shellOwnsTerminal` checks `Lflag & ISIG != 0`). Under `dash` (`dash` 0.5.12 `src/jobs.c` calls only `xtcsetpgrp`, never `tcsetattr`), the prompt runs on pig's raw tty (measured under `dash` 0.5.12 `-i -m`: `ICANON=false`, `ECHO=false`, `ISIG=false`, `ICRNL=false`), so prompt input is unechoed and Enter sends CR instead of NL.
- Process-group stopping: Pi main stops the whole process group with `process.kill(0, "SIGTSTP")`; PiG stops only the signalled process, so other members of pig's process group (not the bash tool, which runs in its own process group) keep running.
- If pig is killed while stopped and never continued: `kill -KILL` leaves the terminal armed (measured under bash 5.2.21: no `ESC[?1049l` is written, whereas Pi main already reset the terminal before stopping); `kill %1` at the shell prompt sends `SIGTERM` followed by `SIGCONT` in the background (bash 5.2 `jobs.c` `kill_pid`), where the background re-arm does not run and pig exits without leaving the alternate screen (`altScreenOff=false` measured under bash 5.2.21).
- In this half PiG differs from the pinned Pi 1.6.0 (`faac585884ae`, which carries `e4f50d76` and `3107a58d`).

3. Missing public member and edge differences from Pi main:
- Public `TUI.setSuspendSignalHandler`: Pi main (`e4f50d76`, `3107a58d`) adds `TUI.setSuspendSignalHandler(handler: (() => void) | undefined): void` on `TUI` / `TuiBase` (`TuiMainScreen` and `TuiAltScreen`). Under this branch, `setSuspendSignalHandler` is absent from Go's `tui.TUI`, all four native SDKs (`extensions/sdk`, `extensions/sdk-py`, `extensions/sdk-rs`, `extensions/sdk-lisp`), `extensions/sdk-ts/pi-pin.d.ts`, `coding/extension/host/subprocess/runtime-node/shims/pi-dist/pi-tui/tui.js`, and `coding/extension/host/subprocess/runtime-node/runtime.mjs` (`factoryTui`). Calling `tui.setSuspendSignalHandler(...)` from a Node extension inside `ctx.ui.custom` or on an imported `TuiAltScreen`/`TuiMainScreen` throws `TypeError: tui.setSuspendSignalHandler is not a function` (measured against the live Node extension host). Go provides only the package function `tui.SetContinueSignalHandler` on SIGCONT.
- Bare foreground `kill -CONT`: Pi main has no SIGCONT listener outside `handleCtrlZ` and does nothing on a bare `kill -CONT` to a running process. Because PiG re-arms unconditionally on foreground SIGCONT so raw-termios-restoring shells work, a bare `kill -CONT` in the foreground runs the full re-arm (leaving and re-entering the alternate screen with `PreserveScreen: true`, closing an open search, clearing selection/scrollbar/click state, and redrawing without dumping scrollback).
- Background continue (`bg`) and subsequent `fg`: on `bg`, SIGCONT arrives while pig is not in the foreground; `rearmWithOps` leaves the terminal untouched and parks the process group again with `SIGTSTP` (matching D227's Ctrl+Z parking). Because zsh (5.9 `Src/jobs.c:2547-2551`, `if (stopped) { ... killjb(jobtab + job, SIGCONT); }`) and bash through 5.2 (bash 3.2 `jobs.c:2818-2823` and bash 5.2 `jobs.c:3633-3638`, `if (already_running == 0) { ... killpg (jobs[job]->pgrp, SIGCONT); }`) send no SIGCONT on `fg` of an already-running job (whereas bash 5.3 `jobs.c:3926-3929` and dash 0.5.12 `src/jobs.c:398` send it unconditionally), parking in the background prevents a stream from painting over the prompt and ensures `fg` always finds pig stopped, sends SIGCONT, and re-arms raw mode (pinned by `TestExternalSIGTSTPBackgroundContinueTouchesNothing` under GNU bash 5.2.21 via `bg; sleep 0.5; ...` followed by `fg`). Pi main's `once("SIGCONT")` runs `ui.start()` in the background, stops on SIGTTOU, and finishes on `fg`.
- Second external SIGTSTP during Ctrl+Z restore: a second external SIGTSTP arriving while `handleSuspend` is mid-restore (before `rawRestore` ends ownership) stops pig with the terminal half reset; `fg` resumes `handleSuspend` which sends `kill(0, SIGTSTP)`, requiring a second `fg` (and can queue one extra re-arm if the first `fg`'s SIGCONT reached both the Ctrl+Z waiter and the tui listener). Pi `3107a58d` keeps its SIGTSTP listener until `stop()` ends and discards that signal.
- Exit termios after external stop: `tui.RearmRawMode` discards the termios returned by `MakeRaw`, preserving launch-time cooked termios for raw-restoring shells, so `stty` changes made at the shell prompt while pig was stopped are overwritten at exit; Pi re-reads termios on each `setRawMode(true)` via libuv.

4. Unchanged: the Ctrl+Z key. `handleSuspend` (`suspendOperations`, `PreserveScreen: false, ExitTerminal: true`, `kill(0, SIGTSTP)`, and the SIGCONT waiter) preserves its behavior, stop signal (`SIGTSTP`), process-group delivery, and orphaned-process-group handling. Its pig-emitted mode sequences (the `modeSequence` subset in stop and resume legs, excluding bash's prompt bytes) are pinned by `TestCtrlZKeyKeepsItsModeSequences`.

The mechanism that drives this: Pi main's cure is a `process.on("SIGTSTP")` listener removed at the end of `stop()`, after which the default stop of SIGTSTP stops pi (`interactive-mode.ts` `handleCtrlZ`, `process.kill(0, "SIGTSTP")` at `3107a58d:4661-4664`; `tui.ts` `updateSuspendSignalListener` and the last steps of `stop()`, `3107a58d:1108-1140`). Under the Go runtime (`runtime/signal_unix.go`, go1.27.4), once `signal.Notify` has been called for SIGTSTP neither `signal.Stop` nor `signal.Reset` restores `SIG_DFL`: `sigdisable` restores the previous handler only when `sigInstallGoHandler(sig)` is false, and `sigInstallGoHandler(SIGTSTP)` is true, so the runtime handler stays installed and SIGTSTP is dropped. PiG instead keeps the kernel's default SIGTSTP stop and listens on SIGCONT, whose default action (continue) is unaffected by the runtime catching it.

Audience: a user who suspends pig with a signal that is not the Ctrl+Z key (a process supervisor, a terminal multiplexer's job control, `kill -TSTP` from another pane), a user of a shell whose prompt receives mouse reports, keyboard flags, or raw termios while pig is stopped by such a signal, and any extension author calling `TUI.setSuspendSignalHandler`.

Why: re-entry needs only SIGCONT, whereas resetting before an external stop requires a SIGTSTP listener that can return to `SIG_DFL`. Stopping with `SIGSTOP` instead (or a fork-per-suspend probe child that still stops with `SIGSTOP`) was measured and rejected in the 2026-11-20 design because it changes the user-visible signal (`suspended (signal)`, `jobs -l` reports SIGSTOP) and freezes an orphaned process group where the kernel discards SIGTSTP. A raw per-OS `sigaction` behind the Go runtime is not built on this branch. A no-op `TUI.setSuspendSignalHandler` stub is not built on this branch; its disposition awaits the owner's decision.

Pi bug: Pi issue #12272 (`kill -TSTP` suspended pi without restoring the terminal), fixed in the pinned Pi 1.6.0 (`faac585884ae`) by `e4f50d76` (#12283) and `3107a58d` (#12339).

Pi issue: https://github.com/earendil-works/pi/issues/12272

Scope: `tui` (`SetContinueSignalHandler`, `RearmRawMode`, terminal ownership in `ProcessTerminal.enterRawMode`, `TuiMainScreen`, `TuiAltScreen` including `BeforeTerminalStart`, and `TuiSurface` including `Suspend`/`Resume`), `internal/codingagent` (`installContinueHandler`, `continueHandler`, `rearmTerminal`, `rearmOperations`), on Unix platforms with SIGCONT (Windows has no-op stubs and no SIGTSTP), and the absent `TUI.setSuspendSignalHandler` member across `tui.TUI`, all native SDKs, `extensions/sdk-ts`, and vendored `pi-dist`. Not: the Ctrl+Z key; SIGINT, SIGTERM and SIGHUP; login signal code (`coding/cli/login_signals*.go`); standalone terminal UIs (`pi --resume` picker, first-run setup, `pi config`), which Pi `3107a58d` notes are out of scope (Pi issue #12338, closed without a fix).

Owner decision: the reviewer of the 0.8.0 line initially approved the mechanism (SIGCONT listener, default stop kept) on the condition that this text names both halves, the unchanged Ctrl+Z path and the Go mechanic; a 2026-11-20 ruling moved this work after 0.8.0, and the owner order of 2026-11-24T06:23Z pulled Pi 1.6.0 (`faac585884ae`) into 0.8.0. The wording, the `TUI.setSuspendSignalHandler` disposition, and bare-SIGCONT behavior await the owner's decision.
