## D142 Settlement keeps idle waiters pending and abort discards deferred prompts (Pi #10704, #10705)

What: Pi 1.4.0 resolves a `waitForIdle()` waiter that was registered during a run as soon as the compaction an `agent_settled` handler awaits has finished, before the prompt the handler deferred has run (#10704). Pi's `abort()` called from a public `agent_settled` subscriber resolves, but a continuation an extension had already deferred still starts a provider request (#10705). PiG keeps a waiter that registered while the Session was busy pending until the `agent_settled` handlers and every prompt they deferred have finished. `waitForIdle()` on an idle Session still returns at once, so a handler can call it. An abort requested while settlement is in progress discards the prompts already deferred. Manual compaction's own abort keeps them, as Pi's `compact()` aborts only the run it replaces.

Why: A host that waits for idle must not report completion while work is still queued, and a stopped Session must not start provider requests.

Scope: `Session.WaitForIdle`, `Session.RequestAbort`, `Session.Abort` and the deferred settled actions (`coding/session_run_state.go`). `agent_settled` dispatch also runs without the Session lock now, so a handler that awaits `ctx.compact()` no longer deadlocks (language mechanics: Pi's single event loop has no such lock). An abort while a deferred prompt runs also discards the prompts deferred behind it, and a waiter stays pending through every deferred prompt, including one whose own run settles before the next starts. Interactive mode drives its own `agent_settled` dispatch and deferred actions (`internal/codingagent/interactive_turn.go`) and is not covered: there a waiter and an abort behave as in Pi.

Owner decision: 2026-10-10, owner ruling that every confirmed Pi bug is fixed now, ported from Pi or not.

Call-site markers: `coding/session_run_state.go` (`WaitForIdle`, `requestAbort`).

Evidence: `TestWaitForIdleStaysPendingThroughSettledHandlerCompactionAndContinuation` (the #10704 order `request:1 compact-complete continuation-queued request:2 idle-resolved`; it hung before the lock change and resolved early before the waiter change) and `TestAbortFromAgentSettledSubscriberDiscardsQueuedContinuation` (the #10705 order) in `coding/session_settled_idle_test.go`. Both are mutation-checked. `TestWaitForIdleStaysPendingThroughEveryDeferredPrompt`, `TestAbortDuringADeferredContinuationDiscardsTheRest`, `TestCustomMessageRunSettledHandlerAwaitsCompaction` and `TestSettledHandlerCompactionKeepsTheContinuationQueuedBeforeIt` fail when the batch count, the epoch check, the custom-run unlock or compaction's deferred-keeping abort is removed.

Parity allowance: none.

Remove when: Pi keeps registered waiters pending through settlement and discards deferred prompts on abort.
