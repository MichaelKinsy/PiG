## D654 Threshold compaction is skipped when the model context window is unknown

What: PiG skips the threshold branch of the shared compaction check (`coding/session.go`, `checkCompactionDecision`) when `contextWindow <= 0`, both after an answer (`checkCompaction` via post-run handling) and before a new run using the previous answer (`promptCompactionDueLocked`), rather than calling `compaction.ShouldCompact(contextTokens, 0, settings)`.

Pi: in pinned Pi 1.5.0 (`f9a26365`), the separate request-projection helper `_exceedsCompactionThreshold` (`packages/coding-agent/src/core/agent-session.ts:783-790`) already returns `false` when `model.contextWindow <= 0` (`agent-session.ts:784`). By contrast, the shared `_checkCompaction` path (`agent-session.ts:3032-3165`), called both after an answer (`_handlePostAgentRun`, `:2029`) and before a new run using the previous answer (`_prepareRun`, `:1947-1953`), computes `const contextWindow = (messageModel ?? this.model)?.contextWindow ?? 0` (`agent-session.ts:3046`) and calls `shouldCompact(contextTokens, contextWindow, settings)` (`agent-session.ts:3162`). Because `shouldCompact` checks `contextTokens > contextWindow - settings.reserveTokens` (`packages/coding-agent/src/core/compaction/compaction.ts:267-270`), with `contextWindow = 0` and positive `reserveTokens` the threshold `0 - settings.reserveTokens` is negative, so `shouldCompact` returns `true` for any positive `contextTokens` and attempts threshold compaction on an unknown window.

Why: a zero context window means the window is unknown, not exhausted; attempting automatic threshold compaction after an answer or before a new run on an unknown-window model is a Pi inconsistency between `_checkCompaction` and Pi's separate `_exceedsCompactionThreshold` helper.

Scope: the threshold branch of `Session.checkCompactionDecision` (`coding/session.go`), reached both after an answer and before a new run via `promptCompactionDueLocked` (`coding/session.go:1035`). Explicit compaction, the preceding overflow branch, and models with a known positive `contextWindow` are unchanged.

Pi bug: yes (`_checkCompaction`'s threshold branch omits the `contextWindow <= 0` guard that Pi's separate `_exceedsCompactionThreshold` helper already has).

Call-site markers: `coding/session.go` (`checkCompactionDecision`, `promptCompactionDueLocked`).

Evidence: `TestCompactionUnknownWindowNoThresholdCompaction` in `coding/compaction_unknown_window_test.go`.

Remove when: Pi guards `contextWindow <= 0` in `_checkCompaction` (or `shouldCompact`) so `_checkCompaction`'s threshold branch matches `_exceedsCompactionThreshold`.
