## D167 A history longer than the model's context window is summarized in chunks

What: when the messages a compaction summarizes, the summary its request carries, the instructions and the output the request asks for (the model's output limit) do not together fit the model's context window, PiG splits the messages into consecutive chunks, each the most messages that fit a request carrying the summary so far, and summarizes them in order. Each chunk's request carries the summary of the chunk before it in `<previous-summary>` and uses `UPDATE_SUMMARIZATION_PROMPT`, the prompt Pi uses when a compaction has a previous summary. The first chunk starts from the compaction's own previous summary, and the usage of every request is added. A chunk the provider still refuses as a context overflow (`ai.IsContextOverflow` on its error) is halved and retried until one message is left. A history that fits the window is one request, byte-identical to Pi's. When a compaction cuts inside a turn and the turn prefix does not fit by the same measure, all but the prefix's last window-sized part joins the history and is summarized by the chunked path; the turn-prefix request keeps the last part. A split turn whose prefix fits keeps Pi's two requests. `/tree` branch summarization keeps Pi's request for the newest entries that fit the window by the character estimate; when the provider still refuses it as a context overflow, PiG retries with the newest half of what it sent, never less than the newest message, until the provider accepts it or one message is left. A retry that would select no fewer messages ends with the provider's error.

Pi bug: `generateSummaryWithUsage` (`packages/coding-agent/src/core/compaction/compaction.ts`) serializes every message of `messagesToSummarize` into one request and `serializeConversation` only caps tool results at 2000 characters. A session already longer than the model's window (a smaller-window model after a switch, or a long session on a 1M model) is refused with `prompt is too long: N tokens > W maximum`, and no later `/compact`, automatic compaction or overflow recovery can succeed. Pi (on the previous pin; its `compaction.ts` is unchanged in Pi 1.4.0) and the PiG integrate tip fail identically on the same session against the same mock endpoint (`prompt is too long: 12034 tokens > 6000 maximum`); Pi main has no chunking either. The owner hit it with `prompt is too long: 1,200,311 > 1,000,000`.

Scope: `GenerateSummaryWithUsageUsing` in `internal/codingagent/compaction/compaction.go` and `GenerateBranchSummary` in `internal/codingagent/compaction/branch_summarization.go`, and `Compact` for the turn prefix of a split turn, so manual `/compact`, automatic compaction, overflow recovery and both halves of a split-turn compaction. A turn prefix whose last part the provider still refuses is not halved; the refusal stays the error, as in Pi. A model without a known context window, a history that fits, and a single message longer than the window keep Pi's single request and its provider error. A request is sized by the four-characters-per-token estimate times the ratio of the provider's real tokens to that estimate on the session's latest assistant usage (between 1 and 2) times a margin of 1.05 (the request body's JSON framing, 2 to 3 percent, which the estimate does not count); a session without trusted usage keeps the first form: chunks of 0.75 x (window - twice the output limit - instructions) by the plain estimate; when the provider refuses a calibrated request as a context overflow the rest of the history is split by that first form.
