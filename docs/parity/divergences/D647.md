## D647 A message or entry that an extension renders is drawn as the placeholder `[<customType>]` until the extension's first answer, where Pi draws the component it returned

What: Pi runs a custom message or entry renderer in its own process, inside the render that builds the component (`packages/coding-agent/src/modes/interactive/components/custom-message.ts` and `custom-entry.ts`, `rebuild`), so the first frame that shows the message shows the component the renderer returned, with its mouse regions. In pig the renderer runs in the extension's subprocess, and the host does not wait for it on the render loop (AGENTS.md: no blocking extension IPC on the TUI input or render loop). The first frame that shows the message therefore draws the proxy's placeholder, the one line `[<customType>]` (`coding/extension/host/subprocess/render_proxy.go`, `fallback`, read by `Render`), the request goes to the extension off the loop at that first `Render`, and the component is drawn by the frame that follows the answer. The placeholder is on screen from the message's first frame to that frame: when a session is resumed or switched, when the transcript is rebuilt, and when a new custom message or entry arrives. A click on the placeholder row is not lost: it is kept and given to the component by the frame that paints it (`holdEarlyClick`).

The three cells marked read were found in the code (`HandleMouse` passes only a click to `holdEarlyClick`; the host's selection and search read the drawn rows) and were not run: no test of the line runs a press, release, drag, move, wheel, selection, search or a taller component over a placeholder.

Why: the renderer lives in another process. Waiting for its answer inside the frame is blocking IPC on the render loop, which stalls every key and every other frame for as long as the extension takes, up to the inactivity boundary. Drawing nothing for the message instead of the placeholder moves every later row when the answer arrives.

Pi bug: none.

Scope: the `render_message` and `render_entry` proxies of every subprocess SDK, isolated and packed. Not a renderer that runs in the host's process (the in-process Go reference returns its component at once). Tool renderers, widgets, header and footer were not examined here.

Observable effect: for the time above a user sees `[<customType>]` where Pi shows the component. A user can click the row and the component acts on the click when it appears. A user cannot drag-select the component's own text, scroll a region inside it or use a region that answers press, drag, move or wheel until the component is drawn; and a click made on a placeholder whose extension never answers (the request fails, or the five-second boundary passes) does nothing.
