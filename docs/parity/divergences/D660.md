## D660 A reply whose model has no known context window starts no threshold compaction, where Pi compacts after every such reply that carries usage

What: Pi's post-reply check `_checkCompaction` takes the window of the model that answered with `const contextWindow = (messageModel ?? this.model)?.contextWindow ?? 0;` (`packages/coding-agent/src/core/agent-session.ts:2918`) and decides with `if (shouldCompact(contextTokens, contextWindow, settings)) { return await this._runAutoCompaction("threshold", false);` (`:3034`). `shouldCompact` is `contextTokens > contextWindow - settings.reserveTokens` (`packages/coding-agent/src/core/compaction/compaction.ts:267-270`), so for a window of 0 it is true for any usage above `-reserveTokens`, that is after every reply that carries usage. Pi's pre-turn check guards the same case: `_exceedsCompactionThreshold` starts with `if (model.contextWindow <= 0) return false;` (`agent-session.ts:741`). PiG's `Session.checkCompactionDecision` (`coding/session.go`) returns without a threshold compaction when the window it read is 0 or below, before it compares the tokens with it. The recovery paths above the threshold check (an overflow error, a recoverable length stop) are Pi's and unchanged, and so are an explicit `/compact`, the pre-turn check and a known window.

Why: a window of 0 means the model did not say what its window is. It is not a budget that is already spent. Pi's own pre-turn check says so; the post-reply check lacks the same guard, and a user whose model has no window gets a summariser request after every reply: cost, latency, and the history replaced by a summary after each turn. PiG has had this since its first release, v0.2.0. The fix is the pre-turn check's guard in the one place Pi lacks it; the fix of pull request #548 (contributor Aubrey Russell, Cpt-Falcon).

Pi bug: not reported upstream, and Pi's main still has the unguarded pair (`agent-session.ts:3135` and `:3251` at `e03dca7a38`, the last commit that touched the file when this was checked on 2026-11-19, while `:833` guards the pre-turn check). A draft for the owner to file is in `docs/parity/gap-closure/ledger-coding-agent-pi-issue-drafts.md` (D660).

Scope: `coding` (`Session.checkCompactionDecision`, so every run that checks a reply: `Send`, the agent loop's post-reply check and the retry paths that call it). Who has a window of 0: a model a Go embedder builds without `ContextWindow`; a model an extension registers with no `contextWindow` (`extension.ProviderModelConfig`, no default); a virtual model whose limits are unset and whose answering physical model cannot be resolved. Who does not: a model of `models.json` (the schema defaults the window to 128000), a catalog model, and a llama.cpp model (`contextWindowOf` falls back to 128000 and never returns 0).

Owner decision: the reviewer ruled on 2026-11-20, by owner principle (decision 29), that the fix of pull request #548 joins 0.8.0 and approved this record the same day.
