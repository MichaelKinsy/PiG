## D659 Auth storage lock is placed beside the resolved store target instead of the symlink path

What: when `auth.json` is reached through a symbolic link (or a chain of symbolic links), PiG resolves the store file's own symlink chain (`resolveAuthPath` in `ai/auth_lock_path.go`) and places the lockfile beside the resolved target file, instead of beside the link path as given. Directory symlinks in the parent path are not resolved, matching `filepath.Abs` + file-link resolution; a dangling link resolves to the missing target, and a symlink cycle fails with `syscall.ELOOP`.

Why: PiG writes `auth.json` through `internal/atomicfile.WriteFile` (`D651`), which follows symbolic links on the target file and atomically replaces the target while keeping the symlink intact. If two processes access the same underlying `auth.json` through two different symlinks, placing the lock beside each link allows both processes to acquire separate locks and race on refreshing or writing credentials (including single-use OAuth refresh tokens). Placing the lock beside the resolved target ensures all links to the same store share one lock.

Pi bug: yes: Pi's `FileAuthStorageBackend` (`packages/coding-agent/src/core/auth-storage.ts:86,131`) calls `proper-lockfile` with `{ realpath: false }`, so two symlinks to the same `auth.json` take distinct locks and can overwrite each other's credential updates concurrently.

Scope: `AuthStorage.withFileLock` (`ai/auth.go`, `ai/auth_lock_path.go`). No file formats, credential keys, or non-linked `auth.json` lock paths change.

Credential printing: `pig auth print-api-key` and `pig auth print-bearer-token` use the file-backed `models-store.json` with model networking disabled, as Pi does (`packages/coding-agent/src/main.ts:162-173`, `core/model-runtime.ts:221-227,252-264`). Restoring a saved catalog does not rewrite it; the read can initialize a missing store with `{}` (`core/models-store.ts:71-95,120-123`, `core/auth-storage.ts:158-188`). Offline Radius refresh imports a legacy catalog from an OAuth credential only when that provider has no saved entry (`packages/ai/src/providers/radius.ts:44-69`, `ai/radius.go`), and still persists only when the legacy credential actually carries a non-empty gateway catalog (`len(legacy) > 0`). `auth check` still uses an in-memory catalog.

SCRUTINIZED:pending-owner-review

Remove when: Pi resolves the auth store file's symlink target before locking (or drops `{ realpath: false }` for `auth.json` locks).

Call-site marker: `ai/auth_lock_path.go` (`resolveAuthPath`), called by `ai/auth.go` (`AuthStorage.withFileLock`).

Evidence: `ai/auth_resolved_lock_r0_test.go` (`TestR0aTwoLinksOneTargetExcludeEachOther`, `TestR0bTwoLinksTwoProvidersBothSurvive`, `TestR0cAsyncRefreshThroughTwoLinksKeepsBoth`), `ai/auth_resolved_lock_link_test.go`, `ai/auth_resolved_lock_r22_test.go`, `ai/auth_resolved_lock_test.go`, and `ai/auth_resolved_lock_xattr_test.go` (`TestR3bExtendedAttributeIsKept`). `coding/cli/credential_print_models_store_test.go` (`TestCredentialPrintUsesSavedCatalog`) checks initialization and selection of a Radius model available only in the saved catalog, leaving its bytes unchanged.

Parity allowance: observable only when `auth.json` is a symbolic link and two writers lock through distinct paths to the same target (PiG excludes the second writer where Pi allows both), or when checking the lockfile location beside the target rather than beside the symlink.
