## D390 A worker that was killed by a signal no longer leaves its lock file failing every later start (macOS and the BSDs)

What: PiG ports Pi main 7aed50ae8 (`fix(chord): clear stale worker lock files on macOS and the BSDs`), which is not in Pi 1.5.0. A worker killed by a signal left its lock's socket file, and every later start of its address failed closed on it. The Workers component now removes a lock socket file nobody accepts on before each start and after a child's exit by a signal, in the address's queue, and `processLock` treats `ENOTSOCK` as stale. Observable difference from Pi: none on macOS and the BSDs. On Linux PiG's lock is an abstract socket with no file, so no stale file exists and the worker-level case is covered by a unit test of `clearStaleLockAt` only.

Why: Starting a worker again after a signal kill failed until the file was removed by hand.

Pi bug: A worker killed by a signal (SIGKILL) left a stale lock file (1.5.0).

Scope: the Workers component (`chord/nextnode/workers/workers_workers.go`) and the process lock (`workers_lock.go`, `workers_lock_unix.go`).
