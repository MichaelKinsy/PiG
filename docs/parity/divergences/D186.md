## D186 Hard-link aliases share the built-in file mutation queue

What: PiG serialises mutations of an existing file across hard-link names as well as symlink and case aliases. Pi's pinned `packages/coding-agent/src/core/tools/file-mutation-queue.ts` keys only by `realpath`, which keeps distinct hard-link names in separate queues.

Why: parallel edits through two hard links can both report success while the later whole-file write loses the earlier edit. File identity makes these mutations wait for each other. Case aliases also share file identity; this restores Pi's native realpath behaviour on a case-insensitive macOS filesystem without folding names on case-sensitive filesystems.

Pi bug: concurrent edits through hard-link names read the same original content and overwrite one another.

Scope: `FileMutationQueue` in `internal/codingagent/tools/mutation_queue.go`, including built-in edit/write tools and the process-wide `WithFileMutationQueue` function. SDK queues and Durable environment queues are outside this change. Missing files keep path ordering. Different files still run in parallel. This queue does not coordinate external processes or filesystem namespace changes made outside the queue.

Owner decision: proposed for maintainer review. The contributor requests approval of hard-link serialisation before merge; no maintainer approval is claimed.

Call-site markers: `internal/codingagent/tools/mutation_queue.go` (`FileMutationQueue.Reserve`, predecessor selection).

Evidence: `TestEditPreservesParallelAliasChanges` in `internal/codingagent/tools/mutation_queue_alias_test.go` holds the first read until the second call has reached its queue wait or finished, then requires both edits through both names. The hardlink and case subtests fail on the original code on macOS. Same-path and symlink controls pass. `TestMutationAliasReservationsKeepDispatchOrder` checks edit/write reservation order, initially missing files and cleanup. Existing queue tests cover independent-file concurrency, callback failure, cancellation and path resolution errors.

Parity allowance: none. The existing paired queue corpus contains no hard links. Its assertions and comparators remain unchanged.

Remove when: Pi serialises hard-link aliases by file identity, or the maintainer declines this difference and narrows the change to realpath parity.
