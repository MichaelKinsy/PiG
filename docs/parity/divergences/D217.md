## D217 Pi bug fixes after the pin that 0.6.0 carries (Pi b3a29f11..79006f06)

What: PiG 0.6.0 pins Pi 1.4.0+b3a29f11 and carries every Pi bug fix that landed on Pi main between that pin and `79006f06` and that PiG can take. Each fix behaves as Pi's merged commit does, so PiG differs from the pinned Pi oracle by exactly these fixes. The table lists the carried commits oldest first. Beyond Pi's fix commits it carries the row removal of `2e0f175b` (realtime and image models that models.dev does not type as chat models leave the chat catalog), the help and description text of `2a46c420` and the wording of `88ffcdc7`. `3bae8527` is the merged form of D155 and is not a row of this record's own behavior: D155 stays its own record, and the table row names the residual deltas that bring PiG to the merged commit. `c2760d32` (`pi update` naming the package manager) needs no change: PiG probes ownership (D39). `c466a359` adds `maxBuffer` to the `pi.exec` options and `truncated` to its result in the Go, Rust, Python and Lisp SDKs and as a PiG-only augmentation of the TS SDK. Pi's `391e83fb`, `018fdcf4` and the Rust, JS-import-graph and V8 fixes (`92c1da1f`, `bb65e3e4`, `a9228305`, `068e972c`) are not carried: they depend on post-pin features or have no Go counterpart.

Why: owner decision 2026-10-30 to carry Pi's post-pin fixes in 0.6.0 ("make all fixes in 0.6.0, no rush"). Three fixes close real exposure: a saved "Do not trust" decision is ignored for projects without trust-requiring resources (`31ade0e0`), `pi.exec` output has no cap (`c466a359`), and the daemon dies on an oversized change event or leaves commands running when it is terminated (`102d1287`, `b6d5c2ec`).

Scope: Go production code and the four SDKs (`extensions/sdk`, `sdk-rs`, `sdk-py`, `sdk-lisp`) and the `durable/core/turn` mirrors. Public surface added: `ExecOptions.maxBuffer` and `ExecResult.truncated` (`c466a359`).

Owner decision: 2026-10-30, owner ruling to carry Pi's post-pin bug fixes in 0.6.0, including `c466a359` with its public API (`maxBuffer`, `truncated`) in all four SDKs and the TS augmentation, the `2e0f175b` row removal, the `2a46c420` help text and the `88ffcdc7` wording.
