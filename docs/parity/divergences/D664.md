## D664 Decision classifiers of llama.cpp that report image input take images, where Pi's register them as text-only

What: Pi at the pin builds every llama.cpp classifier model with `input: ["text"]` (`packages/coding-agent/src/extensions/llama/provider.ts`, `toPiClassifierModel`) and no `compat`. A decision model whose server lists `image` in `architecture.input_modalities` (Clef with its `mmproj`) therefore fails every `models.classify()` call that carries images with "does not support image input", though llama.cpp's System One endpoint accepts them. PiG gives such a model (`output_modalities` has `decisions`, `input_modalities` has `image`) the input `["text", "image"]` and the compat `{imageInput: "images", sendImageOptInHeader: false}`, so the images go to `/v1/systemone` in the `images` list of data URLs and the TypeSafe opt-in header is not sent. A decision model without image input, and every chat model on the `llama-cpp-classify` fallback, stay text-only and still refuse images as before. The compat is carried into the `ai` classifier model that `models.classify()` runs and through the models store.

Why: A user with an image-capable decision model could not classify an image at all, and nothing in the error said the server could take it. This is a Pi bug that Pi main fixed after the pin; under the owner's rule that every bug found is fixed in 0.8.0 (decision 30) PiG carries the fix.

Pi bug: reported as [#12282](https://github.com/earendil-works/pi/issues/12282), fixed on Pi main by `5799e217e` (#12335, "images to llama.cpp decision classifiers"). Pi at the pin: `provider.ts` `toPiClassifierModel` (`input: ["text"]`, no compat).

Scope: `internal/codingagent/llama` (`toPiClassifierModel`, `ClassifierModel.Compat`, `aiModel`, the native provider's `Classify` conversion).

Owner decision: a cure of a Pi defect under the owner's fix-all-bugs rule of 2026-11-13T22:52:04Z and decision 30 (every bug found goes into 0.8.0), the form of D632.

Call-site markers: `internal/codingagent/llama/provider.go` (`toPiClassifierModel`).

Evidence: `internal/codingagent/llama/provider_images_upstream_test.go` (`TestProviderSendsImagesToDecisionModelsThatAdvertiseImageInputAsDataURLs`, the port of the Pi test "sends images to decision models that advertise image input as data URLs" against a mock llama-server, fresh and restored from the models store; `TestProviderRefusesImagesForClassifiersThatTakeNone`) and `provider_images_native_test.go` (`TestAIClassifierModelCarriesImageInputOfDecisionModels`).

Parity allowance: for a decision model that reports image input, PiG lists the classifier with input `["text", "image"]` and compat and sends images to `/v1/systemone`, where the pinned Pi lists it with input `["text"]` and refuses images; every other classifier model is the same.
