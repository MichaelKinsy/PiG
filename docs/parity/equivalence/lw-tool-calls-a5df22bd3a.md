# lw-tool-calls equivalence (slice S8, base a5df22bd3a)

Every change keeps the tool results byte for byte: edit `diff`/`patch`/`firstChangedLine`, read text and notices, ls order, grep context, argument handling and error texts. Each change has a reference or oracle that pins it.

| Change | Why the output is the same | Proof |
|---|---|---|
| Windowed line diff (`internal/jsdiff/lines.go`, Pi-Bolt bf325340) | `DiffLineRuns` runs jsdiff 8's Myers search step for step. The common prefix found by bytes is exactly the run jsdiff's first step consumes on diagonal 0 (the first differing byte lies in the next line of both texts), and no later path goes below it. The suffix shortcut applies only on the diagonal that ends at the end of both texts, where every remaining line pair is at the same distance from the end inside the common suffix, so jsdiff would compare them all equal. Lines are located on demand; values are substrings, which is what joining contiguous tokens gives. Diffing a cut-out window would not be equivalent and is not done. | `TestDiffLinesMatchesFullSearch` (previous full search kept as the reference: 20009 pairs, small line alphabet for ambiguous alignments, CRLF, missing final newline, changes inside a line; checks runs, values, start indexes and every line read backward). Mutation check: applying the suffix shortcut off the end diagonal fails 10244 of 20009 pairs. `TestDiffMatchesJsdiff` (Node jsdiff 8.0.4 oracle) green. |
| Display diff and patch over one `LineDiff` (`diff_string.go`, `unified_patch.go`, `edit.go`) | Same algorithm; lines are read by index instead of splitting part values. A part's split lines (without the trailing empty element) are its tokens without "\n"; `splitLines` of a value re-creates exactly its tokens. Line counts come from run counts and `strings.Count`. The edit tool builds both views from one diff instead of two. | `TestDiffViewsMatchSplitPartReference` (previous split-part code kept as the reference, 6000 random edits, context 0-5), `TestGenerateDiffString_MatchesUpstreamOracle`, `TestGenerateUnifiedPatch_MatchesJsdiffOracle`, `TestEditDiffContextLinesParameterMatchesUpstream`, `TestEditToolMatchesPi`, `TestEditToolMatchesPiOverSeededFiles`. |
| Edit/write argument handling (`edit.go`, `write.go`) | `prepareEditArgumentsRaw` returns the input unchanged only when encoding/json decodes it, one member matches `edits` (any letter case) and it is an array, and nothing matches `oldText`/`newText`: exactly the inputs the ordered parse leaves alone. Everything else takes the ordered parse. Reservations decode into structs with the same field names whose text members accept exactly the values a string accepts (string or null), so they fail exactly where the full decode fails. `writeFileString` is `os.WriteFile` (same flags, mode, error order) via `File.WriteString`. | `TestPrepareEditArgumentsScanMatchesOrderedParse` (21 boundary inputs: duplicate, case-variant and escaped keys, string/object/null edits, invalid JSON, trailing data), the edit/write/mutation-queue tests by name. |
