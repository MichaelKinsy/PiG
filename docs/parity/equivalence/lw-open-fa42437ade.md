# lw-open equivalence (slice S12, base fa42437ade)

Each change keeps what Pi-facing code observes: session file bytes, the extension settings object and its state-push bytes, and `/tree` rows and search results. Each change has a reference test or an oracle that pins it.

| Change | Why the output is the same | Proof |
|---|---|---|
| Settings getters read under the read lock (`internal/codingagent/settings.go`, AS-F8) | Each getter reads the same merged settings field Get() copied, under the same lock; a getter that returns a list, map or pointer copies it, so the caller still cannot change the manager through a result. | `TestSettingsReferenceGettersReturnCopies` (every reference getter mutated, the manager's JSON unchanged), the getter oracles by name: `TestSettingsManagerGettersMatchPi`, `TestSettingsManagerSimpleGettersMatchUpstreamDefaultsAndStoredValues`, `TestSettingsManagerResolvedGettersMatchPi`, `TestSettingsManagerStructuredGettersMatchPi`, `TestSettingsManagerCollectionGettersMatchPi`, the settings_test/upstream/race suites by name. |
| Extension settings encoded once per settings generation (`settings.go`, `coding/extension/host/subprocess/ui_bridge.go`, `coding/cli/session_extension_actions.go`, EX-F4) | Every write of the merged settings goes through setMergedLocked, which starts a new generation; the cached wire bytes encode the map ExtensionSettings returns for that generation. ExtensionSettings still decodes a fresh map per call. With no Session the host action returns `null`, json.Marshal of a nil getSettings. Since review-ca-g-lint the bytes list the members in the order of Pi's merged settings object (the migrated files' order, deepMergeSettings, setters and overrides), where the per-push json.Marshal sorted them; interactive mode binds the same action. | `TestExtensionSettingsJSONEncodesOncePerSettingsGeneration` (bytes decode to ExtensionSettings() after UpdateGlobal, UpdateProject, ApplyOverrides, SetProjectTrusted, Reload), `TestExtensionSettingsJSONKeepsPiMemberOrder`, `TestSessionSettingsJSONIsTheEncodingOfGetSettings` (host action decodes to getSettings() and the state push carries its bytes before a Session, with one, after a write), `TestSnapshotTakesTheHostSettingsEncoding`, `TestSessionExtensionActionsActOnTheLiveSession`. |
| `/tree` search texts read when `/tree` opens (`session_file.go`, `session_store.go`, `session_tree_index.go`, PE-F8) | The text stored for a slot is the same searchTextOf of the same record the open used to read; it is stored only when the slot still locates that record. A row without a stored text takes the per-entry path it always had for long texts. | `TestLazyTreeRowsMatchTheResidentTree` (10 seeds: rows, tags, search and copy texts equal the fully resident tree; also under -race), `TestParallelIndexMatchesTheSerialIndex` (serial and parallel loads store the same texts at the same arena places after the fill), `TestMessageSearchTextMatchesPiInNode`, `TestScanSearchBodyMatchesTheDecode`, `TestTreeSelectorUpstream` and the tree_selector suites by name. |
| ForkFromFile writes Canonicalize(record.Raw()) through one buffered writer (`session_manager.go`, PE-F10) | json.Marshal of a record is its raw text compacted with HTML escapes; the escapes respell code points that Canonicalize writes literally, so both produce JSON.stringify of the same parsed value. The type probe runs on every line that can be of type "session". | `TestForkFromFileLinesMatchTheEncodeRoundTrip` (previous json.Marshal + Canonicalize lines as reference: HTML characters, \u escapes, lone surrogates, duplicate and integer keys, -0, 1e21, padded records, unknown types), `TestSessionForkFromFileMatchesPiOracle` (Pi forkFrom oracle). |
