# lw-ai2 equivalence (slice S16, base fa42437ade)

Every change in this slice keeps the provider request bytes, the events each provider pushes, their order and timing, and the assistant message a consumer observes at each tick. Each change has a reference or an oracle that pins it.

| Change | Why the output is the same | Proof |
|---|---|---|
| pi-messages reader append buffer (`ai/pi_messages_reader.go`) | Pi concatenates each decoded read and runs `buffer.replace(/\r\n/g, "\n")` over the whole buffer. Earlier text that holds no `"\r\n"` is unchanged by that replace, so the reader replaces only the new text plus a carriage return that ends the buffer and meets a line feed. The replace of `"\r\r\n"` leaves a `"\r\n"` that Pi's next replace folds; while the buffer holds one, the reader replaces over the whole buffer as Pi does. A `"\n\n"` can start only at the last byte of what was searched. | `TestPiMessagesReaderMatchesStringBuffer` (the concatenating reader as reference, 20,000 random bodies and splits with CR runs, BOM and split runes), `TestPiMessagesBodyPathTicksMatchPi`, `TestPiMessagesProviderStreamMatchesPi`, `TestPiMessagesDirectMatchesPiTickOrder`, `TestPiMessagesCancelMatchesPi`, `TestPiMessagesOpaqueFetchMatchesPendingDelivery`. |
| Mistral reader append buffer (`ai/mistral_reader.go`) | `findMistralEventBoundary` is the regex's leftmost match with its alternative order; a boundary is at most 4 bytes, so a position with 4 bytes after it that did not match never matches later, and the search starts 3 bytes before the end of what was searched. Records are parsed from the same text in the same order. | `TestMistralReaderMatchesStringBuffer` (concatenating reader and per-alternative regex scan as reference, 20,000 random bodies), `TestMistralBodyPathTicksMatchPi`, `TestMistralRealBodyTicksMatchPi`, `TestMistralProviderStreamMatchesPi`, `TestMistralDirectMatchesPiTickOrder`, `TestMistralCancelMatchesPi`, `TestMistralSSEFramingAndEOFRules`, `TestMistralProviderStreamEventsUpstream`. |
| Gemini SDK generator append buffer (`ai/google_sdk_pipeline.go`) | Same bound for the SDK's delimiters (`"\n\n"`, `"\r\r"`, `"\r\n\r\n"`); each read is decoded onto the buffer and the raw-chunk error check reads exactly the appended text, as it read `chunkString`. | `TestGoogleSDKRecordsMatchStringBuffer` (concatenating generator and per-delimiter indexOf as reference), `TestGoogleSSEDelimiterMatchesTheSDKScan`, `TestGoogleSDKPipelineMatchesNodeTickOrder`, `TestGoogleProviderConsumerMatchesNodeTickOrder`, `TestGoogleProviderRoundsMatchNodeRealSockets`, `TestGoogleUndiciConstantsMatchProbe`. |
| `UnescapeForStringify` span copy (`internal/jsstring/stringify.go`) | The bytes between backslashes are copied unchanged, and each escape is handled as the byte loop handled it. | `TestUnescapeForStringifyMatchesTheByteLoop` (byte loop as reference over 50,000 random escape mixes), `TestUnescapeForStringifyRewritesOnlyRealEscapes`. |
| Kept arguments by identity (`keptArgumentsString`, completions and Mistral converters) | The string is the bytes `ArgumentsJSON` returned, which nothing writes to; its content is what `string(arguments)` copied. The request string cache finds it by identity instead of by hash, and serves the same encoding. | `TestCompletionsRequestSendsKeptArgumentsWithoutCopying`, `TestMistralRequestSendsKeptArgumentsWithoutCopying`, the completions and Mistral payload oracles (`Payload.*Pi`, `PayloadOracle`, `RequestBody`, `RequestString`, `Splice`, `ArgumentOrder`, `NonObjectArguments`: 65 tests). |
| `oaiToolFunction` `wire()` + `MarshalJSONTo` | Writes the value its `MarshalJSON` writes, straight into the request encoder, as `oaiMessage`, `anthTool` and `ResponsesTool` do. | `TestOpenAIToolFunctionEncodesAsItsMarshalJSON` (alone, nested, and as a request body against the stringified MarshalJSON), `TestRequestTypesEncodeAsTheirMarshalJSON`, completions payload oracles. |
| Request string cache generations (`ai/request_body_splice.go`, `marshalSpliced`) | Eviction only drops cached encodings; a miss encodes the string again with `marshalRequestBody`, so the body bytes are unchanged. | `TestTheQuotedStringCacheKeepsHistoryEveryRequestSends` (100 requests, each history string encoded once), `TestTheQuotedStringCacheFreesStringsThreeRequestsDidNotUse`, `TestMarshalSplicedIsByteIdenticalToMarshalRequestBody`, the cache identity tests, payload oracles. |
| `publishPending` in the completions, Responses and Codex WebSocket decoders | A publication copies the producer's message into what consumers observe. Every record change outside a push now marks the message (completions: response id/model, usage, finish reason, thinking signatures; Responses: every record but the push-only deltas; the WebSocket transport-failure diagnostic), so before each record the published message equals the producer's, as it did when every record published. Pushes and suspensions are unchanged. | `TestCompletionsRecordsPublishEveryDirectChange` and `TestResponsesRecordsPublishEveryDirectChange` (one record per read; before each later record the published message must equal the producer's; removing a touch fails them), `TestOpenAIStreamDecoderFollowsOpenAI719SuspensionPoints`, `openai_observation_test.go`, `TestAzureResponsesTickOrder`, `TestRPC33AzureTickOrder`, `TestCodexSSEObservationMatchesNodeOracle`, `TestCodexWebSocketFramesMatchPi` and the rest of `openai_codex_websocket*_test.go`. |
| Responses delta fast decode (`parseResponsesDeltaFast`) | It accepts only a delta event whose members it reads strictly (type, a small non-negative output_index, a non-empty delta) and whose other members cannot reach a `respSSEEvent` field under encoding/json's case folding; for those it yields the event `json.Unmarshal` yields. Anything else takes the previous path unchanged. | `TestResponsesDeltaFastMatchesUnmarshal` (20 seeds and 200,000 random edits), `FuzzResponsesDeltaFast` (30 s, 201,242 executions), `TestResponsesEventFieldFoldMatchesNamesAlike`, the Responses and Codex stream oracles above. |
