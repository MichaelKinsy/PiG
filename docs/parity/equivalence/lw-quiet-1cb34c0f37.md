# lw-quiet equivalence: tool-call arguments parsed on read (slice S27, base b02c2ceabc)

## What changed

`assistantStreamBuilder.toolCallDelta` (ai/stream_builder.go) used to parse the arguments text on every delta. When the builder publishes live views (`managed && turn != nil`), it now stores the text as the block's unexported `ToolCall.deferredArguments` (ai/types.go) and leaves `Arguments` at its earlier value. A custom-input call never defers. An empty text is still parsed at once.

Every way to read a published message settles the deferral first: `cell.view()`, `capture` (`Observe`, `ShallowCopy`, `RefreshEvent`/`delivered`) and `ObserveProjection` use `readLock`/`settleLocked` (ai/assistant_observation_settle.go). `ai.ShallowCapture` settles when it builds its copy. Settling parses the deferred text with the cell's per-call `streamingArgumentsParser` (incremental across reads) and copies the result with `cloneArgumentsFrom`, as publication copied an eager parse. The builder settles its own partial before a terminal push (`push` for Done/Error, `failInvariant`) and before handing out its construction message (`publish` when it does not publish views). `endToolCall` parses the final text once with `SetStreamingArguments`, as before. `setParsedArguments`, `SetStreamingArguments` and the custom-input switch (`setCustomToolCallInput`) clear the deferral.

## Why the output is the same

1. **Every read of an in-flight partial's arguments settles.** An audit of the non-test readers of `ToolCall.Arguments`, `argumentOrder`, `nonObjectArguments`, `ArgumentsJSON` and the ToolCall marshalers (agent, coding, internal, extensions, tui, durable) found that each one reads either a value taken through a cell capture (Observe, ShallowCopy, RefreshEvent, ObserveProjection, view, the agent's shallow message and its streamView, ShallowCapture) or a final message (stream result, Done/Error message, `ToolCallEndEvent.ToolCall`, transcript and request conversion). `ObserveToolCallIdentity` reads only the ID and name. The only provider code that reads an open call's `Arguments` is the custom-input path, which never defers. The one hole was a function call switching to custom input, and the switch now drops the deferral.
2. **A settled value equals the eager one.** `streamingArgumentsParser.parse(text)` returns `parseStreamingJsonArguments(text)` whatever earlier texts it saw (existing oracle tests `streaming_json_resume_oracle_test.go`), and settling copies it as publication did. `TestDeferredToolArgumentsReadAsTheEagerParse` covers 300 random argument streams: strings with escapes, multi-byte runes and surrogate pairs; nested values; non-object texts; chunks split inside escapes and runes. A reader appears at a random delta and reads `Observe` and `ObserveProjection` at every delta from then on. Captures taken at one delta are built after later deltas. The stream ends normally or with an error inside the call. Each read equals `SetStreamingArguments` of the text so far (ArgumentsJSON bytes and DeepEqual of Arguments and non-object text), and the final call DeepEquals the eager final call.
3. **No deferred text escapes.** A settled value has `deferredArguments == ""`, which `sameArguments` asserts for every read, capture and final message. So `reflect.DeepEqual` comparisons of ToolCalls see the same fields as before. `TestCustomInputSwitchDropsDeferredFunctionArguments` covers the custom-input switch.
4. **Which publications exist and when they happen is unchanged.** `sameToolCall` also compares the deferred text, so a publication shares an earlier block only when that block is the same value.
