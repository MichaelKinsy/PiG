# lw-json: encoder and decoder core, equivalence proof

Slice lw-json (LW roadmap S5). No output byte changes in this commit. Each change has a test that compares it with the code it replaces, plus the Node oracles where JSON.stringify is the reference.

| Change | Equivalence evidence |
|---|---|
| JSON.stringify mode in `extensions/sdk/json` (`MarshalStringify`, `AppendStringify`, `appendCompactJS`), `jsstring.MarshalJSON` without `jsText`/`bytes.Clone` | `internal/jsstring/stringify_equivalence_test.go` `TestMarshalJSONMatchesTheRewriteEncoding`: 60,000 random values compared with `referenceMarshalJSON` (the old encoder plus jsText). The values cover nested and foreign Marshalers with whitespace, `\u003c`/`\u003C`/`\u2028`/`\ufffd` escapes, `-0` spellings, RawMessage, json.Number, `,string` fields, TextMarshaler keys, ill-formed UTF-8 and WTF-8 surrogates. It checks bytes, errors, `AppendMarshalJSON` and `StringifyLength`. The existing `TestMarshalJSONMatchesTheUnpooledEncoding` and `TestStringifyLength*` also pass. |
| JSON.stringify against Node | `internal/jsparity/marshal_node_differential_test.go` `TestMarshalJSONMatchesNode`: `MarshalJSON`, `jsparity.AppendString` and `jsstring.AppendString` equal Node `JSON.stringify` on 6,000 fuzzed strings (C0 controls, lone and split surrogates, U+2028/2029, `<>&`, 8-byte block edges) and on a 200 KB string. The ill-formed UTF-8 delta (LW-JSON-1) is pinned by `TestMarshalJSONIllFormedUTF8Delta` until its own commit. |
| `StringifyAppender` splice | In verify mode (the fork's own tests, or `-tags pigjson_verify`), each appended text is checked against `appendCompactJS(MarshalJSON())`. `TestAppenderBuiltOnJsparityDiffersOnlyOnIllFormedUTF8` shows that an appender built on jsparity differs only on ill-formed UTF-8. |
| 8-byte SWAR scan in `jsparity.AppendString` and the codec's `appendString` | `TestAppendStringMatchesJv`: equal to `jv.AppendString` on 200,000 strings. `TestAppendStringMatchesBytewise`: equal to the old byte loop on 200,000 strings in all four escape modes, for string and []byte input. `TestAppendStringMatchesNode` (Node). |
| `UnmarshalTrusted` | `TestUnmarshalTrustedMatchesUnmarshal`: equal to `Unmarshal` on 5,000 encoded records. Verify mode panics on invalid input (`TestUnmarshalTrustedVerifiesInTests`). |
| `orderedjson.UnmarshalFields` single pass | `TestUnmarshalFieldsMatchesThreePass`: the same target state and error as the three-pass reference on 3,000+ inputs. These include repeated, case-variant, escaped and long-s keys, null, whitespace, escaped quotes, preset fields and wrong field types. |
| `jsonstringify.IsCanonical` with more than 24 keys | `TestFastPathMatchesNodeJSON` (Node; corpus extended with 150-key objects and repeated or integer-like keys around the old limits), `TestIsCanonicalLargeObjectsMatchRewrite` (2,000 random large nested objects compared with the full rewrite) and `TestFastPathKeyStackBound`. |

## LW-JSON-1 (separate commit, owner-approved parity fix)

Ill-formed UTF-8 is now one U+FFFD per WHATWG maximal subpart in every codec mode. The stringify mode writes it raw and rewrites nested `\ufffd` escapes (any hex case) to raw. `TestMarshalJSONIllFormedUTF8MatchesNode` checks `MarshalJSON`, `jsparity.AppendString` and the session line of an `ai.AssistantMessage` whose text and tool-call arguments hold the bytes: all three equal Node's `JSON.stringify(Buffer.from(bytes).toString())` on 3,000 random ill-formed inputs. `TestAppenderBuiltOnJsparityMatchesMarshalJSON` shows that jsparity-built appenders now equal MarshalJSON on every string. The reference models (`referenceMarshalJSON`, `appendStringBytewise`) carry the same documented rule.
