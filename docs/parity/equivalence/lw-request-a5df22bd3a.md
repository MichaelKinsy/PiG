# lw-request equivalence (slice S11, base a5df22bd3a)

Every change in this slice keeps the request bytes each provider sends, and the session and event bytes a tool call is written into. Each change has a reference or an oracle that pins it.

| Change | Why the bytes are the same | Proof |
|---|---|---|
| Tool-call arguments are encoded once (`ai/tool_call_arguments.go`, `ToolCall.wire` in `ai/types.go`) | `ArgumentsJSON` keeps the bytes it wrote for an arguments map beside a copy of the map's tree (maps and slices copied, scalars shared) and the member order it used. Later calls return them only while the live arguments still equal that copy member for member, with scalars, maps and slices of the same Go types (a nested `JsonObject` and a `map[string]any` stay distinct, as the ordered encoder treats them differently), and the order is the same map. A write in place, at any depth, a replaced map, value or order, or a map freed and another allocated at its address fails the comparison and is encoded again. The bytes are what the encoder wrote, so a hit returns what a miss would write. `ToolCall.MarshalJSON` uses them where it already used `ArgumentsJSON`; `AppendStringify` uses them for every map, which the JSON.stringify mode writes alike. The cache holds no field of `ToolCall`, so a streamed call still equals the same call built in Go. | `TestKeptArgumentBytesMatchTheEncodedArguments` (400 random argument texts with recorded orders, integer-like keys, `-0`, `1e21`, lone surrogates, HTML characters and separators, plus Go-built maps with ill-formed UTF-8: `ArgumentsJSON`, `MarshalJSON` and `AppendStringify` equal the uncached encodings, for the call and a copy), `TestKeptArgumentBytesFollowAWriteToTheArguments` (12 kinds of write), `TestKeptArgumentBytesLeaveTheCallValueUnchanged`, `TestContentAppendStringifyMatchesMarshalJSON` and the ToolCall tests under `-tags pigjson_verify`, and the provider request oracles below. |
| Responses `function_call.arguments` (`ai/openai_responses.go`) | Arguments of 4 KB or more are quoted by the request string cache from the kept bytes instead of `json.Marshal(string(arguments))`; the splice walk then stands for them with a token. The quoted bytes are `marshalRequestBody(text)`, the JSON.stringify form the body writes for the same string after `UnescapeForStringify`. Smaller arguments keep `json.Marshal`. | `TestOpenAIResponsesPayloadMatchesPi`, `TestAzureOpenAIResponsesPayloadMatchesPi`, `TestConvertResponsesMessagesMatchesPi`, `TestProvidersSendTheSameBodyWithAndWithoutTheCache`, `TestProvidersEncodeEachLargeToolResultOnce`, `TestAQuotedStringIsEncodedOnceAndNeverServedForAnotherString`. |
| Responses tool output (`convertResponsesToolResultOutput`) | One text block is used as it is instead of copied through a builder; several are still joined with `\n`. The text, and so the output, is the same string. | `TestResponsesConvertMessages_EmptyToolResultUsesPlaceholder`, `TestResponsesConvertMessages_ToolResultImagesStayInFunctionCallOutput`, `TestConvertResponsesMessagesMatchesPi`, `TestOpenAIResponsesPayloadMatchesPi`. |
| Request string cache found by identity (`ai/request_body_splice.go`, `ai/request_string_splice.go`) | An entry is also indexed by the data address and length of its source string. Go strings never change and the entry keeps its source alive, so a string at that address with that length is the source; anything else still takes the hash path, which compares the content. A string the cache already holds was UTF-8-checked when it was encoded, so `quoteValid` checks only a miss. | `TestTheQuotedStringCacheFindsARepeatedStringWithoutHashingIt`, `TestTheQuotedStringCacheIndexesTheLatestCopyOfAString`, `TestTheQuotedStringCacheUnindexesAnEvictedSource`, `TestQuoteValidRefusesAStringThatIsNotUTF8`, `TestAQuotedStringIsEncodedOnceAndNeverServedForAnotherString`, `TestMarshalSplicedIsByteIdenticalToMarshalRequestBody`, `TestMarshalSplicedLeavesAStringThatIsNotUTF8ToTheMarshaler`, `TestSplicedCompletionsRequestIsByteIdenticalToMarshal`, `TestProvidersSendTheSameBodyWithAndWithoutTheCache`. |
| `MarshalJSONTo` for `anthContentBlock`, `anthTool`, `ResponsesTool` and `respRequest` (json/v2 builds) | Each writes the value its `MarshalJSON` writes (`wire()`), straight into the request encoder under the caller's options, as `oaiMessage` already did. Only the escaping options differ, and `marshalRequestBody` writes JSON.stringify form either way. | `TestRequestTypesEncodeAsTheirMarshalJSON` (each type alone, nested, and as a request body against the canonical form of its `MarshalJSON`), `TestOpenAIMessageEncodesAsItsMarshalJSON`, Anthropic and Responses payload oracles. |
| Codex WebSocket continuation (`ai/openai_codex_websocket.go`) | The body is read once as the members of its text (`readJSONObjectMembers`) and its input items; nothing is decoded into `map[string]any`, cloned or compared with `reflect.DeepEqual`. Pi 1.1.0 decides the continuation by `JSON.stringify` equality (`requestBodiesMatchExceptInput`, `responseInputsEqual`, openai-codex-responses.ts:1430-1458), and the body text is JSON.stringify text, so the slice compares the member and item texts byte for byte; the response items are kept as `marshalRequestBody` writes each one. The frame keeps the member order and the canonical writer (`writeJSONObjectMembers`); a continued input is the tail of the body's own item texts. Bodies whose members differ only in key order or number spelling, which the decoded comparison treated as equal and Pi does not, are not produced by PiG's encoder. | `TestCodexWebSocketFramesMatchPi`, `TestCodexWebSocketFramesKeepPisKeyOrder`, `TestOpenAICodexResponses_AutoReusesWebSocketWithInputDelta`, `TestCodexWebSocketUpstream`, `TestCodexWebSocketMessageKeepsTheRequestBodyMemberOrder`, `TestCodexWebSocketMessageSpreadsBodiesWithoutInputAndNull`, `TestCodexResponsesMatchPi` and the other `Codex` tests. |
