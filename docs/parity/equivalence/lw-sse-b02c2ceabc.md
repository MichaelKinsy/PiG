# lw-sse equivalence (slice S29, base b02c2ceabc)

The openai-completions record path (`ai/openai_stream_decoder.go`, `ai/openai_chunk_fast.go`, `parseSSE` in `ai/openai.go`) now yields the same records, raw lines, errors, suspension ticks, body reads and closes as at the base, in the same order. Every change has a reference or an oracle that pins it.

| Change | Why the output is the same | Proof |
|---|---|---|
| `nextLineEnding` in `openAIDoubleNewlineIndex` | It returns the first CR or LF at or after the position, as the two `IndexByte` searches did. It searches spans that start at 256 bytes and double each time. In each span it searches for a CR only before the first LF. The span lengths change how far it reads ahead, not what it finds. The loop around it is unchanged. | `TestOpenAIDoubleNewlineIndexMatchesReference` and `TestOpenAIDoubleNewlineIndexMatchesReferenceAcrossSpans` (the per-position scan as reference; records of up to 1,367 bytes cross span boundaries), `TestOpenAIStreamDecoderMatchesBaseDecoder`. |
| Chunk decode in place of `json.Valid` and the member probe (`decodeChunks`, `Chunk`) | It runs only for events that are neither `error` nor `thread.*`. The chunk scanner reads JSON strictly, so a record it reads is valid JSON. It also refuses a top-level member that is `error` after unescaping, or that folds to a chunk field. So `parse` would have found no API error and returned nil with the data unchanged. `parseSSE` receives the chunk `parseOpenAIChunkFast` returns for that record, which is the one `json.Unmarshal` decodes. Every other record takes the previous checks and the previous decode. The decode is pure: it runs before the same suspension points instead of after them. | `TestOpenAIStreamDecoderMatchesBaseDecoder` (6,000 random bodies, see below; each chunk is compared with a fresh decode of its record, and every record a fresh decode reads must be decoded), `TestParseOpenAIChunkFastEqualsJSON`, `FuzzParseOpenAIChunkFast` seeds, `TestOpenAIStreamParseMatchesMapDecodeRule`, `TestOpenAIStreamParseMatchesFullDecode`, `TestOpenAIStreamDecoderMatchesSDK`, `TestOpenAISSEErrorEventMatchesPi`. |
| Chunk arrays reused across records (`openAIChunkDecoder`) | `parseSSE` reads the chunk's choices, tool calls, functions and indexes only during the record's iteration, and copies the index and strings it keeps. The next decode starts after that iteration. The strings are substrings of the record's text or fresh copies, as before. | `TestOpenAIChunkDecoderReuseMatchesFreshDecode` (20,000 records through one decoder, each compared with a fresh decode and with `json.Unmarshal`), `TestOpenAIStreamDecoderMatchesBaseDecoder`. |
| Escaped strings decoded in a stack buffer | Each escape is handled as before, and runs of plain bytes are copied unchanged. The UTF-8 check now runs on the bytes before the copy. Anthropic and Responses delta decoding share this code. | `TestParseOpenAIChunkFastEqualsJSON`, `TestDecodeAnthropicDeltaFastEqualsTheFullDecode`, `TestResponsesDeltaFastMatchesUnmarshal`. |
| Raw line array reused | `Raw` is the event's lines, capped. The next event overwrites the array, so an event's `Raw` is valid until the next `Next`. Production code does not read an OpenAI event's `Raw`: the Responses parser reads `Data` only, and a decode error ends the decoder, so its retained event is never overwritten. Tests that keep events across `Next` clone `Raw` (`retainOpenAIEvent`). | `TestOpenAIStreamDecoderSSEAndLineSemantics`, `TestOpenAIStreamDecoderReusedReaderBufferMatchesWholeBody`, `TestOpenAIStreamDecoderMatchesBaseDecoder` (raw lines traced at each yield). |
| `openAIChunkResponseModel` | It evaluates the base expression without the escaping variable. A model without escapes is compared in place and copied only when it differs from the configured model. | `TestOpenAIChunkResponseModelMatchesBase` (string, escaped, non-string, invalid UTF-8 and absent models, each against three configured models), `TestOpenAICompletionsResponseMatchesPi`. |

`TestOpenAIStreamDecoderMatchesBaseDecoder` holds the decoder to the base decoder, which is kept verbatim (renamed) in `ai/openai_stream_decoder_reference_test.go`. The random bodies have up to 30 lines. They mix text and tool-call chunks, escapes, two choices and two calls, multi-line data, `event:`, `id:` and `retry:` fields, comments, a field without a colon, `[DONE]`, error and `thread.*` events, records that are not JSON, a BOM, invalid and partial UTF-8, blank lines, LF/CR/CRLF endings, and bodies that end mid-line. They arrive whole or in random 1 to 64 byte values, through `ReadChunk` (one reused buffer) or `Read`, with chunk decoding on and off. The test compares the trace an observer of the provider sees: each `beforeNext`, suspension tick, read and close in order, each record with its raw lines, and the error text.
