# lw-observe: one observation per published partial, equivalence proof

Slice lw-observe (LW roadmap S17), commits `afa1e060e9`, `0afbd39cac` and `663228d07d`. These changes affect how often PiG reads and copies a streaming assistant message. The terminal frames, the message_update frames each extension receives, their order, and the handler contexts are unchanged.

## What stays the same, and why

| Change | Argument | Evidence |
|---|---|---|
| `ObserveProjection` in `updateAssistantMessageBlock` | `Observe` returned an owned deep copy, and the block read only each block's kind, text and thinking, the stop reason and the error text. The projection reads the same fields from the same state: a full view reads the cell's current publication, a shallow view reads its retained content reference and its own copied scalars, as `capture` does, and a plain message reads its own fields, as `Observe` copies them. Published content is never written after publication (`cloneAssistantMessageFrom`), so sharing its strings is safe. | `TestObserveProjectionEqualsObserve` (new; plain, full and shallow views across appends, a replaced content reference and an assigned stop reason), `TestAssistantMessageProjectionEqualsObserve` (new; every message_update of a faux agent run and the retained messages after it), `TestAssistantMessageUpstream`, `TestInteractiveMode_StreamingAssistantContentOrder`, `TestInteractiveMode_AssistantTerminalStateLiveAndRedraw` |
| Publication sequence on the message cell | The cell's mutex already ordered every publication against every observation. The sequence is incremented inside the same critical section that replaces the state, so two reads of the same sequence bracket no change to it. | `TestObserveProjectionEqualsObserve`, `TestAssistantMessageFrameEncoderMatchesPiOnAStreamTheLivePartialRunsAheadOf`, `TestAgentLoopMatchesPi` (agent and cli) |
| Shared message_update payload (`messageUpdateShare`) | An extension's payload is a function of the frozen event. Freezing reads the agent message through its stream view, which ignores the agent message's own fields, and the partial through its cell. So for the same event value, the same agent message and the same (cell, seq) of both messages, a fresh freeze returns the same snapshot. The key holds exactly those values, and the share keeps the event's messages alive, so an address in the key can't be reused. A snapshot whose sequences moved while it was being observed is not stored. Events with a mutable member (toolcall_end's tool call) and messages that are not live views aren't shared. The keyframe is `json.Marshal` of the shared snapshot, and a patch is `diffDelta(base, next)` over immutable nodes, so sharing either for the same base returns the same bytes. | `TestMessageUpdatePayloadIsSharedPerPublication` (new): three extensions on a faux agent run. Each one's runtime object equals the whole event's encoding at its delivery, and each delta is prepared once. The partial publishes while the first extension's handler awaits (`AwaitExternal`), and the next two extensions then get a newly prepared payload that carries the new state. With the sequence left out of the key, the test fails. Also `TestMessageUpdateDelta*`, `TestScalingMessageUpdatePayload`, `TestExtensionEventRoundTripAllocationGate`, with `-race` for the delta tests |
| AgentEventContext only for a runner with a handler | The context was passed only to `runner.Emit`, which ran only when `HasHandlers` was true. Building it after the check leaves every handler's context unchanged. | `TestDispatchAgentLoopEventBuildsNoContextWithoutHandler` (new), `TestDispatchAgentLoopEvent_DeliversAllAgentLoopEvents`, `TestEmit*`, `TestSessionInlineDeliveryMatchesExecutorDelivery`, `TestRPCPiMessagesMatchesPi` |
