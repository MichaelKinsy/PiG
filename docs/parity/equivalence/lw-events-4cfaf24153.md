# lw-events: in-process Session delivery, equivalence proof

Slice lw-events (LW roadmap S3), base 4cfaf24153. No output byte changes. Each change below lists what it replaces and the evidence that observers cannot tell the difference.

## Changes

| Change | Old behaviour | New behaviour |
|---|---|---|
| Inline Session delivery (`coding/session.go` `emitSynchronousSessionEvent`, `emitPublishedEvent`, `forwardAgentEvents`; `session_event_barrier.go`; `session_queue_events.go`) | Every Session event went to `rawEvents`; the executor goroutine ran the listener phase (in the event's reserved stream continuation) and closed `done`; the producer waited. The publication after persistence was a second `rawEvents` send. | `execMu` makes "the goroutine executing Session events" explicit. A producer whose event has nothing queued ahead (`queued == 0`, no overflow, executor running) takes `execMu` and runs `forwardAgentEvent` itself. For a streamed event it still prepares the continuation and waits in `AwaitContinuation`; the continuation runs at its reserved FIFO position, only on the producer's goroutine (`RunOwned(observation.Owner(), …)`). Anything queued keeps the executor path, and the executor takes `execMu` for each event, so FIFO order holds across both paths. |
| `Session.DiscardEvents` (print mode) | Print mode drained `Events` on a goroutine and acknowledged `FlushEvents` markers. | Nothing is sent on `Events`; a marker is acknowledged when it executes; `FlushEvents` returns when nothing is queued or executing. |
| Refresh only with a reader (`forwardAgentEvent`) | A listener-only streamed event was refreshed (`agent.RefreshEvent`, two message snapshots) before the listener phase even with no listener. | Skipped when no Session listener is subscribed: nothing reads the refreshed fields. |
| One snapshot per update (`agent/agent.go` `shallowAssistantMessage`) | `agentAssistantMessage(partial.ShallowCopy().Observe())`: the shallow copy, then a second owned copy of it. | `agentAssistantMessage(partial.ShallowCopy())`: the shallow copy's exported fields already are an owned copy of the published state at this tick (or of the immutable emission-time snapshot, D82), taken at the same instant. |
| Streaming message by value (`agent/lifecycle.go` `reduceEventState`) | A heap copy of the `AgentMessage` per update. | Stored in an Agent field; `StreamingMessage` still returns a copy. |
| Argument bytes (`agent/tool_execution.go`, `newPendingToolCall`) | `json.RawMessage(call.args.String())` (two copies) at three sites per call, and an append copy of `ArgumentsJSON`. | The call keeps `ArgumentsJSON`'s own bytes, capacity clipped; the three sites share them. No reader writes them (tool preparers decode them). |

## Evidence

- Differential test `coding/session_event_barrier_inline_equivalence_test.go` `TestSessionInlineDeliveryMatchesExecutorDelivery`: one scripted run (thinking, a streamed `write` tool call, its execution, a streamed text reply) with an in-process extension on every agent-loop event and a Session listener. The reference forces every event onto the executor goroutine (the 4cfaf24153 delivery); the candidate uses inline delivery. The interleaving of listener and extension-handler calls, each with the JSON of the value it received (message state at that tick included), is equal entry for entry (115 calls, 39 streamed updates), with Events discarded (print mode) and drained (RPC mode); the Events sequence is equal too. Clocks and generated IDs are normalized.
- Byte replay of the CLI on Pi-Bolt's fake model (`fake_model_stress.py`, `SCENARIO write:20`, 1,280 argument deltas), base binary vs branch binary, two runs each: `-p` text stdout, `-p --mode json` stdout (1,345 lines, 479 KB) and `--mode rpc` stdout (1,345 lines) are byte-identical after normalizing UUIDs, timestamps and `wall_time_seconds` (which differ between two base runs too).
- Wake test `coding/session_event_barrier_inline_test.go` `TestSessionInProcessDeliveryWakesPerDelta`: goroutine wake-ups whose waker is Session code, per streamed delta, at GOMAXPROCS=1: 2.354 at 4cfaf24153 (print mode's drain), 0.000 now.
- Existing oracles run by name: `agent` `TestAgentLoopMatchesPi` and the tool-argument/steering tests pass. The four heavy RPC observation oracles (`TestRPCAzureOpenAIResponsesObservation`, `TestRPCBedrockConverseStreamObservation`, `TestRPCPiMessagesMatchesPi`, `TestRPCCodexSSEStartMatchesPi`, 200 child processes per case) hit per-run timeouts on the Mac at load 60-85 (single passing runs took 0.5-16 s); they need a quiet-host run against the base before they count as evidence. A pending-body RPC run (headers first, body held until the client sees assistant `message_start`, then a tool call and a reply) completes on both binaries.
- Wake measurement (E1 harness, `large_write.py --sizes 200`, trace + `ana.py`): goroutine unblocks per delta 16.52 at base, 14.23 with this slice; Session sites (`emitOrderedEvent`, `forwardAgentEvent`, `sendEvent`, `emitSynchronousSessionEvent`: 3.52/delta) are gone. Process CPU over six interleaved rounds: base 1.1-1.3 s, lw-events 0.7-0.8 s.

## RPC mode adoption (owner fix-pi-bugs-session)

RPC mode already writes from Session listeners (`subscribeRPCEvents`); its Events consumer only acknowledges barriers and runs `afterSettled` on `agent_settled`. With this slice its listeners already run on the producer goroutine. To drop the consumer goroutine and the per-event Events send: call `session.DiscardEvents()` in `rpcHost.forward`, move the `afterSettled` hook into a Session listener after the writer (it sees `agent_settled` in the same order), and keep `FlushEvents` as is (it returns once every earlier event executed).
