# lw-ipc: extension IPC hops, reads and rescans, equivalence proof

Slice lw-ipc (LW roadmap S10), commit `693a10bf7b`. These changes affect only when frames are written and read and which goroutine runs the work. Frame bytes, frame order on each connection, and the objects extensions receive are unchanged.

## What stays the same, and why

| Change | Argument | Evidence |
|---|---|---|
| Inline write (`Conn.writeInline`) | A caller writes its own frame only when it holds `writeMu` and `queued == 0`. Every frame in the writer queue is counted until its bytes are on the socket, so no frame can overtake one queued before it. A failed inline write fails the connection the same way a failed write in the writer does. | All conn, liveness and writer-failure tests by name, plain and with `-race` (`conn_*_test.go`, `liveness_test.go`, `writer_failure_test.go`, `invocation_admission_test.go`, `frame_buffers_test.go`) |
| Writer coalescing | Frames already queued together go out in one `writev`, in queue order. Each frame's write result, work count and release are the same as before. Pings and chunked frames are still written one at a time. | Same tests, including `TestSaturatedWriter*` and `TestSmallFrameIsOneSocketWrite` |
| 64 KiB buffered reader | The framing is unchanged (4-byte length, then payload). Only the syscall boundaries move. | `conn_framing_test.go`, `conn_framesize_test.go`, `TestConnDispatchReadsAndWakesPerEvent` |
| Request states applied in the read loop | A request with no inactivity lease and no suspension report did nothing for `started` and `progress`. For `blocked` and `completed` it only called `invocation.Acknowledge` and `invocation.Complete`. The read loop now makes those calls itself, before it routes the response, as the requester's drain did. Requests with a lease or a suspension report keep their channel. | `conn_suspension_response_test.go`, `conn_stalled_settled_test.go`, liveness tests |
| Heartbeat armed by transitions | The idle→busy and busy→idle transitions arm and stop the interval under `armMu`, so every arm or stop matches the current count. A ping still goes out each interval while the connection is busy. A ping in flight is still abandoned when work ends. A missed pong still fails the connection. The machine still reports idle after work ends. | `TestHeartbeatRunsOnlyWhileConnectionOwnsWork`, `TestHeartbeatRunsWhileLiveExtensionStateIsHeld`, `TestMissingPongFailsPendingWorkAsExtensionUnresponsive`, `TestRetire*` |
| Node runtime: completed and response in one write; IO worker corks one loop turn | The frames and their order are the same. A close message uncorks before `destroy`, so writes posted before the close still reach the socket first. The only difference is for a response frame above 128 MiB: the throw now comes before any frame is written, instead of after the completed frame. The host treats a missing completed frame like a duplicate one. | Extension conformance (below) |
| message_update validity and prefix | Every long string passes a UTF-8 check before it becomes a delta node. A streamed text grows in a buffer whose written bytes do not change. So when a validated string shares its start address with the new text and is not longer than it, that string is a valid prefix ending on a code point boundary, and only the bytes after it need checking. The old `cleanAppend` re-validated strings that were already known valid. | `TestMessageUpdateDeltaOfSharedBytesEqualsTheWholePayload` (new): 12 seeds × 300 steps of texts grown in place and reallocated, cut inside code points, carrying unmatched surrogates, rewritten from fresh buffers, and cut back to a prefix of the same bytes. After every event the runtime's object equals the decoded whole payload. Also `TestMessageUpdateDeltaEqualsTheWholePayload` and `TestScalingMessageUpdatePayload` |
| Stdout TTY probe cached per `*os.File` | Upstream chalk probes once at import (`supports-color/index.js:186`). The environment is still read on every call, so the existing `FORCE_COLOR`/`NO_COLOR` tests keep working. If `os.Stdout` is swapped, it is probed again. | `TestChalkModifiersEnabledProbesStdoutOncePerFile` (new), `TestResumeHintIsPlainAtChalkLevelZero`, `TestInteractiveQuitPrintsOneHintAfterTerminalRestore`, `TestChalk*`, `TestExtensionThemePalette*` |
| Go SDK `streamText` arena and Rust `take()` | Handlers get the same values. A string view never changes after it is delivered. | `TestEventStreamAppendsMatchConcatenation`, `random_deltas_match_concatenation`, `event_stream_wire` |
| MCP search-offset splitter | Messages, errors and the remainder are identical to the old algorithm on the same read sequence. | `TestStdioSplitterChunkingEquivalence`, `TestSSESplitterChunkingEquivalence`, the mcp upstream oracle and JS-trim tests |
