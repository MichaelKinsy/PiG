# Retained Context host-call lifetime

## Contract and source

Pi 0.87.1 `packages/coding-agent/src/core/extensions/runner.ts:809-886` creates live Context getters and rejects runtime invalidation, not ordinary command completion. `interactive-mode.ts:2495-2516` installs terminal callbacks that can retain that Context. PiG's request parent is subprocess cancellation metadata, not the Context's permanent identity.

A host call from an active originating request carries that request's parent and cancellation scope. After explicit normal completion, a retained Context sends no parent and keeps the same original connection generation. A cancelled origin never acquires runtime ownership. Closing or replacing a connection invalidates host calls from its retained Contexts; they do not bind to the latest request or a replacement connection.

The host guards remain unchanged: reject cancelled call contexts or obsolete Node generations before actions, validate every nonempty parent, track unparented calls in the connection lifetime, reject closed connections, and cancel calls on connection failure. This fix does not modify D56, D78, Provider publication leases, terminal state snapshots, or the Markdown completion policy.

## Failure and source fix

The original union `0b2b8f6fb` has tree `d9859524743c559f298e1fc62dbe14c0f8f72507`. The unchanged `TestConformance_TerminalInput/subprocess-go` times out after 45 seconds. Independent wire observation records command `r1` (`term_subscribe`) and its normal response, then terminal input `r11` with `editorText="current draft"` and `toolsExpanded=true`. Getter call `c2` incorrectly carries `parent_request_id="r1"` on the same socket. The host rejects the dead parent and sends no result. The stack proves waiting; these frames prove the correlation error.

Go, Rust and Python now retain explicit request-parent state with the Context. Normal completion is published before its response becomes visible. Parent selection and frame publication share the connection's writer ordering. Active cancellation is distinct from normal cleanup cancellation. Pending calls retain their selected lifetime and resolve or cancel instead of waiting indefinitely after their parent disappears. Completed request entries leave the active map; retained Contexts own only their small state record and original connection reference. Go and Python arm cancellation state before starting the request worker. Rust's existing pre-worker arming now shares one parent record across cloned Contexts.

Node already retires normal async-local request ownership on the union base. Its cancelled origins were also treated as settled normal work, so a delayed callback could become an unparented live call. The runtime now preserves cancelled ownership separately and rejects it. It captures the connection with the async-local owner and rejects closed/replaced connections. Failed outbound publication removes pending correlation. These are generic lifetime rules, not a terminal or Provider-specific workaround.
