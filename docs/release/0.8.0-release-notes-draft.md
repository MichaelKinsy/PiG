## Upgrading

- If your code supplies or calls `extension.NativeProvider.ResolveAuth` (a host that registers a native provider through `subprocess.Host.SetNativeProviderCallback`, or code that calls the field on a provider it received), change its signature from `func(ctx, *ai.Credential, ai.AuthResolutionOverrides) (*ai.AuthResult, *ai.Credential, error)` to `func(ctx, ai.CredentialStore, ai.AuthResolutionOverrides) (*ai.AuthResult, error)`. The function now receives the registry's credential store and persists a refresh through it (`ai.ResolveProviderAuth` is the implementation to call), so it no longer returns the refreshed credential for the caller to save.
- Node extensions: as in Pi (b7bb7ca905b8), a component's `render()` returns `readonly string[]`, and `Container` returns the same cached array while its children are unchanged. Extensions that modify render output in place, including `super.render()` in a `Container` subclass or an embedded component's output, must copy it first. Applies once the vendored Pi carries the change.
- Go components in the program: a `Container` or `Box` treats a child's lines as unchanged while the child returns the same slice (same first element and length) or equal rows, so a component must return a new slice when its content changes; an in-place edit of a returned slice is not seen. The slice `Container.Render` and `Box.Render` return is borrowed and read-only: copy it with `slices.Clone` before changing a line, also in a type that embeds a `Container` and edits its own `Render` result. Its capacity equals its length, so `append` is safe. A component that changes state without requesting a render stays stale while scrolling, as in Pi (it was already stale without scrolling). The extension SDKs that push lines (Python, Rust, Lisp, subprocess) pass lines by value and are unaffected.
- The experimental `pig-aot` Piglet is now `pig-bolt`, a name that says what it builds on (the Pi-Bolt compiler; it is not an official Pi-Bolt project). `piglets/aot` is now `piglets/pig-bolt`, its Go module is `github.com/MichaelKinsy/PiG/piglets/pig-bolt`, its extension is `boltruntime` and its command is `/bolt-runtime` (was `/aot-runtime`). The TypeScript runtime slot is still `aot`: `extensionsTypescriptRuntime: "aot"`, `PIG_TS_RUNTIME=aot`, the slot directory `aot` and the `PIG_AOT_*` variables work as before. `piglets/pig-bolt/pig-aot.yaml` is a one-file Piglet named `pig-aot` that extends `pig-bolt` (a compatibility alias for the old name): `pig --piglet piglets/pig-bolt/pig-aot.yaml` and `pig piglet build` of that path select and build what `pig-bolt` does under the old name. It does not make the bare name `pig --piglet pig-aot` resolve, the 0.7.0 path `piglets/aot` is gone, and `pig piglet pull` and `update` have nothing to alias because no pig-aot Piglet Binary release exists (remove the alias once no 0.5 or 0.7 setup names it).
- `pig-bolt` pins the Pi-Bolt 1.1.2 compiler (was 0.7.4; Pi-Bolt's `SHA256SUMS` still verifies with the Ed25519 key pinned in the Piglet). The first start after the update installs the new compiler, removes the 0.7.4 one and drops the images the old compiler built; their extension sets run on Bun once and are compiled again in the background.
- Extensions: write `replacement: null` in a `context_edit` draft that omits an entry. A draft without the member is now refused.
- Go extension SDK: `MessageRenderOptions` and `EntryRenderOptions` are no longer comparable, because each gains a `State` map, the renderer state Pi keeps per message or entry in a WeakMap. Compare the fields you need (`Expanded`, `OutputPad`), or use `reflect.DeepEqual`; do not use either type as a map key or compare with `==`. `pig extension upgrade` names the change.
- Rebuild extensions that were built with an SDK before 0.8.0. The extension wire has one shape and no negotiation: a `setModel` that sends the old `provider/id` string is refused with `setModel: model must be a model object`.
- Go: `ctx.SetModel("provider/id")` becomes `ctx.SetModelNamed("provider/id")`. `pig extension upgrade` rewrites every `Context.SetModel` call whose argument is a string and lists, with its line, a call whose argument has another type. `ctx.SetModel(model)` takes a model object, for example one from `ctx.ModelRegistry().Find(provider, id)`.
- Python, Rust, Lisp: no change is needed. A `provider/id` string still works, and the call also takes a model object.
- Node: the call is unchanged, but the object is now used as passed. An extension that selected a registry model with an object carrying only `provider` and `id` must pass the registry's model: `pi.setModel(ctx.modelRegistry.find(provider, id))`.
- If you set an update command (`PIG_SELF_UPDATE_COMMAND`, `PI_SELF_UPDATE_COMMAND` or the `selfUpdateCommand` setting), updating from 0.7.0 to 0.8.0 prints one harmless warning, "Ran <command>, but `pig --version` reports 1.5.1, not 0.8.0". The running 0.7.0 still reads the version from `pig --version`; the update itself succeeded. From 0.8.0 on, `pig update` reads the release from `pig version`, and the warning does not recur.
- extensions (Go embedders): a program that embeds the extension host must call `subprocess.EnableViewWidgets()` (and `subprocess.EnableEditorViews()` for the editor) before it builds a view, or a view that holds one of those kinds is rejected with a message that names the call. The `pig` command is unchanged: it makes both calls before it runs a command.
- One call that worked before is refused now: an event handler that called `waitForIdle` while the session was idle (for example in a `session_start` handler) used to return at once. Call it from a command handler instead, or react to the end of the run in an `agent_settled` handler; the refused call raises (Node: `TypeError`; Go, Python, Rust, Lisp: an error with code `not_a_command_context`).

## Added

- `terminal.framePacing: "adaptive"` in the global settings file, or `PIG_FRAME_PACING=adaptive` for one run (off unless set), lets fullscreen mode begin the next frame of a streaming reply 10 to 16 ms after the last one began: PiG waits four times what the last frame took to draw and write, at least 10 ms and at most Pi's 16 ms. What a frame shows is unchanged, and a key press and the last frame of a reply are never held back. It applies only with the screen writer selected (`terminal.screenWriter: "writer"`, D624, opt-in as well) and on terminals known to show a frame at once at its end (synchronized updates): kitty, Ghostty, WezTerm, Warp, iTerm2, Alacritty, and the VS Code terminal from 1.108 on, never inside tmux, GNU screen, Zellij or herdr, and never while an extension draws on the screen. By default, and with `"pi"`, frames begin 16 ms apart, as Pi's do. Measured with the screen writer on and the terminal declared as Alacritty, the median time between visible changes falls from 15.6 to 9.7 ms on a streamed answer and to 13.4 ms while a file is written, the 95th percentile is under Pi's, the 99th percentile is half a millisecond to 2 ms over it while a file is written, and PiG uses 4 to 7 % more CPU time (D625).
- Interactive mode shows one warning at start when adaptive frame pacing is selected (`terminal.framePacing: "adaptive"` or `PIG_FRAME_PACING=adaptive`) without the screen writer, because the pacing then has no effect: `Adaptive frame pacing (terminal.framePacing, PIG_FRAME_PACING) has no effect without the screen writer (terminal.screenWriter "writer"): frames keep Pi's 16 ms interval.` Print, JSON and RPC mode print nothing new (D625).
- Added Claude Fable 5.2 (`claude-fable-5-2`) to the `anthropic` provider ($8/$40 per million input/output tokens, 1M context, 128K output). Like Fable 5.1 it uses per-message effort and mid-conversation system messages; requests its safety classifiers refuse before any output are answered by Claude Opus 5 through server-side fallback and billed at Opus 5's price. Claude Fable 5.2 and Mythos 5.2 on other providers, such as OpenRouter's `anthropic/claude-fable-5.2`, get the same per-message effort support.
- Added `ModelsProvider.RefreshModelsAuth`. Set it to `RefreshModelsAuthConfigured` for providers whose `RefreshModels` reads a catalog that needs no provider credential, such as pi.dev: `Models.Refresh` then still skips unconfigured providers, but no longer refreshes an expired OAuth token first, so a stale login (`invalid_grant`) no longer fails that provider's catalog refresh. `RefreshModelsContext.Credential` is nil in that network phase.
- `PIG_TELEMETRY` overrides the `enableInstallTelemetry` setting, beside Pi's `PI_TELEMETRY`, which still works alone. When both are set, `PIG_TELEMETRY` decides. `pig` passes the decision on as `PI_TELEMETRY` to the Node extension runtime and to every process it starts.
- An extension can give a child session a member fused into the Piglet Binary by listing `builtin:<member>` in the child's additional extension paths (`AdditionalExtensionPaths`), the form of Pi's `-e builtin:<name>`. A child session never had the Binary's fused members, because they have no path to discover. The path is opt-in: a child that does not list it gets none, so a member that creates children is not loaded in each of them, and a child's child has it only when it lists the path again. `resources.extensionNames` selects the member by its name. A Binary that fuses no member of that name, stock PiG included, reports `Unknown built-in extension` as before.

Roots are `PluginRoot{Path, Required}`: a required root's plugin failing, or a problem discovery reports in it, makes `Plugins.Load` return a `*PluginError` after the host's load settled. ## Changed

- A request to Anthropic or an OpenAI-compatible chat-completions endpoint allocates fewer objects when it is encoded: the encoder state that carried each large string through the request is kept from one request to the next instead of being built again, and dropped when a request fails or the session releases its request caches. The body is the same bytes. Encoding a 200-turn history (BenchmarkAnthropicRequest200Turns, BenchmarkCompletionsRequest200Turns): with the message cache 51 -> 7 and 46 -> 6 allocations per request, without it 2641 -> 2605 and 635 -> 606; mean time per request over ten runs 0.28 ms against 0.31 ms (completions, message cache), 0.33 ms against 0.33 ms (Anthropic, message cache), 0.92 ms against 0.90 ms (completions) and 1.50 ms against 1.49 ms (Anthropic) without it.
- Anthropic message threads are now on by default for any provider whose base URL is on `api.anthropic.com`, not only the `anthropic` provider, as in Pi. Other endpoints still need `compat.supportsMessageThreads`.
- `ai.GetCacheWarmingRequestOptions` takes the request's context first, `(signal, options)`, like every Go call that is cancellable; it was `(options, signal)`.
- `tui.NewOAuthSelectorComponentAnimated` takes Pi's constructor order, `(mode, providers, onSelect, onCancel, initialSearch, ui)`, with the `tui.TUI` whose `RequestRender` the brand animation calls where it took a bare render function first.
- `coding.BuildModel("provider/id", services)` returns the error `Model not found: provider/id` for an id nothing lists, as Pi does, instead of a model for it; it returns the model the registry lists for an id it does list. A program that wants a custom id on a provider uses `coding.BuildFallbackModel`, the copy of one of the provider's models that `--model` makes.
- The named set-model of the Go, Python, Rust and Lisp extension SDKs (`SetModelNamed`, a `provider/id` string) is a lookup of a listed model: an id nothing lists is the error `Model not found: provider/id` and the session keeps its model. To set a custom model, pass a full model object, as with Pi's `pi.setModel(model)`.
- The `pig` binary is a further 16,384 bytes smaller on Linux amd64, 16,512 on macOS arm64 and 15,872 on Windows amd64 (stripped): the screen writer asks the width package the binary already holds whether a Latin, Greek or Cyrillic letter is of ambiguous East Asian width, so a second width table (`golang.org/x/text/width`) is no longer linked. The answers are the same for every letter it can ask about.
- The `pig` binary is 65,536 bytes smaller on Linux amd64 and 68,608 bytes smaller on Windows amd64 (61,890,720 to 61,825,184 and 63,603,712 to 63,535,104 bytes, stripped): three sorts that run once per command no longer compile their own copy of the sort. They are the drift list of `pig extension upgrade` (24,576 and 29,696 bytes), the target list of `pig piglet publish` with the keys of the project trust store (12,288 and 11,264 bytes), and the field table of the extension SDK's JSON encoder (28,672 and 27,648 bytes). The Go extension SDK gains the package `extensions/sdk/upgrade/plan`, the plan, the rules and the drift classification without the type check; `extensions/sdk/upgrade` keeps every name.
- The release binary is 24,576 B smaller on linux/amd64 and 25,088 B smaller on windows/amd64: the plugin UI registry sorts its mounts and the members of a canonical JSON object with the shared sort of `internal/sortx`, so two copies of the sort that came with the registry are no longer linked.
- models: an availability pass (the refresh behind the model list, and the provider count and model list the interactive mode reads at start and after a login) checks the revision of auth.json once instead of 4 to 5 times per provider: an interactive start makes 19 revision stats where it made 455. A write to auth.json during a pass is used by the next request and the next pass; a write through the credential API in the same process is used at once, and a `!command` key is still evaluated on every read. An extension provider whose own auth check rewrites auth.json on disk is seen by the next request and the next pass rather than by the rest of the same pass (D628).
- A model request that cache warming skips (warming off, a request that cannot be replayed, a model without a cache lifetime) no longer copies the session's message list: 64 bytes per message once per request, 0.8 % of the bytes a 20-prompt session allocates.
- A message kept from an OpenAI-compatible completions stream no longer holds the line buffers its response id, finish reason and tool call ids and names were read from: the message keeps its own copy of those four short strings. In the audit's 20-prompt session that was 280 buffers, 61 KB of the memory in use at rest.
- A prompt no longer copies the parameter schema of every declared tool three times. The compaction estimate reads the session's current system message in place instead of replaying a deep copy of it, a compaction is prepared from the entries' own messages and copies only the ones it hands to extension handlers and the summarizer, and the loadout comparison before each request reads a built-in tool's schema in place instead of rebuilding it. In a session with the four default tools and three extension tools of 12 properties each, a prompt allocates about 121 KB and 815 objects less (490 KB and 3,240 allocations before, 370 KB and 2,420 after). The request bodies sent to each provider, what an extension handler may edit, and the re-declaration of a tool an extension re-registers are unchanged.
- A streamed response is searched for reasoning markers only when a keepalive asks. The idle-timeout tracker for server-sent events (D131) counts a comment line or a ping as progress while the last event was a reasoning event; it searched every data line for the providers' reasoning markers and now searches only the line a keepalive follows. The timeout ends the same streams at the same time. On the fake-model benchmark (paired runs against the base, 8 rounds) user instructions per prompt fell by 1.1 % for a headless prompt (8 of 8 pairs), 1.6 % in a 40-prompt interactive session (7 of 8) and 0.7 % in a 20-prompt session (5 of 8, inside that cell's noise); CPU and wall time stayed inside the noise.
- Loading a session decodes its messages faster, with the same result: a message was checked for well-formed JSON once for its record and again for its content and for each content block it holds, and now once. A 20 KB tool result and a 6 KB answer decode in 464 µs instead of 678 µs (-32%); a resumed session of 4,000 entries starts that much sooner.
- A streamed response costs less CPU in a short session. Every read of the response body that waited for the network asked for the calling goroutine's ID, which formats the goroutine's stack header (25 microseconds) until 17 distinct goroutines have asked, so the first requests of a session paid it on each chunk: 15% of the CPU profile of a 400 KB write call's response. The read now compares the goroutine's runtime record address (1.8 nanoseconds, no proof needed) with the one it recorded.
- A long answer that streams in allocates about half as much per frame. Each frame copied the answer's whole row list twice into new arrays (the Markdown block's rows, then the message's), 88 MB of the 255 MB a 60,000-character answer allocates, which made the collector run 48 times where 0.7.0 ran 41. A container that holds a Markdown block or an assistant message now borrows its rows from an array the child keeps for its next render, as it already borrows a nested container's. What a frame draws is unchanged. BenchmarkInteractiveLongAnswerStream (benchstat, count 12 interleaved, one core): 89.3 to 48.2 KB a chunk (-46%), 356 to 293 ms an answer (-17.7%, p=0.000). In the harness's 60,000-character answer: 27 collections and 1.67 s of user CPU (0.7.0: 41 and 1.88 s; before: 48 and 2.20 s; medians of 8 interleaved rounds).
- A streamed delta in a long session costs less. Each frame used to ask every message and tool card of the transcript whether it had changed, which at 4,000 entries took about 75 microseconds of a 190-microsecond frame. A container now reads the invalidations of its children of the transcript's own types (spacers, text, user and assistant messages, and tool cards whose tool has finished) and asks only the others, so the frame at 4,000 entries costs 114 instead of 188 microseconds (a 1,000-entry transcript: 98 instead of 118; an empty one is unchanged). What the frame draws is unchanged.
- A write call that streams a long file in no longer stalls the frame that completes it. The card draws the highlighted lines of the whole file once the call is complete; for a 400 KB TypeScript file that single highlight stopped the screen for about 300 ms. While the content streams in, the card now highlights the whole file a step at a time (a step is 32 KB), so the last frame highlights only what the last step left. The lines the card draws are the same ones a single run over the whole file gives. A step makes one frame longer, so the steps are few enough (a 400 KB file has twelve, under 1% of its frames) that the 99th-percentile frame gap stays at the 18-20 ms it was. In the Pi-Bolt `pauses.py` harness (pinned core, interleaved rounds) the longest stall of the 50 KB, 200 KB and 400 KB files went from 93, 252-271 and 310-366 ms to 59-69, 84-97 and 90-93 ms.
- A large tool-result text (4 KiB or more) is escaped to JSON once: the `read` tool's structured result, the session entry that records the text and the request that sends it share one cached encoding, where each escaped the text on its own. A long session with four file reads per prompt runs about 12 % fewer user-mode instructions per prompt and about 5 % less CPU time (paired `perf stat`, 10 sessions each; CPU time per prompt 38.8 ms to 36.3 ms at 20 prompts, 46.2 ms to 44.3 ms at 40), and a one-prompt headless run about 13 % fewer. The bytes of the tool event, the session file and the request body are unchanged. The encodings a read makes before a request uses them are held to 4 MiB, so a process that reads files and sends no request keeps a few MiB, not the request cache's 64 MiB limit.
- An interactive run collects garbage at a GC percent of 150 until more than 8 MiB of heap is live, then at the default 100 (D621), unless `GOGC` or `GOMEMLIMIT` is set. It cuts the CPU of the interactive and default-theme start-up scenarios by 6-8 % and of a long session by about 3 % per prompt, for about 1.6 MB more peak memory in a short session; a session past 8 MiB live is unchanged.

## Deprecated

- Go: the `SessionID`, `SessionFile`, `Model`, `ThinkingLevel`, `ActiveTools` and `SystemPrompt` fields of `*sdk.AgentSession` still hold what the session had when `ctx.CreateAgentSession` returned, but they are deprecated. Use the methods that read the session's current value: `CurrentSessionID()`, `CurrentSessionFile()`, `CurrentModel()`, `CurrentThinkingLevel()`, `GetActiveToolNames()` and `CurrentSystemPrompt()`, each returning `(value, error)`. The live reads cannot reuse the field names, because a Go field and method cannot share a name, so `SessionID()`, `Model()` and the others do not exist on `*sdk.AgentSession`.
- Lisp: `agent-session-session-id`, `-session-file`, `-model`, `-thinking-level`, `-active-tools` and `-system-prompt` still return what the session held when `ctx-create-agent-session` returned, but they are deprecated. Use `agent-session-current-session-id`, `-current-session-file`, `-current-model`, `-current-thinking-level`, `agent-session-get-active-tool-names` and `agent-session-current-system-prompt`, which ask the host for the current value. The live reads cannot reuse the old names, because a Lisp function has one definition per symbol, so `agent-session-session-id` and the others keep returning the creation snapshot.
- Python: the `session_id`, `session_file`, `model`, `thinking_level`, `active_tools` and `system_prompt` attributes of an `AgentSession` still hold what the session had when it was created, but reading them raises a `DeprecationWarning` (silent by default outside `__main__`; under `-W error` or a `filterwarnings = error` pytest setup the read raises, and so do `hasattr(session, "model")`, `getattr` and `inspect.getmembers(session)` on those names; assignment never warns, and the values are no longer listed by `vars(session)`). Use the properties that read the current value from the host: `current_session_id`, `current_session_file`, `current_model`, `current_thinking_level`, `get_active_tool_names()` and `current_system_prompt`.
- Rust: the `session_id`, `session_file`, `model`, `thinking_level`, `active_tools` and `system_prompt` fields of `AgentSession` still hold what the session had when it was created, but are marked `#[deprecated]`. Use the methods that read the current value, returning `io::Result` (named `current_*`, not `session_id()` and the like, to match the Go, Python and Lisp names): `current_session_id()`, `current_session_file()`, `current_model()`, `current_thinking_level()`, `get_active_tool_names()` and `current_system_prompt()`.

## Removed

- The Go package `chord/host` (Chord v1: `CreateHost`, `Cell`, `Derived`, the v1 contracts, links, host manager and Node facet loader) is gone, as Pi removed Chord v1 when Chord v2 became its root export. Use `chord/next/{contracts,data,state,registries,link,host,store}` and `chord/nextnode`. The root package `chord` no longer has replicated state (`NewReplicatedState`, `AttachReplicatedStateSource`, `ReplicatedState` and its delivery types); it keeps `AggregateError`, `SetUncaughtErrorReporter`, strict JSON and watches.

## Security

- Updated `github.com/klauspost/compress` from v1.19.2 to v1.20.3, which fixes GO-2026-6865 (a panic on two-block zstd frames). PiG reached it through `zstd.Encoder.EncodeAll`, which compresses the request body for the Codex provider.
- A model id that no catalog, `models.json` definition or extension registration lists no longer becomes a model object with no API, endpoint or limits. Such an object was reachable through the library's `coding.BuildModel`, an extension's `set-model` by `provider/id`, and an extension's model stream and complete by `provider/id`. On v0.7.0 the object of an API-key provider was sent as OpenAI chat completions to `api.openai.com` with that provider's key, so the key went to a host the user never configured for it. On the release line a provider that fills in its own API (GitHub Copilot) still posted the object to its own host with the user's OAuth token. `BuildModel` now answers `Model not found: provider/id`, and nothing is sent.
- The Node extension runtime's bundled `undici` is updated from 8.12.3 to 8.12.4, which Pi's `efbcd5adb4bc` does for six advisories that `nodejs/undici` published on 2026-11-05. GHSA-mqg3-3v4r-cm32 (high): with `compose(redirect(), cache())` on an originless `Agent` and a shared cache, the cache decided from the final redirect hop only, so a redirect chain through another origin could poison the cached entry of the original URL or serve one user's response to another; affected `>= 8.12.2, < 8.12.4`. The other five are medium and affected `>= 8.0.0, < 8.12.4`: GHSA-7xg3-fphp-28hg (a shared cache behind `compose(redirect(), cache())` could store a credential-dependent response of a same-origin redirect), GHSA-5rm8-gv32-r954 (a cross-origin redirect during cache revalidation could let a `304` validate another origin's cached response), GHSA-9v6h-8rgp-m69f (the redirect interceptor did not strip credentials on a cross-origin redirect when the request headers were given as `[name, value]` pairs), GHSA-3g9m-rv3r-w5w2 (a handler exception during cache replay could end the process) and GHSA-r4pc-4jcp-7pqc (`fetch()` could skip Subresource Integrity verification when the integrity metadata was separated or surrounded by a tab or another ASCII whitespace other than a space). The severities, ranges and patched versions are those of GitHub's repository advisory API for `nodejs/undici` (`GET /repos/nodejs/undici/security-advisories/<id>`, read 2026-11-16). The only undici that PiG ships is the copy in the Node extension runtime (`runtime-node/shims/undici`); the Go `pig` binary's own HTTP transport is Go's `net/http`. The undici 6.29.1 pins that replace npm's own copy (`automation/images/npm-runtime`, `automation/ci/npm-toolchain`) stay: no affected range includes the 6.x line, the earliest starts at 7.0.0. The parity oracle's installed Pi, the `automation/images/ci-parity` lock, `extensions/sdk-ts` and the benchmark extension sets under `bench/bolt-aot` resolve 8.12.4 too. Follows Pi efbcd5adb4bc.
- Updated the pinned Go toolchain from 1.27.3 to 1.27.4, which fixes GO-2026-6859 (an HTTP/1 server crash from a data race on the response header map when `net/http.MaxBytesReader` or `MaxBytesHandler` limits a request body) and GO-2026-6848 through GO-2026-6858 (cgo compiler and linker flag injection). `govulncheck -show traces` at Go 1.27.3 reported only GO-2026-6859 as reached, through 64 example traces to `net/http` symbols. The trace nearest the flaw is `net/http.maxBytesReader.Read`, reached from `googleSSEReader.Read` in `ai/google.go` through `io.LimitedReader.Read`. PiG code does not call `MaxBytesReader` or `MaxBytesHandler` directly. `govulncheck` did not report GO-2026-6848 through GO-2026-6858. It failed on every build with the previous toolchain because of GO-2026-6859.
- A user or extension that registers a provider again with `insecure: false` now gets certificate verification back for that provider. Before, the earlier `insecure: true` stayed in force until the provider was unregistered.
- A registration's explicit `insecure: false` now verifies certificates on every route; before, a provider built from a model entry kept the file's `insecure: true` and skipped verification. An opt-in written in `models.json` for one endpoint no longer carries over to a different endpoint an extension names.
- A `models.json` provider or model whose `api` is not the name of a registered API (a typo such as `openai-completion`, or any other unknown name) is now refused when its first request starts, with Pi's message `No API provider registered for api: <name>`, and nothing is sent: print mode exits 1 with that line on stderr, and RPC, JSON and interactive mode end the turn with it as the error. Before, PiG built an OpenAI chat-completions request for any unknown name and sent the conversation, system prompt included, to the provider's `baseUrl`. Affects 0.3.0 through 0.7.0. A model object with no api, which PiG built for a model id its registry does not list (for example through an extension's set-model call or the Go library's `BuildModel`), was sent as OpenAI chat completions to `api.openai.com` with the selected provider's credential and the conversation. Affects 0.2.0 through 0.7.0. It is now refused with `No API provider registered for api: undefined`, which is what Pi reports for a model object without an api, and nothing is sent. A GitHub Copilot model whose `api` is empty or is not one the Copilot catalog lists is refused the same way and is no longer sent as chat completions to the Copilot endpoint with the Copilot token, the conversation and the system prompt. What to check: any `models.json` provider or model whose `api` is not one of the known names sent its conversation to that base URL as OpenAI chat-completions. The same holds for a provider an extension registers with an unknown `api` and no stream handler of its own, and for the Go `ai.StreamSimple`, which now reports the same message even when the request has no key.
- PiG's Codex WebSocket transport sent frames masked from a predictable generator (GO-2026-6278, medium); the WebSocket library is moved to the upstream commit that fixes it. Affects 0.7.0 and earlier since 0.2.0.
