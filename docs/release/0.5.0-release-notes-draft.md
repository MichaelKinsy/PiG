## Summary

## Upgrading

- Go API `chord/host`: `Host.Get` and `Ctx.Get` wait until the reference is ready: live, with every state member of its variant. Use `Host.Hold` for the synchronous reference that may still be loading. Before: `ref, _ := host.Get(typ, input, nil)` then `ref.Ready(ctx)`. After: `ref, err := host.Get(typ, input, nil)` for an awaited reference, or `ref, _ := host.Hold(typ, input, nil)` for the old behavior. A failed `Get` releases only its own reference and returns the activation error, `aborted` (`GetOptions.Signal`, or the ctx closing), or `unavailable/ready_timeout` after `HostOptions.ReadyTimeout` (60 s).
- Go API `chord/host`: reading a state member of a reference that is not live yet panics with a `not_ready` ChordError (and `not_in_variant` for a member the variant lacks) where it returned nil. A listener added before the first value gets its snapshot then: the events are `snap`, `ops`, not `snap` with nil, `reset`.
- The Chord link protocol version is 4. A hold implies the state of its variant (`state:false` opts out), state frames are addressed by hold and member (`as: snap | reset | ops | error`, `value`), `sub`, `unsub` and `resync` work per hold, a hold from a client link carries an `origin` the server assigns, and shape frames carry no `codeVersion`. A peer of another version closes the link with `protocol-version`.
- Go API `durable/storage/sqlite`: `Options` is renamed `SqliteStorageOptions`, the name of Pi's type. Before: `sqlite.Open(db, sqlite.Options{WorkingSetBytes: n})`. After: `sqlite.Open(db, sqlite.SqliteStorageOptions{WorkingSetBytes: n})`.
- Go API `durable/storage/sqlite/node`: the connection settings move to `NodeSqliteDatabaseOptions`, and `NodeSqliteStorageOptions` embeds them next to `Prefix` and `WorkingSetBytes`. `OpenNodeSqliteDatabase` takes `NodeSqliteDatabaseOptions`. Before: `OpenNodeSqliteDatabase(path, node.NodeSqliteStorageOptions{BusyTimeoutMs: &ms})`. After: `OpenNodeSqliteDatabase(path, node.NodeSqliteDatabaseOptions{BusyTimeoutMs: &ms})`. A literal of `NodeSqliteStorageOptions` that sets a connection field names the embedded struct (`NodeSqliteStorageOptions{NodeSqliteDatabaseOptions: node.NodeSqliteDatabaseOptions{BusyTimeoutMs: &ms}}`).
- Go API `durable/storage/sqlite/cloudflare`: `DurableObjectSqlCursor` gains `Next() (row, ok, err)`, which returns the next row; a cursor type implements it next to `ToArray`, which then returns the rows not read yet. `OpenDurableObjectSqliteStorage` takes optional `sqlite.SqliteStorageOptions`.
- Go API: `OutputBuffer`, `Progress`, `BoundOutput`, `SanitizeOutput`, `CharacterEnd`, `OutputLimits`, `OutputSlice`, `BoundedOutput` and their helpers move from `durable/harness` to the new package `chord/output`, as Pi 4a5d3729 moves them to `@earendil-works/chord/output`. Before: `harness.NewOutputBuffer(limits)`. After: `output.NewOutputBuffer(limits)`. `PushStringSkipping` and `PushBytesSkipping` take `output.OutputSkip`, which has the fields of `env.ShellOutputSkip`: `output.OutputSkip(skipped)` converts. `Progress`'s clock seam is now exported (`ProgressClock`, `NewProgressWithClock`).
- Go API `ai`: `anthToolResultContent` is internal, but the Anthropic and Bedrock converters now send the images of an error tool result after the tool results of the turn. A caller that read the old note `[image omitted: error tool results cannot contain images]` in an error result sees `(image attached after the tool results)` there and the images in the same user message, after a text block `Images from the error result of tool call <id> (<tool>):`.
- Go API `chord/host`: `CreateHost` needs a principal for the host's own code, as Pi 1.3.0's `createHost({ self })` does, and panics with a `*TypeError` without one. Before: `CreateHost(HostOptions{Name: "server"})`. After: `CreateHost(HostOptions{Name: "server", Self: "host"})`. `HostPrincipal` is gone: PiG no longer makes up principals.
- Go API `chord/host`: `Connect` takes `ConnectOptions` with the principal the parent's own requests act as, and `HostOptions.Upstream` is `&UpstreamOptions{Link: link, ConnectOptions: ConnectOptions{Principal: ...}}`. `Route.Principal` is required. Before: `host.Connect(link, LinkOptions{})`. After: `host.Connect(link, ConnectOptions{Principal: "server"})`.
- Go API `chord/host`: a remote contract says where its objects live and a get no longer names a host. Before: `Remote("t.chat", RemoteDef{...})` and `host.Get(chat, input, &GetOptions{At: &name})`. After: `Remote("t.chat", RemoteDef{..., Host: NewHostFamily("session:", "session")})` and `host.Get(chat, input, nil)`. `GetOptions.At` is gone.
- The Chord link protocol version is 3. A PiG host and a Pi host that speak another version close the link with `protocol-version` and report it through `OnProtocolMismatch`.

## Upgrading from 0.4.x

- Go API: `agent.NewAgent` returns an error, as Pi's `Agent` constructor throws. Before: `a := agent.NewAgent(opts)`. After: `a, err := agent.NewAgent(opts)`, where `err` is `agent.ErrNoDefaultStreamFunction` when no stream function is configured. `Agent.Continue(ctx)` returns only an `error`, and the Go extension SDK's `Context.SetEditorComponent` takes an `sdk.EditorFactory` instead of `any`. The other Go API changes are the **Breaking (Go API)** entries under "Changed". The extension SDK getters already returned errors in 0.3.0 and are unchanged.
- `models.json`: a custom model needs an `api` on the model or on its provider unless it replaces a built-in model of that provider; 0.4.x defaulted it. Without one, PiG reports `Provider "<provider>": Provider <provider>, model <model>: no "api" specified. Set at provider or model level.` and ignores that provider's `models.json` entry, as Pi does. See the **Breaking (config)** entry under "Changed".
- Local Packages: a local directory with no `"pi"` manifest in `package.json` and no `extensions/`, `skills/`, `prompts/` or `themes/` directory now loads its own root as an extension, as Pi does. A library-only local package must add `"pi": {}` to its `package.json`, or loading it fails in every session.
- Go extension SDK: in a `before_agent_start` handler, `data["systemPrompt"]` is an `*sdk.SystemPrompt` instead of a string. Before: `prompt := data["systemPrompt"].(string)`. After: `prompt, err := data["systemPrompt"].(*sdk.SystemPrompt).Get()`. A handler that still asserts a string panics, and the `, ok` form reads an empty prompt. `pig extension upgrade` rewrites both forms. See the **Breaking (Go SDK)** entry under "Changed".
- Go API: `agent.TimingSnapshot.Turns` (a `[]time.Duration` with one entry per turn) is replaced by `TurnCount int`. The recorder no longer keeps a duration for every turn, so a long session's memory stays flat; read `TurnCount` for the number of turns. `/cost` output is unchanged.

## Added

- Add the Go form of Pi's `@earendil-works/pi-env`: remote execution environments over SSH. `env` provides `RemoteExecutionEnv`, a Durable `ExecutionEnv` on another machine whose results match `NodeExecutionEnv` on that machine, with lazy `Connection`s that restart after a loss, watchers that report `overflow` and resume after a reconnect, and the SSH bootstrap (`ConnectSsh`, `SshConnection`, `ScanHostKey`, `AcceptHostKey`, `ForgetHostKey`): strict host keys under a fixed alias, platform detection through the login shell or PowerShell, and daemon deployment verified by SHA-256 (base64 lines through PowerShell on Windows). The daemon, `env/cmd/pi-env`, speaks Pi's wire protocol and is a Go program (D96): `make build-env-daemons` cross-builds it for Linux, macOS, Android and Windows on x86-64 and arm64, and `PI_ENV_DAEMON_DIR` names the directory that holds them (D97). The test suites of Pi's package run over a pipe to the daemon, and the SSH tests use a disposable `sshd` or a scripted `ssh`, so no remote host is needed; `PI_ENV_SSH_HOST` runs the conformance suite over a real server.
- `pig --no-mcp` turns off the built-in MCP support for one run.
- `durable/tools.CreatePowerShellTool` adds a `powershell` tool that runs `pwsh`, or else Windows PowerShell, directly through argv `Exec`, with UTF-8 output and the `bash` tool's output window, spill and errors.
- Codemode `tools.read()` on an image file resolves to an image block that `image()` shows. The `read` tool returns the same value as structured content.
- `pig piglet publish <name|path> --to npm` publishes a Piglet's source to npm so that anyone can add it with `pig piglet add npm:<name>`. It validates the Piglet, replaces each local Package with its `npm:<name>@^<version>` reference, sets the package name and version from the Piglet (`release.version`), adds the `pig-piglet` keyword and `pig.piglet` to `package.json`, and includes the README, LICENSE and system prompt file. It is a dry run until `--yes`, refuses a name and version that npm already has, and runs your own `npm`, so npm handles the login, one-time password, passkey or trusted publishing. `--tag`, `--access`, `--otp`, `--npm-name`, `--package-map` and `--binaries github:<owner/repo>` are available. PiG adds `--provenance` when `ACTIONS_ID_TOKEN_REQUEST_URL` is set. PiG never handles an npm token.
- A Piglet published with `--to npm` records its signed Binary release in `package.json` under `pig.binaries` when it was published with `--to github` on the same machine, or when `--binaries github:<owner/repo>` names the release, so catalogs can show `pig piglet pull` next to `pig piglet add`.
- `pig package publish [<dir>] --to npm` is optional sugar over `npm publish` for a Package: it validates the Package and the `package.json` fields the pi-in-go.dev catalog reads (including the `pig-package` keyword), checks that the version is free, and shows npm's dry run before `--yes` publishes. Plain `npm publish` still works.

The `Agent` runs on the same loop. `AgentLoopConfig`, `AgentOptions` and `Agent` take a `GetAPIKey` resolver that runs before every request, as Pi's `getApiKey`; its error fails the run, as a rejected `getApiKey` does. `AgentLoop` logs a failed run on the process log and ends its stream with the error.

- `chord/host` has the Node facet loader of Pi 1.2.0 (`nodeLoader`): `NodeLoader` and `NewNodeLoader(...).Load` are a `FacetLoader` that imports JavaScript facet modules, so `HostOptions.Loader` loads and hot-reloads them. The facets run in an isolated Node child (one per load, over `ForkDriver`): each facet is named by its module URL, a module whose default export is not a facet fails the load with Pi's `TypeError`, a reload imports fresh copies, and the facets of one load share their module graph. The Go host serves the contracts the child's facets serve and forwards each method call to the child; a ChordError a method throws keeps its code and message, and an aborted root aborts the child's call. A child stops at `Close` or once no facet of its load is referenced, so replaced module copies do not accumulate. Contracts with state or opaque members, several variants, `accepts` adapters or state migrations are refused at load.

## Deprecated

- `delta.ApplyImmutableBatches(target, [][]Op)`: use `delta.ApplyImmutableBatchesSeq`. It still works.
- `delta.AssertValidOp(Op)`: use `delta.AssertValidOpValue`. It still works.

## Removed

- The experimental server, client and plugin stack (`pig_experimental` builds: `pig server`, `pig client`, the coordinator, session workers, the durable agent and its TUI) is gone, as Pi 1.2.0 removed it. Stock `pig` never shipped it.
- The Piglet strip feature `experimental-server` is gone with it; a Piglet that lists it no longer parses. Remove the entry.
- The Chord 1.1.0 service API in `internal/chord` is gone; `chord/host` is the Chord 1.2.0 runtime.
- Divergence D126 (another model's thinking replayed as `reasoning_content` on targets that require it) is retired: PiG follows Pi 1.3.0 and drops the thinking for every target.
- Divergence D171 (an errored Anthropic tool result carries no images) is retired: PiG follows Pi's converter.
