# Pig extension API parity matrix

Pig's subprocess extension API must account for every upstream Pi extension interface. A row is complete only when Pig has a protocol/API mapping, SDK coverage, and a conformance test. If exact parity is impossible or intentionally rejected, record a numbered divergence in `docs/parity/DIVERGENCES.md`.

This matrix tracks behavior. For the SDK surface, symbol by symbol for each runtime, see the generated matrix in `docs/extension-sdk-surface.md`.

Source for upstream inventory: upstream Pi `docs/extensions.md` and `examples/extensions/`.

Pi 0.87.1 added extension events and registration methods. The remaining unported declarations are named by `test/parity/known-gaps.toml` (scope `upstream-parity`), and `test/upstream-parity` fails when one is fixed or a new one appears.

## Parity boundary (read this first)

Pig is a Go-native port of upstream pi. Upstream pi has exactly **one**
SDK (TypeScript) and loads extensions **in-process**. Pig deliberately
rejects in-process production extensions (no embedded JS runtime, no WASM,
no dynamic Go plugins). Two downstream-only constructs exist so that we
can still expose the upstream extension API faithfully:

- **Multi-language SDKs** (`extensions/sdk`, `extensions/sdk-rs`,
  `extensions/sdk-py`): see `docs/additive-features.md` D19. These are
  language bridges into the **same current wire contract** in
  `coding/extension/host/subprocess/protocol.go`. The wire has no independent
  version or compatibility negotiation. They are not separate APIs. Every SDK
  row in this matrix must keep its
  semantics aligned with the in-process Go reference exercised by
  `test/extension-conformance/conformance_test.go`.
- **TypeScript declarations** (`extensions/sdk-ts`): re-export the exact pinned
  Pi extension types and add declarations for PiG-only capabilities. Node
  extensions still run through PiG's compatibility modules. This package does
  not define another runtime API.
- **Runtime cells / packed runners**: see `docs/parity/DIVERGENCES.md` D20. These
  are an internal optimization on the host side. They do **not** change
  the extension API: each contained extension still gets its own socket
  and runs the same wire register handshake. Treat packed cells
  as transparent for parity purposes; a row is only "complete" if it
  preserves identical semantics in both isolated and packed modes.

The wire handler declarations require a positive `handler_id` so multiple
registrations for one event preserve exact identity and order. It identifies a
handler within one extension registration; it is not a multi-register handshake. The host rejects missing, zero, or duplicate identities.

When a row is impossible or intentionally non-parity, record a numbered
entry in `docs/parity/DIVERGENCES.md` and link it from the Status column.

### Async contract requirement

Every upstream Promise-returning extension method, callback, handler, factory,
provider refresh/login function, and UI operation must preserve whether the host
awaits it, completion ordering, rejection/error propagation, cancellation,
concurrency, and event-loop ownership. Go `error` and result returns represent an
awaited Promise only when the host waits for the callback to return. A detached
goroutine is valid only for an intentionally unawaited upstream operation and
must have explicit lifetime ownership, cancellation, error reporting, and
shutdown draining. Conformance for an async row must include premature-return,
cancellation, and error-path assertions; TUI-facing rows must also prove that UI
mutation re-enters the main loop. See `docs/extension-authoring.md` for
TypeScript-to-Go examples.

### Retained Context host-call lifetime

Normal completion retires a request parent before its response is published, without invalidating a retained Context's original connection. Active requests retain parent cancellation; cancelled origins and retired connections never become unparented live calls. Writer ordering serializes parent selection and normal completion. Pending calls resolve or cancel rather than retaining an absent parent. `TestConformance_TerminalInput` retains the original Context across current, empty/reset and replacement UI values in every SDK and isolated/packed/fused realization. The request-lifetime unit tests cover cancellation, racing publication, worker-start failure and disconnect, and scenario48 compares the actual Host/SDK caller with Pi. See `docs/parity/retained-context-lifetime.md`. Host guards, Provider child leases and Markdown callback body completion remain separate.

### Subprocess liveness contract

The current subprocess wire carries `ping`, `pong`, and `request_state` without
version negotiation. Each SDK dispatcher answers `ping` directly. A request
reports `started`, then `progress` or `blocked` when applicable, and
`completed` before its response. Host calls carry `parent_request_id`.
Interactive UI calls automatically report `blocked:user`; other awaited host
calls report `blocked:host_call` and then `progress`.
The blocking-reason vocabulary is `user`, `host_call`, and `external_io`.

The host sends heartbeat only while the connection owns outstanding work or
live provider state. A frame the host has queued or is writing is outstanding
work, and every byte the extension reads renews the pong deadline, so a slow
reader stays connected and a peer that stops reading fails visibly. Missing
`pong` closes the logical connection and returns `extension_unresponsive` with
extension, request, and operation context. The host never drops an outbound
frame and sets no socket write deadline. Loading has no deadline either: like
upstream's awaited factory, a load ends when the extension registers, its
process exits, its connection closes, or the caller cancels. A packed runner
reports a member whose factory fails by closing that member's socket.
Tools, commands, events, and shortcuts have no host completion or inactivity
lease. Their caller-owned context controls cancellation. Renderers use a
generation-scoped inactivity lease off the TUI loop and retain the last
completed frame. A failed logical packed member does not quarantine siblings;
shared process death quarantines the packed cell. Parent cancellation cancels
its blocked host/UI calls and removes response correlation before a late
response can arrive.

Ordering and cancellation coverage lives in
`coding/extension/host/subprocess/liveness_test.go`. `TestLivenessConformanceSDKsMatch`
compares normalized Go, Node/TypeScript, Rust, and Python production recordings for
heartbeat while blocked, awaited and interactive calls, no-result calls,
parent cancellation, completed ordering, and late-response disposal. Node work scheduled by a handler after its response has settled carries no parent request; it belongs to the live extension connection instead. `TestNodeUICallScheduledByAFinishedHandlerRuns` gates that transition in isolated and packed Node cells, and `34-late-overlay` exercises the delayed terminal overlay against Pi. Active-request cancellation remains covered by the liveness suite. This is the D56
subprocess-host behavior; upstream has no subprocess transport.

RPC shutdown async contract: Pi 0.87.1 `rpc-mode.ts:728-744,804-807` removes signal handlers and Session stdout subscriptions before awaiting `AgentSessionRuntime.dispose`. The runtime emits and awaits `session_shutdown` before synchronous Session disposal (`agent-session-runtime.ts:406-413`, `agent-session.ts:1170-1191`). Pending dialogs are not resolved by stdin EOF. A pending Node shutdown Promise may let the event loop drain; PiG reports that transport observation without synthesizing a response. The aborted run's hooks still deliver `turn_end` and `agent_settled` through the stale runner, while a missing persisted assistant entry emits `extension_error` (`agent-session.ts:635-683,870-876`, `runner.ts:928-1017`). The direct Pi comparison tests pin the complete immediate-tail event sequence and stdout records. Node reports post-disposal suspension beyond immediately fulfilled continuations, so a delayed `turn_end` does not postpone process exit (`output-guard.ts:95-108`, `TestRPCInputEndDoesNotJoinDelayedTurnEnd`). General host-call suspension during that tail and keepalive aggregation across separate runtime cells are not closed by those tests.

RPC stdin-end command contract: Pi reads stdin's end one event-loop iteration after the line that started an extension command, and `shutdown()` then exits within microtasks and one tick (`rpc-mode.ts:728-744,804-807`, `output-guard.ts:105-108`; the stdout write callback runs inside the current macrotask). A command answers only if it settles inside that window: microtasks, ticks and the check phase of the line's own iteration. A nested `setImmediate`, file I/O, a child process, a timer and a dialog do not answer; a command that settles while a `session_shutdown` handler that awaits a timer or I/O keeps Pi alive does. The Node runtime arms each command's window at invocation and reports `request_state` `suspended` when it closes unresponded. Only a host call that settles synchronously or through microtasks in Pi keeps the window open. The host records input end at EOF, holds a suspended command's response unless a quit `session_shutdown` handler is itself suspended, and joins each command until it answers or is suspended. The host applies a suspension only after every earlier call of the connection applied, so after input end a command's or quit handler's response waits until the suspension that preceded it is applied; before input end the response does not wait, because a suspension cannot hold it then (`TestResponseAfterInputEndWaitsForItsSuspension`, `TestResponseBeforeInputEndDoesNotWaitForAnotherRequestsCall`, `TestRPCInputEndAfterQueuedReplacementHoldsCommandResponse`). A runtime with no microtask continuation (Go, Rust and Python SDKs, fused and packed placements) has its still-running commands counted suspended at the checkpoint, without an SDK message (`TestConformance_SuspendedCommandFlush`). `setTimeout(0)` and a single `fs.stat` are racy in Pi and have no row. The Node runtime cannot observe a command of another runtime process that settles while a suspended handler of this process keeps Pi alive.

Interactive session-replacement async contract: Pi 0.87.1 `agent-session-runtime.ts:133-164` awaits `session_before_switch` and `session_before_fork` before it touches the session, with its event loop still running. Interactive `/new`, `/resume`, `/fork` and `/clone` emit them through `awaitExtensionUI`, as `session_start` does: the handlers run off the owner loop, and the owner loop keeps serving their `ctx.ui` calls. While a handler waits, input reaches only the extension's dialog, custom UI or terminal-input listeners; other type-ahead waits for the command. The handler's result is read as Pi's `cancel` field from typed and JSON results, and a cancel ends the command without output. Handler failures are reported by the runner and do not cancel. Loop shutdown ends the wait with an error. `extensions-runtime/65-session-before-dialogs` covers the Node-to-host path.

## Actionable Session boundaries

Pi 0.87.1 `agent-session.ts:635-684,787-819,1531-1553` awaits `turn_end` before queue selection and `agent_before_settle` after recovery. Session commits validated drafts, refreshes canonical context and source IDs, and then publishes each appended entry. Previews include queued custom messages. The completed Session subscription persists messages and flushes pending custom context before later Agent subscribers run. Recovery consumes the observed turn, not an older assistant exposed by a context edit.

Every SDK returns boundary mutations with a handler failure. The host applies those mutations before reporting the error and rebuilding the next preview. An explicit prior Agent end decision wins over extension continuation. Invalid explicit continuation never suppresses natural tool continuation. Abort during pre-settlement preserves the awaited handler result and commits its drafts, but suppresses continuation. Closing the Session still cancels and joins its work. Provider preparation and FinishTurn errors enter Agent's synthetic failed-turn lifecycle; Session dispatches that boundary exactly once. These operations run on the admitted Agent worker, not the TUI loop, and add no detached task.

`TestSessionBoundarySubscriptionFinishesBeforeLaterAgentListeners`, the original boundary tests, the real Node Session tests, and the isolated/packed/fused conformance rows retain ordering, mutation, error and cancellation evidence. Cross-process object identity and RPC33 remain unchanged.

## UI prompt events

Upstream's runner wraps the bound UI surface (interactive and RPC modes, not
print) so every `ctx.ui.select`, `confirm`, `input`, `editor`, and `custom`
call reports the outermost blocking prompt (runner.ts `withUIPrompt`). A
nested or overlapping prompt raises the depth without an event, and the end
event repeats the outermost prompt's kind and title. `custom` carries no
title, and an empty title is omitted from the payload.

Async contract: the prompt does not wait for remote asynchronous handler completion. Upstream queues each event with `queueMicrotask(() => void this.emit(event))`; handler errors go to the extension error listeners. Pig admits queued emissions in FIFO handler-body order. A Go in-process handler returns at its only observable suspension boundary; a handler that starts asynchronous work returns before that work finishes. A subprocess handler acknowledges when the SDK reports `blocked` or `completed`, or returns its response; a socket write or `started` state is not handler admission. Go, Rust, and Python report awaited host calls as suspension boundaries. Node reports the return from invoking the handler, before awaiting its Promise. A suspended start handler therefore does not block the matching end emission. Each runtime retains registration order within one emission. Invalidation (reload, session replacement) drops pending events and cancels active handler contexts.
In-process extensions reach the scope through the runner's wrapped UI surface.
`TestPromptHandlerBodyFIFOAcrossSDKs`, `TestPackedPromptHandlerBodyFIFO`, and `TestReviewPromptHandlerBodyFIFOThroughFusedSDK` record handler entry before any host call and check the unsorted sequence association. `TestPromptEndRunsWhileSDKStartWaitsForHost` and `TestNodePromptEndRunsWhileStartPromisePending` prove that admission does not await suspended completion.
Subprocess, packed, and fused extensions reach the terminal through the
subprocess UI bridge, which opens the scope when the dialog call arrives and
before it waits for terminal focus, because the extension already waits on the
user from that point. Interactive mode rebinds the bridge to the new runner on
reload.

Async contract (`pi.events`, several realms): `emit` is a synchronous host call. The Host snapshots the channel's listeners and, for each in order, sends a restricted synchronous request that runs the listener's synchronous prefix in its realm; the emitter waits and services requests from those prefixes (property operations on its payload, nested dispatches) at any depth. `emit` returns after the last prefix. A foreign listener reached while its realm is idle then waits until the emitter's first microtask after `emit` (`events.settle`), drains its own microtasks, and reports back; the emitter's later microtasks run after that. Listener errors are reported by the listener's realm as Pi's `safeHandler` reports them; a transport failure is reported with the same prefix. No timeout is added: a listener that never returns blocks its emitter, as in Pi. A realm exit fails pending operations on its objects and releases the leases it held.

## Event-bus lifecycle

Pi 0.87.1 `core/extensions/loader.ts:createExtensionRuntime` tracks subscriptions until explicit unsubscribe or runtime invalidation. The Node bridge uses that same lifecycle owner. `Runtime.run` invalidates it synchronously when shutdown or connection loss ends dispatch, before awaiting owned task cleanup. Retained ExtensionAPI calls then throw Pi's stale-context message. No task or IPC is added to emission, registration, or unsubscribe. Native `Session.Close` invalidates the runner it owns as Pi's `AgentSession.dispose` does; a runner borrowed from its `Runtime` (`New`, `Resume`, `Open`, `Continue`) or from a `Clone` source stays active for that owner, and `Runtime.Close` invalidates the Runtime runner. Two reloads and disposal preserve an independent host listener while removing each retired extension listener. The #7193 regressions cover the original imported Session path, Node transport cleanup, and direct Go Session closure; the cross-process delivery boundaries remain D83.

## Markdown callback ownership

Pi0.87.1 `modes/interactive/components/markdown-transform.ts:18-29` synchronously finishes the admitted transformer chain before another render can invoke one. PiG snapshots the chain and display context on the owner loop, then runs that individual generation on a Mode-owned FIFO worker. An ordinary replacement cancels the logical generation and revokes its publication, but the already-admitted chain uses the captured Mode lifetime. The next queued chain cannot start merely because the previous generation became stale. Each component keeps at most one queued replacement; replacing it moves the new generation to its new admission position.

The worker retains no UI locks during callbacks. Completion updates the component's protected result and its parent's atomic dirty flag, then uses the existing race-safe render scheduler. Equal-text updates and explicit invalidation carry a new revision. Options replacement and job identity cannot reuse an obsolete transformed frame. Removed components cancel publication and remove pending jobs. Mode cleanup cancels and joins its worker. The socket, request-parent rules, SDK dispatchers, and callback signatures are unchanged.

This closes ordinary replacement, not exceptional remote-body completion. A proxy can still settle after inactivity, disconnect, or shutdown before uncooperative SDK code returns. The lead assigns that remaining behavior to `fix-drift-ext` and the independently profiled64KiB parser scaling blocker to `fix-markdown-autolink`. ## Dynamic tool registration

Pi 0.87.1 `core/extensions/loader.ts:273-284` validates the schema before replacing a named definition and calls `runtime.refreshTools()` synchronously. `core/agent-session.ts:3144-3235` rebuilds definitions and prompt contributions, preserves active order, and activates newly admitted names. Replacing an inactive tool does not reactivate it. The existing allowlist and exclusion filters still apply.

The current subprocess wire carries the update as a `call` with method `registerTool` and one `ToolDecl` as its arguments. It returns `allTools` and `activeTools` after refresh. This is not another registration handshake or protocol version. The host uses a synchronized shared registry so runners see updates without reconstructing unrelated capabilities. Node uses its restricted synchronous socket pump and applies the returned lists before returning from `pi.registerTool`. Its tool getters query the host through the same pump, including when another extension changes the registry during the current handler. Go and Python support captured Extension registration and handler-context `RegisterTool` / `register_tool`. Rust uses `Context::register_tool` after its Extension moves into the runtime. These context methods supply the same registration capability without requiring a second factory or extension identity.

Registration is synchronous, not a detached task. The host serializes publication and refresh, surfaces validation/refresh errors, and rejects retired connections. ## Replacement callback async contract

Native `WithSession` runs after the replacement Session is installed and its host rebind finishes. `Setup` runs before rebind and refreshes the new Session from its initialized log. Cancellation or a rebind failure prevents the callback. Callback errors return on the replacement operation. `ReplacedSessionContext.SendMessage` and `SendUserMessage` await the direct Session operation; they are not the regular extension API's owned background actions. User-message command/template expansion defaults to false.

`CommandContext` forwards its request context to context-aware host actions. Rebinding an operation replaces both its plain and context-aware invocation forms, so an older form cannot override the new owner. Native #2860 cases, callback lifecycle tests, and request-owner tests cover these rules. Session27 compares the three original Pi bodies. Focused subprocess UI classifies wire traffic by semantics: input is an
ordered non-idempotent event, a rendered line set is a replaceable snapshot,
and open/result/cancel/error/close is a lifecycle barrier. Input and barriers
are never coalesced. Timer-driven render requests are coalesced to one pending
request and limited to the upstream TUI's 16 ms render interval. Input-driven
frames remain immediate. A snapshot is suppressed only when both its text and terminal width match the previous snapshot. Each published snapshot carries its terminal width (not the resolved overlay render width) and monotone sequence. The bridge rejects stale-width or out-of-order arrivals, and the UI cache checks terminal width again at paint time. The overlay key is the realization-local
generation and reload ownership includes the connection identity, preventing an
old runner from updating or closing its replacement.

and mutates dialog components on the owning TUI loop while the subprocess call
waits off-loop. Selection/submission returns `ok=true`, Escape returns
`ok=false`, and host/transport failures use a protocol error rather than an
ambiguous empty success. Headless contexts return `ok=false` without opening a
surface. Go and Rust SDK methods return host errors explicitly; Python and Node

### Terminal string transport

Pi `stdin-buffer.ts:251` emits one UTF-16 unit for ordinary input. `tui.ts:1015-1030` passes each chunk unchanged through ordered listeners and applies their rewritten strings. The host and Go SDK share `extensions/sdk/json`, which uses the native `internal/jsstring` WTF-8 convention and writes unmatched units as standard JSON surrogate escapes. This shared codec covers terminal input, owner snapshots, editor/custom input, text getters/setters, completion and render-line carriers. The wire stays valid UTF-8 JSON; it carries no alternate string field or discriminator.

Rust terminal and focused-component callback data and terminal verdicts use `JsString(Vec<u16>)`. Raw request and custom-input notification arguments and typed call results avoid a `serde_json::Value` conversion before decoding those fields. `get_editor_text` returns `JsString`; setters accept `Into<JsString>`. Serialize lossless Rust values directly with `serde_json::to_string` or `to_vec`, not through `Value`. Python's existing JSON encoder and decoder preserve surrogate escapes. Node uses its native JSON implementation.

The existing awaited, ordered verdict contract is unchanged. No task, timeout, coalescing, or TUI-loop work is added. Codec buffers belong to the current bounded frame. `TestTerminalInputNodeSurrogateQualification` drives actual StdinBuffer events and Editor snapshots through Node. `TestConformance_TerminalInput` checks input, rewrites and callback-time editor text through every SDK, isolated/packed modes and fused Go. `56-terminal-surrogate-transport` compares the complete unit trace with pinned Pi. ## Performance and resource contract

The Node socket worker assembles each four-byte header and bounded frame body with linear copying. It parses only complete JSON frames, answers heartbeat on the worker, and retains the existing unread-byte backpressure and socket-error boundary. Assembly adds no task or callback boundary. `TestNodeProviderSocketFrameCopyIsLinear` drives the real worker with fragmented Unicode payloads and a heartbeat; `TestNodeFrameBufferPreservesEveryFragmentBoundary` covers all split positions, empty bodies, the exact size limit, oversized headers, and consumer failure. `TestNodeProviderSocketRejectsBadFrameBeforeNextEnvelope` checks the actual worker's parser/size errors and failure ordering before a following envelope.

Extension parity includes latency/resource behavior at the TUI and lifecycle
boundaries; green payload conformance alone is insufficient. The foundation P6
matrix covers the concrete in-process reference, D31 fused path,
packed subprocess cells, and isolated subprocesses.

- `Render` and input-loop callbacks must not perform blocking extension IPC,
  filesystem/network work, or unbounded transcript traversal.
- Session history stays unloaded until first use. A persisted session is read
  locally by the isolated runtime, then reconciled with the host cursor. Missing
  history and later appends cross the socket in ordered pages no larger than 4 MB.
- Renderer/widget/overlay caching must preserve width, expansion, invalidation,
  ordering, disconnect, timeout, fallback/error, and exact terminal bytes.
- Registration, host-call, event, tool/update, cancellation, reload, quarantine,
  fission, and shutdown paths require representative latency/allocation and
  goroutine/fd/process/memory-lifetime evidence.
- Packed/fused optimization must remain observationally identical to isolated realizations of the current subprocess wire. The host currently serializes extension dialogs and custom overlays without blocking the TUI loop. Floating-overlay serialization is a known parity bug, not the upstream contract; see [overlay release gap](findings/fix-overlay-shim.md). Waiting calls are cancellation-aware. A faster fused realization cannot create a second SDK or skip protocol/conformance semantics.
- The broad `coding/extension.API` interface is not accepted merely because it
  mirrors this document: it needs a production reference implementation/caller
  or deletion under P0/P2. The concrete `*sdk.Extension` author surface remains
  the current production Go factory API.

Current focused-component rendering is cache-backed on the host. The TUI render
loop performs no extension IPC or JSON work. Go/Rust/Python component workers
serialize input and render callbacks away from each SDK dispatcher. Node uses a
bounded 16 ms scheduler and socket backpressure. Isolated, packed, and fused
lifecycle tests cover the current contract.

## High-risk parity areas

These areas need design before they can be marked complete.

### Custom TUI components

Upstream Pi passes in-process TUI components. Pig subprocesses cannot pass Go component objects across process boundaries. Pig needs a declarative component protocol, a restricted built-in component registry, or a numbered divergence.

### Tool and message renderers

Message renderers are production-bound. In-process Go renderers return TUI
components. Subprocess Go/Rust/Python/Node renderers return lines through an
owned background request; the TUI component reads only a generation-checked
cache and retains a visible default fallback on startup, timeout, disconnect,
or invalid output. Width, expanded-state, and output-padding changes replace stale generations. Upstream message renderer callbacks are synchronous. The subprocess bridge awaits their result on the owned request worker; a padding change uses the existing single-flight generation loop and never waits on the TUI loop. It retains the last completed frame until a current result arrives, rejects stale results, and preserves the existing cancellation/error/shutdown ownership.
`BenchmarkRenderProxyCached` measures about 17 ns/op and one 16-byte defensive
slice-copy allocation on the recorded M4 Pro; no socket or JSON work runs in
`Render`. Tool-call renderers remain a separate surface.

### Provider registration and custom streaming

Initially registered custom stream producers and raw native Provider objects retain distinct payloads in the one current wire contract. Producer callbacks use `provider_stream_simple`; native object methods use `provider_stream`. Both share the event decoder and option encoding, retaining explicit numeric presence and raw thinking fields. Metadata lookup and active Session refresh use catalog's shared auth-free composition path. Runtime registration, queue/bind behavior and D78 closure remain separately tracked.

### Extension CLI flags

Upstream Pi extensions register flags during load. Pig subprocess extensions require registration inspection before CLI parsing to expose flags in time.

The wire protocol carries each surface for every SDK that realizes it. The
conformance suite compares the in-process Go reference with the Go,
Node/TypeScript, Rust, and Python subprocess runtimes. Future additions must
land in all applicable SDKs or record the gap in
`test/parity/sdk-surface-exceptions.toml` in the same change.
