# Warm test caches

Test packages that build real extensions share persistent caches, so a package run compiles only what changed.

- Go: tests keep the user's `GOCACHE` and `GOMODCACHE` (`testenv.ScopeTempDir` pins them before a test replaces `HOME`). A test uses an empty cache only when it tests a cold cache.
- Rust: `coding/extension/host/subprocess`, `coding/extension/host/runtimecell`, `coding/cli`, `test/extension-conformance` and the `env` oracle build into `$PIG_TEST_CARGO_CACHE`, else `<user cache dir>/pig-dev/cargo-target`, in a directory named for the package and a hash of the SDK `Cargo.lock` and `Cargo.toml` (their contents and absolute paths; `testenv.SharedCargoTargetDir`). A lock change selects a new directory, so stale output cannot be reused. A checkout at another path selects its own directory, because rustc bakes `env!("CARGO_MANIFEST_DIR")` into a test binary and Cargo does not rebuild it when the checkout moves or is deleted. Cargo locks a target directory, so concurrent runs wait for each other. Set `CARGO_TARGET_DIR` to override. The `runtimecell` target holds the compiled test cell, and `make test-warm` fills it by running that test (a `cargo build` in the SDK directory does not seed the SDK as the path dependency of a generated cell).

`make test-warm` builds all of these once (slow the first time, a revalidation after). It builds the SDK dependencies through a cell crate that `runtimecell.WriteRustWarmCell` renders (`automation/ci/cargocell`), because Cargo keys a path dependency's unit on its path: building the SDK as its own root package leaves every cell compiling `pig-sdk` again. Run it before `make test` or after a lock change. CI restores the Cargo caches and runs it once per Linux job. The CI cache key hashes `automation/ci/test-warm.sh` with the SDK lock, so a target the script gains is saved on the first run that builds it; `test/ci-images` fails when a test names a Cargo target the script does not build.

Extension cells: `test/extension-conformance` runs as sharded `go test` processes, and a cell's cache key names its source directory, so a per-process temporary directory gave every process its own Rust, Lisp, Go and Python cells (about a minute of setup per process, charged to the first test that needed each). `testenv.SharedCellCacheDir` names one directory for them under `$PIG_TEST_CELL_CACHE`, else `<user cache dir>/pig-dev/cell-cache`, for a hash of the absolute path and contents of every file under `coding/extension`, `internal`, `extensions`, `go.mod`, `go.sum` and the conformance fixtures and tests. Each process links its config roots' `cache` to `<dir>/cache` and writes the cell sources the tests generate under `<dir>/sources` (`shareCellCaches` in `testmain_test.go`), so the cells compile once per machine and run. The cell publisher is content-addressed, builds under a per-entry file lock and publishes with one rename; a change to any hashed file selects a new directory, and a directory is never reused for other contents. Each use touches `<dir>/.used`, and a scan under a file lock removes the directories of other hashes that nothing has used for 14 days, except the four most recently used. CI does not restore this directory (it would hit only when no hashed file changed, and the cells build in the first shard's `TestMain` in under a minute), so each job builds the cells once.

A grouped run (`make test`, the CI test targets) builds the Rust fixture first into `tmp/test-fixtures/rust-target` and exports that directory as `CARGO_TARGET_DIR` (`automation/ci/test-fixtures.sh`), so every package of the run, `coding/extension/host/runtimecell` included, builds its Rust cells into that one target and a cell compiles only its own crates there. That holds when the fixture build compiled the SDK as a cell resolves it, because a cell copies `extensions/sdk-rs/Cargo.lock` and Cargo reuses a unit only when its dependencies resolved to the same versions. `test/extension-conformance/testdata/rust-sdk-fixture/Cargo.lock` is therefore the SDK's lock plus the fixture's own package, and `TestRustFixtureLockResolvesWhatTheSDKLockResolves` (`test/ci-images`) fails, with the command that syncs it, when a bump of the SDK's lock leaves them apart. A fixture lock that had fallen behind sent the first Rust cell build of a run into compiling `pig_sdk` and `serde_json` itself: 73 s of one core on an idle host, and more than 8 minutes inside the 12-way package pool of a 4-CPU runner, which cut `TestBuildRustPackedCellBuildsCachedRunner` off at the `go test` deadline.

A test that drives a real terminal session builds its extension before the session starts: a print-mode run in the same `PIG_HOME` (`prebuildExtension` in `coding/cli/extension_sprite_pty_test.go`) fills the build cache, and the session finds it. Inside the session the build comes before the header, so a wait for the header would cover a build that waits for another build's Cargo lock (a run on the same host that shares the cache root holds it too) or compiles a cold target, and no `testbudget` bound can say how long that takes. The print-mode run waits for the process to exit; a build that never ends fails at the `go test` deadline.

A build that no event of the test decides ends at the `go test` deadline, not at a fixed bound: `testbudget.DeadlineContext` bounds the shared pig binary of `coding/cli` (`build_binary_test.go`) and the Rust load of `TestContextResultShapesCrossSDKTransports`, and a step cut there says so (`testbudget.Expired`). A starved host then fails with the deadline named instead of with a killed `go` or `cargo`.
