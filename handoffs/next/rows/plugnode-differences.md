# plugnode: what a Pi user or plugin sees differently from Pi (after the direction flip)

`chord/nextnode/plugins` against Pi `2c8d1feb` `packages/chord/src/next-node/plugins`. The owner decision (2026-11-01, docs/plan/chord-plugins-node-evaluator.md) covers "build in Go, evaluate in a Node subprocess". These are the observable consequences, each checked against the code or a test named here, with whether it can be closed now and the cost. No divergence rows are added for them (the reviewer's S2 asked for numbers; the owner's call is to list, not to number).

Not differences any more (the first port's, closed by the flip, `NodeHost.Link`): one Go host can own any number of NodeHosts, a Go host that has a parent can load plugins, and Pi's end-to-end case (`server.get(Notes)` routed to the worker, `notes.add`, the label frames on the server's reference) is ported with one observing server (plugins_endtoend_test.go).

## Differences

| # | Pi | PiG | Can it close now? Cost |
|---|---|---|---|
| 1 | The app's code `get`s a local type a plugin serves, in process (`server.get(Index)`). | The app's Go host cannot: a local type is the host's own, never placed, so the hold fails `unavailable: test.index is not served here` (`TestEndToEndTheAppsGoHostCannotGetALocalTypeAPluginServes`). JavaScript code in the subprocess can (a core facet, the tests' probe). | Not at the chord level: placement of local types is Pi's semantic. A `NodeHost.Read`/`Watch` control op over a contract described as data would give the app a read path: about 300 lines (a contract encoder from `contracts.Contract` to a JS declaration, the op, results as JSON) and it is not Pi's `get`. The plugin's author can serve the type as a remote one instead (Pi's own way across hosts). |
| 2 | The app's own (core) facets are Pi facets in the app's process, in the same host and closure as the plugins'. | `CoreFacet.Module` is a JavaScript file the subprocess imports: a Go `host.Facet` cannot be loaded into the Node host (`RuntimeLoad.Core`, host.mjs `load`), and one loaded on the Go host is another host: Pi's closure rule (a plugin that needs another's type, the `adopt` rule) does not span the two. | The files part is by design. A cross-host closure rule is a chord/next change (high); not planned. |
| 3 | `createHost({ store })`: persisted documents and tables work on a host created with the app's store. | The Node host has none (host.mjs `createHost` takes `address`, `principal`, `heartbeat`, `onError`): a type that declares a persisted document fails to activate with Pi's own `persist needs a store` (`TestRuntimeAFacetWithAPersistedDocumentFailsToActivateTheHostHasNoStore`). | The Go host's store cannot be shared: `store.Store` is an in-process engine (Export, Outbox, commit queue) and a store has one open host. A store of the Node host's own is moderate: vendor Pi's `next/store` and `sqlite/node.ts` (`node:sqlite`) closure, a `store: {path}` option on `load`, a test of a persisted object across a restart; it is a different store from the app's (own file, not synced with the Go host's). |
| 4 | `HostPackages` is a map of module instances the app made (`probe` objects, the app's live modules). | `HostPackages` is `specifier -> file`: the subprocess imports the file once and the plugins share that instance; no object of the app's process can be handed over (`plugins_runtime.go`). `@earendil-works/chord/next` is always Pi's vendored one. | No: a process boundary. The app ships what a host package does as a module file. |
| 5 | `onError` gets `HostError` objects with all their fields and the original `error` values. | `NodeOptions.OnError` gets `NodeHostError{Kind, Object, Address, Err}`; `failure` is flattened to its error and the fields of `close_failed` (`native`), `routine_failed` (`routine`), `job_*` (`job`, `id`, `restarts`), `derive_failed` (`member`), `parked_long` (`waitingFor`, `state`, `since`) are not forwarded (host.mjs `hostError`, plugins_node.go `control`). Batch and registry errors are forwarded by kind only. | Yes, cheap: forward the whole JSON of each kind (about 60 lines in host.mjs and the Go struct, a test per kind). |
| 6 | Errors are the JavaScript values the plugin threw: classes, `cause` chains, `instanceof ChordError`. | `*NodeError{Name, Message, Stack, Chord}` (`Error()` is the message, `Stack` is `mapStack`'s output, `Unwrap` gives the `*data.ChordError` when it is one). `cause` is not sent (host.mjs `wireError`); a thrown non-Error is its string. | `cause` chains: yes, cheap (recursive `wireError`, a `Cause` field). Classes: no. |
| 7 | Host options of the app's host are the Node host's: `telemetry`, `principalKey`, `revokedBy`, `closeTimeout`, `readyTimeout`, `compression`. | The Node host gets `address`, `principal`, `heartbeat` only (RuntimeLoad). Functions cannot cross: a Go host with a custom `PrincipalKey` or `RevokedBy` ("the same function on every host") has another one than the Node host's default. Links between the two hosts do not compress (no `compression` on either side of this link); Pi's workers pass none either (workers/main.ts), the app's in-process host may. | Plain values (`closeTimeout`, `readyTimeout`, telemetry on/off): yes, cheap. Functions: no. Compression: add `next-node/compression.ts` to the vendored closure and a Go `HostOptions.Compression`: cheap, only for large parts. |
| 8 | A plugin's `console.log` is the app's console; an uncaught exception, an infinite loop or `process.exit` in a plugin is the app's. | The subprocess's stdout and stderr go to `NodeOptions.OnOutput`, else to this process's own (`TestNodeGivesTheProcessesOutputToOnOutputByStream`). An uncaught exception ends only the subprocess: `*NodeExit{Fatal}` (`TestNodeAnUncaughtExceptionEndsTheProcessWithItsFatalAndClosesTheLink`), the app keeps running, the NodeHost stays dead (Pi's workers: never restarted by themselves). Every plugin of that host goes with it. [INFERENCE for Pi: in process the exception ends the app unless it handles `uncaughtException`.] | By design (isolation). Restart policy is the app's: `workers.ts`'s component does it (NWork lane). |
| 9 | `plugins.load`/`reload` are in-process calls. | A process start per NodeHost (about 0.6 s in the tests), a control round trip per request, and requests ordered by the channel. `ReadyTimeout` bounds the start (30 s). A report and the frames of what it changed travel the same socket in order, but the Go host delivers frames through its own batch, so the app must not assume the frames arrived when `Reload` returned (the end-to-end test waits for the frame list, and uses a call as the barrier where nothing may change). | No: the cost of the process boundary. |
| 10 | Node is the runtime that runs the app. | The Go app needs Node.js >= 22.19.0 on `PATH` to evaluate plugins (`discoverNode`; a missing or older one is an error of `Load` that names the requirement, `TestNodeOlderThanTheMinimumNamesTheRequirementAndTheVersionFound`). Building, discovery, the watcher and `Plugins.Scripts` need none. | No (AGENTS.md: no embedded JavaScript runtime). |
| 11 | The link between the server and a worker host: a memory or IPC link the app makes. | The app attaches `NodeHost.Link()`; the Node host closes a link silent for its heartbeat (30 s) and exits with it, so the app attaches it right after `Load` (a link attached later than `Load` and other requests works, `TestNodeALinkAttachedAfterLoadAndOtherRequestsStillCarriesTheHost`; one not attached in time ends the process, `TestNodeALinkNotAttachedWithinTheHeartbeatEndsTheProcessAndTheLink`). | Inherent to Pi's shape (Pi's worker has the same heartbeat). A lazy `connect` on an `attach` control request would remove the window; not Pi's shape. |
| 12 | `buildFacet` on esbuild's JavaScript API. | Go API of the same esbuild (0.28.2), byte-identical scripts and digests (`TestBuildMakesTheSameScriptsAsPisBuildFacetForTheFixtures`). One text differs: an unreadable input's error. Pi's is `<esbuild lib>/main.js:1552:22: EACCES: permission denied, open '<path>'` (the location is the library's, so it depends on where Pi's esbuild is installed); PiG's is `worker.ts:1:19: EACCES: permission denied, open '<path>'` (the import's position, Node's text, `TestEsbuildBuildAForbiddenInputFailsTheBuildWithNodesText`). | The library location is an artifact; not reproducible and not wanted. |
| 13 | Windows: Pi's IPC is Node's. | The channel is a named pipe with a current-user DACL (`plugins_node_listen_windows.go`); it compiles (`GOOS=windows go vet`) and has never run on Windows. The tests that need a fake `node` on PATH, a pid or file modes are unix only (`plugins_node_unix_test.go`). | Needs a Windows runner. |

## Adaptations of Pi's tests (process boundary, not behavior)

- A case that reads a JavaScript object of the evaluated facet (`facet.made instanceof ChordError`, `facet.values`) reads it through the probe (plugins_probe_test.go), marked in each test's comment.
- `plugins.test.ts` "abort after the commit": Pi spies `batch.commit`; the port holds `Attempt.checked` in the subprocess.
- The end to end case routes the server kind's own plugins to a NodeHost of their own, read through a probe held through the same route (`Index` is a local type: difference 1).
