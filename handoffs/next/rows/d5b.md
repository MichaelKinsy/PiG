## Decisions the owner must take

1. Design-outs listed under (c).
2. `routines`: a Go handler runs on its own goroutine, so the interleaving of two handlers' first statements and of a native delivery with the handler's return is not Pi's microtask order. One upstream case (`routines and the end › start in the turn their object went live, next to a method call admitted in that turn`) is `missing` for this reason, and the case `takes every value a busy call left buffered ... [0, 20]` passes with the delivery task awaited inside the handler; a native frame that arrives after a call finished while the routine is idle gets its own call (no `settling` wait). Is a numbered divergence wanted, or a rework of `Loop.Go` handlers into in-section continuations in D5a (the host then owns handler scheduling)?
3. `routines` use in-section callbacks and `Loop.Queue` rather than `Loop.Go` for `void new OnRoutine(...).start()` (DESIGN section 4 said `Loop.Go`): the only owned tasks are the handler calls and the `watch.closed` waiter (`d5b-async.md`). DESIGN-go-layout.md is amended accordingly.
4. API forms: milliseconds are `time.Duration` (`Sleep`, `nativeOptions.CloseTimeout`, `parked`, `deadline`) but `GetOptions.ReadyTimeout`/`ServeOptions.Linger` are `*float64` ms as Pi numbers; D5a should unify before the typed layer (one Go type for Pi's millisecond options).

## State API gaps for D5a / the integrator (D1 `chord/next/state`, not edited here)

1. `Source.Changed()` ignores an embedder's `Watched()` (Pi's `changed()` reads the overridden `watched`): `memberSource` has its own `changed()`.
2. `(*state.Batch).deliveries()` is unexported: `referenceState`, `memberSource` and `keyedMembers` take the batch's `*chord.DeliveryScheduler` as a constructor argument (the host holds it).
3. `documents` (D4) will supply `KeyedSlot`, `Singleton`, `Keyed` handles: `resolveWatchable`/`resolveKeyed` (Pi `reference.ts`, D5a) are injected into the member checks and routines as `func(any) (state.DeriveSource, error)`; the host passes its own.
4. D4's `documents.DocumentsOwner.Do` is `Loop.Run`; when the host gets a `DeliveryScheduler`, D4's loop holds it (`Hold`/release) for an outermost section so frames fold as Pi's microtask turn does: D5a's `Run` wrapper does the same.

## open questions / things the lane owner must decide

1. Routines are in-section state machines with loop.Queue microtasks, not Loop.Go (DESIGN s4 said Loop.Go for `void new OnRoutine(...).start()`): reasoning in async.md; the only owned tasks are the handlers' calls and the `watch.closed` waiter.
2. Order differences that cannot be reproduced with Go handlers (blocking code on its own task): (i) two handlers' first statements, `routines and the end › start in the turn their object went live, next to a method call admitted in that turn` is `missing`; (ii) an `onLive` that ends its owner in its first statement does not deterministically stop the next declaration (its admission, which is in the section, does: tested); (iii) Pi's NativeWatch replays buffered values one per microtask before a finishing call is seen; a Go delivery task is concurrent with the handler's return, so a frame arriving after `called` found the routine idle gets its own call (no `settling` wait). The ported case `takes every value a busy call left buffered ... [0, 20]` therefore waits for the replay (scheduler Wait) inside the handler. If the owner wants Pi's exact rule, D5a's host loop would have to hold the delivery scheduler across a call's completion; say if this needs a divergence number.
3. Seam additions beyond DESIGN s5: callHost.loop() sectionLoop (eventLoop + Run + Go; *Loop satisfies it) because Get/run/resolve resume in sections from goroutines; routineHost = callHost + Report; routeHost = loop + Closing + Report + RouteLink(link, routeLinkOptions, ctx); routePath.Linked() (destination reads Path.linked); routedHolder = empty interface for `Upstream`; destination.hold takes (address WireAddress, type string, link routeLink, principal, ctx) rather than a HoldRequest.
4. Go API forms: Ctx.Principal() returns data.Principal (nil = undefined); FacetHost.Serve/FacetSelf.Contribute return the error Pi throws; Facet.Setup returns an error; ServeOptions.Linger is *float64 ms; RootOptions.Principal data.Principal. D5a's typed layer adapts state.Source to chord.Watchable (Value() is a throwing getter on Source).
5.
