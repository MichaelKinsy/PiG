## Design notes (pick-the-conservative-option decisions; review these)

1. **net/http is Node's `http` module.** The listener is a `net/http.Server` with Node's limits in Go's settings (ReadHeaderTimeout 60 s = `headersTimeout`, ReadTimeout 300 s = `requestTimeout`, MaxHeaderBytes 12288 + Go's 4096 request-line allowance = 16 KiB, IdleTimeout 5 s = keep-alive). Forced observable differences, all refusals with another status or status line (node.go header lists them): two `Host` headers and a `Host` with userinfo are answered 400 by net/http before the component runs (Node: the component answers 403); an HTTP/1.0 request's status line says `HTTP/1.0` (Node: `HTTP/1.1`); the reason phrase of the status line is Go's (the answers' own text is Node's table); header names are written in canonical case; a small unread body is drained by net/http (up to 256 KiB) after the handler. The component's own 403 for those requests is kept for `Fetch`/`NodeRequestOf` (a request handed over by any server) and tested there. A hand-written HTTP/1.1 server would match Node's parser exactly; it was not chosen (security-critical parsing belongs to the standard library). **Owner may reject this.** The draft divergence is below.
2. **Router following is an object, not a watch.** Pi's `#follow` watches the router value on its event loop. A Go registry value may be watched or read only inside the host's sections; the watch's abort and `Start` race the host's close from outside (`-race` showed it). The facet serves a host-lifetime local type `chord.http.follower` whose factory does `self.Registry(Http)` + `self.OnNative(router, ...)`; each new router is handed to a single task that terminates the connections it no longer admits (the newest router only: the newest also ends what older ones admitted). It runs from the host's start, not from the first request. `HttpFollower` is that type.
3. **`host.Root` with no principal.** Pi's explicit `principal: undefined` is anonymous; Go's nil is the omitted form. `RootOptions.Anonymous` was the lane's only edit outside the new package; KFold's `fix/follow-kfold` has the identical change (host_root.go field, `chordHost.Root`), so the merge into this branch carries one copy of it. `host_root_anonymous_test.go` keeps the one case KFold's `TestHostRootRunsAnonymous...` lacks (Anonymous wins over a Principal).
4. **Context abort is not synchronous in Go.** `AbortSignal.abort()` reaches `ctx.abortSignal` at once; Go links contexts by `AfterFunc` goroutines. `Close` therefore waits for each running request's scope to be seen done after it cancels it (Pi's observable "aborted when `close` returns"); one upstream test (`aborted inside the route`) waits for the link before it reads the scope, with a comment.
5. **Sockets are read while their handler runs.** Pi attaches a plugin socket's listeners in the handler's synchronous part before any frame is read. The Go handler returns an error and may run long: reading starts before it (pings, pongs and the peer's close are served, so the heartbeat holds), the data frames that arrive meanwhile are held and delivered to its `OnMessage` listeners in order when it returned. Plugin code gets typed listeners (`OnMessage(func(Message))`, `OnClose`, `OnError`, `OnPing`, `OnPong`); the `any`-typed emitter is unexported and only the link adapter uses it.
6. **Typed Records as ordered slices; functions have no identity.** `routes`/`sockets`/`csp`/response `headers` are ordered slices (conflict-report and header-line order); `HttpSocket` and `HttpRelay` are compared by pointer (Pi: `Set<HttpSocket>`, `relays.includes`).

## DRAFT divergence (unnumbered; the owner approves, the reviewer numbers it)

> **Chord's listener answers some malformed requests as net/http does, not as Node's `http` module and the component do.** Pi's listener (Node `http`) parses a request with two `Host` headers or a `Host` with userinfo and hands it to the component, which refuses it 403 with the default security headers. Go's `net/http.Server` refuses both itself, before any handler, with a canned `400 Bad Request` and none of the default headers (`net/http/request.go` "too many Host headers", `server.go` "malformed Host header"); no `http.Server` option, hook or `ErrorLog` reaches these checks, and a pre-scan or rewrite of the bytes would be an HTTP framing parser. Also: an HTTP/1.0 request's answer has an `HTTP/1.0` status line (Node: `HTTP/1.1`); the status line's reason phrase is Go's (the answers' own text is Node's table); header names are written in canonical case; and net/http watches the connection for a disconnect only once the request body is read, so a client that goes away with an unread body is seen when the route reads or writes (Node sees the socket close at any time). Observable for the owner of the listener only: every affected request is refused either way, no route runs, and `Fetch`/`NodeRequestOf` (a request handed over by any server) answer Pi's 403. Tests: `node_test.go` (`TestTargetsRefuseAnAbsoluteFormTargetTwoHostHeadersAndNone`, `TestTargetsRefuseAHostWithUserinfo403AndAMethodAWebRequestCannotCarry501` and the mounting test assert Go's 400 where `node.test.ts` expects 403; `TestFetchRefusesTwoHostHeaders` and `TestNodeRequestRefusesWhatTheListenerRefuses` assert the component's 403). Source marker: `chord/nextnode/http/node.go` header (the marker line takes the number).
