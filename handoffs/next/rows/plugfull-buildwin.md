## 12. `buildFacet`: an unreadable input's error text

| | |
|---|---|
| Pi | `<relative path of esbuild's lib/main.js>:1552:22: EACCES: permission denied, open '<path>'` |
| PiG now | `worker.ts:1:19: EACCES: permission denied, open '<path>'` (unchanged: the import's position, Node's text; `TestEsbuildBuildAForbiddenInputFailsTheBuildWithNodesText`) |
| Closed? | **No: it cannot be closed without inventing a location.** |

Evidence, by running Pi's shape (a `build()` of esbuild 0.28.2's JavaScript API with an `onLoad` that does `await readFile(path)` on a file with mode 000) and by reading `esbuild@0.28.2/lib/main.js`:

- esbuild's JS API takes the location of an exception thrown by a plugin callback from the callback's stack: `extractErrorMessageV8` → `parseStackLinesV8` walks the frames after the message line and takes the first one whose `file:line:col` it can `readFileSync`. The frames of that error are `at async open (node:internal/fs/promises:697:25)`, `at async readFile (node:internal/fs/promises:1348:14)`, `at async file:///…/t.mjs:7:61` (Pi's callback: a `file://` URL string is no path), `at async requestCallbacks.on-load (…/node_modules/esbuild/lib/main.js:1552:22)`. The first readable one is esbuild's own `let result = await callback({` (line 1552, column 22 in 0.28.2: `awk 'NR==1552' lib/main.js`).
- The probe's error: `{"column":21,"file":"../node_modules/esbuild/lib/main.js","line":1552,"lineText":"        let result = await callback({\n    at async open (node:internal/fs/promises:697:25)\n …"}` with text `EACCES: permission denied, open '/private/tmp/esbprobe/p/locked.ts'`; Pi's `describe()` prints `relative(plugin.dir, file):line:column+1: text`, so `../node_modules/esbuild/lib/main.js:1552:22: EACCES: …`.
- The location is therefore a line of the JavaScript library at wherever Pi's `node_modules` is relative to the plugin (it differs between two installs of Pi), and it exists only because Pi's plugin callback is JavaScript run by that library. The Go API runs `OnLoad` in Go: there is no JavaScript stack, no library file and no such line. Any text that matched Pi's would name a path and line that nothing in PiG read.
- No Pi test or example asserts it: `git grep -i 'EACCES\|chmod\|permission denied' b556cfe5 -- packages/chord` finds nothing, and `build.test.ts` has no unreadable-input case.

The Go text carries the same message (`EACCES: permission denied, open '<path>'`, Node's text, the same path) and a real location (the import that asked for the file). Recorded in `docs/plan/chord-plugins-node-evaluator.md` 10.10.
