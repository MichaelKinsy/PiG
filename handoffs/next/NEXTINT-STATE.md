### chord/next/host: cause per test (Pi e7a0df27)
All failed only in plain runs because Go's hops are goroutines where Pi's are microtasks. Pi's examples and tests rely on microtask order, so each Go test now waits on the event Pi's `await` waits on (no sleeps, retries or longer timeouts). Red = the base binary, green = the fixed binary, plain, -count=200 each (all green).
* TestExample14FlowControl (host_examples_test.go): test. Pi's example (14-flow-control.ts) only prints "the fast tab saw 5 changes", under microtask order. A relay returns each `ack` to the worker, but the next commit here is a call from the test's goroutine, so the third commit met a full window and folded: the fast tab saw 3 changes in 33 of 40 runs (never 5 in 10 s). The test waits (`transported` over every link, the worker's too) after each commit. Red 19/20.
* TestObjectEndRevocationR11 (jobs_job_end_test.go): test. Pi reads `reason` after `await flushed()` (jobs/job.test.ts:1204..1205). The end aborts the run's signal; the run wakes on its goroutine and the outcome is recorded on another. The test waits for `reason`. Red 19/20.
* TestObjectLingerOnly...Race9 (host_object_test.go): test, and a host bug found on the way. Pi's `await flushed()` (host/object.test.ts:683) runs the activation to the open waiting on its gate; `turn` does not wait for the host's tasks (test-only fix: green 200/200; red 16/20). The host bug: Pi checks `#abandoned` and starts `native.open` in one section (attempt.ts #ownSteps, native.ts open); here the open starts on an owned task (awaitTask), so a close could come between and the late open left its value open and never closed. `nativeHandle.open` now refuses a native closed first (host_native.go, 735e4a2a50). Unit test TestNativeAnOpenThatStartsAfterItsCloseOpensNothing: red 20/20 on the old host, green 200/200.
* TestProviderOrigins/keep a window per origin (remote_provider_test.go): test. Pi's link delivers the `ack` a microtask later, before the next commit (provider.test.ts:687..709); here the commit could come first (states of origin 0 = 2 or 3, want 4). The test flushes the link after each ack. Red 20/20.
* TestRemoteObjectReHoldsAfterADrop (remote_remote_object_test.go): test. Pi's `await transported()` twice lets the watch deliver; here the watch delivers on its goroutine after the reference is live: the states were [failed loading live] and the call was made, 300 ms later, in all 37 failing runs. The test waits for the third state. Red 7/20.
* TestRelayIDsAndOrigins, TestRelayDownstreamDrop (remote_relay_test.go): test. Pi calls `resolve` synchronously from `check` (route.ts:120), so two addresses' workers come in hold order (relay.test.ts:165, :456). Here each address resolves on an owned task, because `Resolve` blocks (forced Go difference, now recorded in host_route.go): worker 0 was the second hold's in 347 of 400 runs, the call went to the other worker and `one.Next("call")` waited until the link closed after 30 s. The second hold waits for the first worker, as the windowed-fairness test already did. Red 17/17 and 18/19.
Found by sweeping the whole package (red at the base too): TestExample04Watches (the reset folded into the slow listener's call; paces on the listeners that keep up), TestHostCloseAbortsAPendingOpen... and TestHostAcquiringACancelledContext... (wait for the open to have started: gatedSvc records opens), TestHostReferencesChangesInTheBatch... (deliver each step), TestHostRevokeAbandonsAnActivationInProgress (wait for the open to see its abort), TestRelayReceivedBuffers (the tab's `ack` buffer, under 16 bytes, is part of an allocator tiny block: its weak pointer stayed set for seconds with nothing of the relay holding it, 40 of 100 runs; only buffers of 16 bytes or more are recorded). Those six: plain -count=200 and -race -count=5 green.
Residual difference (documented, not fixed): in Pi a get/hold runs the activation to its first open synchronously; Go's activation goes on over tasks, so an object ended right after its `get` may never call its opener (Pi calls it and closes the late value). Tests that cancel or close right after a get wait for the open first.
