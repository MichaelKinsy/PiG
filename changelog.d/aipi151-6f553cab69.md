### Added

- Added `ModelsProvider.RefreshModelsAuth`. Set it to `RefreshModelsAuthConfigured` for providers whose `RefreshModels` reads a catalog that needs no provider credential, such as pi.dev: `Models.Refresh` then still skips unconfigured providers, but no longer refreshes an expired OAuth token first, so a stale login (`invalid_grant`) no longer fails that provider's catalog refresh. `RefreshModelsContext.Credential` is nil in that network phase.

### Fixed

- `pig update --models` warns about a provider whose OAuth login can no longer be refreshed (`Warning: skipped model catalog for <provider>: ...`, with the `pig auth login <provider>` command to sign in again) and finishes successfully; it fails only for other refresh errors, and the failure lists only those. <!-- fix: 6f553cab69 -->
