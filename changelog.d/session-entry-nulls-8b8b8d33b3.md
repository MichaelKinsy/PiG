### Fixed

- A session entry member that an extension sets to `null` is written as `null` and read back as `null`, as in Pi: the `data` of `pi.appendEntry`, the `details` of `pi.sendMessage`, the `data`, `details` and `usage` of a `turn_end` or `agent_before_settle` draft, and the `details` and `usage` of a `session_before_compact` result's compaction and of a `session_before_tree` result's summary. PiG wrote no member, and a reader of the reloaded session got undefined. The cause: the host decoded a member written as `null` and a member left out into the same value, and the entry types leave out a member without a value. A session file that PiG wrote before this change has no member where Pi has `null`; it reads as Pi reads the same file. <!-- fix: 8b8b8d33b3 -->
- An extension's `SessionManager.branchWithSummary(id, summary)` without the `fromHook` argument writes a branch summary entry without a `fromHook` member, as Pi does. PiG wrote `"fromHook":false`. The cause: the entry type could leave the member out only for an entry it had read from a file. <!-- fix: cc387053a6 -->
- A custom message that an extension writes without `display` (`pi.sendMessage({ customType, content })`, a `custom_message` draft without the member) has no `display` member in the session file, as in Pi, and a draft without `content` has no `content` member. PiG wrote `"display":false` and `"content":null`. The cause: `display` was a Go boolean with no "not given" state, and the entry wrote a missing content as `null`. A session file that PiG wrote before this change keeps its `"display":false`. <!-- fix: f71a1836fc -->
- `setLabel` from an extension writes Pi's three label entries: no `label` member for a call without a label, `"label":null` for a null label and `"label":""` for an empty string. Each clears the label. PiG wrote the entry without a `label` member for all three. The cause: the host decoded the label as a string, and the binders of the session, the interactive mode and the session graph runner mapped an empty string to no label. An extension that clears a label with an empty string now writes `"label":""`, as the same call does in Pi. <!-- fix: 3063e768f4 -->
- A `usage` object that an extension supplies is written to the session file as the extension wrote it, as in Pi: its member order and any extra member. This applies to a compaction draft, to a `session_before_compact` result's compaction and to a `session_before_tree` result's summary. PiG wrote its own member order and dropped extra members. The cause: the host decoded the object into its typed usage and wrote the typed value back. Token and cost totals do not change: they use `input`, `output`, `cacheRead`, `cacheWrite` and `cost.total`, as Pi's do. <!-- fix: 1ea5c18bc2 -->
- A custom message whose `display` an extension sets to `null` (a `custom_message` draft, or `pi.sendMessage` from a JavaScript extension) keeps `"display":null` in the session file, as in Pi. PiG wrote `"display":false`. The cause: `display` was a Go boolean with no null state. Readers take the null for false, as before. <!-- fix: 47ef9ce797 -->
- `pi.sendMessage` with a `content` of `null` writes `"content":[]`, as in Pi, and so does a message without `content` that the interactive mode appends. PiG wrote `"content":null` for the first and no `content` member for the second. The cause: Pi's `sendCustomMessage` reads `message.content ?? []`, and PiG applied that default only to a missing content and only in one of its two paths. <!-- fix: 1b0a657da2 -->
- Python SDK: a `setup` callback of `new_session` that leaves out the `data` of `append_custom_entry` or the `details` of `append_custom_message_entry` writes an entry without that member, as Pi does. PiG wrote `"data":null` and `"details":null` into the session file. The cause: the Python `SetupSessionManager` sent the member on every call, and its default, `None`, is a JSON null. `pig_sdk.NULL` still writes the member as null. <!-- fix: 94bd9a58fe -->

### Added

- Extension SDKs: an explicit `null` for an optional member of a session entry. Node `null`; Go `json.RawMessage("null")`, and `SendMessageOptions.Details` for a message's details; Python `pig_sdk.NULL`; Rust `Context::append_entry_opt` and `Context::send_message_with_details` with `Some(Value::Null)`; Lisp `:null`. The empty value of each language (`nil`, `None`, `Value::Null`, `NIL`) leaves the member out, as before.
- Extension SDKs: `setLabel` without a label and with `null`. Node `pi.setLabel(id)` and `pi.setLabel(id, null)`; Go `Context.SetLabelValue` with `nil` and `json.RawMessage("null")`; Python `set_label(entry_id)` and `pig_sdk.NULL`; Rust `Context::set_label_opt` with `None` and `Some(Value::Null)`; Lisp `ctx-set-label` without a label and with `:null`.
- Rust SDK: `SetupSessionManager::append_custom_entry_opt` and `append_custom_message_entry_opt` write an explicit `null` for the `data` and the `details` of a setup session entry.

### Changed

- An extension that clears a label with an empty string (`setLabel(id, "")`) now writes a label entry with `"label":""`, as Pi does. PiG wrote the entry without a `label` member. The label is cleared in both; a tool that reads session files now sees the empty string.
