### Fixed

- An RPC prompt whose Node `input` handler awaits a timer, I/O or another real wait no longer holds the next stdin line: `get_state` and every later command are answered while the handler waits, as in Pi, in an isolated and in a packed runtime alike. The runtime reported a wait only for commands and the settle tail, so the host held the line until the handler returned. The hold has been there since v0.5.1. <!-- fix: 939416539e --> <!-- tests: coding/cli/rpc_settle_wait_test.go::TestRPCCommandDuringInputHandlerNetworkWaitAnswersAcrossSDKs, coding/cli/rpc_settle_wait_test.go::TestRPCNodeInputHandlerWaitSemanticsComparedWithPi, coding/cli/rpc_settle_wait_test.go::TestRPCNodeInputEndDuringInputHandlerWaitComparedWithPi -->
- The same for a Node `before_agent_start` handler: a `get_state` sent while it awaits I/O is answered at once, before the run starts, as in Pi. It has been held since v0.5.1. <!-- fix: bd00797bde --> <!-- tests: coding/cli/rpc_settle_wait_test.go::TestRPCCommandDuringBeforeAgentStartHandlerNetworkWaitAnswersAcrossSDKs -->
- An RPC prompt that runs a Node extension command which only chains microtasks (never yielding to the event loop) no longer lets the next stdin line overtake the command's response: the runtime took any command whose Promise was unsettled one microtask after the call to be waiting, where Pi's loop reads no line during such a command. The report has existed since v0.3.0 and the hold it releases since v0.5.1. <!-- fix: 7506dc78b8 --> <!-- tests: coding/cli/rpc_settle_wait_test.go::TestRPCNodeHandlerThatOnlyRunsMicrotasksHoldsStdin -->
- An RPC prompt whose `before_agent_start` handler, written with the Go, Rust, Python or Lisp SDK, awaits I/O no longer holds the next stdin line for the whole wait, for ever when the handler never returns: the line is admitted once the handler outlives the 250 ms quantum that already bounds those runtimes' command, input and settle handlers. The hold has been there since v0.5.1. <!-- fix: c485b4e675 --> <!-- tests: coding/cli/rpc_settle_wait_test.go::TestRPCCommandDuringBeforeAgentStartHandlerNetworkWaitAnswersAcrossSDKs -->
