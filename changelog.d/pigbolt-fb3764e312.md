### Upgrading

- The experimental `pig-aot` Piglet is now `pig-bolt`, a name that says what it builds on (the Pi-Bolt compiler; it is not an official Pi-Bolt project). `piglets/aot` is now `piglets/pig-bolt`, its Go module is `github.com/MichaelKinsy/PiG/piglets/pig-bolt`, its extension is `boltruntime` and its command is `/bolt-runtime` (was `/aot-runtime`). The TypeScript runtime slot is still `aot`: `extensionsTypescriptRuntime: "aot"`, `PIG_TS_RUNTIME=aot`, the slot directory `aot` and the `PIG_AOT_*` variables work as before. `piglets/pig-bolt/pig-aot.yaml` is a one-file Piglet named `pig-aot` that extends `pig-bolt` (a compatibility alias for the old name): `pig --piglet piglets/pig-bolt/pig-aot.yaml` and `pig piglet build` of that path select and build what `pig-bolt` does under the old name. It does not make the bare name `pig --piglet pig-aot` resolve, the 0.7.0 path `piglets/aot` is gone, and `pig piglet pull` and `update` have nothing to alias because no pig-aot Piglet Binary release exists (remove the alias once no 0.5 or 0.7 setup names it).
- `pig-bolt` pins the Pi-Bolt 1.1.2 compiler (was 0.7.4; Pi-Bolt's `SHA256SUMS` still verifies with the Ed25519 key pinned in the Piglet). The first start after the update installs the new compiler, removes the 0.7.4 one and drops the images the old compiler built; their extension sets run on Bun once and are compiled again in the background.

### Added

- `pig-bolt` compiles extensions that find files next to their own module: a file that names its own location (`import.meta.url`, `import.meta.dirname`, `__dirname`, `__filename`, `require.resolve`, `import.meta.resolve`, a computed `require()` or `import()`) is compiled from a copy in which those expressions give the installed file's location, as Pi-Bolt's own `pi-bolt compile` does, so the extension reads its skills, locales and data from where it is installed. `@juicesharp/rpiv-todo` and `pi-mcp-adapter` compile in and register identically on Node, Bun and the compiled host. Only `import.meta` used as a value (`const m = import.meta`) in a file that also reads files or starts processes stays refused, and the set runs on Bun.

### Changed

- The default budget of `pig-bolt`'s compiled images is 2 GB (was 1 GB): one image is 240 to 270 MB, so 1 GB held three or four sets and each eviction cost a 20 to 30 s background rebuild. `/bolt-runtime budget` and `PIG_AOT_CACHE_MAX` still set it.
- On Linux a slot TypeScript runtime now runs the file PiG verified: the check keeps the executable open and starts it as `/proc/self/fd/N`, so replacing the path after the check changes nothing that runs (`ps` shows the descriptor number as the process name; `/proc/<pid>/exe` and the command line name the path). The start-check record is no longer read through a symlink or a FIFO, and a file written within two seconds of its hash starting is not recorded. Other platforms start the executable by path.
- A start that selects a slot TypeScript runtime no longer re-hashes an unchanged executable. A passing SHA-256 check is recorded next to the executable, keyed by device, inode, size, modification time and status-change time, and skipped while all of them and the manifest's digest are unchanged. The digest comparison, the Bun lock check and the `--version` probe still run at every start. For a 233 MiB compiled host the digest and probe step fell from about 290 to 370 ms to about 2 to 4 ms on a second start in a new process.

### Fixed

- Building the compiled host with Pi-Bolt 0.7.4 crashed the compiler ("Segmentation fault at address 0x30", on the CI image and on the host) in the ahead-of-time step whenever the build's function order held any record, so `pig-bolt` built no image. Pi-Bolt 1.1.2 builds the same input; the Piglet pins it. <!-- fix: 9b33064ca0, a921aa3352 -->
- A build's training run ended on a 200 ms timer: every extension of every build waited 200 ms, and a registration larger than one read was cut and its runtime's next write failed with a broken pipe. It now ends on the registration frame (339 and 398 ms before, 150 and 197 ms after). <!-- fix: 0684c43cd0, b8b9af5e63 -->
- The training run's socket was in the build's work directory, whose path under a deep agent directory can exceed what a Unix socket address holds (108 bytes); every training run of such a build failed to listen, was logged and skipped, and the build's function order lacked each extension's startup. The socket is in a short directory of its own. <!-- fix: 0a0d27d74a -->
- A set whose file locates itself by a value of `import.meta` (`const meta = import.meta; readFileSync(new URL("./x", meta.url))`) was not refused and compiled to a silently wrong result. It is refused, and the set runs on Bun. <!-- fix: 91e6a2498b -->
