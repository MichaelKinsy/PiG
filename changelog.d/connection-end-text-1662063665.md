### Fixed

- When a provider's server resets or closes the connection before it answers, the retry notice and the turn's error now name what happened the same way every time, as Pi does: `Connection error.: read ECONNRESET` for a reset and `Connection error.: other side closed (UND_ERR_SOCKET)` for a close. A reset that arrived while the request was still being sent was shown, depending on timing, as a bare `Connection error.`, as `other side closed (UND_ERR_SOCKET)`, as `write ECONNRESET` or as `write EPIPE`; with a large request that was nearly every time. The turn was retried in each case and still is. <!-- fix: 1662063665 --> <!-- cause: net/http returns the request body write's error and drops the read side's, and the error mapping named only the "write" and "read" operations, not the vectored "writev" of a request body -->
