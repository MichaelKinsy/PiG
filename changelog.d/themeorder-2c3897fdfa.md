### Fixed

- The Lisp and Python extension SDKs now give each `onThemeChange` handler the theme of its own change, as the Go and Rust SDKs do. They delivered one live theme object to handlers that run on a worker thread, so a handler that ran after the host had switched themes again read the newer palette: two quick changes reached their subscribers as the newer theme twice, and the Lisp SDK test `theme-and-tools-expanded-changes-reach-their-subscribers-in-order` failed on a loaded machine in up to a quarter of its runs. Each delivery now carries a snapshot taken with its palette; `ctx.ui.theme` stays live. A new conformance row, `TestOnThemeChangeDeliversEachChangesOwnThemeAcrossSDKs`, holds the first delivery in a gate handler while the host switches themes and requires the handler behind it to log the theme of its own change in every SDK. <!-- fix: 2c3897fdfa, fecee913ad, b3c3d66b4b -->
