### Fixed

- Follows Pi beffcde92dea (#12230, #10470): in RPC mode `new_session`, `switch_session`, `fork` and `clone` run an extension's `session_start` (and `resources_discover`) handlers once for the new session, with the old session's `session_shutdown` before it, as Pi's RPC mode does since this commit; before they ran twice (the runtime's rebind callback, then the command handler's own rebind), so an extension that started a timer in `session_start` and cleared it in `session_shutdown` leaked one timer per replacement and `appendEntry` in `session_start` wrote its entry twice. The RPC mode also subscribes to the session's events before the extensions are bound, at startup and on replacement: the events a `session_start` handler emits (`entry_appended`, `session_info_changed`, a message it sends) now reach the client, in the order they happen and ahead of the command's response; before the client received none of them at startup and a replacement's first bind wrote nothing. The same for every extension SDK (Node, Go, Python, Rust and Lisp, isolated, packed and fused). Pi's CHANGELOG line: "Fixed RPC `new_session`, `switch_session`, `fork` and `clone` running extension `session_start` and `resources_discover` handlers twice for the new session. RPC clients now also receive events emitted by `session_start` handlers, such as `entry_appended` for entries they append (#10470)". The bug has been in PiG since v0.3.0.
