### Fixed

- OpenAI Chat Completions request bodies now have the member order of the bodies Pi sends. A replayed assistant message that carries reasoning was written `role, content, tool_calls, reasoning_content` (Pi: `role, content, reasoning_content, tool_calls`; the same for `reasoning` and `reasoning_text`), and the z.ai `thinking` member was `clear_thinking, type` (Pi: `type, clear_thinking`). The content was the same. This held for every provider that uses the Chat Completions API. A request built from a transcript that converts to no message now sends `"messages":[]`, as Pi does, where PiG sent `"messages":null`; a first prompt and a compaction's own request cannot produce one; an extension whose `context` handler returns an empty message list can. Not yet in Pi's order: objects a model's catalog entry or a caller supplies (`chat_template_kwargs`, `chat_template_args`, the OpenRouter `provider` routing object, sampling parameters), which PiG writes with sorted keys. <!-- fix: ce136a8bd5 -->
