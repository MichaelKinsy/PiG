### Fixed

- A Codex turn that hits the backend's 60 minute WebSocket limit (`websocket_connection_limit_reached`, "Responses websocket connection limit reached") after output has started, for example during long thinking, is now retried by the agent's auto-retry on a fresh connection instead of failing the turn: you see the retry notice, the interrupted response is redone from the start with the full context, its partial output stays in the session file and on screen but is left out of the retry's context, and no tool runs twice. The retry classifier is shared, so durable and compaction recover the same way. New requests also stop reusing a cached WebSocket after 45 minutes instead of 55, so a long response is less likely to reach the limit; this costs one full-context request per rotation, at most once per 45 minutes (since v0.2.0 the limit was not retried mid-stream). An error after the first WebSocket event, a leading `codex.rate_limits` included, now ends the message in an error that the agent retries, as in Pi; before, PiG reconnected or fell back to SSE inside the provider (since v0.3.0), which a user saw as a silent second request and no retry notice.
