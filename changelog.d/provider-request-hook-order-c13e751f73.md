### Fixed

- A `before_provider_request` handler of a subprocess extension (Node, Python, Go, Rust, Lisp) now receives the request a Google, Vertex or pi-messages provider is about to send with its members in the order Pi's provider creates them (the model, contents and config of Google's parameters, the part members thought, text, thoughtSignature, functionCall before thoughtSignature), where it received them sorted by name. A handler that returns the payload unchanged now sends the same bytes as no handler. The Google and Vertex payload has been a map since v0.3.0 and the pi-messages payload since v0.2.0; before them Google's was a struct.
