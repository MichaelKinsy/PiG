### Fixed

- A `/login`, slash command or prompt typed while PiG is still starting no longer runs before the start-up notices: PiG reads no key typed ahead while it binds the session, as Pi reads none there, unless a `session_start` or `resources_discover` handler is running, and it then serves the terminal while that handler runs, as Pi does. PiG ran the whole bind through a loop that read typed input ahead of the bind's last owner step, so the command could run before the start-up warnings (such as `Warning: No models available. Use /login ...`), the loaded resources list and a resumed session's history were shown, and those appeared below its output, for example the warning below `Error: Failed to login to <provider>`.
