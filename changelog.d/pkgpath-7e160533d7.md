### Fixed

- `pig install /abs/path` (and `~/path` or a `file://` URL) records the path as you typed it in `packages[]`. It was stored relative to the agent directory as spelled at install, so a later start through another spelling of `PIG_HOME` (a symlinked `~/.local/share/...` directory, a synced config) resolved it to nothing and the Package's tools disappeared with only a stderr line. A relative path is still stored relative to the settings directory. Running `pig install <absolute path>` again rewrites an existing entry for the same Package (D215, #389). <!-- fix: 7e160533d7 -->
- A configured local Package whose directory does not exist is now a startup warning in the session, and an extension warning for programs that embed PiG, with the path it resolved to and the `pig remove` command that drops it, instead of a `[pig] Could not install ... (run pig update when online)` line on stderr (D215, #389). <!-- fix: 7e160533d7 -->
