### Changed

- Durable scheduler decisions are decision regions: they read the scheduler's memory while recording the keys they read, and a decision that read what an earlier, still unpublished commit wrote waits for that commit's publication and runs again, so several commits overlap in storage while decisions stay serialized. Each commit writes the ownership memberships its task changes alter (`TaskScheduler.MembershipKeys`), chain loads stay pinned until their job's commit is published, and a tool slot's running status and arguments and a generation's attempt are stored like progress (a run with one tool call stores 12 commits instead of 14). Idle checks after a task change cover only the conversations above it, kept context ranges are advanced by the entries of published commits (no Storage read for the bounds), and idle ranges expire in the order they went idle (Pi `e5c6182b`, `35dfa757`).
