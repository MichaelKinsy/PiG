### Changed

- The reference web client of plugin views (`examples/ui-view-web`) draws a view as controls instead of text. A node is the control its kind and the role and states of its `a11y` record make it: a `mouse-region` is a button, or a native checkbox, switch or radio with its checked state; a `text` with the role `heading` is a heading; a `select-list` is a listbox of rows, or a row of tabs; a `lines` node with `progress` is a progress bar and with `list` a list in columns; a `grid` is a grid; a `loader` is a status with a spinner; a mount of the `dialog` slot is a modal dialog. An intent of the mount is a button that reads the intent's verb in words. What the page sends for a click or a key is unchanged, byte for byte.
- The reference web client draws a mount's `drawing`: it states both profiles (4096 shapes, 1048576 pixels) and `snapshotBytes` 4194304, draws a scene as one SVG element with every shape kind and theme-token colours, and makes each region a focusable element that raises its intent for a click, a key, a press, a release and a drag. A shape with a `key` keeps its element across updates, so a scene that is sent again moves in place. Before, a mount with a drawing reached the page as its fallback.
- The reference web client labels a mount with its `title`, fires key bindings while the focus is inside the mount and shows the named ones as buttons with their key, moves the focus for `request: update`, and takes no focus from a text field that holds text: it reports `unfocused` instead, and a dialog then opens without being modal until the user enters it. It states the claim `input.bindings = [key]` and the node kinds `loader` and `grid`.
- The reference web client updates in place: every element whose node is still in the view is kept, so a state changes by its transition and the focus, the selection and typed text stay.
- The reference web client's look is a default stylesheet of custom properties (`--view-*`: type scale, spacing, radii, colours for light and dark, motion that stops under `prefers-reduced-motion`), which a `--theme` directory overrides. A cell of a view is 8 by 16 px (`--view-col`, `--view-row`), no longer `1ch` by one line. While the chat holds no line the panels and the prompt are one centred column, and with `--connect` the panels take the page. The line of the carrier's numbers under the prompt is shown only when the address has `?debug`.
- `docs/ui-view-carrier.md` proposes how a client fills the argument of a gesture on a drawing's region: `x`, `y`, `dx`, `dy`, `gesture` and `region`, each only when the intent's declared shape names it.
