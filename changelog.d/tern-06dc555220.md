### Fixed

- A Python extension's `ctx.session_name` and a Rust extension's `ctx.session_name()` returned an empty string for the life of the process, because nothing ever read the name from the state the host sends. Every SDK now keeps the session name current from each state update, and a Go extension has the same accessor, `Context.SessionName`. <!-- fix: 06dc555220 -->
- `ctx.model` is the model's id in every SDK, as in Pi (`ctx.model.id`). A Python extension's `ctx.model` and a Rust extension's `ctx.model()` returned the model's display name (`Claude Sonnet 4.5`), so a comparison with `claude-sonnet-4-5` or a `provider/model` string built from it failed there and passed in Go. Python and Rust also have `model_provider` and `model_qualified`, as Go has `ModelProvider` and `ModelQualified`. <!-- fix: 06dc555220 -->
- A read of the session name, the session log or the model right after `setLabel`, `setSessionName`, `sendMessage` or `setModel` could return the old value in a Go, Python or Rust extension. The host now sends its state before the result of those calls, and the Go SDK waits for it, so the next read sees the write as it does in Pi. <!-- fix: 06dc555220 -->

### Upgrading

- A Rust extension that calls `ctx.session_name()` receives a `String` instead of a `&str`, and the `session_name` and `model` members of the wire `ReadyMsg` no longer exist (the session name and the model travel in the ready state). A Python or Rust extension that compared `ctx.model` with a model's display name must compare it with the model's id. <!-- fix: 06dc555220 -->
