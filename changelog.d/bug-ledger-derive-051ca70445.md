### Fixed

- The bug fix ledger no longer puts a fix in the wrong impact class because a word of its release note contains a keyword of that class: a note that says an image is redrawn "when it closes" was classed with fixes of user data, and a note about a `border` with fixes of ordering. Each keyword of the impact and platform classes counts only as a whole word, and `make bug-ledger` reads the class of every committed entry again, so no class outlasts the rule that chose it. <!-- fix: 051ca70445 --> <!-- cause: The impact and platform rules were unanchored patterns that matched inside longer words, and regeneration kept the class of a committed entry as it was. --> <!-- tests: TestImpactAndPlatformKeywordsMatchWholeWordsOnly, TestAKeptEntryTakesItsImpactFromTheRulesAsTheyAre -->
- The bug fix ledger no longer gives a wrong root cause for a fix, the paragraph of its commit message that reports how the fix was tested, and no longer lists as a test of the fix a test that the message only mentions. The cause is what the changelog bullet or the fix commit states outright, or else a paragraph of the message that says why; the tests are the ones the bullet or the commit names as regression tests, or else the ones the fix commit adds or edits. <!-- fix: 051ca70445 --> <!-- cause: Any paragraph of a commit message that held a cause word such as "did not" was taken for the cause, and every test name in the message was taken for a test of the fix. --> <!-- tests: TestTheCauseIsNeverAParagraphAboutHowTheFixWasChecked, TestTheSubagentsRaceFixListsTheTestItAddsAndNoSighting, TestOnlyANamedRegressionTestIsListed, TestABulletStatesItsCauseAndItsTests, TestTheCheckAsksForTheCauseOfANewFix -->
- `make bug-ledger` writes the same ledger in every clone of a commit, and an entry no longer keeps the hash of a commit that a rebase or a re-pick replaced: the fix marker of its changelog bullet decides, and `make bug-ledger-check` names the entry and the fragment while one of them names a commit `HEAD` does not reach. Before, a clone that still held the replaced commit resolved a marker that a fresh clone refused, and a scratch copy of a test file in an ignored directory could remove a test from an entry. <!-- fix: 051ca70445 --> <!-- cause: A committed entry that named a commit missing from the history was kept over a fix marker that names a commit of the history, commit names were resolved against every object of the clone, and the test index walked the directory instead of the files git knows. --> <!-- tests: TestARebasedFixIsRecordedUnderTheCommitThatReplacedIt, TestTheLedgerOfASquashedFixIsTheSameInEveryClone, TestAFixTitledSquashJoinsTheEntryItLandedWhenTheMarkerNamesAnotherCommit, TestAnIgnoredCopyOfATestFileDoesNotChangeTheLedger -->

### Changed

- A `### Fixed` bullet can state the root cause and the regression tests of its fix after the fix marker, as `<!-- cause: <why the bug happened> -->` and `<!-- tests: <test>[, <test>...] -->`; a fix commit can state them with a `Root-Cause:` trailer and `Regression-Test:` trailers (`.github/CONTRIBUTING.md`). `make bug-ledger-check` now also fails for a fix committed on or after 2026-11-14 for which no root cause can be derived, for an entry whose impact or platform class its text no longer reads as, and for an entry that names a commit `HEAD` does not reach while its fix marker names the commit that replaced it; `make bug-ledger` settles the last two.
