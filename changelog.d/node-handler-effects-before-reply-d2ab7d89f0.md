### Fixed

- A Node extension handler's host effects are written before the RPC reply or interactive prompt drain that waited for the handler's first suspension, as Pi writes them. A `session_info_changed` or `thinking_level_select` handler that calls `ctx.ui.notify`, `ctx.ui.setStatus`, `ctx.ui.setWidget`, `ctx.ui.setTitle`, `ctx.ui.setEditorText`, `pi.appendEntry` or `pi.sendUserMessage` synchronously now has that effect written before the reply of `set_session_name` or `set_thinking_level` (RPC mode) and before the prompt drain releases its dialog answer. PiG wrote the reply first, so a client saw the reply and then the notification, status or widget that Pi writes before it (isolated and packed Node extensions, since 0.2.0, the first release with the call lanes that queue those calls). A notification that followed a refused call, such as a failed `pi.appendEntry`, could also be applied after the caller went on outside RPC mode. The host releases the caller only after every call the same extension sent before its report has been applied: the wait is per extension connection, has no timer, and ends with the request, so a handler that ends or goes on, a cancelled caller or a closing session releases it, and a dialog, a model request or a child process the handler starts never holds it.
