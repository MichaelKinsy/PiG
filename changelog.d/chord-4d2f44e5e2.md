### Fixed

- A Chord object whose factory reads a key of another object (`at(key)`) could fail to go live with `not_ready` ("app.exposer: not live yet") when that object failed and went live again, in memory, while the key's first pin still loaded from the store: the key was handed back before its pin on the new instance had landed, and the factory's derive read it with no value. In Pi the event loop lands a pin that reads no store before the old pin's load settles; here the key is now handed back after the new pin has settled when a pin of the key needs no read of the store. A new pin that must read the store is not waited for, as in Pi, where it lands after the first one settled and the consumer's get is rejected with `not_ready` and `activation_failed`.
