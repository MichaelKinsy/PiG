### Fixed

- A handler of `message_start`, `message_update`, `turn_start`, `agent_start` or `agent_end` that assigns, reassigns or deletes a member of the event itself (for example `event.note = 1`, `event.type = "x"` or `delete event.turnIndex`) now changes the event that the later handlers of that dispatch receive, of the same extension and of other extensions, as it does in Pi, where every handler is handed the one event object. The change lives for that one dispatch only: the next event of the same type starts clean, and the session, its entries and the provider request keep what they had. Until now the member stayed in the handler's own copy of the event and was lost, for every out-of-process handler of these events. Each SDK sends back the members the handler changed, and the host refuses a malformed entry before it applies any. The Rust SDK finds the members a handler adds, deletes or changes as a scalar; it cannot tell replacing an object member such as `event.message` from editing inside it, so a Rust handler that replaces one is carried like an edit inside it for the events that already carried those. The loss was present in every release since v0.3.0. <!-- fix: 3e50072e2e, 8c8b498329, 059aac35c1, c745f9200d, 9871d212a3, 17f9d1389d -->
