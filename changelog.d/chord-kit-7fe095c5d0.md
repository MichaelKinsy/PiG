### Changed

- **Breaking (Go API)** `chord/nextnode/app`, `chord/nextnode/surfaces`, `chord/nextnode/workers`, `chord/nextnode/plugins` (Pi `284e63d9`): the server starts off the build path. `StartServer` returns once the server listens; the web and terminal base bundles and each worker kind's base are built right after, from the files as they are then, and the server's own code (its executable) is recorded after them. `App.BasesBuilt()` and `App.BaseWatched()` are channels that close when the bases are built and when the base code is recorded and compared once. `NewWebSurface` and `NewTuiSurface` no longer build: they return a surface with `Build()` and `Built()` (a page, a surface file or a launcher's start waits for the build and answers 503 when it failed; the rollout step waits for it and fails when it did, ending its wait at its context's abort while the build goes on), `WebSurface.Base` and `Inputs` are gone, and `App.Web.Base` and `App.Tui.Base` are now methods, empty until built. `Plugins.WatchBase` returns a channel closing once the record's first comparisons ended. A worker kind's entry that cannot be started no longer fails `CreateWorkers`: `Workers.Build()` copies the entry into a private directory (`WorkersOptions.BaseDir`, the kit's `cache/workers/<kind>/`, emptied first; removed at `Close` once every worker exited) and records its bytes, every worker forks that copy, an edit of the entry marks `base`, and an entry that cannot be started or copied fails the build and every start (`worker failed to start`). The data directory gains `cache/` and `cache/workers/` (`AppLayout.Cache`, `AppLayout.WorkerBases`, mode 0700).
- A base that does not build after the listen is reported as `AppErrorBaseBuild` (`AppError.Base` names `web`, `tui` or the worker kind) and the server runs on. What the app reports after its close is dropped.
- The server's executable changed since the process started (its modification or status-change time after the start, not later than five seconds from now) marks `base` until a restart, as the bytes read may not be the ones running; one stamped in the future is compared by its content alone.
- A link's upgrade waits for the bases to be built (D604): a page reconnecting to a restarted server no longer holds the scripts object's empty set and reloads.
