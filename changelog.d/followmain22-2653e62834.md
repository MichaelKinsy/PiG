### Fixed

- Pressing Esc during a batch of tool calls left the calls that had not started yet without a result in the session: the transcript held an assistant message with tool calls that no tool result answered. Each of those calls now gets its start and end events and an "Operation aborted" error result, and extension `tool_call` handlers are not asked about a call that will not run. A call whose `tool_call` handler in an extension process was still deciding when the run was aborted now reads "Operation aborted" too, where it read "event tool_call: context canceled". `ctx.executeTool` answers an aborted run the same way, before it looks the tool up. A session that an older build left with unanswered calls still opens and continues as before.
