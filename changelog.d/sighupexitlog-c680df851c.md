### Fixed

- A hung-up terminal now leaves exactly one `exit.log` line, and its exit status stays 129. The kernel's SIGHUP, the input reader's EOF and a failed terminal write each recorded an ending of their own and raced `os.Exit`, so a hangup wrote three lines or two lines without the signal's, never the one line D102 promises. The first path now owns the record and names the first cause observed (`received SIGHUP` when pig leads its session, `terminal gone` when it runs under a shell); the line is flushed before the process exits; a second dead-terminal exit blocks behind the first, as Pi's `emergencyTerminalExit` never returns; and no other exit overtakes a running one. Run's error return and an extension's `ctx.shutdown()` claim the same line (D102). <!-- fix: 3d3f4215ac, c680df851c -->
