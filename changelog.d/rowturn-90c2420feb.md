### Changed

- Go hooks of the agent loop receive the run's own messages instead of a copy of the whole history made for every call. `PrepareRequest`, `FinishTurn`, `PrepareNextTurn`, and the before and after hooks of a tool call that runs alone or in a sequential batch get the run's array cut at its length: a hook that replaces a message in place now changes the request that follows and the rest of the run, as writing to `context.messages` does in Pi (with the copy that write was lost); a hook that appends still does not reach the run. The hooks of two or more tool calls executed in parallel can run at the same time, so each of those calls gets its own copy of the messages (before, the calls of one batch shared one copy): what such a hook writes stays its own. pig's own session hooks do not read these messages and extensions receive serialized copies, so nothing changes for the CLI or for extension SDKs.
