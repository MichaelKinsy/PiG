### Changed

- Durable storage on SQLite allocates less per commit. An entry record is written as JSON.stringify text in one pass (`EntryRecord.AppendStringify`: the members of `MarshalJSON` appended in place, byte for byte its text, with `MarshalJSON` kept for every value the writer does not know), into a pooled buffer that every stored value of a commit shares, and the JSON array parameters of a commit's key reads and deletions are appended to one buffer instead of a string per key. On the storage benchmark's SQLite commits, against the same branch without this change (n=10, same host, pinned): a 100-entry commit 19% faster warm (1.40 to 1.14 ms) and 26% faster fresh, with 33% fewer allocations (2,744 to 1,838) and 32% less memory (264 to 180 KiB) per commit; one entry 8% faster warm, a mixed entry/task/submission/document commit 6%. Reads, which this does not touch, are unchanged, and so are the ten-turn session replays of the durable-bench workload (250 and 1,000 turns, one core and sixteen: within noise).
