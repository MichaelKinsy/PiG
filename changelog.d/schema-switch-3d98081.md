### Changed

- Tool arguments are validated as JSON Schema by pi-schema, as Pi does: every tool schema, whether built in, from an extension or from an MCP server, gets the same coercion (`"42"` for a number, `null` for a required string is `"null"`, `"3.5"` for an integer is 3, one value for an array is wrapped) and the same error text (`- limit: expected number, got string`, `- path: missing`, then the arguments received). Features of TypeBox outside JSON Schema no longer apply: `Type.Refine()` refinements are not run, a `BigInt` or `Undefined` schema rejects every JSON argument, a property name is a name rather than a regular expression, and `additionalProperties` converts only undeclared properties. A `$ref` that names nothing (a dangling definition in an MCP server's schema) rejects only the arguments at its place instead of failing every call of the tool.
