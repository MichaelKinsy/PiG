### Security

- In PiG 0.4.0 through 0.5.3, a Piglet's `tools` lists (the root list and the `tools` of an extension entry) removed tools from the model's active set only. A tool that a `codemode` script can call (a tool exposed as `codemode` or `deferred`) stayed callable from `codemode` scripts, and `tool_search` could still find and load it, although the Piglet did not list it. `codemode` and `tool_search` first shipped in 0.4.0, and a Piglet limited tools by name from 0.2.0, so no earlier release is affected. PiG 0.6.0 enforces the scope in the Session tool registry: a tool outside the scope is not registered, so it is not listed, active, callable from `codemode` or findable by `tool_search`, and no later `setActiveTools` call, registration or reload brings it back. A Piglet Binary or a Piglet run with `pig --piglet` gets the fix when you upgrade PiG and rebuild the Binary.
