### Added

- The Durable core defers storing throttled progress as Pi 1.4.0 (6c2fd73b) does. A commit marked `{persistence: {kind: "deferred", withinMs?}}` (`Session.commit`, `Conversation.commit`, `TaskRuntime.commit`, a tool's `api.commit`) that only changes existing latest, initial-fork conversation documents is adopted in memory and shown to watches and views at once, and stored with the next commit that reads or writes the document, before the document leaves memory, at close, or after `withinMs` (default `settings.progress.persistWithinMs`, 1000 ms, the new `persistWithin()` export of `session/session.ts`). Generation partials and running tool output are deferred this way: a streamed answer costs one storage transaction per window, not per partial, and a crash loses up to about one window of it (a stream that crashed before its first store leaves no aborted entry). `Session` options `setTimer` and `persistWithinMs` and `documentCacheSizes.held` follow Pi.
