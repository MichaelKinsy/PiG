### Fixed

- A `message_start`, `turn_end` or `agent_end` handler that edits the event's message in place and returns nothing now changes the message the next handlers, the saved session entry and the next provider request hold, as it does in Pi, in every extension SDK: the `message` of a `turn_end` event and a member of its `toolResults`, a message of an `agent_end` event's `messages`, and a user or system message at `message_start`. An edit of the assistant message at `message_start` reaches the later handlers of that event only, as in Pi, where the event holds a copy of the partial. Until now the edit stayed in the handler's own copy of the event and was lost, for every out-of-process handler of these events, in every extension SDK. Each SDK sends back the messages as the handler left them when they differ from the ones it received, and the host refuses a malformed edit before it applies any. The loss was present in every release since v0.3.0. <!-- fix: 18e1649ef2, 6f3ca3d155, 10c7dc1da2, 75f10dda50 -->
