### Added

- Piglet Binaries: `build.fusedReload: source` lets you develop a fused Go member against its Binary. The build records a digest of each fused member's source; when you start the Binary with that source under the member's name (`-e ./member`) and the source has changed, the start and `/reload` run the member as an ordinary subprocess extension built from the source, so an edit is picked up as it is for any source extension. The fused copy is stopped, the member keeps its name and its place in handler order, and it stays a subprocess until `pig piglet build` fuses the edited source. The first start or reload after an edit pays the member's Go build (about a third of a second for a small extension); later ones use the build cache. Without a Go toolchain the fused copy runs and one warning says so. Without the key a Binary behaves as before: it runs the compiled copy and ignores the edit. See "Editing a fused member's source" in the Piglet Binaries guide.
