### Added

- `durable.SubmissionDraft.OnAbort`, as Pi's `onAbort` (Pi e67aa1a4e): an input submitted with `durable.OnAbortKeep` stays queued through `Conversation.Abort` and abort cascades, as a failed run keeps its queue under `AfterFailedRun` keep: the next input places it and that run answers it. For input its sender cannot take back, such as another agent's message; `Submission.Abort` still withdraws it. The default, `durable.OnAbortWithdraw`, settles the input unanswered with reason `aborted` as before. The inbox item records the flag as `onAbort: "keep"` after its entry, and only for `keep`; an item stored without the field withdraws. The durable core takes the same field in the `submit` event and the transaction op, and the Cloudflare host passes the draft's field through. `harness.WithdrawQueuedInputs` is now `harness.WithdrawAbortedInputs`, and `inbox.WithdrawQueued` of the core is `inbox.WithdrawAborted`; `WithdrawQueuedInputsFor` still withdraws every input.
