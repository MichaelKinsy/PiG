### Changed

- CI: a pre-flight runs first and the full CI waits for it. `.github/workflows/preflight.yml` (Patrick Kappen's engine in `automation/ci/preflight`: commits, DCO and signing, comments, secret scans, lint-class content rules) judges a pull request when it opens or changes and every hour for every open one, records the `preflight` commit status, and `ci.yml`'s new `Pre-flight verdict` job waits for that status before `Bookkeeping` and everything after it; `CI result` fails when the pre-flight rejected the head or never judged it.
- CI: the light pull-request run is one runner. Windows native-1, macOS native and the Node loader move to the queue tier, so a light run (`PIG_PR_CI_LIGHT` `queue` or `label`) runs Linux only. A pull request that changes a path of `automation/ci/os-specific-paths.txt` (`*_windows.go`, `*_darwin.go`, the native platform packages, installers, the Windows and macOS CI definition) runs the full set on every runner, as the `ci:full` label does. The full run also runs nightly on main (it was weekly) and on a push to a `release/**` branch.
- CI: only the nightly run on main (and a dispatch) saves caches. Every `actions/cache` step of `ci.yml` is a restore plus a save under `CACHE_SAVE`, macOS included, `cache-warm.yml` runs only when a lockfile changes, and `cache-prune` keeps the newest PORT_MAP ledger of each shard instead of one for all eight.
- CI: a red nightly starts `nightly-bisect.yml`, which runs CI on the commits between the last green nightly and the red one (a temporary `bisect/*` branch each), names the first bad commit and opens an issue asking for a fix PR; it merges nothing.
