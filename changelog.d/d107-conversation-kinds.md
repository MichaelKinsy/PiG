- Extensions can draw a conversation as the main transcript does, with Pi's conversation components in the component kit: user and assistant messages (with thinking), tool calls, `!` commands and diffs (`docs/plan/extension-component-kit.md` §2.1). PiG draws them with the same code as its own transcript, a node with an id keeps its state (a clicked thinking block, a tool card's elapsed time) across updates, and a frontend such as Tern receives them as its transcript's message, thinking and tool card nodes. Go extensions build them with `kit.NewUserMessage`, `kit.NewAssistantMessage`, `kit.NewToolExecution`, `kit.NewBashExecution` and `kit.NewDiff`; Rust extensions with `kit::UserMessage`, `kit::AssistantMessage`, `kit::ToolExecution`, `kit::BashExecution` and `kit::Diff`; Python extensions with `kit.UserMessage`, `kit.AssistantMessage`, `kit.ToolExecution`, `kit.BashExecution` and `kit.Diff`. Node extensions keep using Pi's own `UserMessageComponent`, `AssistantMessageComponent`, `ToolExecutionComponent`, `BashExecutionComponent` and `renderDiff`, which a frontend now also receives as these nodes.
