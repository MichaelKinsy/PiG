### Changed

- durable: the Cloudflare host (`durable/core/host/cf`), `durable/interop` and the Kubernetes benchmark image's pi-durable project install Pi's durable and chord packages (`pi-durable`, `chord`, `pi-ai`, `pi-codemode`, `pi-schema`, `pi-telemetry`) from `third_party/pi-packs`, the `npm pack` outputs of the pinned Pi source build, through `file:` dependencies whose locks carry each pack's sha512; before, their `package.json` named the npm 1.5.2 release, which lacks suspendable work and chord events, and only the tests swapped the pinned build in. `make pin-bump` regenerates the packs (`make vendor-pi-packs`), and `make pin-check` fails when a pack differs from its manifest, a lock resolves a Pi package from the registry, or a `package.json` names a Pi package by version. `make link-durable-host` and the frozen durable closures are gone.
- sdk-ts: `make test-sdk-ts` fails, naming each declaration, when the exported declarations of the pinned Pi source build differ from the published release the peer dependency names (`extensions/sdk-ts/testdata`, a checksum-verified snapshot; `make vendor-sdk-ts-declarations` writes it).
