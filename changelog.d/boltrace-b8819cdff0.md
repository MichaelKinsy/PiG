### Changed

- A long interactive session uses less CPU per prompt: each request finds the large tool results it re-sends by their address even when the conversation holds several equal copies (the same file read again), instead of hashing and comparing them on every turn. In the Pi-Bolt long-session benchmark, CPU per prompt at 40 prompts falls from about 81 to 72 ms on one pinned core. Over a plain `http://` connection (a local model server) the request body also goes out in vectored writes instead of 32 KiB copies, which brings it to about 63 ms; `https://` connections send it as before. The requests sent are byte for byte the same.
