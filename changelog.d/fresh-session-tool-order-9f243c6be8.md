### Fixed

- Sessions built with both caller-supplied custom tools (`SessionOptions.Tools`, `SessionOptions.CustomTools`, or `SessionStartOptions.ExtraTools`) and extension-registered tools saw a tool-prefix mismatch between a fresh session (`[built-ins, caller custom tools, extension tools]`) and its clone or post-reload session (`[built-ins, extension tools, caller custom tools]`), causing a provider prompt-cache miss; fresh sessions now declare tools in Pi's order (`[built-ins, extension tools, caller custom tools]`) and `Session.Clone` seeds the clone with the source session's active tool order. Existing persisted sessions keep their transcript's recorded tool order and byte-identical tool prefix on resume with no tool-state churn record.
