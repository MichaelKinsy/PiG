### Fixed

- Follows Pi c47ad0432bb8 (#12115, related to #11264): problems found when the session is replaced with `/new`, `/resume`, `/fork`, an import or RPC `new_session`, `switch_session` and `fork` (and an extension's `ctx.newSession()`, `switchSession()` and `fork()`) were never shown: the runtime kept the diagnostics of the replacement and only the startup read them, so a project extension that fails to load after `/resume` into another project, invalid settings of that project, or an `enabledModels` pattern that matches nothing after a settings change gave no chat line, no stderr line and no event. Interactive mode now shows them in the chat, print, JSON and RPC modes write them to stderr (RPC never writes them to stdout), and a problem already reported is not repeated.
