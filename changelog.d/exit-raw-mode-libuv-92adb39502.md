### Fixed

- PiG's raw mode is the one Pi's terminal is in now (libuv's `UV_TTY_MODE_RAW`, which Node's `setRawMode(true)` uses), not the `cfmakeraw` mode of `golang.org/x/term`. While the TUI runs, the kernel turns a line feed into carriage return plus line feed again, as under Pi: a bare `\n` written to the terminal by a child process that shares it (an extension's stray console output, a program the bash tool starts on the terminal, a Go runtime message) returns to column 0 instead of moving straight down and leaving the next text where the previous line ended (the staircase). The input flag `INPCK` is cleared now (PiG left it as the terminal had it), `IGNBRK`, `PARMRK`, `INLCR`, `IGNCR` and `ECHONL` stay as the terminal had them (PiG cleared them; a terminal configured with `INLCR` or `IGNCR` keeps what they do to Enter, as under Pi), and the mode is applied after the output already written has drained, as libuv does. On Windows the console input mode is exactly `ENABLE_WINDOW_INPUT` plus `ENABLE_VIRTUAL_TERMINAL_INPUT`, as under Pi: selecting text in the window no longer pauses PiG's output (the quick edit flag is cleared); this part was built and vetted for Windows but not run on a console. The terminal mode the shell gets back at exit is unchanged.
