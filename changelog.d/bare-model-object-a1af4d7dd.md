### Security

- A model id that no catalog, `models.json` definition or extension registration lists no longer becomes a model object with no API, endpoint or limits. Such an object was reachable through the library's `coding.BuildModel`, an extension's `set-model` by `provider/id`, and an extension's model stream and complete by `provider/id`. On v0.7.0 the object of an API-key provider was sent as OpenAI chat completions to `api.openai.com` with that provider's key, so the key went to a host the user never configured for it. On the release line a provider that fills in its own API (GitHub Copilot) still posted the object to its own host with the user's OAuth token. `BuildModel` now answers `Model not found: provider/id`, and nothing is sent. <!-- fix: a1af4d7dd --> <!-- cause: BuildModel treated a provider that exists as a model that exists and filled the gaps with an empty object, so an id the registry did not list reached the provider's stream function with the provider's credential -->

### Changed

- `coding.BuildModel("provider/id", services)` returns the error `Model not found: provider/id` for an id nothing lists, as Pi does, instead of a model for it; it returns the model the registry lists for an id it does list. A program that wants a custom id on a provider uses `coding.BuildFallbackModel`, the copy of one of the provider's models that `--model` makes.
- The named set-model of the Go, Python, Rust and Lisp extension SDKs (`SetModelNamed`, a `provider/id` string) is a lookup of a listed model: an id nothing lists is the error `Model not found: provider/id` and the session keeps its model. To set a custom model, pass a full model object, as with Pi's `pi.setModel(model)`.

### Fixed

- A resumed session takes the model its registry lists for the saved provider and id, with that listing's API, window and limits, instead of building it a second time from its name. <!-- fix: bc0594500 --> <!-- cause: restore followed the old BuildModel contract, which made a model from any provider and id, so it re-resolved what it had already resolved -->
- After `/new`, `/resume`, `/clone` or `/fork` in the interactive mode, the model selector, an extension's `setModel` and the post-login selection build the model from the new session's registry, not from the registry the program started with.
