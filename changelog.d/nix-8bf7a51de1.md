### Added

- A Nix flake builds PiG from source in the Nix sandbox with pinned inputs: `nix run github:MichaelKinsy/PiG`, `nix profile add github:MichaelKinsy/PiG`, or the flake's overlay. The package installs the extension SDKs and the TypeScript extension runtime read-only in the Nix store and builds and runs Go, Rust, Python and TypeScript extensions with its own toolchains from the store, so it stages nothing under `~/.pig` and a different `go`, `cargo`, `python3`, `node` or `uv` on `PATH` does not change what an extension builds or runs with (D201). The flake's checks load Go, Rust and Python extensions packed and isolated, a TypeScript extension packed and a Node standalone, in the sandbox and with conflicting tools on `PATH`.
- Packagers can install PiG's extension SDKs, TypeScript extension runtime and extension toolchains read-only beside the binary: `pig reload --install-sdks <dir>` writes the SDKs and runtime the binary embeds, and two link-time settings name that directory and a toolchain directory. Such a binary verifies the installed SDKs instead of staging them, reports a missing or mismatched one as an installation fault, and finds extension toolchains only in its toolchain directory; `pig diagnose` shows both (D201).
