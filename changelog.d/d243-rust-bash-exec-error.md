### Changed

- Rust SDK: the exec function of `BashOperations` (`BashExecFn`) now returns `Result<Option<i64>, BashExecError>`, not `Result<Option<i64>, String>`. `BashExecError` converts from `String` and `&str` (`Err("aborted".into())`, `Err(format!(...).into())`), prints as its message and has `message()`. The error `create_local_bash_operations()` returns for a command that timed out after its shell had exited keeps the shell's exit code and run time in a private field, so a bash tool built on it says `The shell exited with code C after S seconds, but background processes it started kept writing output until the timeout.` also when the operations run on another thread, which the previous release's check by the error string's address did not survive; an error built from its message gives the plain `Command timed out after N seconds`, as in Pi. Update an `exec` closure that returned a `String` error with `.into()`.
