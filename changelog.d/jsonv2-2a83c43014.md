### Fixed

- The ordered-object JSON readers keep two object names apart when `JSON.parse` does. `"\ud800"`, `"\ud801"` and the raw bytes `ED A0 80` are three keys in JavaScript; the readers read each as U+FFFD and merged them into one entry (last value wins). A name with a lone surrogate or ill-formed UTF-8 is now keyed on the string JavaScript has (`jsonopts.ReadName`): an escaped lone surrogate is its WTF-8 bytes, and ill-formed raw bytes become one U+FFFD per maximal subpart, as Node decodes them. `internal/orderedjson` writes a lone-surrogate key back as its escape. The readers that hand the key to `encoding/json` still hold it as U+FFFD. <!-- fix: 2a83c43014 -->
### Changed

- The login duplicate-field fuzz target no longer skips a document with a number outside float64 range: the reference reads numbers as raw tokens like the scan, and both accept `1e999` where `JSON.parse` gives `Infinity` (the typed decode of the definition still rejects it).
- The Go language floor of a generated extension module recognises a release candidate or beta by `go/version` instead of a letter set.
