### Changed

- Chord's plugins component is split in three packages, so a worker links no esbuild (Pi's `child.test.ts`, "loads no esbuild"; `go list -deps` of the workers package listed 26 esbuild packages before). `chord/nextnode/plugins/model` holds the data and discovery (`Plugin`, `DiscoverPlugins`, `BuiltFacet`, `BuildOptions`, `BaseInputs`, `ContentHash`, `HashFile`), `chord/nextnode/plugins/build` the esbuild builder (`BuildFacet`, `ScopeCSSModule`, `Recorder`), and `chord/nextnode/plugins` the runtime and the component. The component no longer builds by itself: pass `build.BuildFacet` as `PluginsOptions.Build` (and `TestPluginOptions.Build`); `CreatePlugins` panics without it. `build.BuildFacet` does not start the Node subprocess that reads the mapping of a CSS module: pass the evaluator in `BuildOptions.Mappings`, as the component does. Types that moved are named by their new package (`model.Plugin`, `model.PlatformNode`, `model.BaseInputs`, `build.NewRecorder`), with no aliases left in `plugins`.
