### Fixed

- A provider written with the Go, Python or Lisp extension SDK now reaches the host with each stream event showing the partial message as it was when the provider pushed the event, and with the stream's result as it was when the provider ended it. The SDK queued the event the provider pushed and a goroutine or thread encoded it later, so a provider that appended to its shared partial message right after a `Push` could have the host receive the later text (under load every `text_delta` showed the finished message), and in the Go SDK the encoder's read of the provider's map was a data race with the provider's writes. `Push` and `End` now take the event, and the result, at the call (the Go SDK encodes the event on the provider's goroutine; the Python and Lisp SDKs queue a copy), as Pi's consumer encodes an event before the provider's next `await`; the message the provider reads back from `result()` is still its own. A provider that pushed one event and changed the message in the same synchronous run in Node still shows the host the message as that run left it. The Rust SDK takes the event by value and is unchanged. <!-- fix: 924fe2818c -->
