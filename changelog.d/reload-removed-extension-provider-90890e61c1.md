### Fixed
- An extension that registered a provider and is then removed (its file deleted, or taken out of the extension settings) keeps answering after `/reload`, as it does in Pi: the provider stays listed in `/model`, stays selectable, and a prompt to it is answered by the old extension, even across a second `/reload`. PiG stopped the removed extension and dropped its provider, so the model vanished and a prompt failed with "No API key found". A removed extension that owns a provider (also a bridged OAuth login or a virtual model) keeps its process and its registrations but loses everything else (tools, commands, handlers, widgets, MCP servers, events); its process ends with the session or when another extension takes its last name over.
