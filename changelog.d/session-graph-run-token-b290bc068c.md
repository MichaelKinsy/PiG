### Fixed

- A session-graph client's extension (an `ExtensionRunner` an extension builds, in the Go, Python, Rust or Lisp SDK) no longer lets a handler that kept a run's `ctx.signal` see the next run's abort, and the handler still sees its own run's abort when the next run began before the host read it. The SDK's `getSignal` answer now carries a run token (`run`, new for each signal object the client returns) and `endedAborted` (the previous run's signal had aborted), and the host makes a context for each token; an abort of a client that returns a new signal object on every call costs at most four reads of its `getSignal`. A client built before this change, or one that sends no token, behaves as before (D235). <!-- fix: b290bc068c, e01a57f90c, ae821f41fc, b1ed275cb9 --> <!-- cause: the getSignal answer carried only none, live or aborted, so the host could tell a new run only from an abort it had already read, and no SDK said which signal object a run was -->
