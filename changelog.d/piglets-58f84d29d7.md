### Added

- A Piglet Binary accepts overlay Piglets like stock PiG, so a custom base such as `pig-tern` is a base harness that behaves like stock PiG started with a different Piglet, and no longer needs a fused Piglet for every combination. Its Binary takes `--piglet`, `PIG_PIGLET_PATH` and `PIG_PIGLET_NAME` as stock PiG does, with the same project trust, Piglet directories and Package install flow. The overlay merges onto the Binary's Piglet exactly as an `extends` child merges onto its base: `systemPrompt` replaces, `extends.remove` removes extensions, skills, Packages, strip entries and the frontend slot (the Binary then starts without its compiled-in frontend), and `extends.allowWiden: true` widens `tools`, `discovery`, `agentEnv` and an extension's `tools`. An `extends` block may omit `source` in an overlay; it then extends the Binary. Only what is compiled into the Binary is refused, with the field, the Binary and the reason named: setting a new `slots.frontend`, re-enabling a strip entry a build tag compiled out (`stripped(binary)`, such as `strip.extensions: [mcp]`; runtime strips of tools, commands, themes, skills and prompt templates can be re-enabled), and naming a fused or embedded extension again with origins. A Binary also accepts `--system-prompt` with stock precedence and discovers ambient extensions and skills from its effective Piglet's `discovery`, as stock PiG does. `/piglet` prints `Overlay of: <Binary>` on an overlay run.
- `build.closed: true` in the Piglet you build makes its Binary closed: it refuses `--piglet`, `PIG_PIGLET_PATH`, `PIG_PIGLET_NAME` and `--system-prompt` with a message that names `build.closed`, and it discovers no ambient extensions or skills. The default is `false`. Like all of `build`, it is not inherited through `extends`. The setting is part of the baked Piglet, so its digest covers it and `pig piglet verify --source` fails when a source flips it. `pig piglet show` in a Binary session says whether the Binary is open or closed. A closed Binary also refuses `-e`/`--extension`, `pig install`, `pig remove`, `pig update --extensions` (and `--all`, `--extension` and a package source), `pig mcp add`, `settings.extensions` entries and the servers of the user and project `mcp.json`, each with a message that names the flag, the Binary and `build.closed`; a closed Binary exits 1 for the flag and the commands, and reports a notice for the two configuration files and ignores them. Stock PiG and an open Binary accept all of them as before.

### Changed

- A Binary built with 0.6.0 accepts `--piglet`, `PIG_PIGLET_PATH`, `PIG_PIGLET_NAME`, `--system-prompt` and ambient discovery by default, where a 0.5.3 Binary refused them. Set `build.closed: true` in the Piglet you build to keep the 0.5.3 behavior; a closed Binary also refuses `-e`, the package commands, `pig mcp add`, `settings.extensions` and `mcp.json` servers.
