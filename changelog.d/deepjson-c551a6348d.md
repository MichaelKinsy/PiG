### Fixed

- Extension SDKs: tool arguments nested thousands of levels deep no longer fail or end the extension, in any SDK or on any supported Python (3.11 and later). The host sends arguments nested up to 10000 levels, and Pi's own runtime fails the call with `Maximum call stack size exceeded` only where V8 runs out of stack for `JSON.stringify` (about 4400 levels on Node 24; it moves with the Node version). The Python SDK failed the call from about 1000 levels (`maximum recursion depth exceeded`), and from about 990 on Python 3.11; the Lisp SDK ended its extension from 4000 levels; the Rust SDK ended its extension past 4096 levels and its `Context::tool_params` returned `None` from 128; the Go SDK ended its extension from about 9995 levels. Each now returns the object for every frame the host can send, a request nested past what an SDK reads fails with that error while the extension answers the next call, and a notification nested past it (a `model_stream_event` with deep tool arguments reads fine) is dropped with a line on stderr. The Lisp image is built with a 64 MB control stack per thread (address space, not resident).
