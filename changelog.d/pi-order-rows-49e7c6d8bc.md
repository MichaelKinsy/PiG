### Fixed

- agent (Go API): a message that a tool or an `AfterToolCall` hook of a parallel tool batch replaced in place in its context (`call.Context.Messages[i] = m`) never reached the run: with two or more calls each call wrote a copy, so the batch's other calls and the next model request did not see it. Pi hands every call of the batch one live context: the other calls read the new message and the next request carries it. Every call now receives the run's own messages, as the calls of a sequential batch do. The after hooks of a batch still run one at a time; the tools of a parallel batch run at the same time, so a tool that reads or writes a message another call's code may touch at that moment has to lock with it. No extension is affected: the hook context never reaches an extension. Of the releases, v0.7.0 has the lost write (its hooks receive a copy of the messages that the run never reads back; v0.2.0 and v0.3.0 hand hooks no context). The change also removes a data race of the per-call copy (the second call's copy was taken after the first call's goroutine had started), which was never released. <!-- fix: 49e7c6d8bc87e7251b89a5046b78b64bbea0a6f0 -->
