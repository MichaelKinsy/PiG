### Fixed

- OpenAI-compatible (chat completions) requests write the objects a model entry or the caller supplies with their members in the order the source lists them, as Pi does; PiG wrote each sorted by key. This holds for `chat_template_kwargs` / `chat_template_args` (compat `chatTemplateKwargs` / `chatTemplateArgs`), for `provider` and its nested objects such as `max_price` (compat `openRouterRouting`), and for the sampling parameters at the top level of the request (`samplingParams`, `samplingParamsByThinkingLevel` and a request's own). The content was the same. The order is kept from `models.json`, from a provider an extension registers and from a request an extension streams with; a provider entry's compat merged with a model's and with a model override's follows Pi's spread (the base's members in the base's order, an overridden member in its place, new members after them). The sampling parameters of OpenAI Responses and Azure OpenAI Responses requests follow the same order. Go callers: `ai.Model` and `ai.StreamOptions` gain `SamplingParamsOrder` (`ai.Model` also `SamplingParamsByThinkingLevelOrder`) beside the maps, and `ai.MergeOpenAICompat` merges two compats as Pi's `mergeCompat` does; a caller that sets only the map still sends its members sorted. <!-- fix: 3fe81801cc -->
