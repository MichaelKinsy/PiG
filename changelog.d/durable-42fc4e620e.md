### Upgrading

- Go API `durable/harness`: `ConversationView.Entries` is a window over the transcript instead of the active transcript: the fork-aware history `Conversation.Entries` scans, in entry ID order, with head markers (compaction summaries, resets, handoffs) appended in place instead of cutting the entries before them. A watch starts with the newest 50 entries; new entries are appends, and past 100 the oldest leave in one splice down to 50, which also sets the new `ConversationView.Before`, the ID of the entry just before the window (nil when the window starts the transcript). Read the active transcript the model sees from `Conversation.Context`; render a transcript with `ConversationTranscript`. Ports Pi's windowed conversation view.
- Go API `durable/harness`: `Conversation.Watch(ctx, window)` and `Harness.ObserveConversation(ctx, id, observer, window)` take a `*ConversationWindow` (`From`, `Min` default 50, `Max` default `2 * Min`); nil takes the defaults. Each watch and observer has its own window. Before: `conversation.Watch(ctx)`. After: `conversation.Watch(ctx, nil)`. Bounds that are below 1 or put `Max` below `Min` fail the call.
- Go API `durable/harness`: `WatchEvents`, `AgentEventStream` and the agent event types (`AgentEvent`, `SnapshotEvent`, `MessageChange`, `ToolEventCall` and the rest) are removed, as in Pi. Render state instead: a `ConversationTranscript` over `Conversation.Watch` gives the entries, and `pi.live` the run, the streamed answer, the tool slots, the compactions and why a run failed; a nested call's result is in its caller's `NestedCallDoc`.
- `pi.live` is no longer empty after a run that ended without an answer: it keeps `runFailure` until a later run starts. Code that compares an idle `pi.live` with `{}` checks `Run == nil` instead.
- The Durable core's watch of a conversation view takes the window (`window: {from?, min?, max?}` in the `watch.open` target) and no longer serves `changes`, `completing` or `view.attach`; the Cloudflare facade drops `watchEvents` and `Harness.retryTask` and exports `ConversationTranscript`.

### Added

- `harness.ConversationTranscript` (`NewConversationTranscript`) keeps what a client has of one conversation over any `ConversationView`: `Merge` returns the view with `Items`, the client's whole transcript (entries, a gap where a later window did not continue it, and an earlier marker until the start is loaded), `LoadEarlier` and `FillGap` page entries through a loader such as `Conversation.Entries`, and `Resume` is the window that continues it after a drop. Ports Pi's `ConversationTranscript`.
- `pi.live.runFailure` (`harness.RunFailure`, `RunFailureReason`) records why the newest run ended without an answer: `model_error`, `no_model`, `aborted`, `reset`, `faulted` or `orphaned`, with the run's task and inputs and a detail where one exists. The Durable core writes it too.
