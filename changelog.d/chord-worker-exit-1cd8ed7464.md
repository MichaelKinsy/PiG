### Fixed

- chord: a worker that fails right after it started now reports its reason. The server could handle a worker's exit before it had read, or before it had handed over, the last messages the worker wrote (its answer to a waiting holder and its `fatal` report); it then closed the connection and recorded the fixed `worker failed to start` (in p2, under load: a session whose worker dies at its start showed that text where Pi shows why, for example `Unknown model`). As in Node, which emits a child's messages before its `exit` event, the exit is now told after the channel's reader took and told everything the worker wrote. Limits: the exit waits for the end of the worker's channel as it already waits for the end of its output, so a process outside the worker's tree that holds the channel (a Go worker cannot hand it on: a kept test) delays the exit until the link is closed, where Node does not wait; not run on Windows, where a worker that ends before the server accepted its pipe connection can still lose its last messages. <!-- fix: 1cd8ed7464aba70630fdcdf2ee5c37e5cab1ae9e -->
