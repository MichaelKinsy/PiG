### Fixed

- chord: a worker's exit is told when its process ended even while a process outside its tree keeps writing the worker's stdout, stderr or channel. A process the worker started in a session of its own survives the kill of the worker's process group; when it held a stream of the worker and wrote it without a pause, the server's settlement of the exit never finished (it waited for a read that found the stream empty, and a refilled stream never is), so the worker's exit was never told and its session never learned that its worker had died. The settlement now covers what the stream held when the worker ended: all of that is told before the exit, and what the outside process writes later is told after it, as before. The fault came with the fix that made a worker's exit wait for no stream's end (2026-11-13) and is in no release (no tag contains it; v0.7.0 does not). <!-- fix: 7f4c44a147 --> <!-- cause: the drain took a read that finds the stream empty as the sign that everything written before the exit was told, which holds only while nobody else writes the stream, and a descriptor held outside the tree is exactly someone else -->
