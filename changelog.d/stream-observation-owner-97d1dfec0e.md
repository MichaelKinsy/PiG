### Fixed

- A subprocess `before_provider_headers` extension handler can no longer race the agent loop's continuation turn when `ModelRuntime.Stream` or `StreamSimple` starts request preparation while the agent turn is still active: previously the spawned request-preparation goroutine could receive the agent loop's `StreamObservation` from `StreamObservationFromContext` and detach its coroutine concurrently with `Yield`, dropping the injected headers with an `iter.Pull` handler panic, crashing `Session.Send`, or permanently deadlocking the turn. `StreamObservationFromContext` now requires the calling goroutine to own the active observation (matching `AssistantMessageEventStream.ResultContext`), returning `nil` to any other goroutine so it runs its wait directly. <!-- fix: 97d1dfec0e81afb2ea202c7130715e69936d6530 --> <!-- cause: StreamObservationFromContext, callbackObservation, and activeProducer returned the executor's active StreamObservation without checking observation.ownedByCaller(), so a spawned ModelRuntime.start goroutine inheriting the executor via ObservationContext grabbed and detached the agent loop's active continuationTurn concurrently with the owner's Yield. --> <!-- tests: ai/stream_observation_owner_test.go::TestStreamObservationFromContextReturnsNilToForeignGoroutine, ai/stream_observation_owner_test.go::TestForeignGoroutineAwaitExternalDoesNotRaceOrDeadlockOwner, ai/stream_observation_owner_test.go::TestForeignGoroutineDataRaceOnDeferred, ai/stream_observation_owner_test.go::TestStreamObservationFromContextReturnsNilToForeignGoroutineDuringProducerTurn, coding/session_provider_headers_foreign_observation_test.go::TestBeforeProviderHeadersForeignGoroutineKeepsInjectedHeaderAndNeverRaces -->
