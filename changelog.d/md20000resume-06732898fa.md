### Changed

- tui: a streaming assistant message keeps the rendered blocks of its last frame across a garbage collection, so the frame after a collection renders only what the new text changed instead of every block of the answer. The rows are unchanged. On a stream of a 20,000-character Markdown answer with a collection every 30 frames, a stream takes 27 % less time and allocates 14 % less.
- tui: highlighting a code block allocates far less and takes about half the time. A match of the highlighter no longer records the capture groups of every rule of its matcher, the words of a mode with keywords are found without a regular expression, and a block that streams converts its code into a reused buffer. The highlighted output is unchanged. Replaying the code blocks of a streamed 20,000-character Markdown answer frame by frame takes 47 % less time, 73 % fewer bytes and 64 % fewer allocations; a stream of that answer with a collection every 30 frames takes 29 % less time and allocates 44 % less.
