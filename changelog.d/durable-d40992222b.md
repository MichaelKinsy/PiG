### Upgrading

- Go API `durable/harness`: `Harness.RetryTask` and the `retryTask` request of the Durable core and the Cloudflare facade are removed, with the `task_parked` report (`ReportTaskParked`) and the `restart_limit` blocked reason of a task's inspection. A task cut off `settings.restartLimit` times in a row no longer waits to be retried: it ends visibly (below), so nothing is left to retry. Code that called `RetryTask` or matched `task_parked` or the `restart_limit` blocked reason drops them: read `pi.live.runFailure`, `pi.live.compactionFailure` or the task's outcome, and handle `ReportTaskInterrupted` and `ReportTaskFaulted` with reason `restart_limit`.
- `RunFailureReason` gains `RunInterrupted` (`interrupted`: the host stopped while the model was answering and no retry was left) and `RunRestartLimit` (`restart_limit`: the run's task was cut off `settings.restartLimit` times in a row), so a switch over the reasons handles both. `onReport` gets `ReportTaskInterrupted` (`task_interrupted`, with `ReasonRestartLimit` or `ReasonInterrupted` and `ReportInfo.Restarts`); the telemetry report attributes gain the type `task_interrupted` and the reason `interrupted`.

### Changed

- A task cut off `settings.restartLimit` times in a row ends instead of parking: a tool call ends with an error result (diagnostic code `restart_limit`) and its task fails with detail `{reason: "restart_limit"}`, a compaction fails into `pi.live.compactionFailure`, a generation ends its run with `pi.live.runFailure` reason `restart_limit` (its inputs settle `unanswered` with that reason), and a task of an extension's kind ends `faulted` with detail `{reason: "restart_limit"}`, reported as `task_faulted` with reason `restart_limit`. The built-in tasks are reported as `task_interrupted`. The Durable core's scheduler faults extension tasks at the limit; it does not emit `task_interrupted` from a generic commit hook, the built-in tasks' terminal commits report it.
- A generation whose model request was in flight when the host died no longer resends it on open: the attempt counts as failed under `settings.retry`. Its partial becomes an aborted entry, as before; the next attempt waits for the backoff, shown in `pi.live.generation.retry`, and with no retry left the run ends with `pi.live.runFailure` reason `interrupted` and the inputs settle `unanswered` with that reason. A deferred poll whose fetch was in flight is charged the same way, and its next attempt polls the same deferred response again instead of submitting a new request; a run that ends instead cancels it. A close still resends.

### Fixed

- A host that crashes during a model request no longer resends it forever, adding an aborted entry each time: the interrupted request is a failed attempt under the retry policy, and the run ends with `runFailure` reason `interrupted` once no retry is left; other work cut off `settings.restartLimit` times ends instead of keeping its conversation busy. <!-- fix: d40992222bb3b70407b30b15773c2f4e46c578fc, 19aa87d1a67afafed9ed7934393653156fe73efc -->
