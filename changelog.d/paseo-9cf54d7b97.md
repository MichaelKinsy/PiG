### Fixed

- A Node extension's message payloads now share objects as in Pi. The message in a `message_end` event is the object `ctx.sessionManager.getEntries()` returns in the matching session entry, including when a `message_end` handler (its own or another extension's) returns a replacement: the object holds the stored, replaced message, as Pi writes the replacement into the original object, and only a handler that ran after the replacement holds a different object. A `message_start` message of a system, user or tool result message, the `message` and `toolResults` of `turn_end` and the `messages` of `agent_end` are the same objects as well, and extensions packed in one process hold one object for one message. An extension that finds an entry with `entry.message === message` found none in PiG. Paseo's Pi integration depends on that lookup: through PiG its timeline did not show the user's prompt until the session was reopened, and a conversation rewind was refused. <!-- fix: 9cf54d7b97 -->
