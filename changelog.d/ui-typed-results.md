### Upgrading

- Extension SDKs (Go, Python, Rust): a dialog returns the JSON value the client answered with, as Pi's does, instead of a string or a bool. Go: `Context.Select`, `Context.SelectWithOptions`, `Context.Input`, `Context.InputWithOptions` and `Context.Editor` return `(any, bool, error)`, and `Context.Confirm` and `Context.ConfirmWithOptions` return `(any, error)`. Before: `choice, ok, err := ctx.Select(t, opts); if choice == "Execute" {...}`. After: `answer, ok, err := ctx.Select(t, opts); choice, _ := answer.(string)`. A cancelled dialog returns `nil` where it returned `""`, and `Confirm` returns `false` when cancelled. Rust: `select`, `input` and `editor` return `(serde_json::Value, bool)` and `confirm` returns `serde_json::Value`; read a string with `value.as_str()`, a boolean with `== json!(true)`; cancelled is `Value::Null`. Python: `select`, `input` and `editor` return `(Any, bool)`, `confirm` returns `Any`; the value is a `str` for a client that follows Pi's protocol, and a cancelled dialog's value is `None` where it was `""`. Node is unchanged. The host and every SDK change together; there is no negotiation.

### Fixed

- RPC mode: an `extension_ui_response` whose `value` is not a string, whose `confirmed` is not a boolean, or whose `cancelled` is not a boolean no longer leaves the dialog pending. The dialog resolves with the client's JSON as Pi's does: a Node, Go, Python or Rust extension sees a number, `null`, an object or an array from `select`, `input` and `editor`, and the client's `confirmed` from `confirm`; `cancelled` is read by JavaScript truthiness. <!-- fix: c4bcb663a6 -->
