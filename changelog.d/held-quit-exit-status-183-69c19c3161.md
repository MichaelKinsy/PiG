### Fixed

- After ctrl+c, SIGINT, SIGTERM or SIGHUP while a quit was held by a native extension command (a Go, Rust, Python or Lisp command still running when you quit with ctrl+d, beside another extension whose shutdown never finishes), pig could exit with status 0 instead of the signal's status (130, 130, 143, 129), as Pi's process does; in about one run in 120 of the held-quit tests the shell saw 0 while `exit.log` said `received SIGINT (exit 130)`. The signal's exit ends the extension processes, the host read the end of the process that held the quit as an empty event loop and started the exit of a drained quit (status 0) beside it, and whichever of the two reached `os.Exit` first ended pig. The signal's exit now claims the end of the process before it touches the extension processes, and every other exit waits behind it (D102); the wait for the extension processes to end is the one it was (D56).
