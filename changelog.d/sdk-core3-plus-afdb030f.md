### Added

- Every extension SDK (Go, Rust, Python and Node) gains `OnThemeChange` and `OnToolsExpandedChange` (a change of the host's replicated theme or tool-expansion state, pushed when it changes), `SetWidgetRenderer` (Go, Rust and Python: a widget laid out at the host's width; Node runs Pi's own factory form), `Bell` (`ui.bell`: BEL between frames in the interactive UI, nothing in print, JSON and RPC modes), `ToolCallIndex`, `ToolInput` and `ToolParams` (the tool call's position in its assistant message and its arguments in `Object.keys` order), `ExtensionSourceInfo` (the loader's provenance for the extension) and `OnLoaded` (handlers that run once the extension is registered and before it serves a request). 

### Fixed

- `Context` and the types that hold one (`EventBus`, `ModelRegistry`, `ReplacedSessionContext`, `SessionManager`, `SetupSessionManager`) in the Go extension SDK are comparable again: the tool-call input a `Context` carries (`ToolInput`, `ToolParams`) is a pointer to the request's arguments instead of a slice, so adding it is no longer an incompatible change. <!-- fix: 4b2f12c842 -->

- `pi.events.emit` in a Go, Rust or Python factory behaves as Pi's does: the first factory-time bus call connects to the host (as `parseFrontmatter` does) and `Run` reuses the connection; a listener the factory subscribes is registered with the host at once and answers the host's dispatches on that connection while the factory waits for a host call, so it hears another extension's emit made while the factory runs, a nested reply to the factory's own emit included, as Pi's shared emitter delivers it; the call returns once the host has delivered the emit to every listener, in registration order (the extensions loaded before this one, then this one's own), and each has finished; a listener that throws or panics is written to stderr as `Event handler error (channel):` and reaches neither the emitter nor the next listener; an `error` emit that nobody hears fails with the emitted error. Before, the emit was queued until after ready, and its failure only reached stderr. A factory with no host (no `PIG_EXT_SOCKET`) gets an error from its first bus call. Go gains `sdk.ServeFactory(conn, factory)` for a fused binary, which gives the factory the pipe as its connection. <!-- fix: afdb030f -->
- The Python SDK test `test_provider_transport_shutdown_does_not_settle_owned_stream[True-*]` no longer fails when the worker thread is still returning at the moment the shutdown finds no thread to wait for: it waits for the worker, as the assertion means "ends", not "has already ended". <!-- fix: de19f796 -->
- A Go extension SDK loop that is served without `Run` (a test on its own connection) no longer waits for a loaded gate that never closes; `TestToolRequestAllocBudget` hung for the whole test timeout. <!-- fix: afdb030f -->

- The Node extension API probe of a failed factory (`TestUpstreamFailedFactoryDisablesCapturedAPI`) names `onLoaded`, which the runtime already rejects after a failed load; the test failed with an uncaught assertion since `onLoaded` was added. <!-- fix: 78fa8e4f -->
- A listener a Go, Rust or Python factory subscribes hears another extension's emit made while the factory runs, including a nested reply to the factory's own emit, as Pi's shared emitter delivers it: the listener is registered with the host when it is subscribed, a factory emit goes only through the host's ordered registry, and the factory's connection answers the host's dispatches while the factory waits for a host call. Before, the listener was registered when `Run` connected and missed such an emit. <!-- fix: 19a0df25 -->
