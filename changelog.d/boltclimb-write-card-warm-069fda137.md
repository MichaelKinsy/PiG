### Changed

- A write call that streams a long file in no longer stalls the frame that completes it. The card draws the highlighted lines of the whole file once the call is complete; for a 400 KB TypeScript file that single highlight stopped the screen for about 300 ms. While the content streams in, the card now highlights the whole file a step at a time (a step is the content's sixteenth, between 8 and 32 KB), so the last frame highlights only what the last step left. The lines the card draws are the same ones a single run over the whole file gives. In the Pi-Bolt `pauses.py` harness (pinned core, 5 interleaved rounds each) the longest stall of a 50 KB file went from 72-128 ms to 31-44 ms; the 200 KB and 400 KB files' longest stall is now the 82 ms at the start of the step, no longer the end. About 1% of frames while a file streams in now take 25-35 ms longer (the steps), which moves the 99th-percentile frame gap of those steps from 17-18 ms to 24-33 ms.
