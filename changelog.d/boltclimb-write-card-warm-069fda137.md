### Changed

- A write call that streams a long file in no longer stalls the frame that completes it. The card draws the highlighted lines of the whole file once the call is complete; for a 400 KB TypeScript file that single highlight stopped the screen for about 300 ms. While the content streams in, the card now highlights the whole file a step at a time (a step is 32 KB), so the last frame highlights only what the last step left. The lines the card draws are the same ones a single run over the whole file gives. A step makes one frame longer, so the steps are few enough (a 400 KB file has twelve, under 1% of its frames) that the 99th-percentile frame gap stays at the 18-20 ms it was. In the Pi-Bolt `pauses.py` harness (pinned core, interleaved rounds) the longest stall of the 50 KB, 200 KB and 400 KB files went from 93, 252-271 and 310-366 ms to 59-69, 84-97 and 90-93 ms.
