### Fixed

- Retry classifier now retries `"rate increased too quickly"` throttle errors (OpenAI 429 `slow_down` on Codex and Alibaba Qwen) and explicitly classifies `"provider finish_reason: error"`, `"provider stopped with: error"`, and `"returned an empty response"` instead of injecting retry wording into Mistral error messages (Pi 1.6.1). <!-- fix: 7fc7ced374 --> <!-- cause: retryableProviderErrorPattern lacked request-rate throttle and finish_reason error patterns; mapMistralStopReason appended server error text -->
- Context-overflow detection now matches `request_too_large` only as a complete ASCII identifier so longer error codes such as `plugin_request_too_large` or `request_too_large_flag` are not misclassified as context overflow (Pi 1.6.1). <!-- fix: f0d4e43ea6 --> <!-- cause: overflow pattern matched request_too_large as an unbounded substring -->
- OpenAI-completions streams on OpenRouter now record `choice.native_finish_reason` into `RawStopReason` (`<finish_reason>.<native_finish_reason>`) and error messages, and convert empty stops with non-clean native finish reasons into retryable empty-response errors (Pi 1.6.1). <!-- fix: a1e8423fd6 --> <!-- cause: openai-completions ignored choice.native_finish_reason on OpenRouter streams -->
- OpenAI Responses tool-call replay now includes `status: "completed"` on replayed `function_call` and `custom_tool_call` items so full-history resends match stored server items (Pi 1.6.1). <!-- fix: 01979138bc --> <!-- cause: replayed Responses tool call items omitted status completed -->
- Google Generative AI and Google Vertex streams now parse `promptFeedback` (`blockReason`, `blockReasonMessage`, `safetyRatings`) to report non-retryable prompt block errors separately from incomplete streams, and include the received chunk count when a stream ends without a finish reason (Pi 1.6.1). <!-- fix: df8ff62b1d --> <!-- cause: Google stream decoder discarded promptFeedback and reported all finish-less streams identically -->
- Non-strict Anthropic tool schemas now preserve root `$schema` in `input_schema` so nested dialect keywords such as Draft 7 tuple `items` are interpreted accurately (Pi 1.6.1). <!-- fix: c70fbb99be --> <!-- cause: anthLegacyOptionalRootKeys omitted $schema -->
- Codex Responses requests with `supportsMidConvoEffort` now pin the initial selected effort directly to `reasoning.effort` (reconstructed from retained same-model replies) and emit `configuration_update` items only on effort changes (Pi 1.6.1). <!-- fix: 23c16fab67 --> <!-- cause: Codex always sent medium as reasoning.effort and emitted a configuration_update on every turn -->
- `StreamOptions.OnResponse` (and `after_provider_response`) now receives HTTP error responses (4xx/5xx) and retried attempts across `openai-completions`, `openai-responses`, `azure-openai-responses`, `anthropic-messages`, `google-generative-ai`/`google-vertex`, `openrouter-images`, and classifier requests (reported before reading the body) (Pi 1.6.1). <!-- fix: 3bfed27f85 --> <!-- cause: non-2xx responses and retry attempts bypassed OnResponse callbacks -->
- `Streamed line and SSE readers in `llama.cpp` `/models/sse`, Codex SSE, `pi-messages`, `chord/next/store`, `durable/env/node`, and `env` now scan in linear time with shared LF/CRLF/CR SSE framing (and Anthropic empty-block comments no longer leak into subsequent `Raw` diagnostics) with full LF, CRLF (including split across chunks), and lone CR support, matching Pi 1.6.1 linear-time stream decoding (Pi 1.6.1). <!-- fix: 24905227a5 --> <!-- cause: llama Watch concatenated growing strings and rescanned from offset 0 per chunk -->
