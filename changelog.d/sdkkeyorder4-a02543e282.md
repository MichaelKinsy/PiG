### Fixed

- A Go extension that sorts, swaps or edits objects of an event in place no longer writes another object's member order into what it hands back. The order of an event's objects was matched back to the event's text by the first string members of the moved elements, so sorting an OpenAI provider request's `tools` by name re-sorted each tool's `properties`, siblings with the same leading strings or only numbers swapped their orders, an escaped string or an in-place string edit gave the wrong order, and a context of 3,000 messages edited in place took 1.2 s to answer (10 s at 10,000). The Go SDK now records the member order of every object while it decodes the event and knows each object by its own map, so a moved, copied, edited or twice-listed object keeps exactly the order the host wrote it: redacting every message of a 10,000-message context takes 97 ms, and a context handler that returns nothing costs 2% more than the decode it already paid. <!-- fix: a02543e28246c21cbd27db66336563146f94ceb4 -->
