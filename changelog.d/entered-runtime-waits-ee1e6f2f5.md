### Fixed

- The waits that keep upstream's one-thread order (a chord output waiter's caller, a chord host call, a durable codemode tool call a script made) no longer return early for a goroutine the Go runtime has stopped for its own work: one that allocates while a collection marks (it waits for assist credit) or scans its stack, or that a trace or a heap dump stops. The wait took that stop for a wait of the program's, so the caller went on while the code it awaited was still on its way to its next wait; a caller that may hold a lock (`AwaitBlocked`) also took the world lock of a collection that is starting for one.
