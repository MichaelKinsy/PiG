### Changed

- CI: a pull request no longer saves the big caches. `ci.yml` and `security.yml` restore the Go build cache, the Go modules, the Cargo registry and test targets, the npm cache and the Durable Cloudflare host's TinyGo and Pi reference with `actions/cache/restore` and save them with `actions/cache/save` only on main (the weekly run, a dispatch) and on a dispatch of a release branch (`CACHE_SAVE`); a pull request or merge queue run falls back to the newest copy that main saved. A pull request's caches are visible to that pull request alone, so one copy of each per pull request filled the repository's cache limit and evicted main's. The Linux jobs that used `setup-go`'s `cache: true` and every `setup-node` `cache: npm` restore the same entries explicitly, so each cache has one copy. Cache diagnosis by @Patrick-Kappen.
- CI: a new `cache-cleanup.yml` deletes the caches of a pull request's merge ref when the pull request closes (token scope `actions: write`, no checkout), and `ci-images.yml` cancels a superseded pull request run while a push to main, the schedule and a publish dispatch still run to the end.
