### Fixed

- A Piglet Binary with a TypeScript or JavaScript extension compares the extracted copy of the extension's sources with the archive inside the Binary at every start, as it compares an embedded Go, Rust or Python cell binary with its embedded bytes. Before, a later start reused the copy under `piglet-binary-cells/node/<digest>/sources` by its `ready.json` alone, so a file changed or deleted there, a file added that the extension would import, a `node_modules` or `package.json` beside the sources, a file or folder replaced by a link, or a widened mode reached Node and ran in place of the code the Binary was built with, until the `<digest>` directory was removed. Now a copy that differs is replaced from the archive, one warning line on stderr names the first difference (`pig: warning: the extracted Node sources in <folder> differ from the Binary's archive (changed: sources/greeter/index.ts); extracted them again`) and nothing reaches stdout, and two Binaries starting at once do not disturb each other. A `node_modules`, `package.json`, `tsconfig.json` or `jsconfig.json` in `piglet-binary-cells` or `piglet-binary-cells/node` stops the start and names the path; the PiG configuration directory and the folders above it are not checked. The check runs at startup, not at a `/reload`. It reads every extracted file, which adds 0.3 ms to a start with an extension of 10 to 13 files, 9 ms to one with 561 files and 1.9 MB, 16 ms to one with 1,064 files and 28.5 MB, and 73 ms to one with 3,665 files and 17.5 MB (Linux, median of 20 starts). A Binary built before this change has no check: build it again to get one. An extension keeps its data outside its extracted sources, in the agent directory.
