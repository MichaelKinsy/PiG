### Fixed

- A `tool_call` handler that assigns a new object to `event.input` now gives it to the next handlers of the call, as in Pi, in Node extensions and in the Go, Python and Lisp SDKs; before, the next handler read the original input (in Node, Go and Python from v0.5.0 to v0.7.0, and in Lisp in v0.7.0). The call itself still runs with the input it carried, as in Pi, so nothing a released extension could rely on is lost; a Rust handler keeps its own behaviour, which is unchanged in every released version: the Rust SDK holds the event as one value, so assigning the input and editing it in place are the same edit and the tool runs with what the handler left. <!-- fix: 85791f823c --> <!-- cause: the reply protocol had one member for the input, meant for in-place edits the tool must receive, so an assigned input had no way across the process boundary and was dropped as no edit -->
