### Added
- A Piglet can strip built-ins with a `strip` key: built-in tools, slash commands, built-in extensions (`mcp`, `codemode`, `tool-search`, `pig-login`, `llama.cpp`), model APIs (`bedrock-converse-stream`, `google-vertex`, `mistral-conversations`) and features such as `themes`, `skills`, `node-extensions`, `syntax-highlight`, `export-html`, `self-update`, `changelog` and `docs`. Strip lists inherit through `extends` and come off with `extends.remove.strip`. `pig piglet show` lists each stripped ID in its `Slots` section. Stock PiG and a Piglet without `strip` are unchanged (D92).
- A Piglet Binary leaves the code of a stripped built-in extension, model API or feature out of the executable. A request for it reports `<what> is stripped from this Piglet (strip.<list>: <id>)` (D92).
- A stripped built-in leaves every surface that offers it: `--help`, `pig piglet` usage, `pig config`, `/hotkeys`, the startup hints, slash autocomplete, `/settings`, `/login`, the system prompt docs section, the extension API and RPC `get_commands`. A stripped command's keys do nothing, and a stripped `bash` tool also stops `!` and `!!` user bash (D92).
- The models of a stripped model API are not offered by `--list-models`, `/model`, model cycling, `--models`, the startup default, RPC `get_available_models` or an extension's model registry, including `models.json` models on that API. `--model` or `--provider` naming one reports the strip (D92).
- In experimental builds, `pig server --piglet <name|path>` and `pig client --piglet ...` read that Piglet: one that strips `experimental-server` leaves the command to the stable CLI (D92).
