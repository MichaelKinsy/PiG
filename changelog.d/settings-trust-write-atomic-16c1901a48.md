### Fixed

- A full disk or a killed process while pig saved `settings.json` or the project trust store could leave the file empty, and the next change then saved it with that one setting or decision alone, so every other setting or trust decision was lost. Both files are now replaced as a whole through a temporary file in the same directory, so where one can be replaced a failed write leaves the old file untouched; the bytes written are the same. Where one of them cannot be replaced atomically, for example a single file mounted into a container, pig writes it in place as before, and a failure half way through that write can still leave the file empty or cut short. <!-- fix: 16c1901a48 --> <!-- cause: settings.json and trust.json were written with os.WriteFile, which truncates the file before it writes, so a write that failed after it began left an empty or cut-short file and the next change was saved on top of that. -->
