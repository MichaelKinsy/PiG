### Upgrading

- Rust SDK: a `before_agent_start` handler registers with `Extension::on_before_agent_start` (or `EventSubscriber::on_before_agent_start`) and receives a `BeforeAgentStartEvent` instead of `&mut serde_json::Value`. `Context::current_system_prompt` is removed; the event's `system_prompt()` and `Context::get_system_prompt()` replace it. Before: `ext.on_event_result("before_agent_start", |ctx, data| { data["systemPromptOptions"]["appendSystemPrompt"] = json!("x"); ctx.current_system_prompt(data)?; Ok(None) })`. After: `ext.on_before_agent_start(|ctx, event| { event.edit_system_prompt_options(|options| options["appendSystemPrompt"] = json!("x")); event.system_prompt().map_err(|e| e.to_string())?; Ok(None) })`. `event.payload()` is the host's event without `systemPrompt` and `systemPromptOptions` (`messageType`, `prompt`, `images`, `message`), `event.system_prompt_options()` copies the options, `event.set_system_prompt_options(value)` replaces them, and `event.snapshot()` is the whole event with the prompt and options as they are now. A `before_agent_start` handler still registered through `on_event`, `on_event_result` or `EventSubscriber::on_event` fails each emission with an error that names `on_before_agent_start`. The upgrade rules of `pig extension upgrade` cover Go extensions only, so a Rust extension is rewritten by hand. <!-- fix: 0b6bd6bd45 -->

### Fixed

- In a Rust extension's `before_agent_start` handler, `ctx.get_system_prompt()` returns the prompt the handler's own edit of `systemPromptOptions` renders, as Pi's `ctx.getSystemPrompt()` and the Go, Python and Node SDKs do. It returned the prompt rendered before the edit, because the handler held the event exclusively and the context could not read it. The handler now edits the options through the `BeforeAgentStartEvent` the context shares, and a read after an edit asks the host to render the edited options. <!-- fix: 0b6bd6bd45 -->
