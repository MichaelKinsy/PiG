### Fixed

- Closing the terminal of an interactive session (a closed window, `tmux kill-session`, a dropped connection) now gives extensions `session_shutdown` with the reason `quit` before the exit, as Pi does when the hangup reaches it as SIGHUP. PiG's input reader saw the dead terminal before any signal and exited 129 without the event, and it killed the extension processes under an event the signal path had already started, so an extension lost its last write (reported for a fused Piglet extension whose session log ended without its shutdown record). The exit waits for the handlers for at most one second, writes nothing new to the dead terminal, stays 129 and leaves one `exit.log` line; a session without a `session_shutdown` handler exits as fast as before. D186 records the differences from Pi, which waits for a slow handler without a limit, cuts a working session's handler at its next terminal write, and emits nothing when its event loop is empty. <!-- fix: 5b36a5f599baa42fccb554fbea75d7f2c07c116f, aef7184ef313f3d4bbd3254d4cfb7ce01e773c30 -->
