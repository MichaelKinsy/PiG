### Changed

- Fullscreen scroll frames reuse the previous frame's component output: the wheel, page and line keys, top and bottom, prompt jumps, scrollbar drag and selection auto-scroll request a view-only frame, and Container.Render and Box.Render return the same slice while their children's lines are unchanged. Follows Pi b7bb7ca905b8. Breaking for in-process Go components: the slice a Container or Box returns is borrowed and read-only; copy it (slices.Clone) before changing a line, also in a type that embeds a Container and edits its own Render result; its capacity equals its length, so append is safe. Known limit, as in Pi: a component that changes state without requesting a render stays stale while scrolling (it was already stale without scrolling). A Node extension gets Pi's rule exactly once the backport is vendored: "Extension components: `render()` now returns `readonly string[]`, and `Container` returns the same cached array while its children are unchanged. Extensions that modify render output in place, including `super.render()` in a `Container` subclass or an embedded component's output, must copy it first".. The SDKs that push lines (Python, Rust, Lisp, subprocess) pass lines by value and are unaffected.
