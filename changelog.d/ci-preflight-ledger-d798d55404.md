### Changed

- CI: the pre-flight's `test-expectation` check admits what the line lint admits. A pull request that changes expected values of a Go test together with production code passes when `test/parity/testprune-reviewed.toml` at the PR's head holds a row of that test file whose commit prefix (at least 10 characters) names exactly one commit of the PR and which passes the lint's validation (CITE to a Pi file main inventories, DIVERGENCE to a record on main or in the PR, NOBEHAVIOR, message-only); the `Pi-Behavior-Change:` trailer in the PR body and a commit still admits it as before. Every admission is printed (a log line, a `::notice` annotation and a comment row) and asks for nothing, a ledger that cannot be fetched or read leaves the check undecided, and a row that does not apply changes nothing. The validation is one package, `automation/ci/preflight/reviewed`, which the line lint calls too. Text of a pull request that the pre-flight prints (a ledger reason or cite, a file name) is now one line in the job log and one code span in the comment cell.
