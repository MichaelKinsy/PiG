### Changed

- CI: the pre-flight's `test-expectation` check admits what the line lint admits. A pull request that changes expected values of a Go test together with production code passes when `test/parity/testprune-reviewed.toml` at the PR's head holds a row of that test file whose commit prefix (at least 10 characters) names exactly one commit of the PR, that commit changed the file, and the row passes the lint's validation (CITE to a Pi file main inventories, DIVERGENCE to a record on main or in the PR, NOBEHAVIOR, message-only); the `Pi-Behavior-Change:` trailer in the PR body and a commit still admits it as before. The pre-flight asks the API for the files of each commit a row names (one call per commit, at most 50 commits per PR). Every admission is printed (a log line, a `::notice` annotation and a comment row) and asks for nothing, a ledger or a commit that cannot be fetched or read leaves the check undecided, and a row that does not apply changes nothing. The validation is one package, `automation/ci/preflight/reviewed`, which the line lint calls too. Text of a pull request that the pre-flight prints (a ledger reason or cite, a file name, an error of the API) is now one line in the job log, and a ledger reason or cite in the comment is one code span.
- CI: the pre-flight's `test-expectation` check leaves the `[[tooling]]` directories of `test/testdata-provenance.toml` on main out of its rule, as the line lint does (one shared parser and prefix match). A prefix that only the pull request adds exempts nothing, a list that cannot be read on main fails the check, and each skip is printed.
- CI: the pre-flight prints text of a pull request so that it cannot start a workflow command in either form the runner reads, `::command::` or the legacy `##[command]` (`##[` is printed as `# #[`); an admission notice is stored whole in the record of the verdict and cut only when printed.
