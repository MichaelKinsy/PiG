### Fixed

- The provider bridge (`pig` `--provider-bridge`), the Durable core's `model_context` effect, the durable generation task and an extension host's `modelStream` call now send each provider event with the partial message as it stood when the provider pushed the event, as Pi does. Each created the provider's stream and read it from an ordinary goroutine, so under load the goroutine could start reading after the provider had filled the shared partial, and a `start` event reached the wire carrying the finished message (`toolUse`, the whole content and the final usage) where Pi sends `stopReason: "pending"` and no content. Each now creates the stream and reads it inside one stream continuation, as the Agent does; event content, order, cancellation and errors are unchanged. <!-- fix: b9de6a2def -->
