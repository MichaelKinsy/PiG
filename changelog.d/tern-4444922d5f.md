### Added

- PiG follows Pi 1.3.0+1402973a. The `telemetry` package has Pi's propagation, span links and metrics (Pi 48909d98): `TelemetryPropagation` (`Inject`, `Extract`) over an opaque `TelemetryCarrier`, `SpanOptions.Links` and `TelemetrySpan.AddLink`, `TelemetryMetrics` (counter, up-down counter, histogram) with `NoopTelemetryMetrics` and `NoopTelemetryPropagation`, typed metric schemas through `TelemetrySchemaDefinition.Metrics` and `CreateTypedMetrics`, and an in-memory recorder that records links, propagation and measurements. `telemetrytest` checks adapters for propagation and metrics as Pi's conformance kit does. `TelemetrySpan` gains `AddLink`, so a custom span type must implement it.
- `chord/context` has Pi's explicit `Context.telemetry` (Pi 48909d98). `Telemetry(ctx)` returns the context's telemetry parent and is never nil: `Background()`, `TODO()`, and any context that carries none return `telemetry.NoopTelemetryContext`. `WithTelemetry(parent, telemetry)` derives a context with a telemetry parent and leaves the parent, its cancellation, and its values unchanged. `TraceIn[T](ctx, options, fn)` runs a child span of `Telemetry(ctx)` and passes `fn` the derived context, whose telemetry is that span (`Telemetry(child)`, which `AddLink` and `AddEvent` use); Pi passes one context typed with a narrowed `telemetry` member, which Go cannot express. Concurrent `TraceIn` calls keep independent parents, and there is no ambient current span. These helpers do not instrument Chord hosts, methods, or network frames.
- `durable/harness.HarnessOptions.Telemetry` accepts a host-owned `telemetry.TelemetryContext` that may also implement `telemetry.TelemetryPropagation` and `telemetry.TelemetryMetrics`, found by type assertion where Pi marks them `Partial`. The option reserves the configuration boundary: Durable emits no spans or metrics yet and persists no carriers.
