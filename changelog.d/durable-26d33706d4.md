### Fixed

- The Go Durable SDK's scheduler no longer resolves the Harness settings for the context a run itself reads: `contextRetentionMs` is read only when the conversation is idle, as Pi's `runtime.context` does, which removes four settings resolutions from every round of one generation with a tool call. <!-- fix: 0021db7cfcbff9f9b43bd83dc31d1dd4dc8e5510 -->
- The Durable core's host calls `HarnessOptions.settings` as often as Pi does: the core reports how many times it resolved the settings while it handled an event (a settings notice, ABI 12) and the host resolves them as often, so a settings callback sees the 49 resolutions Pi makes for a round of one generation with one tool call, not the 193 reads of the extensions the host made before every send. <!-- fix: 26d33706d4ec8268bc913c578f2fdee2ae78a0ef -->
