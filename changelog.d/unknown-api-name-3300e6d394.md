### Security

- A `models.json` provider or model whose `api` is not the name of a registered API (a typo such as `openai-completion`, or any other unknown name) is now refused when its first request starts, with Pi's message `No API provider registered for api: <name>`, and nothing is sent: print mode exits 1 with that line on stderr, and RPC, JSON and interactive mode end the turn with it as the error. Before, PiG built an OpenAI chat-completions request for any unknown name and sent the conversation, system prompt included, to the provider's `baseUrl`. Affects 0.3.0 through 0.7.0. What to check: any `models.json` provider or model whose `api` is not one of the known names sent its conversation to that base URL as OpenAI chat-completions. The same holds for a provider an extension registers with an unknown `api` and no stream handler of its own, and for the Go `ai.StreamSimple`, which now reports the same message. <!-- fix: 3300e6d394b58b2723b581c0f82feb0e71915942 --> <!-- cause: the default branch of the api switch that builds a model's provider built an OpenAI chat-completions provider for any name outside the API constants, where Pi looks the name up in its API registry and refuses -->
