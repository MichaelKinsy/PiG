### Added

- `BashToolDetails` (`coding/extension`), `BashResult` (`coding`, `coding/cli`, `coding/rpcclient`, `extensions/sdk`), `cli.RPCBashResult.FullOutputError`, `subprocess.ViewBashComplete.FullOutputError`, `BashExecutionMessage`, and the `bash`/`powershell` structured output schema (`full_output_error`) now expose `FullOutputError` when truncated output could not be saved to a temp file.
- `tui.BashExecutionComponent.SetCompleteWithError` and `SetCompleteWithOutputAndError`, Go SDK `kit.(*BashExecution).SetCompleteWithError`, Rust SDK `kit::BashExecution::set_complete_with_error`, and the optional trailing `full_output_error` parameter on Python `kit.BashExecution.set_complete` and Common Lisp `kit-bash-execution-set-complete` record and render full-output save failures without changing existing 0.8.0 signatures.
- `tui.AuthSelectorStatusUnresolved()` represents a stored credential whose value did not resolve in `/login`.

### Fixed

- Sessions with very many entries (200k+) after the last compaction are verified to build context entries without stack overflow. <!-- fix: 157db55c3f --> <!-- cause: upstream spread push(...path.slice(...)) overflowed JS call stack; regression test ported -->
- Stored `auth.json` credentials whose `!command` fails now report `AuthStatus{Configured: false, Source: AuthSourceStored}`, render as `stored key did not resolve` in `/login` without synchronously executing uncached `!command` lookups, and clear their cached command result in `AuthStorage.Modify` when written again. <!-- fix: fd64f62259 --> <!-- cause: ModelRuntime.GetProviderAuthStatus returned Configured: true for any stored provider and AuthStorage.Modify did not evict the command cache -->
- Windows bash discovery in `internal/shellconfig` and `durable/env/node` now queries `git var GIT_SHELL_PATH` (Git 2.47+) for Git for Windows installed outside Program Files before falling back to `bash.exe` on `PATH` (which usually finds the WSL launcher in System32). <!-- fix: cb3d1e7d3c --> <!-- cause: Windows shell discovery only checked ProgramFiles before falling back to where bash.exe -->
- Self-updating a Windows managed installation (`PI_MANAGED_INSTALL_ROOT` with a Windows entrypoint path in `managed-install.json`) when run from WSL is now refused before any network fetch or package-manager rebuild. Note: a native Windows `pig.exe` invoked from WSL runs as a Windows process (`runtime.GOOS == "windows"`), and PiG uses its own D39 standalone/package-manager tiers rather than Pi's npm managed-install layout, so this guard fires only when a non-Windows `pig` binary is executed inside a Pi `PI_MANAGED_INSTALL_ROOT` tree whose `managed-install.json` records a Windows entrypoint. <!-- fix: 88f9c1280c --> <!-- cause: managed install check did not reject Windows entrypoints on non-Windows platforms -->
- Temp file write/open/close failures in bash tool output, user `!` bash execution, external editor launch, and TUI width-overflow crash logging no longer crash or drop output; unsaved bash output keeps the retained tail, persists and propagates `FullOutputError` / `full_output_error` across sessions, `tool_result` events, interactive `user_bash` overrides, and all 4 SDKs, strips the model footer in the bash renderer, and avoids false omission markers or non-truncated error reports. <!-- fix: 53d35397b6 --> <!-- cause: unhandled output file errors and missing FullOutputError fallback paths -->
