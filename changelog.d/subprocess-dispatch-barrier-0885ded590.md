### Fixed

- A connection to an extension process ends when it is closed or fails even while the host's queue of incoming frames is full. When an extension had sent more frames than the host had taken and the reply to a `session_start` handler request or a tool call was read behind them, the connection's read loop waited to queue its dispatch marker until the host took a frame, and only the context of that request ended the wait. A connection that failed in that state stayed open for the host (its `Done` never closed), and `Close` of a live one did not return while the host's incoming loop waited for a call that only the close ends, such as a call held behind the embedder's background gate.
