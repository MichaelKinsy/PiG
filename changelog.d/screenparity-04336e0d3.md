### Added
- An opt-in screen writer (D624): with `terminal.screenWriter` set to `"writer"` in the global settings file, or `PIG_TUI_SCREEN_WRITER=writer`, fullscreen mode sends the terminal only what a frame changes on the screen, through a screen writer under the terminal's write. Pi sends every row a frame writes, and so does PiG in 0.8.0 when the writer is not selected. With the writer on, a row that already shows what the frame writes is not written; a row whose cells change is written in place, from its first cell through its last changed one, where that leaves the terminal the line the frame's own bytes leave it, and whole otherwise (a row as wide as the screen that changes through its last cell is written whole); a frame that changes nothing is not written; the rows the frames rewrote and the writer did not write whole are written whole once 250 ms pass without a frame. Frames are translated only while autowrap is known to be off, and regular mode, print, JSON and RPC mode are sent the bytes as they are written. In a replay of the recorded streams at 160 by 48 the writer sends 89.2 % of the bytes of a long streamed answer and 19.8 % of those of a file write. A raw capture of the output (`script`, `tmux pipe-pane`) holds other bytes than Pi's for the same frames. The lines tmux 3.4 and 3.6 keep are those of Pi's bytes (51 cases, asked of tmux itself by the tests). `PIG_TUI_SCREEN_WRITER=pi` sends the terminal Pi's bytes whatever the setting says; `PIG_TUI_SCREEN_WRITER_LOG=path` records every write as it came and as it was sent.
