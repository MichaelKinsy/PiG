### Fixed

- On Windows, saving `auth.json`, the settings, trust, keybindings and MCP files, or any other file pig writes through a temporary file, now leaves the whole security descriptor of the file as it was, as Pi's in-place write does. The replacement kept the owner-only access of a credential file only as far as `ReplaceFileW` merged it: it always marked the file as auto-inherited and could rewrite the inherited flag of entries or add explicit copies of inherited ones, so a login or token refresh could change who may open `auth.json`. The access (the entries with their flags, and the protected flag) is now put on the temporary file before anything is written to it and read back, and again after the replacement, which puts the old file back and fails if the access still differs; a file system that cannot take it gets the in-place write, as before.
