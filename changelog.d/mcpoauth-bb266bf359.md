### Added

- Added MCP OAuth sign-in in two halves to `mcp/oauth`, moved from the coding agent: `StartMcpSignIn` refreshes the stored tokens or returns the authorization URL, and `CompleteMcpSignIn` exchanges the code later, possibly in another request with the same state store. The code comes from a loopback callback server (`ListenForLoopbackSignIn`, `WaitForLoopbackSignIn`), the application's own callback route, or a pasted redirect URL (`ResponseFromRedirectURL`). Client ID Metadata Documents (`ClientMetadataDocuments`) and the client name are the caller's. `CreateMcpAuthProvider` refreshes tokens once across requests and, through `McpOAuthServerStore.WithRefreshLock`, across processes. `OAuthFlowOptions.RefreshOnly` makes a failed refresh report `REDIRECT` without registering a client or replacing a pending sign-in's PKCE verifier and state. Ending a sign-in's context also stops `StartMcpSignIn` while it waits for the refresh lock; a store's `WithRefreshLock` returns `McpRefreshLockBusyError` when another process holds the lock for the whole wait, and `StartMcpSignIn` then goes to the browser step. `CreateMcpAuthProvider` takes the application's `RedirectURL` for refreshing tokens of a Client ID Metadata Document sign-in. The coding agent's `SignInMcpServer` is a thin wrapper over them.

### Fixed

- A failed token refresh of an MCP connection no longer registers an OAuth client or replaces the PKCE verifier of a sign-in in progress, which made that sign-in fail. MCP sign-in now refreshes the stored tokens with the stored client even when the loopback callback port changed, instead of registering a new client and opening the browser.
- Tokens from a Client ID Metadata Document sign-in through an https callback route are refreshed with that route's redirect URI, which the documents list, instead of the loopback one, which they do not, so an expiry no longer needs a browser sign-in. Ctrl+C in `/mcp` and the `--timeout` of `pig mcp login` now also stop a sign-in while it waits up to 25 seconds for another PiG process's token refresh, and a refresh lock that fails for another reason than that wait now fails the sign-in instead of opening the browser.
