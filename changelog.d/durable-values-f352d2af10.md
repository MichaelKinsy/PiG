### Changed

- Durable's SQLite storage inserts every row through bound multi-row `VALUES` statements (1, 2, 4 ... rows, at most 100 parameters each) instead of one JSON array read through `json_each`, so SQLite no longer parses and extracts each row it is given. The stored rows are byte for byte the ones Pi's statement stores, in the same storage classes, with the same errors (a differential test compares every table over random batches: NULLs, Unicode, ill-formed UTF-8, lone surrogates, integer edges and the 8 KiB boundary). Warm commits take 10 to 38% less time and make 11 to 31% fewer allocations (one entry 72 to 57 us, 100 entries 2.4 to 1.5 ms, mixed entry/task/submission/document 305 to 272 us); the first commit of 100 entries takes 34 to 42% less; reads are unchanged, and reopening a storage allocates 12% less. An `INSERT` statement of the Node driver keeps one compiled copy whatever 0/1 integers it binds, since only a planned term can be planned again.
