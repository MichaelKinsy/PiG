### Fixed

- Releasing a session's services no longer leaves the model selector's catalog refresh running. Before, the refresh the selector starts and the shared catalog operation behind it were not joined by anything, so with a file-backed registry the operation could still write `auth.json` and `models-store.json` in the agent directory after the registry's model tasks were closed. The selector's refresh is now an owned task of the interactive mode, and the operation a task of the model registry; both are cancelled and joined when the session's services are released (for example on session replacement), while at quit the process exits, as Pi's does. The refresh result and the picker are unchanged. <!-- fix: 81a9b7614 -->
