### Changed

- A long answer that streams in allocates about half as much per frame. Each frame copied the answer's whole row list twice into new arrays (the Markdown block's rows, then the message's), 88 MB of the 255 MB a 60,000-character answer allocates, which made the collector run 48 times where 0.7.0 ran 41. A container that holds a Markdown block or an assistant message now borrows its rows from an array the child keeps for its next render, as it already borrows a nested container's. What a frame draws is unchanged. BenchmarkInteractiveLongAnswerStream (benchstat, count 12 interleaved, one core): 89.3 to 48.2 KB a chunk (-46%), 356 to 293 ms an answer (-17.7%, p=0.000). In the harness's 60,000-character answer: 27 collections and 1.67 s of user CPU (0.7.0: 41 and 1.88 s; before: 48 and 2.20 s; medians of 8 interleaved rounds).
