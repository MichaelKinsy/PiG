### Changed

- CI: the required checks `CI result` and `Security result` now run on `merge_group`, so a GitHub merge queue entry reports them. `automation/ci/ci-tiers.txt` assigns every CI job to a light pull-request run or the full run, and `automation/ci/ci-plan.sh` builds the job matrices from it under unchanged check names. The light run keeps build and vet, `lint-changed`, the drift and contract gates, the sharded unit tests, one parity shard and the Windows and macOS smoke shards. The full run, which is the merge queue's, the weekly schedule's and a manual dispatch's, adds the PORT_MAP evidence shards, the other parity shard, SDK conformance and the race, integration and extension gates, `module-size`, the Node extensions and Cloudflare host jobs, and the remaining Windows and macOS shards. A pull request keeps running the full set until the repository variable `PIG_PR_CI_LIGHT` is set to `true`, which is done once the merge queue is required. `.github/AGENTS.md` holds the table with its Actions-minutes estimate. <!-- fix: e43252637e -->
- CI: the secret scan skips `gitleaks-action` on `merge_group`, which the action rejects, and runs TruffleHog over the commits the queue added; the change classifier reads a merge group's diff and fails when it cannot compute one, rather than reading an empty change as docs-only. <!-- fix: e43252637e -->
