### Changed

- CI: the required checks `CI result` and `Security result` now run on `merge_group`, so a GitHub merge queue entry reports them. `automation/ci/ci-tiers.txt` assigns every CI job to a light pull-request run or the full run, and `automation/ci/ci-plan.sh` builds the job matrices from it under unchanged check names. The light run keeps build and vet, `lint-changed`, the drift and contract gates, the sharded unit tests, one parity shard and the Windows and macOS smoke shards; the full run adds the PORT_MAP evidence shards, the other parity shard, SDK conformance and the race, integration and extension gates, `module-size`, the Node extensions and Cloudflare host jobs, and the remaining Windows and macOS shards. The repository variable `PIG_PR_CI_LIGHT` selects the mode: unset keeps every pull request on the full run; `queue` runs the light subset on a pull request and leaves the full run to the merge queue; `label` runs the light subset and makes `CI result` fail with "full run required: add the ci:full label" until the full run has run on the pull request's current head, started by the `ci:full` label, by marking the pull request ready for review, or by dispatching CI on its branch. `.github/AGENTS.md` holds the table with its Actions-minutes estimate. <!-- fix: e43252637e -->
- CI: the secret scan skips `gitleaks-action` on `merge_group`, which the action rejects, and runs TruffleHog over the commits the queue added; the change classifier reads a merge group's diff and fails when it cannot compute one, rather than reading an empty change as docs-only. <!-- fix: e43252637e -->
