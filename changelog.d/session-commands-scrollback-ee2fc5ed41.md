### Fixed

- `/new`, `/resume`, `/fork`, `/clone`, `/tree` navigation and a compaction no longer erase the terminal's scrollback. The text above the TUI (the `Installing ...` lines of a package install at startup, or what a wrapper script printed) and the older transcript rows that had scrolled above the frame stayed in Pi and were gone in PiG. The transcript repaint now clears the chat and renders normally, as Pi's does, and the clearing redraw is sent only where Pi sends it: when the first changed row is above the viewport, and once for the box of `/reload`. This has been so since 0.2.0 for the session commands and since 0.3.0 for a compaction. <!-- fix: ee2fc5ed41 --> <!-- cause: rebuildChat and renderCompactionResult called ForceFullRender, which writes ESC[2J ESC[H ESC[3J and replays the transcript from the top, where Pi's chatContainer.clear() plus renderInitialMessages() request an ordinary render that repaints only from the first changed row -->
- `/logout` of a provider no longer erases the terminal's scrollback. It changes no transcript row, and Pi asks for an ordinary render after it. <!-- fix: 59aa6f6818 --> <!-- cause: runOAuthLogout called ForceFullRender after the logout, where Pi's logout shows its status and requests an ordinary render -->
- The frame that a key press requested before an awaited `/new`, `/resume`, `/fork` or `/clone` is painted before the session operation begins, as in Pi, instead of only when the operation outlasts the 16 ms frame throttle. The footer of a long forked session now ends in the row where Pi's does. <!-- fix: 904c7332f1 --> <!-- cause: replaceSessionFromCommand began the awaited swap with the frame the closed picker had requested still waiting behind the throttle, where Pi's frame runs on the next tick inside the await -->
