### Added

- Added `BlockedKind` (`"permission"`, `"question"`, `"auth"`) to `ExtensionUIDialogOptions` and all extension SDKs (`DialogOptions.BlockedKind` in Go, `blocked_kind` in Python, `DialogPromptOptions` + `DialogBlockedKind` in Rust, `:blocked-kind` in Common Lisp) so `select()`, `confirm()`, and `input()` dialogs can specify their OSC 7501 blocked program status kind.
- Added per-notice transcript visibility settings (`notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`, `notices.reasoningDrops`) under Notices in `/settings`, along with `SettingsManager.GetNotices` and `SettingsManager.SetNotice` (and `coding.NoticeKey`, `coding.NoticeSettings`, and `coding.NoticeKey*` re-exports).

### Changed

- Simplified first-time setup to remove the theme picker step and default to the system theme (preserving PiG's sprite step and pig head logo under D88).

### Deprecated

- Deprecated `showCacheMissNotices` in favor of `notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`, and `notices.reasoningDrops`. Existing `showCacheMissNotices` values are migrated to all four keys on load and dropped on save.
- Deprecated `SettingsManager.GetShowCacheMissNotices` and `SettingsManager.SetShowCacheMissNotices` (plus equivalent wrappers in the Python, Rust, and Common Lisp SDKs and `coding.Settings.ShowCacheMissNotices`); in 0.8.x they delegate to `notices.cacheMisses` and are scheduled for removal in 0.9.0 (`SettingsManager.GetNotices` and `SettingsManager.SetNotice` replace them).

### Fixed

- Startup dialogs (project trust prompt, missing session folder prompt, and first-time setup) now report OSC 7501 `blocked` program status, multi-line dialog titles report only their first line as the blocked message, project trust and first-time setup report `kind=permission`, and `FormatProgramStatus` omits unknown or malformed `kind` values. <!-- fix: d58069bb30 --> <!-- cause: startup dialogs ran on a temporary TUI before ProgramStatusReporter existed and in-session dialogs passed multi-line titles unsplit -->
- Rebuilt `!` bash execution blocks now follow the current `ctrl+o` (`toolsExpanded`) state on `/reload`, `/resume`, `/tree`, and compaction rebuilds. <!-- fix: e59e98a419 --> <!-- cause: renderSessionEntries constructed BashExecutionComponent without calling SetExpanded(m.toolsExpanded) -->
- Markdown after an unclosed currency `$` before a digit (such as `+$50`) or across a line break now renders normally instead of being swallowed as pending inline LaTeX. <!-- fix: 8c6c8644da --> <!-- cause: tokenizeInlineLatex treated any unclosed $ matching looksLikePendingDollarMath as pending math even before a digit or across newlines -->
- Synthetic right-click paste on Windows is now skipped in Tabby (`TERM_PROGRAM=Tabby`) in addition to VS Code to prevent double paste. <!-- fix: 4dcc3d7a2f --> <!-- cause: handleRightClickPaste only excluded TERM_PROGRAM=vscode -->
- `Hyperlink()` (in `tui` and all extension SDKs) no longer emits OSC 8 sequences for URLs longer than 8192 UTF-16 code units, preventing quadratic memory growth when wrapping bare URLs that run into multi-megabyte lines. <!-- fix: 274758129b --> <!-- cause: wrapTextWithAnsi reopened the full OSC 8 URL on every wrapped line without a URL length cap -->
- `wl-copy` now receives explicit `-t text/plain` on Wayland so clipboard managers such as Klipper do not drop text whose inferred MIME type is non-text. <!-- fix: d9edfc9742 --> <!-- cause: wl-copy was invoked without -t text/plain and guessed non-text MIME types for inputs starting with keywords like def -->
- Completed Mermaid diagrams wider than the available terminal width now display a `Mermaid diagram not rendered: needs N columns, M available` note below their source (while staying silent during streaming and prioritizing parse warnings over width warnings). <!-- fix: 904cc8fad2 --> <!-- cause: renderMermaidToken returned raw source silently when art.Width > context.AvailableWidth -->
