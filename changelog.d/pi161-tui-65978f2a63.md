### Upgrading

- Replaced the `showCacheMissNotices` setting with per-notice toggles (`notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`, `notices.reasoningDrops`) under Notices in `/settings`. Existing `showCacheMissNotices` values are migrated to all four keys. `SettingsManager.GetShowCacheMissNotices` and `SettingsManager.SetShowCacheMissNotices` were removed; use `SettingsManager.GetNotices` and `SettingsManager.SetNotice` instead.

### Added

- Added `BlockedKind` (`"permission"`, `"question"`, `"auth"`) to `ExtensionUIDialogOptions` and all extension SDKs (`DialogOptions.BlockedKind` in Go, `blocked_kind` in Python and Rust, `:blocked-kind` in Common Lisp) so `select()`, `confirm()`, and `input()` dialogs can specify their OSC 7501 blocked program status kind.
- Added per-notice transcript visibility settings (`notices.cacheMisses`, `notices.cacheWarming`, `notices.compactionCosts`, `notices.reasoningDrops`) under Notices in `/settings`.

### Changed

- Simplified first-time setup to remove the theme picker step and default to the system theme (preserving PiG's sprite step and pig head logo under D88).

### Removed

- Removed `SettingsManager.GetShowCacheMissNotices` and `SettingsManager.SetShowCacheMissNotices` in favor of `SettingsManager.GetNotices` and `SettingsManager.SetNotice`.

### Fixed

- Startup dialogs (project trust prompt, missing session folder prompt, and first-time setup) now report OSC 7501 `blocked` program status, multi-line dialog titles report only their first line as the blocked message, and project trust and first-time setup report `kind=permission`. <!-- fix: d58069bb30 --> <!-- cause: startup dialogs ran on a temporary TUI before ProgramStatusReporter existed and in-session dialogs passed multi-line titles unsplit -->
- Rebuilt `!` bash execution blocks now follow the current `ctrl+o` (`toolsExpanded`) state on `/reload`, `/resume`, `/tree`, and compaction rebuilds. <!-- fix: e59e98a419 --> <!-- cause: renderSessionEntries constructed BashExecutionComponent without calling SetExpanded(m.toolsExpanded) -->
- Markdown after an unclosed currency `$` before a digit (such as `+$50`) or across a line break now renders normally instead of being swallowed as pending inline LaTeX. <!-- fix: 8c6c8644da --> <!-- cause: tokenizeInlineLatex treated any unclosed $ matching looksLikePendingDollarMath as pending math even before a digit or across newlines -->
- Synthetic right-click paste on Windows is now skipped in Tabby (`TERM_PROGRAM=Tabby`) in addition to VS Code to prevent double paste. <!-- fix: 4dcc3d7a2f --> <!-- cause: handleRightClickPaste only excluded TERM_PROGRAM=vscode -->
- `Hyperlink()` no longer emits OSC 8 sequences for URLs longer than 8192 bytes, preventing quadratic memory growth when wrapping bare URLs that run into multi-megabyte lines. <!-- fix: 274758129b --> <!-- cause: wrapTextWithAnsi reopened the full OSC 8 URL on every wrapped line without a URL length cap -->
- `wl-copy` now receives explicit `-t text/plain` on Wayland so clipboard managers such as Klipper do not drop text whose inferred MIME type is non-text. <!-- fix: d9edfc9742 --> <!-- cause: wl-copy was invoked without -t text/plain and guessed non-text MIME types for inputs starting with keywords like def -->
- Completed Mermaid diagrams wider than the available terminal width now display a `Mermaid diagram not rendered: needs N columns, M available` note below their source (while staying silent during streaming and prioritizing parse warnings over width warnings). <!-- fix: 904cc8fad2 --> <!-- cause: renderMermaidToken returned raw source silently when art.Width > context.AvailableWidth -->
