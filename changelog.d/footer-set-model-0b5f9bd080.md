### Fixed

- In the interactive mode, an extension's `pi.setModel` whose extension has `model_select` handlers could leave the footer on the previous model's context window until the next keystroke. The model changed at once, but the footer was pushed only after the handlers replied, so a frame drawn in between (a key press, a stream tick) came from the cached footer and no render followed. The footer now changes in the same owner-loop unit as the session's model, and the handlers are awaited after it, off the owner loop.
