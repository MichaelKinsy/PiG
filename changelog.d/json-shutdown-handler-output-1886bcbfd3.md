### Fixed

- `--mode json` no longer writes what an extension's `session_shutdown` handler emits after `agent_settled`: the `entry_appended` line for `pi.appendEntry`, the `session_info_changed` line for `pi.setSessionName` and the `message_start` / `message_end` lines for `pi.sendMessage` are saved in the session file and not written, as in Pi, which detaches the JSON stream before it runs `session_shutdown` handlers. The stream ends with `agent_settled`, in a normal run and after a termination signal; lines already queued still reach a slow reader, and an extension error from the handler still goes to stderr. The bug has been in every release since v0.3.0. <!-- fix: 1886bcbfd3 --> <!-- cause: the normal teardown detached the JSON writer after closing the runtime (session_shutdown), and the entry_appended line was written outside the subscription without checking that the writer was detached -->
