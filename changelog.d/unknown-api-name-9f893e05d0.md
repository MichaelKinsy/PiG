### Security

- A `models.json` provider or model whose `api` is not the name of a registered API (a typo such as `openai-completion`, or any other unknown name, `constructor` and `toString` included) is now refused when its first request starts, with Pi's message `No API provider registered for api: <name>`, and nothing is sent: print mode exits 1 with that line on stderr, and RPC, JSON and interactive mode end the turn with it as the error. In 0.3.0 through 0.7.0, PiG built an OpenAI chat-completions request for any unknown name and sent the conversation, system prompt included, in one `POST` to `/chat/completions` under the `baseUrl` configured for that provider entry. The request went to that configured base URL and to no other host. What to check: a `models.json` provider or model whose `api` is not one of the known names sent each prompt's conversation to its own base URL in that form. The same held for a provider that an extension registers with an unknown `api` and no stream handler of its own. An `api` name for which an extension registers an implementation keeps working. The Go `ai.StreamSimple` reports the same message for an api without an implementation. <!-- fix: 9f893e05d0 -->
