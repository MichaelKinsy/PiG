### Security

- A `models.json` provider or model whose `api` is not the name of a registered API (a typo such as `openai-completion`, or any other unknown name) is now refused when its first request starts, with Pi's message `No API provider registered for api: <name>`, and nothing is sent: print mode exits 1 with that line on stderr, and RPC, JSON and interactive mode end the turn with it as the error. Before, PiG built an OpenAI chat-completions request for any unknown name and sent the conversation, system prompt included, to the provider's `baseUrl`. Affects 0.3.0 through 0.7.0. A model object with no api, which PiG built for a model id its registry does not list (for example through an extension's set-model call or the Go library's `BuildModel`), was sent as OpenAI chat completions to `api.openai.com` with the selected provider's credential and the conversation. Affects 0.2.0 through 0.7.0. It is now refused with `No API provider registered for api: undefined`, which is what Pi reports for a model object without an api, and nothing is sent. A GitHub Copilot model whose `api` is empty or is not one the Copilot catalog lists is refused the same way and is no longer sent as chat completions to the Copilot endpoint with the Copilot token, the conversation and the system prompt. What to check: any `models.json` provider or model whose `api` is not one of the known names sent its conversation to that base URL as OpenAI chat-completions. The same holds for a provider an extension registers with an unknown `api` and no stream handler of its own, and for the Go `ai.StreamSimple`, which now reports the same message even when the request has no key.
