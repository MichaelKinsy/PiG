### Changed

- A reload, a second session, `/resume` and `/fork` no longer read the Go SDK's files again to find the built cell of an extension. A process reads and hashes the SDK that this pig staged under `<config root>/state/pigsdk` once (212 files, 2.1 MB for an installed pig) and keeps the hash with each file's size and modification time; a later load walks the directory and checks those, reads no file, and looks for the cell under the kept hash. On the repository's larger SDK tree (424 files) a lookup takes 2.2 ms instead of 11 ms and 0 file reads instead of 424. A file that changed size or modification time, or was added, removed or renamed, makes the hash be computed again from the files, so an edited SDK still selects another cell and rebuilds it. The SDK of a source checkout (`extensions/sdk` found from the working directory, `PIG_SDK_GO_ROOT`) is still hashed by content on every load. A one-shot `pig -p` gains nothing, since its single load reads the SDK once. One edit is not seen: one that keeps both the size and the modification time of a file already older than two seconds (a tool that restores times); pig's own staging, the only writer of the staged SDK, replaces the directory with newly dated files. A build never uses the kept hash: it hashes the tree under its build lock, and again when the compiler returns.
