### Fixed

- Follows Pi c8c456c85c6e (#12234, same class as #12115): when the saved model of a session you resume, fork or continue no longer exists or has no login, the model Pi falls back to is now reported in every mode and after every replacement. The warning `Could not restore model <provider>/<id>. Using <provider>/<id>` was shown only at interactive startup; `/resume` and `/fork` into such a session, and RPC `switch_session` and `fork`, changed models without a word, and print, JSON and RPC mode never showed it even at startup. Interactive mode now shows it in the chat, above `Resumed session` after `/resume`, and print, JSON and RPC mode write `Warning: <message>` to stderr (RPC never writes it to stdout); a message already reported is not repeated (a second `/resume` into the same session shows nothing, a fallback to a different model shows its own line). The fallback model rule is unchanged (the saved model if it has a login, else the default model, else the first available model of the shared provider order). <!-- cause: the fallback message was read only by interactive startup through the modelFallbackMessage option; the runtime recomputed it on each replacement and nothing reported it, and the print and RPC runtime inputs never carried it; present since v0.3.0 (the startup model's ModelFallbackMessage) --> <!-- fix: 8f2ed99753 --> <!-- tests: TestRPCSwitchSessionReportsTheModelFallbackOnStderr, TestRPCStartAndForkReportTheModelFallbackOnStderr, TestPrintAndJSONReportTheModelFallbackOnStderr, TestNoModelsAvailableIsReportedOnceAsAWarning -->

### Changed

- Follows Pi c8c456c85c6e (#12234): with no model at all (no login, no `models.json` model) the `No models available. Use /login ...` guidance is now also a warning in the runtime diagnostics, so print, JSON and RPC mode write `Warning: No models available. ...` to stderr once, before the missing-key error that print and JSON mode already print, and RPC mode once at startup (not again after `switch_session` or `fork`). Pi's changelog line does not say this; it is what Pi itself does, measured: its model is never undefined (the agent starts with a placeholder model), so the commit's "unchanged" for this case does not hold.
