### Added

- Durable crash-loop guard (Pi `a30c2a81`): open counts each task that a crash, eviction, or reset cut off (`TaskRecord.Restarts`); a close writes the tasks it stopped back as `pending` without a count, and a new state the task commits starts the count over. At `HarnessSettings.RestartLimit` (default 5; `+Inf` never parks) the task is parked: blocked with reason `restart_limit` in `Inspect` and the task graph, not active in `Wake`, and reported once. `Harness.RetryTask` runs it again. An abort handler cut off that many times ends its task `faulted` with detail `{reason: "restart_limit"}`. Both Durable engines (the reference Harness and the core) implement it.
- `OnReport` receives a second argument, `durable.ReportInfo`, that says what the report is about: `session_failed`, `task_faulted`, `task_parked`, `migration_failed`, `task_outdated`, `task_error`, `extension_error`, `host_error` or `listener_error`, with the task, the extension that installed its definition, the failing host callback, or the conversation. `TaskRuntime.Report` takes an optional `durable.ReportFrom` to report extension or host code a task called.
- `HarnessSettings.AfterFailedRun`: a run that fails with `model_error` or `no_model` keeps the inputs queued behind it (`keep`, the default), starts the next run with them (`continue`), or settles them `unanswered` with reason `run_failed` (`withdraw`).
- The task graph shows why a task cannot run (`TaskGraphNode.Blocked`: `missing_task`, `task_too_old`, `migration_failed`, `restart_limit`) and follows registry changes and failed migrations. A registry change that unblocks a task makes `OnWake` report the Session active.

### Changed

- A task phase that faults is reported through `OnReport` as `task_faulted`, not only recorded in its outcome. A reconcile pass with work to do, such as the recovery of `OpenHarness`, keeps `Wake` active until it lands.
- `harness.AgentHooks` returns each hook handler table with the name of its extension, `harness.ResolveAgent` and `harness.RenderSections` pass the extension or section to their report callback, and `harness.NewTaskGraphView` takes the scheduler's blocked-reason source.
- The core's ABI gains the `retryTask` api op, and its `report` notice carries an `info` member.

### Upgrading

- `HarnessOptions.OnReport` is now `func(err error, info durable.ReportInfo)`, and `durable.TaskRuntime` has `Report(err error, from ...ReportFrom)`: code that sets either must take the new parameter. `harness.Harness` has `RetryTask`.
- A task cut off by a crash 5 times in a row without committing a new state is parked instead of run again; set `HarnessSettings.RestartLimit` to `+Inf` to keep the old behavior. `TaskInspectionState.Reason` can be `restart_limit`.
