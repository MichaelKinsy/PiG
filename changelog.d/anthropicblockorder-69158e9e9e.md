### Fixed

- Anthropic Messages requests are now byte for byte the requests Pi sends. PiG wrote four objects of the request body with their members in another order than Pi's `JSON.stringify` does; the content was the same. A text block carrying the conversation's cache breakpoint was `type, cache_control, text` (Pi: `type, text, cache_control`). An image source, in a user message or in a tool result, was `data, media_type, type` (Pi: `type, media_type, data`). The request's optional members were `system, tools, tool_choice, metadata, thinking, output_config, temperature` (Pi: `system, temperature, tools, thinking, output_config, metadata, tool_choice`). A tool choice object sent by an extension had its keys sorted, where Pi sends the extension's own order. This held for every provider that uses the Anthropic Messages API: Anthropic with an API key or OAuth, GitHub Copilot, OpenRouter, OpenCode, Vercel AI Gateway, MiniMax, Fireworks, Cloudflare AI Gateway and custom base URLs. Anthropic's prompt caching documentation says a cache hit needs an identical prompt prefix and names the key order of `tool_use` blocks as part of it; it does not say whether the member order of the objects fixed here is. <!-- fix: 69158e9e9e -->
