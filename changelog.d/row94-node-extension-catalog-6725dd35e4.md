### Changed

- A start with a Node extension waits less before the extension's first handler runs. The host built the model catalog it hands the extension (about 2,500 models, 1.45 MB) on one processor; it now converts the models on up to eight processors, never more than the machine runs at once, and joins them in the catalog's own order, so the frame the extension receives is the same sequence of bytes as before. Measured with 30 warm starts of pig with a Node extension in json mode, on a loaded 192-processor host with the client held to four processors: the first reply began after 317 ms (median), now 275 ms; Pi with the same extension began after 336 ms. On a machine with one free processor the start takes as long as before. Extensions in Go, Python, Rust and Lisp, which ask the host for the catalog when they read it, are not affected.
