### Added

- Durable JSONL storage opens read-only with `JsonlStorageOptions{ReadOnly: true}` (`jsonl.Open`, `OpenNodeJsonlStorage`), for a viewer of a directory another process writes, as Pi's `{ readOnly: true }` does. A writable open repairs files on recovery: it truncates torn lines and unconfirmed sidecar records and reclaims sidecars, which can cut records a running writer just appended. The read-only open creates and writes nothing, skips those records in memory, holds the state committed at open, and `Commit` rejects with `*JsonlStorageReadOnlyError`. A recovery that fails because it raced a writer's commit is retried (up to five opens). `HarnessOptions.ReadOnly` does not reach the storage open, so a read-only viewer opens JSONL storage this way too; `NodeFileSystem` gains `FileInfo`, which the retry check reads, and the exported `jsonl.FileSystem` interface now requires `FileInfo(ctx, path) (env.FileInfo, error)`: an implementer outside this repository must add it (any `env.FileSystem` already has it).
