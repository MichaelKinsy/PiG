### Fixed

- A Go extension that reorders, filters or sorts an array of an event in place (the content blocks of a message, a provider request's `tools`, a list of messages or entries) and hands it back no longer re-sorts the keys of the moved objects, so tool-call arguments and tool schemas reach the session and the provider in the order the host sent them. The order of every object is recorded when the event is decoded and each object is identified by its own map, so no object is ever given another's order: sorting a provider request's `tools`, swapping siblings whose leading strings match, or editing a string in place keeps every member order, and redacting every message of a 10,000-message context in place takes 97 ms where it took 3 s. A Go handler that returns nothing does not read the event to write its reply. `Context.ObjectKeys` lists integer-like keys first and ascending, as `Object.keys` does. <!-- fix: 3de4b8e877c8fc4d3b7bedafa5e8ae8cbad7161f -->
