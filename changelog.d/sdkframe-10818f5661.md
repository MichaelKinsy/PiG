### Fixed

- Go extensions that receive large event payloads (`before_provider_request`, `agent_end`, `turn_end`) decode them about four times faster and allocate about half as much: the SDK and the host validated each frame with a byte-at-a-time scanner, scanned a request's arguments again to skip them, copied them, and validated and scanned them twice more to hand the event to a handler. On a 43 MiB provider payload, the read and decode of one request frame fell from about 600-800 ms to about 225 ms and from 181 MB to 101 MB allocated, and the host's read of a frame an extension sent from about 130 to about 500 MB/s. Malformed frames end the connection with the same error as before, and every value decodes to the same Go value. The Lisp SDK decoded a frame with many escaped strings in time quadratic in the frame (a 16 MiB frame took 20 s, now 0.15 s). <!-- fix: 10818f5661 -->
