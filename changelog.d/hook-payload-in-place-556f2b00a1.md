### Fixed

- A `before_provider_request` handler that edits `event.payload` in place and returns nothing now changes the request the provider receives, as it does in Pi, in the Go, Node, Python, Rust and Lisp extension SDKs, and so does an edit made before the handler throws. A `before_provider_headers` handler's in-place edit of `event.headers` is kept the same way when the handler throws, and in the Go, Python, Rust and Lisp SDKs when it returns normally (the Node SDK already kept it then). Until now only a payload a handler returned took effect, so an edit in place was lost, for every provider, in every SDK. Each SDK sends back the payload as the handler left it when it differs from the one it received, in the member order the handler's object has. The loss was present in v0.7.0. <!-- fix: 556f2b00a1 -->
