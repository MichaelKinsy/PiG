### Fixed

- Closing a `coding.Session` that built its own `DefaultResourceLoader` now shuts down its Extension Host (D19) when the last Session sharing it closes, and a failed `NewSession` closes that loader before returning. Previously, child sessions created by an extension with no resources of their own (one Extension Host process per child stayed until the parent exited) and Go SDK embedders who create a Session without a loader leaked extension subprocesses past `Session.Close`, blocking directory cleanup on Windows. Affects 0.7.0. <!-- fix: 649bef3ed6 --> <!-- cause: resolveResourceLoader constructed a DefaultResourceLoader for Sessions without a supplied or Services-owned loader, and neither Session.Close nor NewSession error paths ever closed it, leaking its Extension Host subprocesses. -->
