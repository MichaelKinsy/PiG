### Fixed

- Closing a `coding.Session` that built its own `DefaultResourceLoader` now shuts down its Extension Host (D19) when the last Session sharing it closes, and a failed `NewSession` closes that loader before returning. Previously, child sessions created by an extension with no resources of their own (one Extension Host process per child stayed until the parent exited) and Go SDK embedders who create a Session without a loader leaked extension subprocesses past `Session.Close`, blocking directory cleanup on Windows. A `Clone` of a Session that was already closed now constructs a fresh resource loader and Extension Host of its own (previously it ran on the closed Session's leaked one), which an embedder can observe as a new extension process.
