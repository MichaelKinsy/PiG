### Fixed

- A `tool_result` handler that edits the event in place now has the edit seen by the next handler of the chain and kept for the result, as in Pi, in every extension SDK. Assigning `event.content`, `event.details` or `event.isError` is what the next handler reads; editing a block of the content or a member of the details in place also changes the result the tool returns, and an edit made before the handler throws holds as well. A member assigned another value reaches the result only through a result a handler returns, as in Pi. Until now only a result a handler returned took effect, so every in-place edit was lost, in every SDK, in every release since v0.2.0. The Go and Rust SDKs cannot tell assigning a new list or object from editing the one they received, and treat a changed list or object member as an edit of the received one. <!-- fix: 549df8005d -->
