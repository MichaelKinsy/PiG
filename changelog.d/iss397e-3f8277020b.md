### Fixed

- A terminal write that fails for a reason other than a lost terminal while the keyboard protocol is on no longer hangs the exit: the terminal restore does not wait for the output lock the failing write holds, so the terminal is handed back and the process exits 1 as Pi's uncaught-exception handler does (#397). <!-- fix: 3f8277020b -->
- On Windows, `ERROR_PIPE_NOT_CONNECTED`, `ERROR_BAD_PIPE`, `ERROR_GEN_FAILURE`, `ERROR_IO_DEVICE` and `ERROR_NOT_CONNECTED` on the terminal now exit 129 as Pi does, instead of a crash report and exit 1 (#397). <!-- fix: 3f8277020b -->
