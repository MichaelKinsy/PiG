### Fixed

- Closing an RPC client's input while a `bash` command is running, or quitting interactive mode with Ctrl+D while a `!` command is running and an extension's `session_shutdown` handler never settles (the drained-loop quit), left that shell command and its descendants running after `pig` exited 0. `pig` now kills tracked shell process trees before exiting on both paths, as it already does on `/quit`, and on Windows bounds the whole exit-path kill (taskkill, job termination, and waiting on job members) at 2,000 ms (following Pi 31b407dc63, #11889).
