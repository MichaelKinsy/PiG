### Changed

- `--mode rpc` sessions collect garbage less often when `GOGC` is not set in the environment, as `-p` and `--mode json` runs already do: the Go GC target is 400 until a collection finds more than 64 MiB live, then the default 100. Measured on a mock-provider session with one tool call per turn (Linux arm64, 4 CPUs): CPU per turn fell from 5.7 to 4.7 ms at 200 turns and from 6.7 to 5.4 ms at 1,000 turns (the run-to-run spread of the same binary is about 0.3 ms), and 32 concurrent sessions of 50 turns fell from about 4.7 to 3.3 ms per turn. Peak memory rose from 52 to 74 MiB at 200 turns, from 57 to 81 MiB at 1,000 turns and from about 38 to 55 MiB per session in the 32-session run. A `GOGC` you set is used as is, interactive sessions are unchanged, and output is unchanged.
