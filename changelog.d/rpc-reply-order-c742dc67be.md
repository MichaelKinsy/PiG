### Fixed

- An RPC client could receive a Node extension's notification or other fire-and-forget UI call (`notify`, `setStatus`, `setWidget`, `setTitle`, `setEditorText`, `pasteToEditor`, or `entry_appended` from `pi.appendEntry`) before the reply of the command that caused it (`set_session_name`, `set_thinking_level`, `cycle_thinking_level`, or `set_model` / `cycle_model` when the thinking level changes without an awaiting `model_select` handler). Post-acknowledgment fire-and-forget output calls now wait off the read loop until the originating command's reply is written, matching Pi's event-loop microtask ordering, and release immediately on command error, abort, session close, stdout failure, or shutdown. <!-- fix: c742dc67be --> <!-- cause: Conn.readLoop acknowledged blocked unawaited handlers before the RPC command wrote its response, letting post-await fire-and-forget UI calls overtake the command reply -->
