### Security

- The Node extension runtime's bundled `undici` is updated from 8.12.3 to 8.12.4, which Pi's `efbcd5adb4bc` does for the six advisories GHSA-mqg3-3v4r-cm32 (high: the cache interceptor could store a redirect chain's final response under the original request key, poisoning a cache or exposing one user's response to another; affected `>= 8.12.2, < 8.12.4`), GHSA-7xg3-fphp-28hg (a shared cache behind `compose(redirect(), cache())` could store a credential-dependent response of a same-origin redirect), GHSA-5rm8-gv32-r954 (a cross-origin redirect during cache revalidation could let a `304` validate another origin's cached response), GHSA-9v6h-8rgp-m69f (the redirect interceptor did not strip credentials from request headers given as `[name, value]` pairs), GHSA-3g9m-rv3r-w5w2 (a handler exception during cache replay could end the process) and GHSA-r4pc-4jcp-7pqc (`fetch()` could skip Subresource Integrity verification when the integrity metadata was separated or surrounded by a tab or another ASCII whitespace other than a space). The last five are affected `>= 8.0.0, < 8.12.4`. The ranges and patched versions are those of GitHub's repository advisory API for `nodejs/undici` (`GET /repos/nodejs/undici/security-advisories/<id>`, read 2026-11-16). Only the Node extension runtime that PiG embeds (`runtime-node/shims/undici`, used by extensions that run on Node) carries undici; the Go `pig` binary has its own HTTP transport and is not affected. An extension that imports the runtime's `undici` and sets `integrity` on `fetch()` or composes its redirect and cache interceptors ran the vulnerable code. `npm audit` reports 0 vulnerabilities for every PiG lock before and after, because the npm advisory feed does not list these six yet (it does not flag undici 7.30.1 either), so it is not evidence either way. The two npm-bundled `undici` 6.x pins (`automation/images/npm-runtime`, `automation/ci/npm-toolchain`) are outside every affected range (all start at 7.0.0) and stay at 6.29.1. The parity oracle's installed Pi, the `automation/images/ci-parity` lock, `extensions/sdk-ts`, and the benchmark extension sets under `bench/bolt-aot` resolve 8.12.4 too. Follows Pi efbcd5adb4bc.
