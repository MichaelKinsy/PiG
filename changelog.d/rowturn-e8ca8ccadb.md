### Changed

- A tool that produces the same large text again returns the string the conversation already holds. `read`, `grep`, `find`, `ls` and `bash` share an output of 4 KiB or more with an equal output produced earlier in the process (a file read again, a search or a listing repeated), so the conversation keeps that text once however often it was produced; tool results, request bodies and session entries are the same bytes. On the fake-model benchmark, where each prompt reads the same four files, the process's own memory after 40 prompts fell from 35.8 MB to 23.4 MB (33.5 % less, 7 of 7 paired runs against the base) and after 20 prompts from 24.9 MB to 20.1 MB (18.1 % less, 8 of 8); CPU per prompt stayed inside the noise (1.1 % more, 5 of 7 and 4 of 8 pairs) and user instructions rose by 5.0 % and 1.4 % because the smaller heap is collected more often. A session whose reads are all different gains nothing: there the process still holds each large text and its encoding (51 MB after 40 prompts of 160 different reads, the same as Pi-Bolt 1.2.1).
