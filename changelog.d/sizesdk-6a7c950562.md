### Changed

- The `pig` binary is 344,064 bytes smaller (64,368,903 to 64,024,839 stripped on linux/amd64). Each embedded SDK (Go, Python, Rust and Lisp) is one solid zstd frame of its files instead of a gzip per file (the Lisp SDK, a gzip tar): the Go SDK is 427,851 bytes (was 547,801), Python 244,679 (297,245), Rust 381,912 (470,923) and Lisp 230,586 (260,343). Staging decodes the frame once and writes every file from that buffer: staging the Go SDK allocates 2.6 MB in about 12 ms where it allocated 13.0 MB in about 35 ms, and staging the four SDKs together grows the process by 6.3 MB of resident memory at most instead of 7.9 MB. The staged files are the same bytes as before.
- A start whose staged SDKs are current no longer hashes the embedded SDKs: the staging hash of each SDK is generated with it, so the check reads one marker per language and decodes nothing (a warm `EnsureSynced` took 1.6 to 2.4 ms and 1,950 allocations, and takes 0.13 ms and 69). The Go, Python and Rust staged directories get new names once (`sdk-<hash>`, `sdk-py-<hash>`, `sdk-rs-<hash>`), because their hash now covers the files' text, as the Lisp hash already did; the first start after the upgrade stages them again, and extension builds whose SDK files did not change stay reachable.
- The Go SDK module `extensions/sdk` is unchanged: its `Source` and `BundledFiles()` are what the published module has. The root module packs the module's sources itself, in `internal/gosdkbundle`, which `automation/gen/packsdk` generates from `extensions/sdk` (a zstd frame, `sdk.zst`, with the file list and the staging hash); the Python, Rust and Lisp SDK packages hold the same kind of frame. In those three packages `Source` holds the one file `sdk.zst`, `BundledFiles()` names the staged files themselves, and the new `StagedHash()` returns the hash the staged directory is marked with. None of them decodes the frame: `coding/extension/pigsdk` does. `make sdk-bundles` regenerates every frame and list.
