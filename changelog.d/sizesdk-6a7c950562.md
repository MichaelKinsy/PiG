### Changed

- The `pig` binary is 344,064 bytes smaller (64,368,903 to 64,024,839 stripped on linux/amd64). Each embedded SDK (Go, Python, Rust and Lisp) is one solid zstd frame of its files instead of a gzip per file (the Lisp SDK, a gzip tar): the Go SDK is 427,851 bytes (was 547,801), Python 244,679 (297,245), Rust 381,912 (470,923) and Lisp 230,586 (260,343). Staging decodes the frame once and writes every file from that buffer: staging the Go SDK allocates 2.6 MB in 12 ms where it allocated 13.0 MB in 33 ms, and the four SDKs together stage with a peak of 6.3 MB resident instead of 7.9 MB. The staged files are the same bytes as before.
- A start whose staged SDKs are current no longer hashes the embedded SDKs: the staging hash of each SDK is generated with it, so the check reads one marker per language and decodes nothing (a warm `EnsureSynced` took 1.6 to 2.4 ms and 1,950 allocations, and takes 0.13 ms and 69). The Go, Python and Rust staged directories get new names once (`sdk-<hash>`, `sdk-py-<hash>`, `sdk-rs-<hash>`), because their hash now covers the files' text, as the Lisp hash already did; the first start after the upgrade stages them again, and extension builds whose SDK files did not change stay reachable.
- The Go SDK's `Source` now holds the one file `sdk.zst` (a zstd frame; `internal/sdkpack` lays out its files) where it held one gzip per file, and `BundledFiles()` names the staged files themselves, not `.gz/<name>.gz`. The new `StagedHash()` returns the hash the staged directory is marked with. The SDK module does not decode the frame and stays free of dependencies. `make sdk-bundles` regenerates the frames and lists of all four SDKs with `automation/gen/packsdk`.
