### Upgrading

- If your code supplies or calls `extension.NativeProvider.ResolveAuth` (a host that registers a native provider through `subprocess.Host.SetNativeProviderCallback`, or code that calls the field on a provider it received), change its signature from `func(ctx, *ai.Credential, ai.AuthResolutionOverrides) (*ai.AuthResult, *ai.Credential, error)` to `func(ctx, ai.CredentialStore, ai.AuthResolutionOverrides) (*ai.AuthResult, error)`. The function now receives the registry's credential store and persists a refresh through it (`ai.ResolveProviderAuth` is the implementation to call), so it no longer returns the refreshed credential for the caller to save.

### Fixed

- Quitting while an OAuth token refresh is in flight no longer loses the new token. If pig exited after the token request went out but before the new token was written, `auth.json` kept the refresh token the provider had already spent and the next request failed with `invalid_grant`; an RPC client that stopped pig right after startup, while the background catalog refresh refreshed an expired login, hit this. Interactive, print, JSON and RPC mode now wait for a refresh that has started to be saved before the process exits, with no timeout beyond the 15 s refresh and the 30 s auth lock wait; a second signal exits at once in RPC and print mode. The wait comes before pig stops its extensions, and a refresh that has started (a subprocess extension provider's, in the catalog refresh or at request time, or the Radius gateway's) is no longer cut or discarded when its caller is cancelled, as Pi main does (D237). <!-- fix: 7febcec6be -->
