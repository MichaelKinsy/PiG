### Fixed

- OpenAI Responses requests replay a stored reasoning item as it was stored, and the items of a client tool search have Pi's member order. A replayed reasoning item was rewritten `type, id, summary, encrypted_content` and lost any member PiG does not know; Pi sends the stored object as the provider wrote it. The `tool_search_call` and `tool_search_output` items were written `type, status, call_id, ...` (Pi: `type, call_id, execution, status, ...`). This held for OpenAI, Azure OpenAI and ChatGPT (Codex) Responses. A stored reasoning signature that is not JSON now ends the request with the JSON error before anything is sent, as in Pi, where PiG dropped the block and sent the request; only a block of the same provider, API and model id with such a signature reaches this, which means a hand-edited or corrupted session. <!-- fix: 202aea01ba -->
