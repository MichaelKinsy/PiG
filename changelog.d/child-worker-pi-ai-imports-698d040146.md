### Changed

- A worker thread or a forked child of a Node extension no longer resolves `@earendil-works/pi-ai` (the root and `/compat`, `/models`, `/oauth`, `/providers/all`) when the extension has no copy of the package in its own `node_modules`. It resolved there up to v0.7.0 because PiG started the extension with `--import` of its loader, which a child or worker inherited; since the change that starts the extension without that flag (698d040146, the `process.execArgv` fix) they get none of PiG's module hooks and resolve as they do under Pi, so `import "@earendil-works/pi-ai"` fails there with `Cannot find package '@earendil-works/pi-ai'`. Install the package beside the extension (`npm install @earendil-works/pi-ai`), as under Pi. Where the extension has its own copy, the child and the worker now load that copy, as under Pi, instead of PiG's module; the extension's own process is unchanged. <!-- fix: 698d040146 -->
