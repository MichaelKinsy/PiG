### Added

- Go, Python and Rust extensions can override a built-in tool and delegate to the original, as Pi's `create<Tool>ToolDefinition` factories let Node extensions do. `sdk.CreateReadToolDefinition(cwd, opts)` (and the write, edit, bash, grep, find, ls and powershell siblings; Python `create_read_tool_definition`, Rust `create_read_tool_definition`) return the tool's definition, which registers as is, and whose `Execute` runs the host's own tool with Pi's options: `operations` and `spawnHook` functions stay in the extension and are called back while the call runs. The `create<Tool>Tool` forms, `createCodingTools`, `createReadOnlyTools`, `createLocalBashOperations` and `createLocalPowerShellOperations` come with them. New host calls `builtinTool.definition`, `builtinTool.execute` and `builtinTool.localExec`. A built-in's result is a value an `Execute` can return or pass to `OnUpdate` as it is. `TestConformance_BuiltinToolDelegationAcrossSDKs` compares every SDK with Pi's own code. <!-- fix: 1b5b705930 -->

### Upgrading

- Go SDK: `sdk.AgentToolResult` now marshals as the wire object a tool returns (`content` blocks, `structured_content`, `is_error`) instead of Pi's member names; it was only ever decoded before. Code that marshals it for another purpose should build its own struct.
