### Fixed

- An extension that a child agent session's resource loader loads now receives the session's events, as in Pi, where `createAgentSession` over a `DefaultResourceLoader` that loads an extension gives it `session_start` (after `bindExtensions`), `input`, `before_agent_start`, `agent_start`, `turn_*`, `message_*`, `context` and `agent_end`. In the Go, Python and Rust SDKs (through the `resources` option or a `resourceLoader` handle) the extension registered its tools and then received nothing: the loader started its extensions under the context of the call that reloaded it, which ends when `createAgentSession` returns, so the host stopped every extension it had just loaded and reported no error. The loader now owns its extensions until its next load or `Close`; the context of a reload still ends the reload itself. <!-- fix: 5f03fa4a4e, d8da9b372a, 78c1d22259 -->
- The contexts of those extensions read the child session: `ctx.model`, `ctx.scopedModels` (the session's `scopedModels`, which the child wire accepted and no extension saw), `ctx.isIdle()`, `ctx.hasUI` (false) and the headless dialogs (`notify`, `select`, `input` and `editor` answer nothing, `confirm` answers false), as the context of a Pi child session has. The loader's extension host has a headless UI bridge for this, and a child session binds the state print mode binds to it. <!-- fix: 5f03fa4a4e, d8da9b372a -->
- `coding.CreateAgentSession` binds the Session it returns to the Extension Host its resource loader started, as it does for a child session an extension creates: the loader's extensions read the Session's model, scopedModels, idle state, tools and session, with no UI. The helpers that bind a Session to subprocess extensions in every mode (`ExtensionHostSessionActions`, `BindSessionExtensionActions`, `BindSessionReadActions`, `BindSessionModelOperations`, `WatchSessionRunSignal`) moved from the CLI package to `coding`, so print, JSON, RPC and interactive mode and a library caller run the same code. <!-- fix: 5ac5e1ad05 -->
