### Changed

- CI: the nightly workflow's race and allocation jobs prepare the pinned Pi oracle with `make upstream-mirror`, the step `ci.yml`'s Linux job runs, so the Pi-oracle tests find the npm trees they import from (`durable/interop`, `internal/typebox/testdata/npm`, `ai/testdata/sdk`) and the two workflows cannot list different installs; the race job installs the pinned SBCL as `ci.yml` does, which `cmd/pig`'s Lisp SDK test needs. The agent, ai, libs and rest shards failed every night with `ERR_MODULE_NOT_FOUND`, and cli shard 4/4 with `sbcl is required`.
- CI: the nightly fuzz job's timeout is 60 minutes, not 30: the 47 targets take 41 s each (30 s of fuzzing, 11 s of build and corpus work), so the job was cancelled at the 41st on 2026-11-05, 11-06 and 11-08 and the last targets were never fuzzed. A test fails when targets are added past what the timeout covers.
- CI: `FuzzMarkdownRenderStaysWithinWidth` allows the one row Pi's Markdown emits wider than the width, a double-width character at width 1 (`breakLongWord` appends a grapheme to a fresh row whatever its width); every other wider row still fails.
- The allocation benchmarks that start a program (`BenchmarkClipboardImageCommand`, `BenchmarkNpmMetadataLookup`, `BenchmarkPackageInheritedOutput`) run with `PATH` alone, and `BenchmarkClipboardImageCommand` reads no `binfmt_misc` handlers (every spawn reads each one the machine registers, about 14 allocations each), so their allocs/op no longer follow the variables, the `PATH` and the kernel registrations of the machine that runs them; `BenchmarkAutocompleteCommandOrder` runs with a one-directory `PATH`.
- The allocation baseline lowers 32 entries that the code had improved on, adds the 23 benchmarks it had no entry for, and raises `BenchmarkSessionClone` from 26213 to 36097 allocs/op: `/fork` of a file-backed session streams the branch to the clone's file and opens that file as a resume does, which holds a 427 MB session's peak at Pi's level and costs the clone's index build, about 16 allocations a record.

### Fixed

- Searching a long session in `/tree` allocates 30% less than in 0.7.0: lowercasing text with non-ASCII characters (the search text of every row, model ids and names, and other callers of `jsstring.ToLower`) made a second copy of each text, which raised `BenchmarkTreeRecompute` by 43%. <!-- fix: 87d4c01443 -->
- `/fork` of a session that is not file-backed builds the clone's entries from the source's decoded messages again instead of decoding every record a second time, which doubled the allocations of that clone. <!-- fix: a0eeb24909 -->
- Every frame the renderer paints allocates two fewer objects: the cursor's hide and show copied their escape sequence into a new slice, where they had copied it into a pooled buffer before dead-terminal handling routed them through `WriteToTerminal`. <!-- fix: 72999669a8 -->
