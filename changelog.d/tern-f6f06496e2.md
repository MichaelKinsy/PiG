### Changed

- The release job now builds the release commit the way `go install github.com/MichaelKinsy/PiG/cmd/pig@v<version>` does, before it creates the draft release. `go.work` resolves `extensions/sdk` to the working tree in every other build, and `make module-publication` only proves that the nested tags exist, so a release commit that used SDK API its tag lacked could reach a root tag that nobody could build. `automation/ci/check-module-build.py --fresh-cache` builds the root module and every workspace module with `GOWORK=off` from an empty module cache, after the nested tags exist, and fails the publish job on any compile error. `make module-build` runs the same gate, and `make module-build-selftest` proves on a fixture module and a file proxy that it fails while the required SDK version lacks an API a `go.work` supplies and passes once the requirement or a local replace supplies it. `make module-build-report` runs in the drift shard and in `make check`; it never fails, and it lists in the job summary each symbol the required nested versions lack and the files that use them. <!-- fix: f6f06496e2 -->
