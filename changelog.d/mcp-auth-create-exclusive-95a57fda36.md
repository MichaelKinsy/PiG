### Fixed

- Two pig processes opening the MCP OAuth credential file (`mcp-auth.json`) for the first time at the same moment, or reaching it while it was being replaced, could overwrite every stored MCP login with `{}`. The initial file creation used a truncating write after an unlocked existence check instead of exclusive creation, so a late create could land on top of a credential another process had already written; `mcp-auth.json` is now created exclusively with owner-only access (following dangling symlinks), so an existing file is never overwritten by the create. <!-- fix: 95a57fda36 --> <!-- cause: FileAuthStorageBackend.WithLock used unlocked os.Stat followed by truncating os.WriteFile("{}") before locking, so a concurrent caller seeing mcp-auth.json absent overwrote an existing credential file. -->
