### Fixed

- Typing `@` in the editor, the `find` and `grep` tools and the tools status no longer treat a program that is not fd or ripgrep as one. Debian's `fdclone` package installs a file manager as `/usr/bin/fd`; it opened `/dev/tty` and took over the terminal, and it hid a real fd installed as `fdfind`. A system `fd`, `fdfind` or `rg` is now used only if `<bin> --version` exits 0 and prints `fd `, `fdfind ` or `ripgrep ` first; otherwise PiG tries the next name and then downloads its own, and the tools status no longer counts the impostor as installed. The check runs once per binary (cached by path, modification time and size), in a new session with stdin on `/dev/null` and a 5 s bound, and starts the program the way the searches do. The `@` search also runs fd in a new session, and on Windows without a visible console window. Pi has the same bug. <!-- fix: 4d731f2eec, 39b6e4dbe3 -->
