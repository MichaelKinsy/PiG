### Fixed

- Two calls of a Go, Python or Rust extension tool in one assistant message that each open a dialog now behave as Pi's one thread makes them behave, as Node extensions already did: the dialogs open in call order (a port's second dialog could open first), and when the user answers them back to back the calls respond, and end, in the order of the answers. The SDKs keep these orders for the calls of one parallel batch, which the host now names on each `tool_call` request (`batch`); calls of other batches, other sessions' calls and tools that open no dialog take no part and are never held. A handler that blocks on something other than a host call before its first dialog holds the first dialogs of the later calls of its batch, and a handler whose dialog was answered holds the later-answered handlers' responses until it returns or makes its next host call (recorded as divergence D187: Pi's single thread lets a call that awaits real work be overtaken). <!-- fix: 7fbd629d13, 835390ada3, 710ef28883, 0bb10c0c59, 631ca46e27, 1f93c47342, dc47fe5631 -->
