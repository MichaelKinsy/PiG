### Added

- Each release now publishes PiG Standard as its own artifact: `pig-standard-<version>-<os>-<arch>` archives (`.tar.gz`, `.zip` on Windows) for linux, darwin and windows on amd64 and arm64, separate from the Stock `pig-<version>-<os>-<arch>` archives. Each holds the Piglet Binary that `pig piglet build piglets/standard/pig-standard.yaml --format binary` builds on a native runner for its target. They carry their own SBOMs, vulnerability scan, checksums (in the release `SHA256SUMS`), build-provenance attestation and Sigstore bundle. A smoke run on every target extracts the archive and starts the Binary offline, and requires `pig-standard version` to report the release version, `pig-standard verify --json` to report that version as its Piglet release, and `pig-standard status` to name `pig-standard` as the active Piglet. Termux has no PiG Standard archive. The Binary reports `build: dev`, so each archive also ships its Piglet build record (`-build-record.json`) with the source commit it was built from. `make set-version` now writes the exact release version, not a `-dev` one, into `piglets/standard/pig-standard.yaml`, so a release-prepared tree builds Standard.
