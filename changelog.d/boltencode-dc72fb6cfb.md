### Changed

- A large tool-result text (4 KiB or more) is escaped to JSON once: the `read` tool's structured result, the session entry that records the text and the request that sends it share one cached encoding, where each escaped the text on its own. A long session with four file reads per prompt runs about 12 % fewer user-mode instructions per prompt and about 5 % less CPU time (paired `perf stat`, 10 sessions each; CPU time per prompt 38.8 ms to 36.3 ms at 20 prompts, 46.2 ms to 44.3 ms at 40), and a one-prompt headless run about 13 % fewer. The bytes of the tool event, the session file and the request body are unchanged. The encodings a read makes before a request uses them are held to 4 MiB, so a process that reads files and sends no request keeps a few MiB, not the request cache's 64 MiB limit.
