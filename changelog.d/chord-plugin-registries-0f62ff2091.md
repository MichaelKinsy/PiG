### Fixed

- In the unreleased app kit, a plugin's contribution to `Translations` (server and worker) or `Themes` (server) was seen by no one, and a plugin object that read `self.registry(Translations)` or `self.registry(Themes)` never became ready (`registry chord.translations: no plugin serves it here`); a worker's plugins had no translations registry at all. The plugins' Node host now loads Pi's own `translationsFacet` (server and every worker) and `themesFacet` (server only, as Pi's worker has none) before the plugins, as Pi's one host does, so a contribution and a read meet in one registry, an unloaded or reloaded plugin's catalogs follow it, and a plugin that serves `Translations` again is refused as in Pi.
