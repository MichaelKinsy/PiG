### Changed

- A TypeScript extension project that imports `@michaelkinsy/pig-extension-types` type-checks `@earendil-works/pi-coding-agent`, `pi-ai`, `pi-tui` and `pi-agent-core` against the Pi build PiG is pinned to, not against the installed release. The package ships `pi-pin.d.ts`, the pinned build's declarations as ambient modules, which `index.d.ts` references; it needs no `tsconfig` entry and works with `moduleResolution` `Node16` and `Bundler`. While the pin equals the published release the declarations are the release's. Once the pin is past it, the header of `pi-pin.d.ts` lists the exported declarations PiG has and that release lacks, and `make test-sdk-ts` prints them; the test that failed on such a difference now requires the bundle to equal the pinned build.
- `@michaelkinsy/pig-extension-types` declares the packages its declarations import as peer dependencies, at the versions the pinned Pi packages declare: `@anthropic-ai/sdk`, `@earendil-works/pi-codemode`, `@earendil-works/pi-mcp`, `@earendil-works/pi-schema`, `@earendil-works/pi-telemetry`, `@google/genai`, `marked`, `openai` and `typebox`. npm 7 and later and pnpm install them with the package. They are packages Pi's own install already brings, at the same versions while the pin equals the release, so the install adds nothing. `make vendor-sdk-ts-pin-declarations`, a step of `make pin-bump`, writes the bundle and the peer list.

### Fixed

- The README installed `@michaelkinsy/pig-extension-types` from the source tree as a link, and the compiler then resolved the package's imports from the folder: the PiG-only members, `ctx.ui.setLogin` of the README's own example among them, were missing from Pi's types. The install command now passes `--install-links`, and the README names `preserveSymlinks` for a project that keeps a link. <!-- fix: 849f5f9c8d -->
- `registerMarkdownTransformer`'s `context` and `ui.onThemeChange`'s `theme` were `any`: `index.d.ts` named `MarkdownTransformContext` and `Theme` without importing them. <!-- fix: 849f5f9c8d -->
