### Fixed

- Accepting an autocomplete suggestion after the cursor moved off the typed text (a word move, Home or End) cuts the line where Pi does when the text before the cursor holds non-ASCII characters, instead of a few bytes away, where it could split a character. <!-- fix: 532a0099a8 -->
- Typing a space or a letter such as `é` right after a slash command whose arguments have completions no longer opens the argument popup unless Pi opens it. Pi opens a closed popup only for `/` at the start of the message, for a trigger character, and for a letter, digit, `.`, `-`, `_` or CJK character in a slash command or trigger context. <!-- fix: 24b67ccb05, e790f48f58 -->
- Typing fast into an `@`, `#` or provider-trigger token, or while a slow autocomplete provider is still working, no longer loses the popup: a character that triggers nothing (a space, `é` or `/` after `@al`) leaves the pending request alone, and the request asks the provider about the text the editor holds when it starts, as Pi does, instead of asking nothing. <!-- fix: 74c3fde97e -->
- The `@` file search of an editor without a host loop (the extension view editor) takes the text current when its debounce ends, as Pi does: typing a space, `é` or `/` right after `@al` no longer loses the search. <!-- fix: a1be5452a3, f294c50ce3 -->
