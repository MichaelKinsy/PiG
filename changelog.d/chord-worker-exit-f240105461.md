### Fixed

- chord: a worker that fails right after it started now reports its reason. The server could handle a worker's exit before it had read, or before it had handed over, the last messages the worker wrote (its answer to a waiting holder and its `fatal` report); it then closed the connection and recorded the fixed `worker failed to start` (in p2, under load: a session whose worker dies at its start showed that text where Pi shows why, for example `Unknown model`). As in Node, which emits a child's messages before its `exit` event, the exit is now told after the channel's reader took and told everything the worker wrote. Present in v0.7.0 (the one release with the workers component). Limits: not run on Windows, where a worker that ends before the server accepted its pipe connection can still lose its last messages. <!-- fix: f2401054610c5a07d40c3a4eeaa39a1f32b96f0d -->
