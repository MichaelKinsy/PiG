# Ten pigbench extensions on PiG's TypeScript runtimes: ready, per-turn CPU split, RSS (PROVISIONAL: do not publish)

Tip: integrate-042 3352c45971 plus bench/bolt-aot (`bench/bolt-aot/ext10_bench.py`, 12 interleaved rounds after a warm-up, order rotated each round). Set: `bench/evals/fixtures/extensions/bench-ext-01..10.ts` (the rpc-ext10 shape: each extension has a tool, a command and four event handlers). Per run: `pig --mode rpc` with the ten extensions and a scripted local model; ready = spawn to the ten `bench-NN` commands listed; then 20 turns, each a prompt, a model tool call, the tool and a final answer. CPU is /proc utime+stime (10 ms ticks, summed over 20 turns) of the pig process (the Go host) and of its descendants (the extension host). Cells are median [min-max] of 12 runs; one shared host, 1-minute load average median 186, so only ratios inside the run mean anything. Each run asserts the extension host process is the tier the arm names.

Arms:
- **node**, **node2** (A/A repeat of node), **bun** (Bun 1.4.2 stock slot).
- **aot** = pig-pi-bolt: the merged aot Piglet with the ten extensions compiled into the host at build time (image built by the Piglet's worker from the first launch's build request; it runs from the next start).
- **aot-dyn** = the prebuilt aot host with jiti compiled in and no extension compiled in (the dynamic host of `make test-aot-conformance`), loading the ten from source at run time.

## Reading it

- **A/A:** node and node2 agree within 1-6% on every row, so a difference under about 10% is noise here.
- **The Go host dominates the turn on every runtime.** CPU per turn is about 285-293 ms in the Go host against 81-96 ms in the extension host, on node, bun, aot and aot-dyn alike. The runtime changes the extension side by at most 15 ms (aot 84, aot-dyn 81 against node 88): this matches pig-evals' finding (handoffs/pig-evals-ext10-profile) that the per-turn cost is in the Go host's boundary work, not in the runtime. Wall per turn is 255-261 ms on all five.
- **Ready on this set: aot is not faster than Node.** The ten extensions import nothing, so Node loads them in 0.5 s; aot needs 0.6 s (compiled in: 605 ms, dynamic: 634 ms), Bun 2.1 s. The extension host itself is cheaper compiled in (215 ms CPU to ready against Node's 500 ms), but PiG's Go host spends about 225 ms more CPU to ready on the aot arms (555 and 550 against Node's 330): it hashes the 233 MB executable (SHA-256 of the file takes 0.22 s here) each time it selects the runtime (`coding/extension/host/tsruntime/verify.go`). That cost is in core, not in the Piglet. (The five-extension set of 2026-10-11-12-rounds-aa.md, where Node needs 1.65 s because its extensions import large packages, is where aot's start wins 2.8x.)
- **Memory:** the compiled-in host holds the least (RSS 99 MB at ready, 92 MB after 20 turns; Node 129 and 216; Bun 321 and 362). The dynamic host sits between (135 and 127). The Go host is 67-69 MB on every arm.
- Compiled in against run-time loading: 29 ms less to ready, 36 MB less RSS at ready and 35 MB less after the turns, and the same per-turn CPU: for ten trivial extensions the d1 shape (compiled in) is only a memory win, not a speed win.
