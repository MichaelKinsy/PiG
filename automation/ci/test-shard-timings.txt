# Recorded durations of the top-level tests of a sharded package, read by shard-balance.py (see its docstring).
# `serial <seconds> <Test>` is a test that runs alone, `parallel <seconds> <Test>` one that calls t.Parallel; the seconds are
# the median of `go test -v` runs of the package's shards in a container limited to 4 CPUs (a CI runner's), where
# the eight-shard run had shards of 337 to 578 s. The model lines are fitted to the shard times of those runs:
# a shard's predicted time is fixed + serial-factor * (its serial tests' seconds) + parallel-factor * (its parallel
# tests' seconds), and default is the cost of a test the file does not name (the mean of the 90% shortest).
#
# To record again (a test that took a minute is not here, or the check in test/ci-images/shard_balance_test.go names a shard over
# its limit): run the package's shards with GOFLAGS=-v in a 4-CPU container, `make test-conformance` or the two
# test-conformance-N targets, keep the logs, and
#   automation/ci/shard-balance.py record --package ./test/extension-conformance LOG... > new.txt
# then replace this section with new.txt and rewrite the pins with
#   automation/ci/shard-balance.py pack --package ./test/extension-conformance --shards 14
# into the 14-shard section of test-shard-weights.txt. Several logs make the median steadier; the logs of CI's own
# runs (go test -v output in the job log) do too.
